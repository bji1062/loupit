# jobcho.wiki(loupit) — 같이 만들 개발자를 찾습니다

> **한 줄로**: 로그인 없이 두 직장의 실질 처우를 비교하는 도구입니다. 이미 `jobcho.wiki`에 라이브로 떠 있고, 회사 102개·복지 1,465행·테스트 1,470개가 돌아가고 있습니다. 지금 필요한 건 새 아이디어가 아니라 **이 원칙을 깨지 않고 사용자를 늘릴 사람**입니다.

**결론부터 세 가지**

1. **제품은 이미 살아 있습니다.** 기획 단계가 아닙니다. 문서 8단계(PRD→TASK)를 다 통과했고, 프로덕션에 배포돼 실사용자를 받고 있으며, 로그인·재직인증·복지편집까지 켜져 있습니다.
2. **이 서비스의 정체성은 "사용자에게 아무것도 요구하지 않는다"입니다.** 가입도, 개인정보도, 서버 저장도 없습니다. 이건 기능 목록이 아니라 **깨면 안 되는 불변식**이고, 코드와 테스트로 강제돼 있습니다.
3. **가장 큰 약점은 트래픽입니다.** 실브라우저 세션이 하루 고유 IP 2~10개 수준입니다. 제품은 됐고 유통이 안 됐습니다. **그 구간을 같이 넘길 사람**을 찾습니다.

## 1. 이 서비스의 ego — 무엇을 포기하고 무엇을 지키는가

대부분의 서비스는 "무엇을 할 수 있는가"로 자기를 설명합니다. 이 서비스는 **"무엇을 하지 않기로 했는가"**로 자기를 설명합니다. 아래 다섯 개가 이 제품의 자아이고, 이걸 지우면 그냥 흔한 취업 사이트가 됩니다.

### ego 1. 사용자에게 문턱을 만들지 않는다 — 로그인 0단계

비교 도구를 쓰는 데 회원가입·로그인·소셜 로그인이 **하나도** 없습니다. 검색으로 들어와서 바로 쓰고 나갑니다.

- 익명 경로에는 인증 미들웨어가 존재하지 않습니다(있으면 아키텍처 테스트가 깹니다).
- 비밀번호 로그인·OAuth·소셜피드는 **영구 제외** 결정입니다. "나중에 붙이자"가 아니라 안 붙입니다.
- 예외는 딱 하나, **복지 데이터를 등록·수정하는 기여자**뿐입니다(아래 ego 4).

### ego 2. 사용자 데이터를 서버에 두지 않는다 — 그래서 팔 것도 없다

연봉, 복지, 통근시간, 우선순위 — 사람들이 가장 말하기 싫어하는 숫자를 다루는 서비스입니다. 그래서 **서버로 보내지 않습니다.**

- 비교 계산은 **100% 클라이언트 사이드**입니다. 서버는 참조 데이터만 내려줍니다.
- 입력값·최근 비교·입력 초안은 브라우저 `localStorage`에만 있습니다. 서버 전송 0.
- 서버에 남는 익명 데이터는 **"어떤 회사쌍이 비교됐는가" 카운트 1종**뿐입니다(개인 식별 불가, 세션 중복 제거 후 기록).
- 수익 모델에 "사용자 데이터 판매"가 구조적으로 들어갈 수 없습니다. 팔 데이터가 없으니까요.

> 이건 프라이버시 마케팅이 아니라 **아키텍처 제약**입니다. 서버가 사용자 상태를 모르기 때문에 백엔드가 얇고, 백엔드가 얇아서 무료 티어 서버 1대로 굴러갑니다. 원칙과 비용 구조가 같은 방향을 봅니다.

### ego 3. 모르는 것은 모른다고 말한다 — 정직한 데이터

취업·연봉 정보 서비스의 고질병은 "그럴듯하지만 근거 없는 숫자"입니다. 여기서는 숫자마다 **자기 출처와 신뢰도를 달고 다닙니다.**

- 금액 출처를 `stated`(회사가 명시) / `estimated`(추정)로 구분해 표시합니다.
- 신뢰도에 따라 **불확실성 밴드**를 계산에 반영합니다 — 명시 ±5%, 추정 ±20%, 만료된 정보 +15%.
- 배지는 **출처 계보**를 보여줍니다: `공식` / `공식·재직자 수정` / `재직자 등록`. 어디서 온 숫자인지 사용자가 압니다.
- 데이터 정확성을 100% 보장하지 않는다고 면책 문구로 **먼저** 말합니다.

정직하게 말하면 숫자가 덜 화려해집니다. 그 손해를 감수하는 게 이 제품의 성격입니다.

### ego 4. 익명 열람 + 인증 기여 — 나무위키식 참여 모델

읽는 사람에겐 아무것도 안 묻고, **고치는 사람에게만** 자격을 묻습니다.

- 열람·비교는 끝까지 익명입니다.
- 복지 데이터를 등록·수정하려면 **무비밀번호 이메일 코드 로그인 + 회사 도메인 이메일 재직 인증**을 통과해야 합니다.
- 그마저도 PII를 최소로 받습니다 — 로그인 이메일과 닉네임뿐. 회사 이메일 원문은 **파기하고 HMAC 해시만** 보관합니다. 세션 토큰도 해시만 저장합니다.
- 편집 이력은 append-only로 공개됩니다. 누가 뭘 바꿨는지 숨기지 않습니다.

### ego 5. 콘텐츠가 수익의 뼈대다 — 광고가 UX를 이기지 못한다

수익원은 AdSense와 제휴 링크뿐입니다(유료 구독·결제 없음). 그런데 광고 배치에 **스스로 건 제약**이 있습니다.

- **비교 입력 화면은 무광고 강제** — 자동광고 스니펫도, 수동 슬롯도, 제휴 컴포넌트도 렌더링하지 않습니다. 코드에서 게이팅합니다.
- 결과 화면은 리포트 하단 1슬롯만. 판정 카드 위나 본문 중간 삽입 금지.
- 광고 밀도는 회사 상세·비교 조합 같은 **콘텐츠 페이지**에만 실립니다.
- 광고·제휴에는 "광고" 표기(공정위 표시광고 규정 준수).

돈은 검색으로 들어온 정적 콘텐츠 페이지에서 벌고, 도구를 쓰는 순간에는 방해하지 않는다 — 이게 수익 설계의 전부입니다.

## 3. 기술 스택 — 그리고 왜 이렇게 골랐는가

| 레이어 | 선택 | 이유 |
|---|---|---|
| 프론트 | **바닐라 JS(무빌드) + ES 모듈 + HTML5/CSS3** | 번들러·프레임워크 없음. 소스가 곧 배포물. Core Web Vitals "양호" 유지가 SEO 수익 모델의 전제라서 |
| 백엔드 | **FastAPI(async) + aiomysql + 원시 SQL(no ORM)** | 참조 데이터 읽기가 대부분. 얇게 유지하는 게 목적 |
| DB | **MySQL 8.0 (utf8mb4)** | 기존 큐레이션 데이터 자산 승계 |
| 정적 생성 | **파이썬 빌드 스크립트** | 회사·조합 페이지 + sitemap을 원자적 스왑으로 배포(`dist.prev` 롤백) |
| 인프라 | **Oracle Cloud ARM(Always Free) + Nginx + systemd + Let's Encrypt** | 서버 비용 0원. 제약이 설계를 얇게 만듭니다 |
| 디자인 | 크림 캔버스 + 코랄 액센트 + 세리프 디스플레이, CSS 변수 토큰 전용 | 컴포넌트에 색상 리터럴 금지(테스트로 강제), WCAG AA 62/62 통과 |

**즉, 유행하는 스택은 하나도 없습니다.** 프레임워크를 안 쓰는 게 자랑이 아니라, "무료 서버 1대 + 검색 유입 + 클라이언트 계산"이라는 제약에서 역산한 결과입니다. 이 제약을 재미있다고 느끼는 사람에게 맞는 프로젝트입니다.

## 4. 개발 문화 — 여기가 좀 별납니다

### 문서 주도 개발
`docs/`에 8단계 파이프라인(PRD → USECASE → FRD → FLOW → WIREFRAME → SPEC → TASK → 구현)이 전부 작성돼 있습니다. 97개 FR, 34개 화면 와이어, 286개 작업 리프까지 ID로 추적됩니다. **"왜 이렇게 돼 있지?"의 답이 거의 항상 문서에 있습니다.**

### TDD 필수
red-green-refactor. 새 모듈·공개 함수·라우트는 테스트 먼저. **완료 기준 = 구현 + 테스트 green 둘 다.** 한쪽만이면 진행 중입니다.

### 함정 로그
지금까지 밟은 함정 66개가 번호를 달고 핸드오프 문서에 남아 있습니다. 예를 들면:

- *"테스트가 '이 키는 환경에 없다'를 전제하면, 그 키를 쓰는 날 반드시 깨진다"* — 로그인 기능을 켜는 릴리스가 4번 만에 성공한 이유.
- *"사양대로 동작한 소멸은 오류를 남기지 않는다"* — "TOP 10이 사라졌다"를 회귀로 오진할 뻔했다가, 진짜 원인이 **사용자가 없어서**였다는 걸 찾은 기록.
- *백업과 시드가 같은 테이블을 두 번 복원하다 데이터를 실제로 잃은 사건* — 그래서 "시드가 복원하는 테이블은 백업 대상이 아니다"라는 불변식 테스트가 생겼습니다.

**실패를 지우지 않고 번호를 붙여 남깁니다.** 새로 합류하는 사람은 이 목록부터 읽으면 같은 함정을 두 번 밟지 않습니다.

### 애매하면 묻는다
결정이 필요한 지점에서 임의 판단하지 않습니다. 결정 게이트(DG-1~4)와 승인 게이트(프로덕션 컷오버 등)가 문서에 명시돼 있습니다.

## 5. 지금 필요한 사람 (실제 남은 일)

솔직히 적습니다. 아래는 만들어낸 로드맵이 아니라 **현재 핸드오프 문서의 남은 작업**입니다.

| 역할 | 하게 될 일 | 왜 급한가 |
|---|---|---|
| **그로스 / SEO** | 색인 확대, 콘텐츠 페이지 구조 개선, 유입 실험 | 트래픽이 하루 2~10 세션. 제품이 아니라 유통이 병목 |
| **프론트엔드** | 접근성 QA(포커스링·axe/Lighthouse·200% 확대·reduced-motion), 터치 기기 롤링 오조준 수정, 비교 입력 UX | 모바일 우선 사용자인데 터치 대응에 실결함이 남아 있음 |
| **데이터** | 회사·복지 데이터 확장, 그룹 공통 복지 태깅, 출처 확증 | 콘텐츠가 곧 SEO 자산이자 수익 기반. **회사명에서 도메인을 추측하는 건 금지** — 잘못 매핑하면 엉뚱한 사람이 재직 인증됨 |
| **백엔드 / 인프라** | 서버 밖 백업 자동화, DMARC 승급, 호스트 방화벽, 404 noindex | 서버 1대·백업 서버 밖 사본 없음이 현재 최대 운영 리스크 |

## 6. 솔직한 리스크 (합류 전에 아셔야 할 것)

- **트래픽이 거의 없습니다.** 하루 고유 IP 2~10개. 수익은 사실상 아직 0에 가깝습니다.
- **서버는 1대(무료 티어)입니다.** 이중화 없음. 백업은 서버 안에만 있습니다.
- **데이터 정확성은 완전 보장 대상이 아닙니다.** 그래서 배지·밴드·면책으로 정직하게 처리하는 쪽을 택했습니다.
- **수익 추정은 전부 (가정) 표기입니다.** 문서에 붙은 매출 수치는 규모 감각용이지 약속이 아닙니다.
- **원칙이 셉니다.** "로그인 붙이면 리텐션 오를 텐데", "데이터 좀 모으면 되는데" 같은 제안은 이 제품에선 받아들여지지 않습니다. 그 제약 안에서 문제를 푸는 걸 즐길 수 있어야 합니다.

## 7. 합류하는 법

```bash
git clone git@github.com:bji1062/loupit.git
cd loupit
npm install            # 또는 bun install (프론트 테스트용 jsdom)
bash infra/deploy/run_tests.sh
```

그다음 읽을 순서:

1. `README.md` — 5분
2. `docs/HANDOFF-2026-07-31.md` — **재개 정본.** 현재 상태·남은 작업·최근 함정
3. `docs/PRD/01-개요.md`, `docs/PRD/04-범위.md` — 무엇을 하고 무엇을 안 하는지
4. 함정 목록 — `HANDOFF-2026-07-27-B §5` → `-28 §4` → `-29 §4` → `-29-B §4` → `-30 §4` → `-31 §4`
5. 손댈 도메인의 `docs/SPEC/`, `docs/TASK/`

⚠️ **테스트는 반드시 `bash infra/deploy/run_tests.sh`로만 실행하세요.** 맨 `pytest`로 DB 테스트를 돌리면 서빙 스키마를 날립니다(가드가 막지만, 우회하지 마세요).
