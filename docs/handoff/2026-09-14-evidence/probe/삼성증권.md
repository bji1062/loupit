## 수집 설계 시 유의 (수집·SQL은 이번 범위 밖)

1. **hm_url(samsungpop)을 따라가면 0건이다.** 회사 도메인은 `samsungsecurities.co.kr` 이고, 그 안에서도 GNB·사이트맵이 `FnMenu.data.js` 로 JS 렌더라 원본 HTML 링크 크롤로는 `/kor/recruit/benefit.do` 에 닿지 않는다. URL 을 직접 고정할 것.
2. **출처는 도메인별로 갈라 적는다.** 정본(자기 도메인 24개, 라벨만)과 보조(samsungcareers E40 23개, 설명문 포함)는 17개가 겹치고 이름이 다르다(「선택형 복지 포인트 지급」↔「선택적 복지 포인트」, 「휘트니스 센터 운영」↔「사내 피트니스」, 「전국 리조트 이용 지원」↔「휴양소 지원」). 합칠 때는 정규화로 중복을 없애고, 배지 계보는 자기 도메인과 그룹 채용사이트로 나눠 표기한다. 그룹 공통 `/insight/welfare` 는 섞지 않는다.
3. **법정 제도 제외**: 정본 「4대 보험」은 수록하지 않는다. 「자녀 학자금 지원」의 `<br>` 뒤 괄호 줄과 「출산선물, 돌반지 지원」의 쉼표는 항목 경계가 아니다.
4. **갱신 감지는 복지 블록 해시로 한다.** 정본 `<title>` 에 서버 노드 표기(`[A1]`/`[A3]`)가, CSS·JS 링크에 13자리 캐시버스터가 붙어 요청마다 바뀐다. 페이지 전체 해시를 쓰면 매번 「변경」으로 잡힌다. 정본은 `div.benefit`, 보조는 `ul.welfareList` 만 해시할 것. 보조는 파싱 전에 `h2` 의 「삼성증권」과 `ss.recruit@samsung.com` 으로 법인을 검증한다. E40 코드가 바뀌면 다른 법인을 조용히 긁는다.
5. **재무 축 확인 요청(리드)**: 설립 1982-10-19의 장기 상장사라 사업보고서 이력 문제는 없어 보인다. 다만 증권사는 손익계산서가 금융업 양식(매출액 대신 「영업수익」)이다. 리포에서 금융업 매출 매핑을 처리한 기록은 찾지 못했다(`docs/handoff` 2026-09-05 이후 증거·`server`·`infra`·`scripts` 에서 `영업수익` 0건). 삼성화재 등록 때 매출 축이 어떻게 채워졌는지 확인 바란다(이번 프로브에서 DART 는 조회하지 않음).
