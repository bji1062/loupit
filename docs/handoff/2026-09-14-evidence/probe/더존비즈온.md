## 수집 설계 시 유의

1. **어느 출처로 등록할지가 먼저다.** 안정적인 텍스트 출처(benefits.jsp)는 「더존ICT그룹」 표기 + 5개 법인 공용이라 **그룹 공통 계보로 낮춰 표기**해야 하고, 법인 명시 출처(REM2026048 이미지)는 **이미지 판독 필요 + 2026-09-16 23시 마감 후 목록에서 사라질 수 있다**. 법인 확정 배지를 원하면 마감 전에 판독·원문 대조를 끝내야 한다.
2. **두 목록을 합치지 말 것.** benefits.jsp 8개와 공고 9개는 겹치지만 같지 않다(휴가제도·각종행사 vs 명절선물·통근 노선·사내 카페). 합집합을 만들면 어느 출처도 하지 않은 목록이 된다. recruit SPA `/benefits` 는 benefits.jsp 의 중복본이라 따로 세지 말 것.
3. **법정 제도 제외**: benefits.jsp 의 「4대 사회보험」(단체상해보험 설명 속 전제)·「연차휴가」·「출산전후휴가」, 공고의 「법정복리: 4대 사회보험, 퇴직금」은 미수록. 「정기 건강검진」은 법정 일반건강검진과 경계라 판단이 필요하다.
4. **한 항목에 여러 제도가 묶여 있다.** benefits.jsp 「복리후생시설」 한 줄 = 카페테리아·사내식당·헬스케어센터·사내어린이집·통근버스. 분할 규칙을 정하고, 「강촌캠퍼스/강촌 본사 한정」 같은 **거점 한정어를 설명에 보존**할 것(어린이집·식당·카페는 전 사업장 제도가 아니다).
5. **호출 규약**: robots.txt·sitemap.xml·없는 경로가 전부 200 HTML(53,387B 404 페이지 / 1,347B SPA 셸)이라 robots 파서가 HTML 을 규칙으로 읽지 않게 방어할 것. SPA 청크는 `\uXXXX` 디코드 후 파싱, 공고 API 는 파라미터 없이 부르면 500. 인증서 2026-12-12 만료.
