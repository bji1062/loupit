# 씨젠 (Seegene, Inc. · KOSDAQ 096530) — 복지 수집 가능성 실사 프로브

**판정: 가능** — 회사명이 붙은 전용 채용 서브도메인 `seegene.recruiter.co.kr` 의 복리후생 페이지에 항목 20개가 텍스트로 있다(JS 렌더). 공식 본사 도메인에는 채용·복지 섹션이 아예 없다.

- 정본 URL: `https://seegene.recruiter.co.kr/career/welfare` (제목 「복리후생 | 씨젠 채용」)
- 항목 수: 20개 라벨(설명문·금액 없음) · 카테고리명 없음(슬로건 헤딩 2개 아래 8 + 12) · 법정 제도 1개 포함(산전후휴가/육아휴직)
- 렌더 방식: Next.js App Router CSR — 원본 HTML 에 항목 0, Playwright 렌더 필요. 항목 데이터는 `infra1-static.recruiter.co.kr` 빌더 JSON

주의(리드 확인 요청 2건): ① 항목 JSON 의 URL 을 알려주는 `api-recruiter.recruiter.co.kr` 가 robots `Disallow: /` 다(페이지 경로 자체는 허용 — ③ 참조). ② 공식 사이트(`kr.seegene.com`)에서 이 채용 서브도메인으로 가는 링크가 없다. 반대 방향(채용사이트 → 공식 사이트) 링크만 있다.
AI 봇 UA 를 이름으로 막는 robots 그룹은 조사한 4개 호스트 어디에도 없다.

- 회사: (주)씨젠 / 분자진단 시약·장비. 본사 서울특별시 송파구 오금로 91(채용사이트 기업소개 기재값)
- 프로브 일시: 2026-09-14
- 요청 수: curl HTTP 33회(리다이렉트 홉 포함) + Playwright 페이지 로드 2회. 단, 렌더 2회가 하위 리소스를 대량으로 불렀다(채용 호스트 84건 — 대부분 `_next` 청크·라우트 프리페치, 이미지·폰트·미디어는 차단). 수집 설계 시 렌더 1회 비용이 크다는 점 참고.

## 수집 설계 시 유의

1. **공식 회사 사이트와 그 sitemap 에서 출발하지 말 것.** `kr.seegene.com`·`www.seegene.com` 에는 채용·복지가 없고, sitemap 에 남은 `/careers/career-at-seegene`·`/careers-list` 는 404 다(`lastmod` 는 생성 시각이라 신선도 신호도 아니다). 출처는 `seegene.recruiter.co.kr/career/welfare` 하나. 공식 사이트가 이 서브도메인에 링크하지 않는다는 점을 출처 표기에 남긴다.
2. **렌더가 필요하고, API 는 직접 부르지 말 것.** 원본 HTML 에 항목 0. JSON URL 은 날짜+UUID 라 재게시하면 바뀌고, URL 을 주는 `api-recruiter` 는 robots `Disallow: /` 다. Playwright 렌더 DOM 에서 뽑고, 갱신 감지는 빌더 JSON 해시로 한다. 하위 리소스 robots 해석(③)과 `infra1-static` robots 403 은 리드 결정 사항.
3. **줄 단위로 자르면 25조각이 된다.** 복합 라벨 5개가 「A/」「B」 두 문단이라 `inner_text` 줄 분리로는 `장기근속자 포상/` 과 `포상휴가` 가 따로 나온다. TEXT 콘텐츠 하나를 한 항목으로 잇고, 헤딩 「당신이 있어 ~ 아름답습니다.」 2개는 카테고리가 아니라 슬로건이니 항목·카테고리에서 뺀다. `경조금/경조휴가`·`힐링데이/돌봄데이` 처럼 서로 다른 제도가 한 라벨에 붙은 것은 코드 분리 여부를 어휘표로 판단.
4. **법정 `산전후휴가/육아휴직` 제외 → 실수록 후보 19개, 전부 라벨만.** 설명문·금액이 0이라 행마다 원문 근거는 라벨 문자열 자체뿐이고 본문 분량 기여는 작다. 금액(AMT)을 채울 원문이 없다.
