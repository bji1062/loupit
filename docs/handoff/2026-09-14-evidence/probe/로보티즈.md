## 수집 설계 시 유의 (수집·SQL은 이번 범위 밖)

1. **공식 도메인만 긁으면 0건**이다. `www.robotis.com` 에는 복지 페이지가 없고, `/ko/recruit.php` 의 302 착지점도 `/welfare` 가 아니라 `/jobs` 다. 정본은 `robotisrecruiter.ninehire.site/welfare` 로 고정하고, 출처 표기에 「공식 도메인이 연결한 회사 전용 ATS(나인하이어)」임을 남긴다. `customDomain` 이 비어 있고 `isDefaultDomain: true` 라서, 회사가 나중에 커스텀 도메인을 붙이면 URL이 바뀐다. 갱신 때 `robotis.com/ko/recruit.php` 의 302 대상을 먼저 확인할 것.
2. **`__NEXT_DATA__` 는 페이지 8개 전부(초안·「개인정보처리방침 샘플」 포함)를 모든 URL에 통째로 싣는다.** 전체 문자열에서 복지를 뽑으면 다른 페이지 텍스트가 섞인다. 반드시 `homepage.pages` 에서 `pageUrl == "welfare"` 인 페이지만 골라 `sections → layouts → columns(invisible=false) → blocks` 순으로 읽을 것.
3. **엔티티가 이중 이스케이프돼 있다.** 원본 데이터에 `출산&middot;육아&middot;가족돌봄 지원` 이 리터럴로 저장돼 있고, SSR HTML에는 `&amp;middot;` 로 나가서 **실제 화면에도 「&middot;」가 글자 그대로 보인다**. 파싱 후 `html.unescape` 를 한 번 더 걸거나 `·` 로 정규화하되, 원문 보존 필드를 따로 둘 것.
4. **`what is NEXT...?` 예고 카드를 걸러낼 것.** 항목 카드와 구조가 똑같아서 그대로 두면 10개가 11개로 부풀고 「로보티즈의 다음 복지를 기대해주세요!」가 제도로 등록된다. 이것도 계약 §3 기준으로 항목이 아니다.
5. 사이트가 2026-02 개설에 2026-09-09까지 편집 중이라 **항목이 자주 바뀔 수 있다**. 갱신 감지는 URL이 아니라 welfare 페이지 `sections` JSON 해시로 하고, 인증서가 Let's Encrypt 90일(현재 ~2026-11-26)이라는 점도 재수집 때 참고한다. 항목이 10개에 설명이 한 줄씩이라 본문 분량 기여는 삼성화재(30항목)보다 작다.
