- `*.kiwoom.com`: curl 11회(GET 10·HEAD 1) + Playwright 렌더 1회에 딸린 39회(문서 1 + CSS·JS 38, 이미지·폰트·미디어는 차단) = **50회**. **계약 한도(회사당 ≤40)를 넘었다** — 헤드리스 렌더의 하위 리소스를 막지 않고 계산에 넣지 않은 탓이다. 렌더 이후에는 kiwoom.com 에 요청하지 않았다. curl 요청 간격은 ≥1.1초, Playwright 하위 리소스는 브라우저 기본 병렬.
- 그 밖: `kiwoom.saramin.co.kr` 3회, `www.kiwoomam.com` HTTP 1회(TLS 검증 실패로 HTTP 교환이 없던 시도 2회 별도).

## 수집 설계 시 유의 (수집·SQL은 이번 범위 밖)

1. **정본은 `www3.kiwoom.com/h/ir/recruit/VWelfareView`, 선택자는 `div.box-grid-wrap.welfare`.** hm_url `www.kiwoom.com` 루트는 JS 리다이렉트 껍데기라 긁으면 0건이다. 원본 `<title>` 이 IR 기본값(「개요/주주현황…」)이라 제목 대신 **`strong.subject` 6개 + `li` 16개 존재**와 푸터 사업자등록번호 `107-81-76756` 으로 법인·페이지를 검증할 것.
2. **갱신 감지는 페이지 전체가 아니라 복지 블록 해시로.** 인라인 안티봇 토큰(`IbMNZ`·`?evfw=`)이 요청마다 바뀌어 전체 바이트 해시는 늘 「변경」으로 나온다. 안티봇이 지금은 통과지만 탐지 로직이 켜지면 막힐 수 있으니, 본문 20KB 미만이거나 `welfare` 블록이 없으면 **차단으로 처리**할 것.
3. **한 `<li>` 안에 제도가 여러 개 있다.** `경조 휴가, 경조금 및 장의용품 지원` · `공동직장보육시설 및 수유실 운영` · `생일, 결혼기념일 선물 지급` · `설, 추석 명절 선물 지급` · `주택구입·임차 자금 대출 지원`. 쉼표로 기계 분할하면 「설」「추석 명절 선물 지급」 같은 조각이 생긴다. 분할 여부는 어휘표 기준으로 사람이 정할 것. `선택적 복리후생제도 운영` 은 복지포인트(카페테리아) 계열 매핑 후보다.
4. **법정 제도 여부 검토 대상**: `공동직장보육시설 및 수유실 운영` 은 직장어린이집 설치 의무(영유아보육법) 이행분일 수 있다. 「법정 제도 미수록」 규칙에 걸리는지 리드가 판단할 것. 나머지 15개는 회사 재량 제도로 보인다.
5. **호출 규약**: GET, 일반 브라우저 UA, `www3.` 호스트(www 도 동일). EV 인증서가 **2026-10-09 만료**라 그 뒤 재수집 때 검증 실패를 먼저 확인할 것. 헤드리스는 필요 없다 — 원본 HTML 로 충분하고, 렌더를 쓰면 하위 리소스 40여 회가 따라온다(이번 프로브가 한도를 넘은 원인).
