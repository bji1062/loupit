- 가온전선은 **같은 카테고리에 「하기휴가」가 별도 `li` 로 있다** → `summer_leave` 는 그 항목이 쓰고, BENEFIT_CD 가 회사당 UNIQUE 라 休weeks 를 거기 넣을 수 없다. 원문이 두 항목을 따로 적었으므로 같은 제도로 합치지도 않았다.
- 남는 선례가 두산에너빌리티(`refresh_leave`)다. `summer_leave` 와 `refresh_leave` 를 한 회사가 함께 가진 선례도 있다(LIG넥스원 「여름휴가 5일」 + 「리프레시/Re-Fill 휴가」).
- ⚠ **반대 논거·대안**: 집중 휴가제가 추가 휴가 부여가 아니라 보유 연차를 몰아 쓰게 하는 운영 방식이라면 `refresh_leave`(리프레시 휴가 보유)는 급부를 부풀린다. 대안은 `leave_general`(휴가제도, time_off) — SORT·카테고리 그대로 코드만 바뀐다. 코퍼스에 「집중 휴가」를 `leave_general` 로 둔 행은 없다. 사용자 노출 서술은 「휴가 기간·부여 일수·사용 방식 미기재」로 두어 추가 일수를 주장하지 않았다.

### 판단 ② 「하기휴가, 하기휴가비 지급」 → `summer_leave` 1행 (휴가비 서술 포함) ⚠ 세션 중 번복

- 처음에는 `summer_leave` + `summer_vacation_subsidy` 2행(14행안)으로 썼다가 코퍼스 대조 후 1행으로 되돌렸다.
- 근거: (a) **같은 라벨 선례** — 한국항공우주산업 「하기휴가」 = `summer_leave` 1행, 서술 「하기휴가(5일) 연차와 별도 제공, 하기휴가비 지급」. (b) 휴가비 서술을 담은 휴가 행이 코퍼스에 여럿이다 — `summer_leave`: HPSP 「여름휴가」·솔브레인 「하계 유급휴가」·현대로템 「하계휴가」·한국항공우주산업, `refresh_leave`: 두산에너빌리티·한미반도체 「특별 휴가 1주일 + 휴가비」 등. (c) `summer_vacation_subsidy` 는 코퍼스 1행(심텍 「하계휴가비」)뿐이고, 심텍 원문에는 하계휴가 항목이 **없었다**(휴가비 단독 라벨). 가온전선은 휴가와 휴가비가 **한 `li`** 다.
- 2행으로 나누면 비교에서 `summer_vacation_subsidy` 보유사가 심텍·가온전선 둘만 되고, 휴가비를 휴가 행에 적은 위 회사들은 빠져 비교축이 틀어진다.
- ⚠ **대안**: 규칙 9(「병합은 같은 코드로 귀결되는 항목만」)를 엄격히 읽어 휴가비를 다른 코드로 보면 14행안이다 — `summer_vacation_subsidy` / leisure / SORT 51 / NM 「하기휴가비」 / QUAL_DESC 「하기휴가비 지급 (공식 채용 페이지 복리후생 여가 지원 항목 — 지급액·지급 시기 미기재)」, `club` 은 52 로 밀린다.

### 판단 ③ 「기념일 선물(생일선물, 추석선물)」 → `birthday_gift` + `holiday_gift` 2행

- 괄호 안에 계기 두 개가 명시된 복합 라벨이고 두 계기의 코드가 다르다. 선례: 원익IPS 「선물지급 제도」 → `holiday_gift` + `birthday_gift`, 웨이브 3 대한전선 「선물 지급」 → `birthday_gift`·`holiday_gift`·`parenting`, 웨이브 3 키움증권 `birthday_gift`(생일·결혼기념일) + `holiday_gift`(명절).
- 「기념일 선물」 라벨 전체를 `birthday_gift` 1행으로 둔 선례(삼성화재·대덕전자)도 있으나, 그러면 추석 선물이 생일 코드에 묻힌다.
- `holiday_gift` 카테고리 = **compensation**(어휘표 compensation 25 / perks 12 / family 1 — 지배 카테고리. 웨이브 3 대한전선·키움증권도 compensation). 원문이 현금이 아니라 「선물」이라 perks 논거도 있다. 옮기면 SORT 는 perks 23, compensation 섹션은 사라진다.
- **추석만** 명시돼 있다 → BENEFIT_NM 「추석 선물」, 서술에 「추석 외 명절 선물 미기재」. 설 선물을 만들지 않았다.

### 판단 ④ 「지방근무자 사택지원」 → `dormitory` (근무지 조건 — 부문 한정 아님)

- 규칙 8-2: `dormitory` = 사택·기숙사 등 주거 **시설**. 원문 「사택」은 시설이고 임차비·주거비 같은 현금 문구가 없어 `housing_support` 가 아니다.
- 규칙 6 의 제외 대상은 부문·자회사·임원 한정이다. 「지방근무자」는 근무지 조건이다. 코퍼스 선례: LS일렉트릭 「지방사업장 근무 시 기숙사 또는 사택 제공」·LIG넥스원 「지방사업장 기숙사」·한화생명 「사택지원」(비연고 근무 조건) = `dormitory`, 웨이브 3 삼성증권 「사택 지원」 = `dormitory`.
- 조건을 지우지 않고 QUAL_DESC 에 「지방근무자 대상」으로 명시했다.
- 참고(행 근거 아님): 같은 JSON 1200 「부서 및 직무소개」 총무 직무 설명에 「본사와 지방근무자에 관한 지원업무」가 있어 「지방근무자」가 이 회사의 실제 인사 구분임을 보강한다.

### 판단 ⑤ 「주택구입자금 및 전세자금 지원」 → `housing_loan` 1행

- 주택구입자금·전세자금 두 대상이 같은 코드라 한 행(같은 `li`). 선례: 고려아연 「주택구입·전세자금 융자」, 웨이브 3 삼성증권 「주택 구입 및 전세 자금 지원」·키움증권 「주택구입·임차 자금 대출」 = `housing_loan`.
- ⚠ 원문 동사는 「지원」이라 대출인지 이자 보조인지 불명이다. 대출이라고 단정하지 않고 QUAL_DESC 에 「대출·이자 지원 등 지원 방식, 한도, 자격 요건 미기재」로 적었다. `housing_support`(임차비·주거비 현금)는 현금 지급 문구가 없어 쓰지 않았다.

### 판단 ⑥ 「경조 휴가 및 경조금 지급」 + 「경조물품 지원」 → `event` 1행

- 두 `li` 모두 경조사 급부(휴가·현금·물품)이고 같은 코드로 귀결된다(규칙 9 병합). 선례: 테크윙 「경조휴가/물품 지원」 = `event`, 웨이브 3 대한전선 「경조금, 경조화환, 장례용품 지급 및 휴가 부여」 = `event` 1행.
- LS일렉트릭은 「경조휴가」를 `leave_general` 로 뗐지만, 가온전선 원문은 휴가와 경조금을 **한 `li`** 로 묶었고 경조 구분별 일수가 없어 휴가 코드로 떼지 않았다.
- 결혼 한정 서술이 없어 `wedding`(현금 축하금+휴가) 아님.

## 6. 금액 (규칙 4)

**stated 0건 · 13행 전부 `BENEFIT_AMT = NULL` · `NOTE_CTNT = NULL` · `QUAL_YN = TRUE` · `QUAL_DESC` 존재.**

4600 원문에 원 단위·만원 단위 금액이 **하나도 없다**. 정량 표현은 「만 35세 이상」(연령 조건) 하나이고 금액이 아니다. 신규 회사라 승계할 앵커가 없고 타사 금액을 끌어오지 않았다.

## 9. 배포 시 주의

- ⚠ **신규 회사 — `INSERT IGNORE INTO TCOMPANY` 가 실제 등록을 수행한다. 적재 후 정적 페이지 재생성 필수**, 대문 2단계 이후 **회사 등록 이력 파일 추가 필수**. 등록 접점(`company_meta.py` 별칭·`test_seed_badge_backfill.py` 집합)은 커밋 `2b81bba` 에 이미 있고 slug 가 일치한다.
- ⚠ **게재 시점 불명**: 4600 메뉴 객체에 수정일 필드가 없다(키 목록 실측: `menuSn`·`displayPriority`·`useYn`·`contents` 등, 날짜 키 없음). JSON 안 날짜는 `companyInfo.createDatetime "2018-08-02 13:55:06"`(사이트 생성)과 채용공고 기간(2026-04~08)뿐이고, 자기 홈 푸터는 「COPYRIGHT@2014」. 복지 목록이 언제 작성·갱신됐는지 알 수 없으므로 「현재 공식 채용 페이지 기준」으로만 두고 시행 시점을 단정하지 말 것. 사용자 노출 필드에는 날짜를 넣지 않았다.
- **재수집 경로**: `POST /appsite/company/getMainView`(`appsiteSn=2331&settingType=B`) 1회로 끝낸다. **헤드리스 렌더 금지**(금지 경로 JS·XHR 를 끌어온다). 메뉴는 `menuCode == "4600" && useYn == 1` 로 **코드 선택**, `headerContents` 에 「가온전선」 포함 여부로 법인 확인. **다른 메뉴를 키워드로 훑지 말 것** — 비활성 4400·4500 에 벤더 샘플(연봉 4,000만원·자동승진)이 있다.
- **변경 감지**: JSON 전체 해시는 채용공고 목록 때문에 바뀐다(프로브 대비 실측). 기준값은 **4600 `contents` sha256 `c551d130…0962403`**(4,616자)로 둘 것.
- **robots 파서 함정**: `urllib.robotparser` 는 이 파일을 금지로 오판한다. RFC 9309(가장 긴 일치) 구현으로 판정할 것. `/resources/`·`/app/` 는 실제로 금지다.
- **TLS 인증서**(openssl 실측): ATS `CN=*.recruiter.co.kr`, Amazon RSA 2048 M01, 2026-06-23 ~ **2027-01-06**. 자기 도메인 `CN=gaoncable.com`, Let’s Encrypt YR2, 2026-09-03 ~ **2026-12-02**(90일 자동갱신 주기). `-k` 우회 금지.

- **파싱 함정**: h2·li 에 `\xa0`(학비 지원·여가 지원·경조 휴가 및) — 정규화하지 않으면 문자열 비교가 어긋난다. 「팬션」은 원문 오기, SQL 은 「펜션」.
