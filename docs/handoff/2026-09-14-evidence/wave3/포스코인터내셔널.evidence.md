## 8. 검증자가 봐야 할 지점

### ① SORT 21 `housing_loan` vs `welfare_fund_loan`
- 원문 #10 은 제목이 「사내근로복지기금」, 설명이 「주택구매/임차, 생활자금 저리 대부」다.
- **housing_loan 채택 이유**: 대부 용도가 명시돼 있고 첫머리가 주택구매/임차다. 비교축으로 `housing_loan` 은 68개사, `welfare_fund_loan` 은 2개사라 주택대출 유무를 비교하는 사용자에게 이 법인이 빠지면 누락이 된다. 코퍼스에 사내근로복지기금 재원 주택대출을 `housing_loan` 으로 둔 행이 있다.
- **반대 논거**: 라벨이 기금 자체이고 생활자금 대부까지 포함하므로 삼성화재 「사내 근로복지기금 대출」(`welfare_fund_loan`)과 같은 축으로 볼 수 있다.
- 뒤집히면 코드만 `welfare_fund_loan` 으로 바꾸고 NM·QUAL_DESC 는 그대로 쓸 수 있다.

### ② SORT 40 `refresh_leave`(출장 Refresh 휴가) · SORT 41 `leave_general`(심야근무 보상휴가)
- 두 항목 모두 **특정 근무 사건(주말·야간 항공편 출장 / 심야 근무)에 붙는 보상성 휴가**다. 전용 코드가 어휘표에 없다(보상휴가·대체휴가 행 0건 — `grep` 결과).
- #5 는 원문 라벨이 「Refresh 휴가」라 `refresh_leave`, #6 은 휴가제도 일반 축 `leave_general` 에 두었다. BENEFIT_NM 에 「출장」「심야근무」 조건을 그대로 남겨 일반 리프레시 휴가로 오인되지 않게 했다.
- **`refresh_leave` 에 대한 반론**: 코퍼스 `refresh_leave` 는 대체로 연중 사용하는 휴식성 휴가(「연중 사용 가능한 Refresh 휴가 3일」 등)라, 출장 조건부 휴가를 같은 축에 두면 「리프레시 휴가 있음」 비교가 부풀 수 있다. 대안은 #5 를 `leave_general` 로 옮기고 #6 을 거기에 병합(1행)하는 것.
- **#6 경계**: 원문은 「심야 근무시 익일/차주 휴가 부여」뿐이라 야간근로 수당과 **별개로** 주는 휴가인지, 수당을 휴가로 **대체**하는 방식인지 알 수 없다. 대체 방식이면 추가 혜택으로 보기 어려워 행 삭제가 맞다. QUAL_DESC 에는 판단을 넣지 않고 「심야 근무 인정 기준·부여 시간 미기재」만 적었다.

### ③ SORT 74 난임 — 휴가 「최대 10일」 제외
- 원문이 휴가 일수와 치료비를 한 문장에 담았고 법정분·회사분을 구분하지 않는다. #22 육아휴직(원문이 「법정휴직(1년)외 일반휴직(1년)」으로 스스로 나눔)과 대비해 **원문이 상회 조건을 밝히지 않은 경우**로 처리했다.
- 검증자가 법령 원문으로 법정 난임치료휴가 일수를 확인해 10일이 명백한 상회라고 판정하면, 문안에 「치료휴가 최대 10일」을 더하는 선택지가 있다(행 수 불변). 이번 세션은 법령 사이트를 요청하지 않았다.

### ④ SORT 51 `resort` AMT 20
- 「격년 40만원 지급」을 연 20만원으로 나눈 것은 SI-B2(월액×12)와 같은 연 환산이다. 한도가 아니라 지급액이라 AMT 로 두었다. 보수적으로 NULL 로 두자는 판단이면 NOTE 를 QUAL_DESC 로 옮기고 QUAL_YN TRUE 로 바꾸면 된다.

### ⑤ SORT 73 `parenting` 병합
- 출산장려금(현금 1회성)과 육아 일반휴직(휴직 기간)은 성격이 다르지만 둘 다 코퍼스 `parenting` 축이고 코드가 UNIQUE 라 한 행에 담았다. 원문 두 항목 인용은 §3.

### ⑥ SORT 11 거점오피스 「/셔틀」
- 「5개 거점오피스/셔틀 운영」의 셔틀 성격이 원문에 없다. 해석을 넣지 않고 원문 표기 그대로 적었다.

## 9. 이메일 도메인 관측 (계약 규칙 7)

- **페이지 관측: 미관측.** S1·E1·E2 세 페이지에서 회사 이메일 주소 0건(`mailto:` 0건). E2 문의하기는 폼과 「대표전화 : 02-759-2114」만 있고, E1 개인정보처리방침은 본문이 원본 HTML 에 없다(`<main>` 180자).
- **MX(DNS, 이번 세션)**: `poscointl.com` → `mxa-008bb301.gslb.pphosted.com`(5) · `mxb-008bb301.gslb.pphosted.com`(5) · `SAMETIME.poscointl.com`(20). → **`poscointl.com` 이 메일을 받는 도메인임은 확인**. 웹 도메인과 같다.
- 참고: 그룹 `posco.com` MX 는 `antispam.posco.net`(10) — 별개 체계. 재직인증 화이트리스트에 `posco.com` 을 넣으면 그룹 전체가 이 법인으로 인증될 수 있으니 넣지 말 것.
- 프로브 기록상 TLS SAN 에 옛 상호 도메인 `*.daewoo.com`·`*.posco-daewoo.com` 이 있다 — 재직자가 옛 도메인 메일을 쓸 가능성은 이번 세션에서 확인하지 않았다.

## 10. 배포 시 주의
