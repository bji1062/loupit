### 신규 코드 — **0개** (19행 전부 `_VOCAB.md` 86종 안)

### 판단 ① 「자기개발포인트」 → `welfare_point` (self_development 아님) — 다툴 만한 판단

- S2 가 사용처를 「복지몰 및 복지카드 통해 이용 가능」 이라고 밝힌다. 복지몰·복지카드는 선택적 복리후생 포인트의 표준 사용 경로라, 기능은 복지포인트다. `self_development`(자기계발비)로 넣으면 비교 화면에서 씨젠이 「복지포인트 없음」 으로 보이는 쪽이 더 큰 왜곡이다.
- 코퍼스에 사용처가 자기개발·여가인 포인트를 `welfare_point` 로 둔 행이 있다(넷마블 「복지포인트 연간 250만원 — 자기개발·여가·취미 활동에 사용」 등).
- 명칭은 원문대로 「자기계발 포인트」 로 남겨 성격을 숨기지 않았다. ⚠ 검증자가 원문 영역명(자기계발)을 무겁게 보면 `self_development`/growth 로 재코딩할 근거도 있다. 금액이 없어 어느 쪽이든 금액 영향 0.

### 판단 ② 「장기근속자 포상/포상휴가」 → `long_service_bonus` + `long_service_leave` 2행

- S1 은 한 라벨이지만 포상(금품)과 휴가 두 제도를 병기한다. 계약 함정: `long_service_leave`=휴가만, 포상금은 `long_service_bonus`. KAI 「근속기념품/휴가/축하금」 분리 선례.
- S2 「장기근속자 포상 및 리프레쉬 휴가」 가 휴가 쪽 이름을 「리프레쉬 휴가」 로 부른다. `refresh_leave` 후보였으나 S1 이 「**포상**휴가」 이고 둘 다 「장기근속자」 에 걸린 문장이라 근속 연계 휴가로 읽어 `long_service_leave` 를 택했다. ⚠ S2 를 「(장기근속자 포상) 및 (리프레쉬 휴가 — 근속 무관)」 으로 끊어 읽으면 `refresh_leave` 가 맞다. 그 경우 판단 ③ 행과 같은 코드가 되어 두 행을 합쳐야 한다(UNIQUE).

### 판단 ③ 「힐링데이/돌봄데이」 → `refresh_leave` (time_off) — 이 파일에서 가장 근거가 얇은 코드

## 9. 배포 시 주의

- ⚠ **회사 추가 시 정적 재생성 필수**. 등록 이력 파일 추가 필수(대문 2단계 이후 규칙).
- 신규 회사 — `INSERT IGNORE` 가 실제 등록. `UPDATE … CAREERS_BENEFIT_URL` 은 재실행 멱등용으로 유지. 잔존 구본 행 없음.
- ⚠ **S1 재수집 배선**: 빌더 JSON 주소는 날짜+UUID 라 재게시 때 바뀐다. 주소를 주는 `api-recruiter` 는 robots 금지이고 헤드리스 렌더는 그 호스트를 끌어온다 → 재수집 때는 **S2(SSR, 자기 도메인)를 먼저 대조**하고, S1 은 기존 JSON 주소 GET 이 404/내용 변화일 때만 리드 판단으로 경로를 정할 것. 갱신 감지는 JSON 바이트 해시(`cd1726a7…`)와 `last-modified`.
- ⚠ S1 복합 라벨은 문단 2개(「A/」 + 「B」)로 나뉘어 있다 — 줄 단위 파싱은 25조각이 된다. TEXT 콘텐츠 1개 = 항목 1개.
- ⚠ S2 원문에 ASCII 작은따옴표(「'온(溫, ON)마음 프로그램'」)가 있다 — SQL 에는 옮기지 않았다(분할기 보호).
- `kr.seegene.com` robots 는 `User-agent: *` 그룹이 2개라 합쳐 읽어야 한다. `seegene.co.kr` apex 는 TLS 불일치(프로브), `www.seegene.co.kr` 은 301 → kr.
