   - 대안: `commute_subsidy` 1행에 병합(「출근버스 및 차량 보조금」) → 15행.
3. **독감예방접종 → `health_check` 병합**
   - 예방접종 전용 코드는 어휘표에 없다. 코퍼스 선례: 셀트리온 `health_check` 「종합 건강검진 지원(예방접종 포함)」, 현대모비스 `health_check` 「전직원 예방접종/건강검진/여성검진」. 두산에너빌리티는 사내의원(`clinic`)이 접종을 해서 `clinic` 에 넣었지만 SK바이오팜은 사내 의료시설 언급이 없다.
   - 대안: `medical` 서술로 이동. 신규 코드(`vaccination`)는 규칙 5 에 걸려 만들지 않았다.
4. **「장기 근속자 포상·휴가 지급」 → `long_service_bonus` + `long_service_leave` 분리** — 계약 함정(`long_service_leave`=휴가만, 포상금은 `long_service_bonus`) 그대로. 원문 「포상」은 금품 여부를 밝히지 않지만 휴가와 병기돼 휴가 외 포상이라 `long_service_bonus`(심텍·삼성화재 분리 선례).
5. **`summer_leave`** — 「여름 휴가」 라벨. 하계휴가는 법정 제도가 아니다. 다만 원문은 일수·유급 여부·휴가비를 밝히지 않는다 → QUAL_DESC 에 「휴가 일수·휴가비 지급 여부 미기재」. ⚠ 연차를 몰아 쓰는 기간일 뿐일 가능성을 원문으로 배제할 수 없다 — 회사가 복리후생 목록에 독립 라벨로 올렸다는 점만 근거다.
6. **「다양한 교육 기회 및 지원금 제공」 → `edu_support`** — 계약 규칙 8 기준 「지원금 제공」 = 명시적 비용 지원이라 growth 행 ○. 「교육 기회」 부분은 커리큘럼 성격이지만 한 줄이라 쪼개지 않았다. `self_development`(자기계발비)보다 「교육 … 지원금」 문형이 `edu_support`(대표명 「자기계발 지원 · 교육 프로그램」)에 가깝다. 원문 카테고리가 「주거 및 여가 활동」 이지만 코드 카테고리는 growth.
7. **「경조사 발생 시 휴가·경조금 지급」 → `event` 1행** — `wedding` 은 결혼 한정 현금+휴가라 해당 없음. 경조휴가는 법정 제도가 아니다(배우자 출산휴가 같은 법정 휴가를 원문이 언급하지 않는다).
8. **「주택 구입·임차 시 대출 지원」 → `housing_loan`** — 계약 8-2: 대출·이자 = `housing_loan`. 현금 임차비가 아니라 「대출」이라 `housing_support` 아님. 구입·임차 두 용도를 한 행에 담았다(같은 코드).
9. **「사내 식당 운영(중·석식 제공)」 → `meal`, AMT NULL** — 끼니(중·석식)는 있으나 단가가 없다. 계약 함정: 단가 명시 없으면 NULL.
10. **「유치원~대학교 교육비 지원」 → `child_edu`** — 원문에 「자녀」 단어는 없지만 「자녀 양육」 카테고리 아래 줄이다. 직원 본인 학자금이 아니다.
11. **`welfare_point`·`club`·`medical`·`remote_work`** — 코퍼스 대표명과 라벨 일치(「선택적 복리후생」·「사내 동호회」·「의료비 지원」·「재택근무제」).

## 9. 배포 시 주의

- 신규 회사 → `INSERT IGNORE INTO TCOMPANY` 가 **실제 등록**. 적재 후 **정적 페이지 재생성 필수**, 대문 2단계 이후 **등록 이력 파일 추가 필수**(회사 등록 PR 규칙).
- DART 정식명이 「에스케이바이오팜」이라 `corp_code_map` 을 이름으로 매칭하면 놓친다 → corp_code `00878696` 으로 매칭. KOSPI 상장 2020년이라 재무·직원 5개년 추이가 채워지는지 리드 확인(프로브 ⑤).
- 신규 BENEFIT_CD 0 → 어휘 추가 작업 없음. 구본 없음 → 잔존 행 삭제 마이그레이션 불필요.
- **SQL 검산 실측**: 분할기(`load._split_sql_statements`) **5문장** · 행 16 · 중복 BENEFIT_CD 0 · 중복 SORT 0 · 카테고리 9종 밖 0 · 어휘표 밖 코드 0 · 겹따옴표 0 · 홑따옴표 178개(짝수, 줄마다 짝) · 주석 속 홑따옴표 0.
- **SORT 블록**: flexibility 10~11 / compensation 20 / time_off 30~31 / perks 40~44 / family 50~51 / health 60~61 / growth 70 / leisure 80. 섹션 순서 = 원문 16줄에서 각 카테고리가 처음 나온 줄(L1 flexibility → L2 포상 compensation → L2 휴가 time_off → L3 perks → L4 family → L10 health → L14 growth → L16 leisure).
- 재수집 배선: `www.` 필수(apex 타임아웃) · GET · 법인 검증은 `<title>` 끝 「SK바이오팜」 + `<h4 class="mb-0">복리후생</h4>` 존재 · 갱신 감지는 `ul.m_list.n2` 블록 sha256(위 `318a050c…`) · 국문판만. sitemap `lastmod` 는 전 URL 동일 생성 시각이라 갱신 신호가 아니다(프로브). TLS `*.skbp.com` 2027-01-18 만료(프로브).
- **최신성**: 같은 페이지 성과 수치가 2021~2023년에 멈춰 있다(프로브). 복지 16줄 자체의 게시 시점은 페이지에 없다.

## 10. 검증자가 봐야 할 지점

1. **SORT 10 해피프라이데이 병합** — `flex_work`(카카오·카카오게임즈 선례) vs `leave_general` 별도 행(원문이 여름 휴가와 한 줄). §4-1.

3. **L8 「태아 검진·난임 치료 시 휴가」 제외** — 법정 「시간」 대 원문 「휴가」 차이로 상회분일 가능성. 원문에 일수·유급 조건이 없어 제외했다. §5.
