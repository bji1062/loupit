# 웨이브 5 적대 검증 계약 (W-2) — 2026-09-21

목적: 수집 산출물(시드 SQL + evidence)을 **독립 재수집으로 반증**한다. 수집기가 옳다고 가정하지 않는다. 회사 간 비교축(BENEFIT_CD 의미)을 망치는 행 하나가 통계 전체를 오염시키므로, 「그럴듯함」이 아니라 「원문이 그렇게 말하는가」만 본다.

## 입력 (회사마다)
`…/scratchpad/wave5/<회사>.sql` · `<회사>.evidence.md` · 프로브 `<이번 웨이브 프로브 폴더>/<회사>.md`(**산일전기·ISC 는 `docs/handoff/2026-09-19-evidence/probe/` 에 이미 있다 — 재실사 불필요**, 나머지는 웨이브 5 폴더. 리드가 착수 시 치환) · 수집 계약 `docs/handoff/2026-09-19-evidence/_COLLECT-CONTRACT.md`(규칙 1~9 — 웨이브 5 착수 시 갱신본으로 교체) · 어휘표 `docs/handoff/2026-09-21-evidence/_VOCAB.md`(**90종 갱신본** — 87종 구본을 보지 말 것).

## 절차
1. **evidence 를 읽기 전에** 프로브의 정본 URL 을 직접 가져와 **독립 항목 목록**을 만든다(이미지면 직접 판독, `__NEXT_DATA__`/번들이면 직접 추적, CSR 이면 Playwright, CSS 숨김 탭이면 원본 HTML). UA 는 일반 브라우저 문자열, HEAD 대신 GET, 요청 간 ≥1초, 회사당 ≤40회. robots.txt 는 호스트마다 단독으로 먼저 받아 RFC 9309 기준(가장 긴 일치 우선 — `urllib.robotparser` 금지)으로 판정한 뒤 본문을 요청한다(헤드리스 렌더는 원본 HTML·데이터 JSON 에 항목이 없을 때만 — 하위 리소스도 요청 수에 든다).
2. 그 다음 SQL 행 하나하나를 독립 목록·원문과 대조해 판정한다:
   - **CONFIRMED** 원문이 그 행을 그 코드·그 조건으로 뒷받침한다.
   - **SUSPECT** 원문은 있으나 코드 선택·조건·귀속·금액·문안이 의심스럽다(검수자 결정 필요) — 이유와 대안을 적는다.
   - **REFUTED** 원문이 없거나 반대로 말한다(유령·오독·다른 법인·임원 한정·법정 제도·커리큘럼·급여).
   - **MISSED** 원문엔 명시적 제도가 있는데 행이 없다. 단 계약 규칙 3(법정)·8(커리큘럼)·9(억지 확장 금지)로 뺀 것이 정당하면 MISSED 가 아니다 — evidence 의 제외 목록과 대조.
     ⚠ **MISSED 는 원문을 훑어 눈에 걸리길 기다리지 말고, 코퍼스 비교축을 기준으로 적극적으로 찾는다.** 어휘표에서 **n 이 큰 코드부터** 짚어가며 「이 회사엔 왜 이 축이 없는가」를 묻고, 없으면 원문에서 그 낱말을 직접 검색한다. 회사 간 비교는 **없는 축**으로도 표시되므로, 원문에 있는데 빠진 행은 틀린 값과 같은 무게의 오류다.
3. 특히 공격할 지점:
   (a) **법인 귀속** — 다른 법인·그룹 공통·부문·자회사·임원/연구위원 한정, 「(그룹 통합/컴퍼니 공통 기준)」 각주 누락, 그룹 sitemap 으로 샌 형제 법인 페이지
   (b) **법정 제도 혼입** — 행으로든 **다른 행 QUAL_DESC 속 문구로든**(시차 출근·난임휴가·근로자의 날 등 — 웨이브 2 감사가 4행에서 발견)
   (c) **어휘 오염** — 코드 뜻과 다른 행(어휘표의 대표 명칭·카테고리와 대조). 웨이브 2에서 실제로 걸린 유형: 급여성 수당(`degree_allowance`)·옥외 조경을 `lounge`·명상실을 `lounge`·GWP 담당자 활동을 `team_dinner`·사이버 연수원을 `edu_support`·상담실 운영만으로 `clinic`·뜻 없는 축(`disability_veteran`)·사택을 `housing_support`·업무 공간을 `lounge`
   (d) **금액** — 원문 명시 아닌 AMT, 연환산 오류(월×12), 대출 한도·비율·상한·1회성을 AMT 에 넣은 것
   (e) **유령 항목** — HTML 주석·샘플 템플릿·모바일/구본 잔재·캐러셀 중복·직군 전용 처우
   (f) 병합·분리 — 같은 코드 2행(UNIQUE 위반) 또는 다른 제도 억지 병합
   (g) **등록 INSERT** — COMP_NM·COMP_TP_CD·INDUSTRY_NM(기존 값 합류)·LOGO_NM(영문 이니셜)·slug 가 지시와 같은가, `grep -h "VALUES ('" db/seed/benefit/sql/*.sql` 로 slug 충돌 0 인가
   (h) **SQL 형식** — 주석·문자열 홑/겹따옴표, 카테고리 값 9종 밖, SORT 중복, 실제 분할기(`from db.seed import load; load._split_sql_statements`)로 5문장인지
   (i) **사용자 노출 문안** — QUAL_DESC·NOTE·BENEFIT_NM 속 편집 주석(「코퍼스」「선례」「병합」「판독」「규칙」「어휘」「⚠」 등). 발견하면 행 판정과 별도로 대체 문안을 적는다.
4. 3자 사이트(사람인·잡코리아·잡플래닛·캐치·인크루트·블라인드·원티드) 인용 0건 확인. 검색엔진 스니펫 인용도 0건.

## 보고 형식 (`<회사>.verify.md`)
- 상단: **요약 표** `CONFIRMED n / SUSPECT n / REFUTED n / MISSED n` + 한 줄 결론(반영 가능 / 조치 후 반영 / 재수집). 범례 문단에 판정어를 다시 쓰지 말 것(집계가 틀어진다).
- **독립 목록**(내가 직접 본 항목 n개, 출처 URL·렌더 방식·해시).
- **행별 표**: SORT · 코드 · 판정 · 근거 원문(인용) · 조치 권고(유지 / 삭제 / 재코딩→코드 / 병합 / 각주 추가 / AMT NULL / 문안 교체).
- **MISSED 표**: 원문 항목 · 권고 코드 · 수집기 제외 사유 타당성.
- 마지막: **수집기가 놓친 함정**(재수집·다음 웨이브에 남길 것) 3줄 이내.

## 상설 — 기계 스윕 의무 (절차 5)

행을 다 판정한 뒤, 반드시 아래를 돌리고 **결과 표를 보고서 끝에 붙인다**.

```
python3 docs/handoff/2026-09-19-evidence/_legal_scan.py …/scratchpad/wave5/<회사>.sql
```

왜: 웨이브 3 에서 회사별 검증이 207행을 전부 통과시킨 뒤, 횡단 감사의 검출어 스윕이 법정 문구 1행(포스코퓨처엠 「본인/배우자 태아 검진 휴가」 — 근로기준법 74조의2)을 잡아냈다. 읽어서 판단하는 것과 검출어로 훑는 것은 다른 일이고, 검증이 먼저 훑는 게 싸다.

- 검출은 **단서지 판정이 아니다.** 오탐이 많다(「근속 연차」의 연차, 「연차휴가 조기사용 제도」 같은 회사 제도명). 한 줄씩 판정하고 `허용 / 삭제 / 문안 교체` 를 적는다.
- 허용은 **원문이 법정분과 회사 상회분을 스스로 나눠 밝힌 경우**뿐이다(「육아휴직 자녀당 최대 2년 중 회사지원 추가 1년」은 허용, 「육아휴직 제공」은 삭제).
- 편집 주석 검출(「코퍼스」「선례」「병합」「판독」「규칙」「⚠」 등)은 사용자 노출 필드에 들어가면 안 되는 말이다 — 하나라도 남으면 대체 문안을 적는다.

## 상설 — 근거표 인용 실재 확인 (절차 6)

보고서를 닫기 전에, 수집기 근거표가 **코퍼스 선례로 인용한 것을 전수 대조한다**(「○○사도 이 코드를 쓴다」·「코퍼스 중간값 ○○만원」 따위).

- 인용된 회사·코드가 **시드에 실제로 있는지** 확인한다: `grep -l "'<코드>'" db/seed/benefit/sql/<회사>.sql`
- 인용된 **수치**(중간값·최댓값·n)는 코퍼스에서 직접 다시 센다. 선례를 근거로 AMT·코드를 정한 행은 그 선례가 틀리면 같이 틀린다.
- 대조 결과를 보고서에 **표 한 줄씩** 남긴다(인용 / 실재 / 불일치). 하나라도 불일치면 그 행은 SUSPECT 로 내린다.

왜 상설인가: 웨이브 4 A/B **직후 남은 10사에** 이 두 줄(①·②)을 넣자, **Opus 가 앞섰던 항목을 Fable 이 같은 계약 문구만으로 찾아냈다**(그 10사에는 Opus 대조 레인이 없어 동등성 자체가 측정된 것은 아니다) — MISSED 4건(티에스이 「인센티브」·풍산 EAP 등)을 찾아냈고, 인용 9건 전수 대조로 **수치 오기 2건**을 잡았다. 모델을 올려서 얻은 줄 알았던 차이가 대부분 **계약 문구로 재현된다.** 그래서 검증 기본 구성은 **Fable 5.1**, 난도 높은 1~2곳만 Opus 로 둔다.

## 이번에 특히 공격할 어휘

### 웨이브 4 에서 실제로 걸린 것

- **같은 뜻 두 코드** — `smoking_cessation` ↔ `nonsmoking_bonus` 가 같은 웨이브에서 갈렸다(→ `smoking_cessation` 통일). 신규 코드를 볼 때마다 **어휘표 90종 전체에서 같은 뜻을 먼저 찾을 것.** (웨이브 4 에서는 검증 두 레인이 다 SUSPECT 로 잡았다 — 비교적 잘 걸리는 유형이다.)
- **코드가 원문보다 좁은 것** — HL만도 `welfare_fund_loan`(원문에 「대출」이 없다) → `welfare_fund`. 코드가 원문에 없는 조건을 덧붙이면 비교축이 오염된다. ⚠ **웨이브 4 어휘 충돌 3건 중 검증 2레인이 통과시키고 횡단 감사가 뒤집은 유일한 유형이다** — 검증 보고서가 「원문에 「대출」 낱말이 없으나 … 유지」라고 **스스로 이상을 적고도 CONFIRMED** 로 넘겼다. **원문에 없는 낱말이 코드에 들어 있으면, 그 행이 CONFIRMED 여도 SUSPECT 로 내려라.**
- **AMT 세 유형**: 분포형(직급 구간)을 최댓값으로 적은 것(→ 중간값) · 조건이 삼중으로 걸린 값(→ NULL) · **그 축 최댓값의 3배가 넘는 값**(명절 정기상여 혼입 — 축 분포와 대조해 튀면 의심한다).
- **법정 문구가 행 안에 숨은 것** — 안전보호구(산안법 사업주 의무) · 직무발명규정(발명진흥법 15조) · 모성보호제도. 절차 5 스윕으로 먼저 훑는다.
- **ATS 샘플 템플릿 오염** — 나인하이어 샘플 복지 8개가 한 페이지에 7번 반복돼 있었다(「휴가비 200만원」). 수집기의 격리를 **독립 재현**해 오염 0 을 증명할 것.
- ⚠ **리드 프롬프트가 규칙 3 을 임의 확대한 사고** — 시차출퇴근·선택적근로시간은 **법정이 아니다**(근로기준법 52조 선택근로는 사용자가 도입을 선택하는 제도). 규칙 3 열거·`legal_baseline.json` 15항목·검출어에 없는 것을 법정으로 거르면 **그 회사만 축이 비어 「유연근무 없음」이라는 거짓 표시**가 된다. 리드 지시가 계약과 어긋나면 계약이 이긴다.
- **연차·반차 = 법정(문안에서 제거) / 반반차·회사가 밝힌 시간 단위 = 복지**(2026-09-20 확정). 단 화면에 「반반차」를 쓰지 않고 **「2시간 단위 휴가」**로 적는다.
