```

-- 4) 기존 추정 데이터 삭제 (official 보존)
```

### 2-3. 행

- **정성 행**(금액 없음): `NULL, '<category>', 'est', NULL, TRUE, '<서술>'` — 서술은 `QUAL_DESC_CTNT`.
- **금액 행**: `<금액>, '<category>', 'est', '<서술>', FALSE, NULL` — 서술은 `NOTE_CTNT` **하나**다(리드 판정 (83)). 코퍼스의 금액 행은 예외 없이 `QUAL_YN=FALSE` · `QUAL_DESC=NULL` 이라 금액을 넣는 순간 조건 칸이 사라진다 — 조건이 붙은 급부는 금액 행으로 만들지 않는다(규칙 4-7, W4감사 §3-3).
- **카테고리는 고르는 것이 아니라 `W5/_VOCAB.md` 표의 카테고리 열을 베끼는 것이다.** 코드가 표에 있으면 표의 카테고리를 쓴다 — 더 어울려 보여도 바꾸지 않는다. 다르게 넣어야 할 이유가 있으면 행을 만들지 말고 근거표 「판단 요청」에 올린다. 표에 없는 신규 코드는 가장 가까운 뜻의 기존 코드가 쓰는 카테고리(규칙 5). 9칸 고정: compensation · health · family · leisure · perks · growth · time_off · flexibility · work_env(09-21 계약 — 웨이브 1~4 에서 같은 코드가 회사마다 다른 축에 들어가 6종 30행을 재코딩했다).
- `BENEFIT_CD` 는 회사당 한 행(UNIQUE). 같은 코드로 귀결되는 제도는 한 행에 합쳐 서술한다. 다른 제도를 억지로 합치지 않는다.
- **SORT:** 카테고리별 10단위 섹션(첫 섹션 10, 다음 20 …, 섹션 안 +1). 섹션 순서 = 정본 페이지에서 그 카테고리가 처음 나온 순서, 보조 출처에만 있는 카테고리는 끝. 섹션 머리 주석 `-- ── … ──` 를 단다(09-21 계약 · 본보기 시드).
- 문자열 안 홑 · 겹따옴표 금지 — 「」를 쓰고, 아포스트로피가 꼭 필요하면 U+2019 ’(09-21 계약).
- **필드 길이:** `BENEFIT_NM` ≤ 100자 · `NOTE_CTNT` ≤ 200자 · `QUAL_DESC_CTNT` ≤ 500자(DB 컬럼 — 넘으면 적재가 실패한다). 줄일 때는 출처 괄호를 줄인다. 사실 · 「(추정)」 · 「환산」 표지는 지우지 않는다(R-3 기준 9 · 리드 판정 (83)).

## 3. 등록 값

- `COMP_ENG_NM` = 리드가 준 snake_case slug. 기존 147사와 충돌 금지 — `grep -h "VALUES ('" /home/ubuntu/loupit/db/seed/benefit/sql/*.sql` 와 `_row_check.py` 의 slug 대조로 확인한다(`generator/slug.py` `slug_of` 정규화 뒤 비교).

3-6. 법정만 적힌 원문은 행을 만들지 않는다. 코퍼스의 법정 표시 등록표(`/home/ubuntu/loupit/generator/data/row_marks.json`)는 이미 있는 행에 「법정」 표시를 다는 장치라 신규 회사에는 등록하지 않는다(⚖ C-6).

### 규칙 4 — 금액

4-0. 금액 칸(`BENEFIT_AMT`)은 **만원 · 연 단위**다. 금액 출처는 적재 때 서술 낱말로 다시 판정된다 — `derive_amt_source`(`/home/ubuntu/loupit/db/seed/backfill_dec2.py:46-53`): 금액 행의 NOTE 에 「추정」이나 「환산」이 있거나 NOTE 가 비면 **estimated(추정치)**, 아니면 **stated(회사 공식 수치)**. 「회사 공식 수치」의 정의 = 「회사가 밝힌 숫자로 연 금액을 적은 것」이고 월액 × 12 는 추정치 · 1회성 금액은 금액 미등록이다(SPEC 21 SP-GUIDE · 가이드 A 검토 R-2). 그래서 **표지를 빠뜨리면 추정이 공식 수치로 나간다**(사용자 결정 2026-09-28 M-4 폐기 뒤 표지가 유일한 장치 — 메모리 loupit-m4-anchor-removed). 같은 금액이 다른 회사와 겹치는 것은 아무 판단의 근거도 아니다(M-4 폐기 — 다시 제안하지 않는다).

4-1. **stated(표지 없음)** — 원문 숫자가 곧 연 금액일 때(⚖ C-1):
- 「연 N만원」 · 「연간 N만원」 · 「매년 N만원」. NOTE 에 원문 그대로.
- **합산**: 원문에 고정 금액이 나뉘어 적힌 것(「설 80만원 · 추석 80만원」 · 「50 + 35 + 35만원」 · 「각 N만원 × 횟수」)은 더한 값을 stated 로, NOTE 에 구성 원문 그대로(사용자 결정 2026-10-02 · R-3 기준 24). ⚖ C-2 — 그 축 기존 최댓값의 2배를 넘으면(명절 상여 · 귀성여비 축 지금 최댓값 160) 금액을 넣되 근거표 「판단 요청」에 「급여성 혼입 의심」으로 올린다.
- 복지포인트 · 복지카드처럼 **연초에 그 금액을 전부 배정**하는 제도는 원 단위 배정액이 곧 지급액이다(R-3 기준 1 L6 예외 — 원문에 「지급」 · 「배정」 · 「부여」처럼 전액을 준다는 말이 있을 때).
- 건강검진 금액은 원문에 **주기(매년 · 연 1회)** 가 있을 때만 stated(사용자 결정 2026-10-06 「그대로 두기」 · 리드 판정 (80)). 주기가 없으면 NULL(⚖ C-10).
- stated 행의 서술에는 원 · 만원 숫자가 보여야 한다(SI-12 게이트 — 숫자 없는 stated 는 앵커가 새어 든 것으로 본다).

4-2. **estimated(표지 필수)** — 원문 숫자로 셀 수 있지만 원문이 연 금액을 직접 말하지 않을 때. 넷뿐이다(⚖ C-1):
- **월액 × 12**: NOTE 에 「월 N만원을 연 M만원으로 환산」처럼 **「환산」** 을 적는다. 대상이 좁은 월 지원금(보육지원금 · 장애 자녀 치료비)도 같다(R-1 계약 R6 · R-3 기준 28 · 리드 판정 ㉖). 월액을 그대로 금액 칸에 넣지 않는다(SI-B2).
- **포인트 → 원**: 「연간 100만 포인트」 → 100, NOTE 끝 「1포인트 1원 기준 환산」(엘앤에프 · LG유플러스 선례 — ⚖ C-11).
- **분포형 구간의 중간값**: 직급 · 호봉별로 나뉘어 각자 한 값을 받는 정액(「직급별 130~220만원」) → 중간값 175, NOTE 에 「직급별 구간 130~220만원의 중간값 (추정)」. 하한 · 상한을 쓰지 않는다(리드 판정 ⑱ · R-3 기준 22 · W4감사 §3-2).
- **식대**: 규칙 4-5 식(꼬리에 「추정」).

4-3. **NULL(정성)** — 아래는 금액이 아니다. 금액 · 조건은 서술에 남긴다:
- 원문에 숫자가 없는 제도 — **타사 금액 · 「같은 종류 제도의 기준 금액」(틀 값)을 신규 회사에 쓰지 않는다.** 기준 금액은 재수집에서 옛 추정치를 이어받을 때만 쓰던 장치다(09-21 계약 규칙 4 · R-1 계약 R6 — ⚖ C-1). 예외는 식대 하나(4-5).
- **한도 · 상한**(「연 N만원 한도」 · 「최대 N만원」 · 「N만원까지 실비」)(R-3 기준 1 L6). 배정형인지 한도인지 원문에 안 드러나면 NULL + 「판단 요청」.
- **1회성 지급**: 입학 · 출산 · 결혼 축하금 · 경조금 · 근속 포상금(「10년 근속 시」) · 인재추천 포상금 — 연 금액이 아니다(09-21 계약 규칙 4 확장 · 사용자 결정 2026-10-08 · 리드 판정 (88) — 웨이브 4 감사의 「사다리형 포상금 = 상한」은 이 결정으로 폐기됐다).
- 비율(「본인 100%」 · 「50% 지원」 · 「상여 800%」) — 비율을 금액 칸에 넣으면 100 = 100만원이 된다(현대제철 사고).
- 대출 원금 한도 · 이율 · 담보 · 질권 금액 · 자기주식 처분 총액 같은 회사 전체 금액(R-1 감사 계약 L5 · 후속 정리 5 D18 보로노이 질권).
- 조건부 급부: 대상 한정(신입 · 특정 직군 · 「대상자에 한하여」) · 기간 상한(「2년간」) · 선발 조건이 하나라도 붙으면 NULL · 정성(W4감사 §3-3 — 제주반도체 주거비 600 → NULL).
- 비율 · 횟수만 있고 단가가 없는 것, 주기가 없는 1회 값(「100만원 상당 VIP 검진」).

4-4. 금액 행의 NOTE 는 그 행의 서술이다(규칙 8-3 문안 규칙 그대로) — 원문 구절 + 출처 괄호 + 꼬리 「 — ○○ 미기재」 + 맨 끝 표지(「(추정)」 · 환산 문장 · 식대 꼬리 식).

4-5. **식대 기준 금액**(사용자 결정 2026-10-06 · 리드 판정 (82)(84) · 메모리 loupit-meal-unit-12000): `meal` 행은 원문에 끼니가 적혀 있으면 금액(만원) = **1끼 단가 × 하루 끼니 수 × 연 240일**.
- 단가 = 회사가 1끼 · 1일 단가를 밝히면 그 값(파두 1끼 15,000원 · 로보티즈 일 18,000원), 아니면 **12,000원** → 한 끼 288 · 두 끼 576 · 세 끼 864.
- 끼니 = 회사가 제공 · 지원 · 무료 · 무상 · 지급으로 적은 조식(아침) · 중식(점심) · 석식(저녁) 각 1, 「삼시세끼 · 세 끼 · 3끼 · 3식」 3, 「1일 2식」 2, 최대 3. 「사업장별 상이」는 적힌 끼니로 센다.
- **세지 않는 것**: 야식 · 간식 · 편의식 · 음료 / 야근 · 초과 근무 · 연장근로 조건부 끼니 / 회사 부담이 일부인 것(「보조」 · 「일부 지원」 · 「저렴한 · 합리적인 가격」) / 끼니가 안 적힌 「사내 식당 운영 · 식사 제공 · 식대 지원」(금액 NULL) / 「조식부터 야식까지 … 식사 또는 편의식」처럼 글자로 적힌 끼니가 불분명한 것.
- NOTE 맨 끝에 꼬리 식을 그대로 단다 — `(하루 N끼 × 1끼 12,000원 × 연 240일 추정)` · 회사 단가면 `(점심 1끼 15,000원 × 연 240일 추정, 야근 시 저녁 제외)` · `(하루 18,000원 × 연 240일 추정, 연장근로 추가분 제외)`. 「×」는 U+00D7. 제외한 끼니는 꼬리 안 「, ○○ 제외」. 꼬리의 N 은 이름 · 본문에서 센 끼니보다 클 수 없다(SI-9 게이트).
- 회사가 식대를 **월액 · 포인트로** 밝히면 회사 조건이 먼저다 — 월액 × 12 환산(4-2), 꼬리 식 없음. ⚖ C-12 — 이 경우 적재 게이트 SI-9 의 허용 목록(`server/tests/test_seed_integrity.py` `_MEAL_NO_TAIL_OK`)에 회사를 더해야 하므로 근거표 「배포 시 주의」에 적는다.

4-6. 금액 행마다 근거표 「금액」 표에 원문 숫자 인용 · 산식 · 예측 금액 출처(`_row_check.py` 출력 — stated / estimated)를 적는다.

4-7. 조건이 붙은 급부를 금액 행으로 만들지 않는다 — 금액 칸을 쓰면 `QUAL_YN=FALSE` 로 「조건 없음」이 구조적으로 찍힌다(W4감사 §3-3).

### 규칙 5 — 어휘

- 새 코드를 만들기 전에 `W5/_VOCAB.md`(89종)에서 같은 뜻을 찾는다. 함정 절을 끝까지 읽는다 — 그 절은 이 규칙과 같은 효력이다.
- 신규 코드는 대응 어휘가 정말 없고 원문이 혜택 내용을 밝힐 때만. 근거표 「신규 코드」 절에 ① 사유 ② **그 제도어로 코퍼스 전문을 grep 한 결과 전부**(1건 찾고 멈추지 않는다 — 웨이브 4 피에스케이가 테크윙만 찾고 엠씨넥스 · LIG넥스원을 놓쳐 `nonsmoking_bonus` ↔ `smoking_cessation` 충돌이 났다) ③ 제안 카테고리(가장 가까운 기존 코드의 카테고리)(W4감사 §10 ③).
- 코드 이름은 **지급 형태가 아니라 제도 영역**으로 짓는다(`smoking_cessation` ○ / `nonsmoking_bonus` ✗). 코드 이름은 그 자체가 주장이다 — `_loan` 을 붙이려면 원문이 대출 · 융자를 밝혀야 하고, 원문에 없는 낱말이 코드에 들어가면 안 된다(웨이브 4 HL만도 `welfare_fund_loan` → `welfare_fund`)(W4감사 §10 ③).
- 코퍼스에 대응 어휘가 있으면 신규 코드가 아니다(현대백화점 `housekeeping` → `parenting`).

### 규칙 6 — 귀속 (그룹 · 형제 · 부문)

6-1. 그룹 공통 복지를 개별 법인에 갖다 붙이지 않는다. **그 법인 원문에 있는 문장만 싣는다** — 같은 그룹 정본 문장과 글자까지 같아도 이 법인 페이지에 없으면 싣지 않는다(09-21 계약 규칙 6 · R-3 묶음 4 R8).
6-2. **법인 자기 도메인 페이지에 실린 문장은 형제 · 지주와 글자까지 같아도 그 법인 원문이다** — 각주 없이 싣는다(R-3 기준 26 · 리드 판정 ㉔).
6-3. 자기 도메인 채용 페이지의 **주어가 「OO그룹은」** 이어도 「계열사별 상이」 · 「일부 계열사」 같은 단서가 없으면 그룹 공통 제도로 싣고 출처 괄호 안에 「, ○○그룹 공통 문구」를 단다(덕산네오룩스 · 한미약품). 단서가 있으면 이 법인 적용이 확인된 제도만(R-3 기준 32 · 리드 판정 ㉝).
6-4. **형제 법인 이름이 주어인 페이지는 자기 도메인에 있어도 이 법인 근거가 아니다**(덕산 영문 Welfare 「DUKSAN Hi-Metal」). 같은 글이 여러 도메인에 있으면 이 법인 이름 · 도메인으로 실린 쪽만 근거다(R-3 기준 29 · 32 · 리드 판정 ㉗).
6-5. 그룹 통합 채용 사이트 · 그룹 채용 템플릿을 정본으로 쓸 수밖에 없으면(프로브가 귀속 경로를 확인한 경우) 귀속 경로를 머리말에 적고 **전 행 서술 끝에 「(그룹 통합 채용 기준)」**(컴퍼니 공통이면 NOTE 에 「(○○컴퍼니 공통 채용 기준)」 — 넷마블). 이 각주는 귀속의 전제라 절대 떨구지 않는다(09-21 계약 규칙 6 — ⚖ C-13 각주 두 꼴).
6-6. **그룹 템플릿 공고**(형제 법인 공고와 복리후생 블록 문장이 같음)는 전 행 각주 + 같은 템플릿의 형제 법인을 코퍼스에 또 등록하지 않는다(더존비즈온). 형제가 이미 등록돼 있으면 프로브가 「보류」를 냈어야 한다 — 수집 중 발견하면 SQL 을 쓰지 말고 보고(09-21 계약 · W5 프로브 계약 「바뀐 것 4」).
6-7. **한정의 종류에 따라:** 자회사 · 관계사(다른 법인) · 임원 · 연구위원 · 사내이사 전용은 **제외**(한정을 지우면 허위). 같은 법인의 **부문**(사업부문) 한정은 싣고 이름 끝 「(○○부문)」 + 서술에 적용 부문(삼성물산 · ㈜한화 · 한화시스템 ICT부문 — ⚖ C-7). **직군** 한정(생산직 · 교대근무 · 공장 근무 · 해상직)은 싣고 이름 · 서술에 대상 직군(R-1 감사 §2-5 #1 · R-3 묶음 3 HMM). 단체협약이 강제하는 직군 수당은 회사가 복지로 공시한 문장일 때만.
6-8. 그룹 · 형제 점검 결과(형제 법인 정본 문장과 겹친 행 · 처리)를 근거표 머리에 적는다(R-3 묶음 4~7 산출물 절).

### 규칙 7 — 이메일 도메인 관측

채용 페이지 · 개인정보처리방침 · 문의처에서 관측된 회사 공식 이메일 도메인을 근거표에 적는다(재직인증용 — 없으면 「미관측」). 웹 도메인과 메일 도메인이 다를 수 있다(파두 fadu.io → fadutec.com · HL만도 → hlcompany.com · 현대백화점 → thehyundai.com) — MX 를 확인했으면 적는다(09-21 계약 규칙 7 · W4인계 §7).

### 규칙 8 — 교육 (사용자 결정 2026-10-04 · PR2-SURVEY-v2 §5-1)

- **growth 행인 것:** 회사가 비용을 대는 것(학자금 · 자격증 취득비 · 어학비 · 사외 교육비) · 회사가 직접 여는 **어학 강좌 · 어학 과정 · 전화외국어 · 랭귀지 세션**(`lang`) · 직무 필수가 아닌 **자기계발 · 교양 강좌 · 특강 · 자율 수강 온라인 과정 · 학습 플랫폼 · 학습모임 지원**(`edu_support`).
- **행이 아닌 것:** 회사가 일을 맡기려고 여는 **업무 교육** — 신입 · 입문 교육 · 온보딩 · OJT · 멘토링 · 직무 필수 교육 · 리더십 · 직급별 · 승진자 교육 · 법정 의무 교육 · 선발형 핵심인재 과정. 업무 교육만 적힌 원문은 행을 만들지 않는다(⚖ C-6).
- 한 원문에 둘이 섞이면 복지 쪽만 서술에 남긴다.
- 판정 기준: 「회사가 지원하지 않으면 직원이 제 돈으로 들어야 하는 교육인가」.

8-1. **파견형 육성**: 학위 · 해외 파견형(MBA · EMBA · 석사 · 학술연수 · 지역전문가 · 주재원)은 `mba`(학위) 또는 `career`(파견 · 경력). 원문이 독립 항목이고 그 회사에 `career` 행이 있으면 `career`, 없으면 `mba` 행 서술에 흡수(행 신설 금지), MBA 와 한 복합 라벨이면 `mba`. **정본 페이지 안에 있으면 복리후생 블록 밖이어도 싣는다**(SK바이오팜 · 포스코퓨처엠). 사내 아카데미 · 직무 커리큘럼은 제외(09-21 계약 8-1 · 웨이브 4 추가 규칙).
8-2. 어휘 함정은 `W5/_VOCAB.md` 함정 절이 정본이다(09-21 계약 8-2 의 예식장 대관 · 주거 4분할 · lounge · 급여성 수당 · GWP 담당자 · 상담실 운영 · 보훈 · 장애 법정 의무 서술은 거기로 옮겼다).
8-3. **사용자 노출 필드 문안**(`BENEFIT_NM` · `NOTE_CTNT` · `QUAL_DESC_CTNT` — `/api/v1/companies` · 회사 페이지 · 비교 엔진 · 항목 페이지 · `/find` 로 그대로 나간다)(09-21 계약 8-3 · W4감사 §10 ④ · 후속 정리 5 서술 형식 · SPEC 20 SP-BEN-3):
- **모양:** `원문 구절 (출처 표기) — ○○ 미기재` — 원문 구절 뒤 출처 괄호(「공식 채용 페이지 복리후생 ○○ 항목」 · 「2026 지속가능경영보고서 47쪽 ○○ 항목」 · 「2026 반기보고서 직원 등 현황 항목」), 끝에 원문에 없는 사항 꼬리 하나. 출처가 둘 이상이면 「원문 구절 (출처1), 원문 구절 (출처2) — ○○ 미기재」.
- **「 — 」 꼬리는 서술 맨 끝 하나뿐이다.** 항목 페이지가 첫 「 — 」부터 끝까지를 수집자 메모로 걷어 내므로, 원문 내용 사이에 「 — 」를 쓰면 그 뒤 원문이 집계에서 통째로 사라진다(SI-11 — 2026-10-04 29행 정리). 원문 사이 구분은 「, 」 · 「 · 」.
- **허용** = 원문 라벨 + 출처 페이지명 + 조건 · 대상 + 미기재 사항. **금지** = 판단 근거 · 법조문 · 행 구조 · 수집 방법 · 페이지 품질 — 「코퍼스」 「선례」 「어휘」 「규칙 N」 「수집」 「검증」 「병합」 「판독」 「정본」 「미수록」 「흡수」 「회피」 「항목명 그대로」 「카드에는 별도 항목 없음」 「○○로 표기」 「영문 표기로 기재」 「⚠」 「구본」 「승계」 「앵커」 「틀 값」(전부 근거표 몫).
- **레인 메모 낱말 금지:** 「전문:」 · 「을/를 합친」 · 「덧붙인 · 덧붙일」 · 「을/를 빼면」 · 「#숫자」(SI-12 게이트).
- **「연차」 · 「반차」 · 「반반차」 낱말 금지** — 원문 항목명을 인용할 때도(「생일 반차」 → 「생일 반일 휴가」). 예외는 원문이 법정분과 회사분을 스스로 가른 「연차 외 추가 N일」 · 「연차와 별도」 꼴뿐(R-3 기준 3 · R-1 감사 §2-5 #6 — ⚖ C-3).
- **서술은 명사로 끝낸다.** `format.benefit_desc` 가 화면 문장을 만들어서 조사 · 부사형 어미(…에서 · …까지 · …회사가)로 끝내면 「회사가를 지원합니다」가 나온다(09-21 계약 서술 어미).
- 복합 라벨을 코드별로 쪼갰으면 **각 행은 자기 몫만** 말한다. 원문 라벨 전체를 모든 행에 복사하지 않는다 — 「미기재」 목록에 원문에 없는 제도를 전제하게 된다(W4감사 §10 ④ 농심).
- 공시 문장은 공시가 말한 것만, 연도 · 대상은 공시 그대로 쓴다. 「전 직원」처럼 원문 밖의 단언 금지(R-1 감사 계약 L5 · 리드 판정 (59)).

### 규칙 9 — 행 수

목표 12~25. 원문 항목이 적으면 억지로 늘리지 않는다(라벨만 있는 회사는 라벨 수 그대로). 원문 항목이 많고 코드가 다 다르면 넘어도 결함이 아니다 — 억지 분리 · 억지 확장만 결함이다. 병합은 같은 코드로 귀결되는 항목만(09-21 계약 규칙 9 · RV-1 L4).
- **이름만 있는 항목:** 회사가 **복리후생 목록의 항목**으로 적은 이름은 설명이 없어도 라벨만으로 싣는다(꼬리에 미기재 사항). 사옥 시설 나열 · 사진 캡션의 시설 이름(샤워실 · 회의실 · 탈의실) · 보고서 지표 표의 이름 칸(운영 근거와 어긋나는 것 — 같은 기간 대상이 있었는데 지급 0)은 싣지 않는다(W4감사 M-4 · R-1 감사 §2-5 #4 · 리드 판정 ㊻ — ⚖ C-5).

### 규칙 10 — 휴가 코딩

10-1. 휴가 코드 나누기(웨이브 3 확정 · 사용자 결정 2026-10-04 · PR2-SURVEY-v2 §5-5~5-7 · R-3 기준 18 · 23 · 31 개정):
- `refresh_leave` = 연차 **외에** 주는 휴가(리프레시 · Refresh · 재충전 · 안식 · 「연차 외 추가 5일」 · 「법정 휴가 외 추가 휴가」). **이름만 있어도 싣는다** — 서술 꼬리 「휴가 일수·부여 조건 미기재」. 근속 연동이면 `long_service_leave`.
- `long_service_leave` = 근속 연동 휴가(휴가와 포상을 한 줄에 함께 적은 원문 포함 — SPEC 20 경계). `long_service_bonus` = 휴가 없는 근속 포상금 · 기념품 · 여행. 원문이 휴가와 포상을 다른 항목으로 나누면 두 행.
- `leave_general` = 사건 보상(출장 · 심야근무 보상) · 이름 있는 집중 · 단체 휴가(PlusWeek · 하계 / 연말 단체 휴가 · 집중휴가제 · 월말휴무) · 「○○데이」 · **연차 일수를 밝힌 문장**(「연간 휴가 총 N일」 · 「최초 N일」 · 「법정보다 N일의 추가」 — 이름 · 서술에 「총」 · 「추가」를 남기고 「연차」 낱말은 걷는다) · 그 밖에 전용 코드가 없는 회사 재량 휴가(병가 · 인병휴가).
- `summer_leave` = 「하계 · 하기 · 여름」 이름 + 회사가 일수를 더 주는 휴가(현대오토에버 「하계 휴가 추가 5일」).
- `foundation_day_leave` = 창립기념일 휴무 · `birthday_leave` = 생일 휴가(「반일」로 적는다).
- 리프레시 · Refresh · 재충전이 아닌 **이름뿐인 휴가**(자기계발휴가 등)는 `leave_general`. 회사가 날을 정해 **본인 연차를 쓰게 하는** 공동연차는 법정(규칙 3-5), 「공동연차 N일 추가」처럼 회사가 더 주는 날이면 `leave_general`(파두)(W4감사 §10 ② · 사용자 정의 2026-10-04 — ⚖ C-15).
10-2. **이름 있는 집중 · 단체 휴무에 일수 · 대상 · 유급 여부가 없어도 싣는다** — 꼬리 「연차 사용일인지·일수·유급 여부 미기재」(사용자 결정 8a 2026-10-04 · 리드 판정 (65) LG에너지솔루션 월말휴무 — ⚖ C-4). 원문이 그날을 **본인 법정 휴가로 쓰는 것**이라고 밝히면 싣지 않는다(규칙 3-5)(R-3 기준 10).
10-3. 2시간 단위 휴가(규칙 3-4) = `leave_general` 「2시간 단위 휴가」.
10-4. 선택근로 안에서 주는 월 1회 휴무(Happy Friday · 부분적 주 4일)는 별도 휴가 행이 아니라 `flex_work` 서술(R-3 기준 21 · 리드 판정 ⑰). 적립휴가 · 보상휴가(초과근무 시간을 휴가로 바꾸는 것)도 `flex_work` 서술(W4감사 §10 ②).
10-5. 법정 휴가와 겹치는 휴가는 상회분만(규칙 3-2).

### 규칙 11 — 보상 · 포상 · 주식

11-1. **성과급:** 원문이 「임직원」 · 「전 직원」에게 성과금 · 인센티브가 있다고 밝히면 `incentive` 행을 세운다(지급 기준 · 지급률 미기재를 꼬리에). 이익 배분(PS) · 경영성과급을 **단독 제도**로 밝히면 `profit_sharing`, 개인 · 조직 평가 차등이나 PS 와 PI 를 한 줄에 적은 원문은 `incentive`(R-3 기준 20 · 리드 판정 ⑯ · PR2-SURVEY-v2 §5-9).
- 직군 · 집단 한정 성과급도 `incentive` — 서술에 대상(R-3 기준 27 · ㉕).
- 회사 자기 채용 공고 급여수준 칸의 「성과급 내부 규정에 따라 지급」 = `incentive`(대상 직무를 서술에)(R-3 기준 35 · ㊳).
- 재무제표 주석 「종업원에게 지급할 성과급」 충당부채 문장 · 기관 경영공시 평균보수 표의 성과상여금 = 직원 대상 성과급을 밝힌 공시 원문 → `incentive`(리드 판정 ㊹ · ㊾).
- 「모든 임직원」에게 주는 안전장려금은 선별 포상이 아니라 `incentive` 서술(리드 판정 ㊿).
- **임원 · 사내이사 전용** 보수 산정 문장(「전사 조직목표」 등)은 직원 복지 근거가 아니다 — 「직원과 동일한 기준」처럼 직원 적용이 문장에 있으면 그 부분만(R-3 기준 17).
11-2. **정기 상여율**(「상여금 연 800%」 · 「특별상여 연 3회」)은 회사가 **복리후생 블록 안에** 적었을 때만 `bonus` 행 · 금액 NULL. 임금 구성 문장(「임금은 기본급, 제수당, 명절 상여로 구성」)은 행이 아니다(R-1 감사 §2-2 · §2-4 — ⚖ C-8). 명절 상여금 · 귀성여비는 `holiday_gift`(어휘표).
11-3. **포상:** `excellence_award` = 회사 포상 제도(라벨만 있어도 선다 — R-1 감사 §2-2). 싣지 않는 것: 인재추천 포상금(채용 보상 — 리드 판정 ⑦) · 안전 · EHS 포상(안전관리 수단 — R-3 기준 30 · ㉙) · 「직무발명 보상(제도)」(법정 — R-3 기준 34 · ㉟). 회사 포상 제도 안의 「특허 · 제안 · 직무발명 포상」은 `excellence_award` 서술.
11-4. **주식:** 스톡옵션 · RSU 처럼 경영진 · 핵심인력에게 재량으로 고르는 부여는 복지가 아니다(루닛 REFUTED · 웨이브 4 추가 규칙). **우리사주조합은 전원 대상이라 싣는다 — 코드는 `stock_option`.** 공시 주주 현황 표의 「우리사주조합 N주」 한 칸만으로는 세우지 않는다 — 복리후생 목록 · 보고서 · 보도자료의 제도 문장이 있어야 한다(리드 판정 ㊼). 직원 대상 자사주 지급 = `stock_grant`(공시 문장 그대로 · 처분 총액은 금액이 아니다 — R-1 감사 계약 L5).
11-5. 퇴직금 누진제 등 법정 퇴직급여를 넘는 상회분 = `severance_plus`(compensation · 금액 NULL · 누진율은 서술에)(사용자 승인 2026-10-04 · 리드 판정 (62)).
11-6. 급여성 수당(학위 · 자격 · 직무 · 초임 · 무사고 운전 수당)은 복지가 아니다(09-21 계약 8-2).

### 규칙 12 — 대출 · 기금 · 주거

- **사내 대출 · 대출이자 지원은 용도 · 이율이 적혀 있지 않아도 싣는다**(사용자 결정 2026-10-04 · R-3 기준 13 개정 · PR2-SURVEY-v2 §5-4). 코드는 원문이 밝힌 용도를 따른다 — 주택 구입 · 전세 · 임차 = `housing_loan` / 생활안정 · 긴급 · 의료비 또는 **용도 미기재** = `welfare_fund_loan`. 사내근로복지기금 대출인지는 코드를 가르지 않는다. 원문에 없는 용도를 서술에 덧붙이지 않는다 — 꼬리 「대출 용도·한도·이율 미기재」. 원금 한도 · 이율은 금액이 아니다(규칙 4-3).
- 원문에 대출이 없는 기금 운영 · 생활안정자금 지원 = `welfare_fund`. 원문에 기금 낱말이 없으면 이름 · 서술에 기금을 쓰지 않는다(R-2 어휘 경계 · 웨이브 4 HL만도).
- 주거: `housing_loan`(대출 · 이자) / `housing_support`(임차비 · 주거비 현금) / `dormitory`(사택 · 기숙사 시설) / `relocation`(이주 · 정착지원금 — `housing_loan` 에 넣지 않는다)(웨이브 4 추가 규칙 어휘 갱신).
- 혜택이 적히지 않은 그룹 제휴카드 · 제휴 할인 **이름만**은 싣지 않는다. 회사가 복리후생 목록에 적은 「제휴 할인 혜택」(영역 · 대상이 드러남)은 `discount`(R-3 묶음 1 감사 후속 · R-1 감사 §2-5 #2 · 엘앤에프 — ⚖ C-16).

### 규칙 13 — 근무형태 칩 이름 (사용자 결정 6c 2026-10-04 · SPEC 03 SP-SEED-6.2 · SI-13d)

`remote_work` · `telecommute` · `wfh` · `flex_work` · `refresh_leave` · `long_service_leave` 행은 회사 페이지 · 비교 · 이직 계산기의 근무형태 칩이 **이름만** 읽는다(`/home/ubuntu/loupit/db/seed/company_meta.py` `ws_conditions`). 전 직원 제도가 아니면 한정을 이름에 **정해진 꼴**로 적는다:
- 대상 한정: 이름 **앞** 「육아기 」 · 「자녀돌봄 」 · 「부서별 」(뒤에 띄어쓰기 — 「육아기재택」처럼 붙이면 조건이 안 읽혀 맨 칩으로 샌다), 자녀 연령으로 대상을 정하면 이름 끝 「(자녀를 둔 …)」.
- 사유 한정: 이름 끝 「(필요 시)」(누구나 신청하는 「필요시 신청」 일반 제도에는 달지 않는다) · 끝 「(조건부)」.
- 부문 한정: 이름 끝 「(○○부문)」(한 행 일부만이면 「(휴가는 건설부문)」).
- 이 꼴 밖의 괄호(「(주 1회)」 · 「(WFA)」 · 「(재택근무 포함)」)와 이름 중간 괄호는 한정으로 읽지 않는다.
- 이름에 육아 · 자녀 · 부문 · 필요시가 보이는데 조건으로 안 읽히면 게이트(SI-13d)가 깬다 — `_row_check.py` 가 같은 판정을 한다. 근거표에 행마다 「칩: 맨 칩 / 조건 ○○」를 적는다.

### 규칙 14 — 공고 · 공시 근거 표시

14-1. **공고 근거:** 회사가 운영하는 채용 공고(그리팅 · 나인하이어 · 자기 도메인 공고)를 근거로 쓴 행이 있으면 근거표 머리에 **「공고 근거 N행 / 전체 M행」** 을 적는다 — 공고가 닫히면 근거가 사라지고 주간 점검기는 못 잡는다. 상시 페이지 · 공시 · 자기 발행 보고서로 받칠 수 있으면 그쪽을 정본으로. 같은 복리후생 블록이 **지금 게시 중인 공고 여럿에** 있으면 현행 원문으로 인정한다. 공고 원본(HTML · 이미지)은 `W5/<eng>/` 에 사본 + sha256(R-3 기준 36 · 레인보우 판정 · W4감사 §10 ⑤ — 이마트 · 제주반도체 한시 공고).
14-2. **공시:** 사업 · 반기보고서 본문의 「임직원 복지」 문장(사내 카페 · 시차출퇴근제 · 우리사주 제도 등)은 이 법인 공시 원문이다(R-3 기준 37). 임원 · 사내이사 전용 칸은 아니다(규칙 11-1). OpenDART 는 loupit 운영 키(`/home/ubuntu/loupit/server/.env` 의 `DART_API_KEY`)로 부르고, **키 문자열을 사본 · 로그 · 근거표에 남기지 않는다**(로그에는 `<키 생략>`)(R-3 묶음 7 근거표 관례). 접수번호 · 보고서 이름 · 항목명을 근거표 출처 표에.

### 규칙 15 — 출처가 없을 때 · 벽에 막혔을 때

15-1. **출처 없음:** 규칙 1 의 공식 출처를 끝내 찾지 못하면 **SQL 을 쓰지 않는다.** 근거표에는 「출처 탐색」 절(찾아본 URL · robots · 제외 사유)만 채우고, 최종 응답 첫 줄에 **「출처 없음」**. 3자 사이트 · 검색 스니펫 · 다른 법인 페이지로 채우지 않는다. 0행 파일을 만들지 않는다(R-3 묶음 2~7 「출처가 없을 때」).
15-2. **벽(robots · 렌더):** 본문이 robots 금지 호스트(`api-recruiter.recruiter.co.kr` · `api-builder` 등)에만 있거나 렌더 벽으로 못 읽으면 우회하지 않는다. **사람이 브라우저로 열면 그 본문이 보이는 공식 페이지의 정확한 URL** 을 근거표 「출처 탐색」 첫 줄과 최종 응답 첫 줄에 `붙여넣기 필요: <URL>` 로 적는다. 다른 공개 원문(보고서 · 자기 도메인)으로 행을 세울 수 있으면 세워 두고 붙여넣기 뒤 보강한다. 리드가 사용자에게 붙여넣기를 부탁할지 정한다(R-3 기준 16 · 25 · 유한양행 · 묶음 4-B 선례).
15-3. **검색 AI 요약은 신규 등록의 근거가 아니다.** 재수집에서 공식 출처 없는 기존 3사(케어젠 · 리노공업 · 리메드)에 쓴 「검색 AI 요약 수록」(R-3 기준 39)은 신규 회사에 쓰지 않는다 — 공식 출처가 없으면 등록하지 않는다. 사용자가 붙인 요약본이 와도 수집하지 않고 보고만 한다(리드 지시 2026-10-10).
15-4. **공시만 있는 경우:** 자기 도메인 · 회사 채용 페이지 · 자기 보고서에 복지 원문이 없고 공시 문장으로만 행을 세울 수 있으면 「출처 없음」으로 보고하고, 공시로 서는 행만 `W5/<eng>/<파일명>.candidate-<N>row.sql` 에 따로 둔다(collect/ 에 쓰지 않는다). 등록 여부는 리드가 정한다(R-3 기준 38 · HPSP 선례 — ⚖ C-9).

### 규칙 16 — 예절 (요청 · robots · UA · 렌더)

16-1. **robots.txt 는 호스트마다 단독으로 먼저 받고**, 판정이 끝난 뒤에만 본문을 요청한다(웨이브 3 프로브 4곳이 한 배치로 보내 금지 경로에 닿았다). 판정은 RFC 9309 — 가장 긴 일치 규칙 우선(`urllib.robotparser` 는 첫 일치라 `Disallow: /` + `Allow: /appsite/` 를 금지로 오판한다 — 쓰지 않는다). UA 줄 여러 개가 한 레코드로 묶인 robots 는 레코드 단위로 읽는다(09-21 계약 예절 · 웨이브 4 프로브 계약).
- `User-agent` 줄 없이 `Disallow: /` 만 있는 robots.txt 는 금지로 본다(R-3 기준 33 · 리드 판정 ㉞).
- robots.txt 가 **4xx(403 포함)** 이면 RFC 9309 대로 「규칙 없음 = 허용」이다(출처 점검기 `server/source_check.py` 와 같은 해석). 다만 **robots.txt 도 본문도 403 · 접속 거부**(사이트 전체가 막힘 — 케어젠)면 그 호스트는 요청하지 않는다(사용자 결정 2026-10-05 · R-3 기준 33 개정 · 동진쎄미켐 판정). S3 `AccessDenied` 로 403 인 CDN robots 는 「파일 없음」 = 허용(리드 판정 ㊷).
16-2. **벤더 호스트 robots 는 구속력이 있다** — 페이지 경로가 허용이어도 본문이 `Disallow: /` 인 다른 호스트(ATS 의 API · 빌더 · 정적 호스트)에만 있으면 읽지 않는다. 헤드리스 렌더로 우회하는 것도 같다 — 렌더가 그 호스트를 부른다(사용자 결정 2026-09-20 · W4인계 §3-1).
16-3. **UA 는 그 회사 robots 가 정한다** — `*` 는 막고 AI 봇(ClaudeBot 등)만 이름으로 허용하면 ClaudeBot UA(농심). 엣지가 AI 봇 UA 를 403 하고 robots 는 경로를 허용하면 일반 브라우저 UA(`Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/128.0 Safari/537.36`). 우리가 누구인지 숨기지 않는 쪽을 먼저 고른다. 막혀도 UA 를 바꿔 다시 두드리지 않는다. 프로브 판정문이 정한 UA 를 그대로 쓴다(W4인계 §3-2 · W5 프로브 계약 「바뀐 것 2」).
16-4. **요청 상한 = 회사당 60회**(프로브가 받아 둔 원문 재사용은 0회 · 렌더가 끌어오는 하위 리소스 · robots · OpenDART 호출 포함). 상한에 닿으면 멈추고 그때까지의 원문으로 판단하거나 「출처 없음 — 상한 도달」로 보고한다. 요청 수를 근거표 머리에 적는다(R-3 기준 14 — 위메이드 135회 · 텔레칩스 141회 사고 — ⚖ C-14).
16-5. **사이트 JS 에 박힌 키 · 토큰으로 API 를 부르지 않는다** — 페이지 스크립트가 쓰는 공용 키라도 꺼내 쓰는 것은 자격 증명 사용이다. 키 없이 열리는 데이터 API(JSON) · 정적 HTML · 요청 상한 안의 헤드리스 렌더만 쓴다. 권한 시스템이 요청을 거부하면 우회하지 않고 근거표 「확인하지 못한 것」에 적는다(R-3 기준 15 · 묶음 3 위메이드).
16-6. **헤드리스 렌더는 원본 HTML · `__NEXT_DATA__` · 데이터 JSON 에 항목이 없을 때만.** 렌더 전에 페이지가 부르는 데이터 API 를 먼저 찾는다(엔씨소프트 렌더 80요청 → API 1요청). 렌더할 때는 **그 페이지가 끌어올 호스트의 robots 를 먼저 받고**, 문서 요청 밖의 하위 요청(prefetch · `other` 포함)은 전부 끊는다(텔레칩스 렌더 1회에 prefetch 127회가 차단을 빠져나갔다). 요청 간 ≥1초를 렌더에도 적용한다(R-3 기준 5 · W4인계 §3-3 · 리드 메모 묶음 7).
16-7. GET 만(HEAD 를 믿지 않는다) · `--max-time 20` · 요청 간 ≥1초 · 내려받은 파일은 `W5/<eng>/` 아래에만(09-21 계약 예절 · 웨이브 4 프로브 계약).
16-8. **이미지 안 항목**은 내려받아 판독하고 URL · 크기 · sha256 · 판독 사본(`image_transcript.txt`)을 남긴다. **SPA** 면 번들 · API 를 추적해 본문을 확보하고 경로를 기록한다(청크 해시는 index → 청크 순)(09-21 계약 규칙 1).
16-9. 캐시버스터(`?v=<ts>`) · CSRF 토큰이 박힌 사이트는 페이지 sha256 이 증거가 되지 않는다 — 정규화한 **항목 텍스트의 해시**를 남긴다. 숨김 검사는 HTML 이 아니라 외부 CSS 에서 한다(W4감사 §10 ⑤).

필수 절:
1. **출처 표** — 채택 · 제외 URL · robots 판정(호스트별) · UA · 렌더 방식 · 받은 날 · sha256 · 프로브 사본 재사용 여부. 정본 URL 을 고른 이유와 점검기 조건(1-4).

4. **법정 제도** — 걷은 문구 · 상회분 판정 · 직원 수와 재취업지원 의무 판정(3-3).
5. **법정 · 편집 낱말 스윕** — `_legal_scan.py` 검출 줄마다 허용 / 교체 / 삭제(§2-4 ③).

7. **제외 목록** — 원문에 있었지만 싣지 않은 항목 · 이유(법정 · 업무 교육 · 다른 법인 · 임원 전용 · 급여성 · 이름뿐인 시설 등).
8. **판단 요청 · 애매** — 규칙으로 결론이 안 나는 것(추측으로 메우지 않는다).
9. **이메일 도메인 관측**(규칙 7).
10. **배포 시 주의** — 정본 URL 점검기 조건 · 한시적 출처 · SI-9 허용 목록 등 리드가 처리할 것.
11. **검증자가 볼 곳** 3~5줄.
