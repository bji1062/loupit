## 절차

### 1. 독립 목록 먼저 — **근거표를 읽기 전에**

- 프로브 판정문의 정본 URL 과 보조 출처(보고서 · 공시 · 공고)를 직접 가져와 **독립 항목 목록**을 만든다. 이미지면 직접 판독하고, `__NEXT_DATA__` · 번들이면 직접 추적하고, CSS 로 숨긴 탭이면 원본 HTML 로 본다(09-21 검증 계약 절차 1).
- 예절은 수집 계약 규칙 16 그대로다: robots.txt 를 호스트마다 단독으로 먼저 받아 RFC 9309(가장 긴 일치 우선)로 판정 · `User-agent` 줄 없는 `Disallow: /` = 금지 · robots.txt 4xx = 규칙 없음(다만 본문도 403 이면 그 호스트 요청 안 함) · 벤더 호스트 robots 구속 · 프로브가 정한 UA · GET 만 · 요청 간 ≥1초 · **회사당 60회**(렌더 하위 요청 · robots · OpenDART 포함) · 사이트 JS 키 · 토큰으로 API 호출 금지 · 렌더는 원본 HTML · 데이터 JSON 에 없을 때만, 문서 밖 하위 요청 차단(R-3 기준 14 · 15 · 33 · 개정 2026-10-05 · 리드 판정 ㉞ · ㊷).
- **권한 시스템이 요청을 거부하면 우회하지 않는다.** 거부된 확인 항목을 보고서 「확인하지 못한 것」에 적는다(묶음 4 검증 계약).
- **붙여넣기 사본이 정본인 회사**(ATS 벽 → 사용자 붙여넣기): 그 페이지 본문을 다시 받지 않는다. 사본 sha256 을 다시 계산해 `.sha256` 과 대조 · 행마다 원문 글자가 사본에 그대로 있는지(사본 경로:줄) · 사본 안의 MISSED · 보조 출처(보고서 · 공시) 재확인 · 정본 셸의 robots · 점검기 조건만 실측(R-3 묶음 4-B · 6-B 검증 방식).
- 3자 사이트(사람인 · 잡코리아 · 잡플래닛 · 캐치 · 인크루트 · 블라인드 · 원티드 · 크레딧잡) · 검색엔진 스니펫 · 검색 AI 요약은 수집기도 너도 인용 0건이어야 한다(수집 계약 규칙 1-2 · 15-3).

### 2. 행 판정

SQL 행 하나하나를 독립 목록 · 원문과 대조한다.
- **CONFIRMED** 원문이 그 행을 그 코드 · 그 조건 · 그 금액 · 그 문안으로 뒷받침한다.
- **SUSPECT** 원문은 있으나 코드 선택 · 조건 · 귀속 · 금액 · 금액 표지 · 문안 · 칩 이름이 의심스럽다(검수자 결정 필요) — 이유와 대안을 적는다. ⚠ **원문에 없는 낱말이 코드에 들어 있으면(`_loan` 인데 원문에 대출이 없다 등) CONFIRMED 처럼 보여도 SUSPECT** 로 내린다 — 웨이브 4 어휘 충돌 3건 중 검증이 스스로 이상을 적고도 CONFIRMED 로 넘긴 유일한 유형이다(09-21 검증 계약).
- **REFUTED** 원문이 없거나 반대로 말한다 — 유령 · 오독 · 다른 법인(형제 · 지주 · 자회사 페이지에만 있는 문장) · 임원 · 사내이사 전용 · 법정 제도 · 업무 교육만 적힌 원문(신입 · 입문 · 온보딩 · OJT · 멘토링 · 직무 필수 · 리더십 · 승진자 · 법정 교육) · 급여성 수당 · 공개 원문이 아닌 것(로그인 · 렌더 안 되는 키 · HTML 주석 · 메뉴 밖 옛 판 — 수집 계약 1-3) · stated 금액인데 원문에 그 숫자가 없음.
  - **REFUTED 사유가 아닌 것**(사용자 결정 2026-10-04 · 2026-10-05): 회사가 여는 어학 · 자기계발 · 교양 강좌 · 학습 플랫폼 · 용도 · 이율 미기재 사내 대출 · 이름만 있는 리프레시 휴가 · 이름만 있는 단체 휴무(⚖ C-4) · 부문 · 직군 한정 제도(한정이 이름 · 서술에 있으면 — ⚖ C-7) · 시차출퇴근 · 선택근로 · 수유 시설 · 반반차(2시간 단위). 본인 연차 사용을 밝힌 원문만 법정으로 제외한다.
- **MISSED** 원문엔 명시적 제도가 있는데 행이 없다. 단 수집 계약 규칙 3(법정) · 8(업무 교육) · 9(억지 확장 금지) · 11-3(인재추천 · 안전 포상 · 직무발명 보상) · 11-4(주주 표 한 칸 우리사주)로 뺀 것이 정당하면 MISSED 가 아니다 — 근거표 제외 목록과 대조한다.
  - ⚠ **MISSED 는 원문을 훑어 눈에 걸리길 기다리지 말고 코퍼스 비교축으로 적극 찾는다.** `W5/_VOCAB.md` 에서 **n 이 큰 코드부터** 짚어 가며 「이 회사엔 왜 이 축이 없는가」를 묻고, 없으면 원문에서 그 낱말을 직접 검색한다. 회사 간 비교는 **없는 축**으로도 표시되므로 원문에 있는데 빠진 행은 틀린 값과 같은 무게의 오류다(09-21 검증 계약 상설 ① — 웨이브 4 에서 이 줄 하나로 MISSED 4건이 나왔다).
  - 헤더 메뉴 안 영문판 · 보도자료 · 공시 「임직원 복지」 문장 · 공고 급여 칸 성과급이 자주 빠지는 원천이다(R-3 기준 6 · 12 · 35 · 37).

```
import sys

from server import source_check as sc
t = [sc.Target(1, sys.argv[2], sys.argv[2], sys.argv[1])]
for r in sc.run_checks(t, expectations={}):

```

### 8. 항목 페이지 영향 — `generator/data/benefit_pages/*.json`

복지 항목 페이지(37쪽)는 회사 원문을 규칙(정규식)으로 분류해 센다. 규칙이 새 행을 틀리게 분류하면 회사 이름과 함께 틀린 칸에 나간다. 수집본의 행 가운데 **설정 파일이 있는 코드**(`ls /home/ubuntu/loupit/generator/data/benefit_pages/`)를 규칙에 돌려 본다:
```
cd /home/ubuntu/loupit && python3 - /home/ubuntu/loupit-evidence/2026-10-10-wave5/collect/<파일명>.sql '<eng>' <<'EOF'
import sys, importlib.util
sys.path.insert(0, '/home/ubuntu/loupit')
from generator import benefit_rules as br
spec = importlib.util.spec_from_file_location('lc', '/home/ubuntu/loupit-evidence/2026-10-02-recollect-3-7/_len_check.py')
lc = importlib.util.module_from_spec(spec); spec.loader.exec_module(lc)
pages = br.load_pages()
src = open(sys.argv[1], encoding='utf-8').read(); comp = sys.argv[2]
m = lc.INS.search(src); cols = [c.strip() for c in m.group(1).replace('\n', ' ').split(',')]
for t in lc.parse_values(src, m.end()):
    r = dict(zip(cols, t)); code = r['BENEFIT_CD']
    if code not in pages:
        continue
    res = br.classify(pages[code], [{'comp': comp, 'desc': r['QUAL_DESC_CTNT'], 'note': r['NOTE_CTNT'], 'unverified': False}])
    row = res['rows'][0] if res['rows'] else None
    print(code, 'h', br.text_hash(r['QUAL_DESC_CTNT'], r['NOTE_CTNT']), 'mode', row and row['mode'], 'facets', sorted(row['facets']) if row else None)
EOF
```
- 행마다 분류 결과(방식 `mode` · 원문 항목 `facets`)가 원문 뜻과 맞는지 본다. 틀리면 **시드 문안으로 고칠 수 있는지 먼저**(원문 낱말을 살린 문안), 안 되면 예외를 권고한다: `{"comp": "<eng>", "h": "<text_hash>", "mode" | "facets_add" | "facets_remove": …, "why": "<원문 근거 한 문장>"}` — 해시는 **모의 최종 문안 기준**이다(조치로 문안이 바뀌면 해시도 바뀐다). 코드가 틀린 행은 예외(`exclude`)가 아니라 재코딩을 권고한다(SPEC 20 SP-BEN-3 · SP-BEN-5 · R-3 묶음 7 검증 레인 5 방식).
- 권고 예외를 메모리에서 적용해 `br.validate_all(<수정한 설정 dict>)` 오류 0 을 확인하고 결과 줄을 적는다(사람 글 숫자 · 수량어 금지 규칙은 설정 쪽이라 예외 추가로는 걸리지 않는다).

### 9. 조치 권고 — 감사 · 통합이 판단 없이 집행할 수 있는 모양
