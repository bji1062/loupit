### 채용사이트 `/career/welfare` 가 불가인 이유

- ATS sitemap(`/sitemap.xml`, 19 URL)에 `/career/welfare` 가 있고 요청은 허용이다. GET **200 · 22,937B**, `<title>에스엘 채용 | 일하는 문화</title>`, meta description 「에스엘의 일하는 문화를 소개하는 페이지입니다.」, JSON-LD publisher 「에스엘」 — **법인 귀속은 맞다**.
- 그러나 원본 HTML 의 가시 텍스트는 제목 17자뿐이고, 인라인 RSC 페이로드(`self.__next_f.push`) 13개에도 복지 문구가 없다(「복리·복지·휴가·학자금」 0회). Next.js(JOBFLEX `career/[path]` 라우트) **클라이언트 렌더**다.
- 본문을 주는 API 호스트는 이번 세션에서 **확정하지 못했다** — 라우트 청크 2개(`page-cf854d….js` 599B, `2767-4fdfdb….js` 141,693B)에서 `/brand/v1/font/design` 같은 상대 경로만 보였고 base URL 은 다른 모듈에 있다. 웨이브 4 현대해상(같은 JOBFLEX 구조, 본문 `api-recruiter.recruiter.co.kr/design/v2`)과 같은 구조로 보이며, 후보 API 호스트 두 곳이 모두 `Disallow: /` 이므로 **헤드리스 렌더도 하지 않았다**(계약 웨이브 4 벤더 호스트 규칙).
- 결론: 채용사이트 본문은 **불가(robots)**. 붙여넣기 후보 = `https://slworld.recruiter.co.kr/career/welfare`. 「일하는 문화」 페이지라 복지 블록이 실제로 있는지도 확인하지 못했다.
