# 세션 기록 — 2026-08-27 · 관제 · 히트맵 칸 강조·판독줄 (T-16.5)

브랜치 `lane/heatmap-hover`. 요청: "마우스를 갖다대면 해당 카테고리와 선택한 회사가 하이라이트 — prober 에도 있는 기능".

## prober 실측
번들에서 히트맵 hover 핸들러를 찾았다: 칸에 `mouseover` → 자기 칸 `stroke #2962FF 2px`, 그리고
`sector-rect` 중 **부모 섹터와 같은 것**에 `stroke 1.5px`. `mouseout` 에 둘 다 해제. 1초 뒤 툴팁.

## 우리 구현 (같은 동작 + 둘 더)
1. 칸 실선 강조 + **소속 그룹 사각형** 테두리(브랜드색 inset 2px, 머리글자도 브랜드색) — prober 와 동일.
2. **같은 회사의 다른 칸** 점선 — 카테고리 모드는 한 회사가 여러 항목 묶음에 흩어진다(실측: 복리후생
   패널에서 카카오페이 8칸·카카오 7칸). "이 회사의 다른 복지는 어디에?"가 한 번에 보인다.
3. **판독줄**(`aria-live=polite`) — 작은 칸은 글자가 안 들어간다. prober 는 1초 지연 툴팁으로 풀지만
   우리는 지도 위 한 줄에 즉시 띄운다. 키보드 포커스도 같은 강조·판독을 받는다(prober 는 마우스 전용).

연결 정보(`data-g`·`data-c`·`data-nm`)는 정적 HTML 에 있고 JS 는 class 만 토글한다 — 1,400칸을 일괄로
dim 하지 않고 관련 요소 몇 개만 건드린다.

## 알게 된 것
- **그룹 키는 배치마다 매기면 안 된다.** squarify 는 가로·세로에서 그룹 순서가 달라서, 배치 안에서
  번호를 매기면 두 배치의 키가 어긋나 강조가 엉뚱한 묶음을 칠한다 → `_group_keys` 를 패널마다 한 번
  만들어 두 배치가 공유. 테스트가 두 배치의 키↔이름 대응이 같은지 잰다.
- **칸에 묶음 이름을 중복 출력하면 90KB 커진다**(2,930칸). 이름은 그룹 요소(`data-nm`)에만 두고
  판독줄이 거기서 읽는다. 1,478 → 1,385KB(gzip 173 → 168KB).
- 그룹 사각형은 타일 **뒤**에 깔린다 — 강조가 보이는 곳은 테두리와 머리줄뿐이라 둘 다 세게 준다.
