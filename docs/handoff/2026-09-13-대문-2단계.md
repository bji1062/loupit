## 결정 (1단계와 달라진 점)

1. **등록 이력은 커밋되는 파일이다.** 번들에 등록일 필드가 없고 `TCOMPANY.INS_DTM` 은 `load.py --fresh` 한 번에 전부
   그날로 초기화된다. 파일이면 CI 가 검사할 수 있다 — `test_registrations_file_lists_every_seed_company_exactly_once` 가
   시드 SQL 126개 회사가 이력에 정확히 한 번씩 있는지 강제한다. 다음 웨이브 PR 이 이력을 빠뜨리면 붉어진다.
2. **「2026-09-12 기준」 → 「복지 항목 최근 확인 {max(verified_dtm)}」.** 생성 HTML 에 빌드 시각을 넣으면 sitemap lastmod
   지문이 매 빌드 바뀐다(`release.lastmod_index`). 데이터에서 나온 날짜만 쓴다. 지금 값은 2026-09-05.
3. **직원 순위는 연도 하나 — 보유 회사 80% 이상이 가진 최신 연도.** 1단계 스크립트는 회사마다 자기 최신 연도를 써서
   「2025 사업연도 기준」 문장과 2024 값이 섞일 수 있었다. 그냥 최신 연도를 쓰면 공시 시즌 부분 수집 때 소수 회사끼리의
   순위가 나간다(적대 검증 MED) → 커버리지 문턱. 실측 결과는 1단계와 같다(123사 전부 2025 보유).
4. **표기 함수는 회사 카드와 공유.** 연봉 `employ._to_manwon`(반올림 한 곳) · 근속 `_to_year`.
5. **「KRX 업종 분류를 따르므로 에코프로(금융)·코웨이(일반서비스)처럼 낯선 자리가 있습니다」** → 「사업 내용과 다르게
   보이는 자리가 있습니다」. 회사를 콕 집은 문장은 분류 CSV 가 바뀌면 거짓이 된다.
6. **확인일 기준점 = 최빈 확인일**(1단계는 2026-04-15 를 손으로 적었다). 금액 빈 정량 행·확인일 없는 행이 생기면 문장이 붙는다.
7. **「공동」은 정수 항목 수 축에만**(1단계 handoff 결정 6을 코드로). 소수 지표는 원값 순서 + 표시 반올림.
8. **폰트 preload 는 다른 페이지와 같게 둔다(결정 번복).** 1단계 handoff 의 「base 상속하면 2MB preload 가 붙으니 빼라」는
   전제가 틀렸다 — `styles.css` 의 `@font-face`(swap)가 preload 없이도 같은 2MB 를 받는다. 빼면 발견만 늦어져 대문만
   폴백 글꼴이 더 오래 보인다(적대 검증 LOW). 전송량을 줄이려면 서브셋·`unicode-range` 가 답이고 이번 범위 밖이다.
9. **푸터가 생성 페이지 공용으로 바뀌었다.** 수기 셸 푸터의 면책 문단(「본 서비스의 복지·연봉 정보는 참고용이며 실제와 다를 수
   있습니다…」)이 빠지고 `© jobcho.wiki` 가 붙는다. 정책 실질은 「읽기 전에 알아 둘 것」 문단과 `/disclaimer` 링크가 유지한다.
   다른 생성 137쪽과 같은 푸터이고, 대문에만 문단을 넣지는 않았다(넣으려면 `_footer.html` 에 넣어 전 페이지가 갖게 할 것).

### 이번에 밟은 함정

- **`{#-` 주석이 앞줄 줄바꿈을 먹는다.** `_head_meta.html` 에 설명 주석을 `{#-` 로 달았더니 og:image 와 preload 태그가
  한 줄로 붙어 **137쪽 전부**가 한 바이트씩 달라졌다. 테스트는 전부 초록이었다 — 실데이터 빌드 diff 로만 잡혔다.
  `{#`(대시 없음)는 `trim_blocks` 가 뒤 줄바꿈만 지워 출력이 같다. 공유 partial 을 건드리면 **반드시 빌드 diff**.

## 배포 (이 순서로)

이 PR 은 수기 셸을 지우지 않아 어느 순서로 해도 404 는 나지 않는다(적대 검증 확인). 다만 conf 가 없으면 생성 대문이
나가지 않고 SM-1b 가 실패하므로 아래 순서가 정본이다. **「순서가 틀리면 404」는 셸을 지우는 후속 PR 에서만 참이다.**

1. 스냅샷: `curl -s https://jobcho.wiki/ > ~/index-before-2026-09-13-home2.html`
2. **nginx conf 먼저**(머지 전에 해도 무변화 — dist 에 index.html 이 아직 없어 수기 셸이 나간다):
   - `diff /etc/nginx/sites-available/loupit.conf <worktree 또는 main>/infra/nginx/loupit.conf` → **`location = /` 한 곳만** 달라야 한다(다르면 멈추고 드리프트부터 본다)
   - 백업 `sudo cp /etc/nginx/sites-available/loupit.conf /etc/nginx/sites-available/loupit.conf.bak-$(date +%F-%H%M)`
   - 배치 → `sudo nginx -t && sudo systemctl reload nginx` → `/` 200 이고 바이트가 `web/index.html` 과 같은지
3. PR 머지 → 메인 트리 `git pull --ff-only`(여전히 수기 셸이 나간다 — 파일을 지우지 않았으므로)
4. `RELEASE_CONFIRM=1 bash infra/deploy/release.sh` → `web/dist/index.html` 생성 순간 `/` 가 생성 대문으로 넘어간다
5. 확인: `/` 에 `naver-site-verification` · `data-home-generated` · 「복지 항목 최근 확인」 · `/index.html` → 301 `/` · sitemap 에 `https://jobcho.wiki/` 1회 · 스모크 PASS(SM-1b 포함)
6. 롤백: `web/dist/index.html` 을 치우면 즉시 수기 셸로 돌아간다(폴백). conf 까지 되돌리려면 백업 복사 + reload.
7. beta conf 는 release.sh 가 배포하지 않는다 — 필요하면 같은 방식으로 수동 배치.
