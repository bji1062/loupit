## 신규 코드 (3건)

정식 어휘 9범주 전체와 코퍼스 실사용 코드 68종을 전수 대조한 뒤, 대응 코드가 없는 것만 신설했다.

- **`uniform`** (work_env) — 원문 "유니폼 제공(여름용ㆍ겨울용)". 어휘에 피복·근무복 코드 없음. `work_tools` 는 코퍼스 실사용 12건이 전부 노트북·듀얼모니터·스탠딩책상·사무용품 등 **장비**라 의류를 넣으면 의미 오염.
- **`team_dinner`** (perks) — 원문 "팀 회식비 지원". 어휘에 회식·팀 활동비 코드 없음. `meal`(주 5회 점심)·`event`(경조사)·`club`(동호회)이 모두 다른 제도로 이미 점유되어 병기 불가. 코퍼스에서 "회식"이 나오는 유일한 선례(주성엔지니어링)는 `transport`='대리운전비'로 전혀 다른 제도.
- **`visa_support`** (perks) — 원문 "비자 발급 지원". 어휘에 비자·체류자격 코드 없음. `relocation`(코퍼스 1건 = 현대모비스 '부임이사 지원' — 이사비·부임여비)은 이주 실비라 의미가 다름. 실리콘투는 채용 페이지에서 "외국인 비자 제공" 을 별도로 내세우는 회사라 흡수보다 신설이 정확.

**신규 코드 안전성 확인**: `BENEFIT_CD` 는 `db/schema.sql` 에서 `VARCHAR(30)` 이고 ENUM/CHECK 제약 없음. 서버 검증은 `server/models/benefit_edit.py` 의 `^[a-z][a-z0-9_]{1,29}$` 정규식뿐이라 세 코드 모두 통과. `generator/pages/heatmap.py` 의 `ITEM_LABEL` 은 화이트리스트가 아니라 **미등록 코드는 가장 흔한 `benefit_nm` 으로 폴백**하도록 되어 있어 렌더링도 깨지지 않는다.

## 병합/분리 판단 내역

- **분리**: "성과급 및 명절 상여 지급" → `incentive` + `holiday_gift` (어휘에 둘 다 존재, 성격도 다름)
- **분리**: "직무 교육비 지원(자기계발 및 도서 구입비 지원)" → `edu_support` + `books` (구본 `books` 앵커 보존 목적 포함)
  - `self_development` 를 세 번째 행으로 만들지 **않은** 이유: 원문 괄호는 **하나의 직무 교육비 제도가 무엇에 쓰이는지**를 열거한 것이라, 세 행으로 쪼개면 같은 예산이 3중 계상된다. 자기계발 부분은 `edu_support` 서술에 원문 그대로 남겼다.
- **병합**: "사내 카페테리아 운영" + "음료 및 간식 무료 제공" → `snack_bar` 1행 (영문본이 "Operation of in-house Cafeteria (Free Coffee)" 로 같은 시설을 가리킴)
- **병합**: "자사 쇼핑몰 제품 할인" + "외부 제휴 복지 서비스 제공" + "외부 제휴 식음료 할인 제공" → `discount` 1행 (셋 다 할인/제휴 혜택, `uq_comp_benefit` 로 코드 중복 불가)
- **병합 안 함**: "휴게 공간 운영(사내 카페, 안마의자)" 은 `snack_bar` 의 카페테리아와 별개 문장·별개 시설로 보고 `lounge` 로 유지
