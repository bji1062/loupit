## 수집 설계 시 유의

1. **법인 페이지와 그룹 문서를 절대 합치지 말 것.** 수록 대상은 `view.nhd?coCd=HDEHR` 의 16개뿐이다. 매력적인 항목(복지포인트·자녀 학자금·주택자금·휴가비·계열사 할인·기업대학·출산휴가 100일)은 **그룹 문서에만** 있고 사이트가 「회사별 상이」라고 명시했다 — 붙이면 삼성화재 `/insight/welfare` 와 같은 허위가 된다. 형제 법인 페이지(HDHOME·HDGF·HDHAN)의 학자금·어린이집·귀향여비도 마찬가지다.
2. **항목이 「카드 제목」이 아니라 「설명문 속 나열」이다.** `가족까지 행복한 회사` 같은 테마를 항목명으로 쓰면 복지 이름이 아니게 된다. 설명문을 쉼표·「등」 기준으로 쪼개 제도명을 뽑되, **한정어를 보존**할 것(가사도우미 = 만 8세 이하 자녀 / 근속 포상 = 5·10·15·20년 / 안식월 = 1개월). 금액은 원문에 **한 건도 없으므로 금액 칼럼은 전부 NULL**.
3. **법정 제도 분리**: `육아휴직`은 법정이라 미수록 대상. `건강검진`은 법정 일반건강검진과 경계라 판단 필요(더존비즈온과 동일 쟁점). 그룹 GWP 의 「출산 전/후 휴가 100일」은 법정 90일 초과분이라 매력적이지만 **그룹 문서라 채택 불가**.
4. **파싱·갱신 감지**: 페이지 전체 해시는 CSRF 토큰과 JS 캐시버스터 때문에 **매 요청 바뀐다**. 반드시 `div.for-flex.benefit-box` 블록만 잘라 해시할 것(실측 2,664B, 2회 동일). 파싱 시 `<h3 class="f80b tit">` 가 `현대백화점`인지로 법인 검증을 넣고, **없는 `coCd` 는 200 + 461B + `alert("존재하지 않는 데이터입니다")`** 로 오므로 상태코드로 성공 판정을 하면 안 된다.
