### 자기 도메인 `www.hi.co.kr` — 고객 포털 SPA, 회사소개 실페이지는 robots 금지 구간

| `https://www.hi.co.kr/index.jsp` | 200, **17,142B**, UTF-8. `body {display:none;}` 인 SPA 셸. **원본 HTML 에 `채용`·`복리`·`recruit`·`career` 링크 0건**. GNB 는 JS `HDMF_MENU` 가 런타임에 만든다 |

⚠ **회사소개 실페이지는 `/bin/...` 이고 robots 가 `Disallow: /bin` 으로 막는다.** 검색 색인에 노출된 실례(가져오지 않음):
`/bin/CI/CI/CICI8002G.jsp`(회사소개) · `/bin/CI/ON/CION3011G.jsp`(정기경영공시) · `/bin/CI/CI/CICI8087G.jsp`(보도자료) 등 회사소개·공시실 전 구간.
즉 **자기 도메인 쪽에서 복지 페이지를 찾더라도 그 경로대는 애초에 금지 구간**이다.

⚠ 우회로가 하나 있지만 **쓰지 않았다**: `/serviceAction.do?view=bin%2FKC%2F00%2FHHKC00000M` 처럼 `/bin` 경로를 쿼리스트링에 넣어 부르는 SPA 래퍼는
RFC 9309 경로 매칭상 **허용으로 계산된다**(`Disallow: /bin` 은 `/serviceAction.do` 에 매칭되지 않음). 금지 의도를 쿼리로 우회하는 꼴이라 이번 프로브에서는 요청하지 않았다.

### 정본 = 법인 전용 채용 서브도메인 `hi.recruiter.co.kr`

계약 §1 이 인정하는 「회사명이 붙은 전용 채용 서브도메인」 형태다(`hankooktire.recruiter.co.kr` 선례와 같은 잡플렉스/recruiter.co.kr ATS).

| 용도 | URL |
|---|---|
| **복리후생 (정본)** | `https://hi.recruiter.co.kr/career/welfare` |
| 채용 홈 | `https://hi.recruiter.co.kr/career/home` |
| 채용공고 | `https://hi.recruiter.co.kr/career/recruit` · 공고 상세 예 `/career/jobs/122743` |

`sitemap.xml`(200, 1,573B, 11 URL, robots 의 Sitemap 지시로 도달):
`/career/` 아래 `apply` · `faq` · `grow` · `home` · `map` · `notice` · `process` · `recruit` · `rule` · `taleted` · `welfare` 11개.
**KAI 선례와 달리 중복 슬러그(`home2`·`ideal(1)`·`faq78` 류)가 없다.** 다만 `lastmod` 가 11개 모두 조회 시각(`2026-09-20T00:29:26.433Z`)이라 **동적 생성값이지 수정일이 아니다**(한화생명과 같은 유형).

**법인 귀속 근거 (셸·메타 수준에서는 확실)**

1. 서브도메인 자체가 법인 약칭(`hi` = hi.co.kr 과 같은 브랜드 도메인)이다.
2. `<title>복리후생 | 현대해상 채용`, `<meta name="author" content="현대해상">`, `<meta name="description" content="현대해상의 복리후생을 소개하는 페이지입니다.">`, `og:site_name=현대해상 채용`.
3. `keywords` 가 이 법인 전용 직급·직무 체계다: `현대해상 4급채용`, `현대해상 6급채용`, `계리사 채용`, `손해사정사 채용`, `자산운용 채용`, `전문대졸 신입사원 채용`.
4. 렌더 후 DOM 에 남는 JSON-LD:
   `{"@type":"WebSite","name":"현대해상 채용","url":"https://hi.recruiter.co.kr/career","publisher":{"@type":"Organization","name":"현대해상"}}`
5. 테넌트 고유 소유확인 토큰 2종: `google-site-verification=552ypAMZ…`, `naver-site-verification=4671328e…`.

⚠ **그러나 본문 귀속은 검증하지 못했다.** KAI 선례에서 **같은 ATS 의 `/career/welfare` 가 마켓컬리 샘플 템플릿**이었고, 그때도 도메인·GNB·메타는 KAI 였다.
이번에는 본문을 한 글자도 받지 못했으므로 **「슬러그 `welfare` 가 샘플 템플릿일 가능성」을 배제할 수 없다.** 판정이 뒤집히면 이 검증이 첫 관문이다.

## ③ robots — **정본 페이지는 허용, 본문 API 호스트는 전면 금지**

판정은 `urllib.robotparser` 를 쓰지 않고 RFC 9309(가장 긴 일치 우선, `*`·`$` 와일드카드) 규칙을 직접 구현해 냈다. 전 호스트 **BOM 없음**.

| 호스트 | robots.txt | 레코드 구조 | 정본/대상 경로 판정 |
|---|---|---|---|
| `www.hi.co.kr` | 200, **367B**(CRLF), BOM 없음(`55 73 65`) | 레코드 1개: `User-agent: *` + `Allow: /` + **Disallow 16개** (`/jsp/bin/CL`·`/jsp/bin/CO`·`/jsp/bin/CS`·`/jsp/bin/MY`·`/Coocon`·`/META-INF`·`/product`·`/solution`·`/jsp/cache`·`/jsp/common`·`/jsp/error`·`/jsp/layout`·`/jsp/login`·`/jsp/main`·`/jsp/bin`·**`/bin`**). Sitemap 지시 없음 | `/`·`/index.jsp`·`/serviceAction.do`·`/js/…` **허용** / **`/bin/…` 금지** |
| `hi.co.kr` (apex) | **302 → www 의 robots.txt** | — | www 와 동일 |
| **`hi.recruiter.co.kr`** (정본) | 200, **250B**, BOM 없음 | ⚠ **UA 5줄이 한 레코드**다 — `*`·`Googlebot`·`Yeti`·`Daumoa`·`Bingbot` 이 규칙 없이 연달아 오고 그 뒤에 `Allow: /` + Disallow `/*/attachFile`·`/attachFile*`·`/bbs*`·`/resources*`·`/app*`. **UA 줄마다 그룹을 끊으면 정반대 판정이 난다**(웨이브 2 신한 함정과 같은 모양) | `/career/welfare` **허용**(`Allow: /`, 길이 1 매칭). `/sitemap.xml`·`/_next/static/**` 허용, `/app*` 금지 |
| **`api-recruiter.recruiter.co.kr`** (본문) | 200, **27B**, BOM 없음 | `User-agent: *` / **`Disallow: /`** | `/design/v2` **금지** |
| `infra1-static.recruiter.co.kr` | **403** (CloudFront `<Error><Code>MissingKey…`, 146B — robots 파일이 아니라 서명 URL 오류) | robots 부재 | RFC 9309 상 4xx = **허용** |
| `direct.hi.co.kr` | 200, **114B**, BOM 없음 | UA 3줄 한 레코드(`*`·`Googlebot`·`Yeti`) + `Disallow: /bin/` + Sitemap 지시 | `/service.do` 허용, `/bin/` 금지 |

**AI 봇 UA 별 판정**: 다섯 호스트 어디에도 `ClaudeBot`·`anthropic-ai`·`GPTBot`·`CCBot`·`Google-Extended` 를 지명한 레코드가 **없다**. 전부 `*` 그룹을 따른다.
→ 정본 `/career/welfare` 는 AI 봇 5종 모두 **허용**, 본문 `api-recruiter…/design/v2` 는 AI 봇 5종 모두 **금지**. 네패스식 AI 봇 선별 차단은 아니다.

## 수집 설계 시 유의 (수집·SQL은 이번 범위 밖)

1. **지금 규칙대로면 수집 불가다.** 복지 본문은 `api-recruiter.recruiter.co.kr/design/v2?languageType=KOR` 응답 안에만 있고, 그 호스트 robots 는 27바이트짜리 `User-agent: * / Disallow: /` 다. 정본 페이지(`/career/welfare`)가 허용이라고 해서 본문을 가져올 수 있는 게 아니다 — **허용된 페이지를 렌더하는 행위 자체가 금지 호스트 호출**이다. 웨이브 3 이탈 4건(금지 경로 하위 리소스)이 바로 이 실수였다.
2. **판정을 뒤집으려면 리드가 먼저 정책을 정해야 한다.** 「ATS 벤더가 API 호스트에 기계적으로 건 `Disallow: /` 는 콘텐츠 소유자(현대해상)의 의사가 아니다」로 볼 근거는 있다 — 같은 페이지에 `<meta name="robots" content="index, follow">` 와 구글·네이버 소유확인 토큰이 붙어 있어 **색인은 명시적으로 원하고 있다**. 그러나 이건 프로브가 아니라 리드의 판단 영역이다.
3. **정책이 열려도 KAI 함정 검증이 먼저다.** 같은 ATS 의 `/career/welfare` 슬러그가 KAI 에서 **마켓컬리 샘플 템플릿**이었다. 현대해상 sitemap 은 중복 슬러그가 없어 KAI 보다 깨끗해 보이지만, 본문을 못 봤으므로 보증할 수 없다. 첫 수집 때 **본문에 「현대해상」·4급/6급·계리사·손해사정사 같은 이 법인 고유 문구가 실제로 들어 있는지**, 그리고 타사명(컬리·기타)이 섞이지 않았는지부터 확인할 것. 실패하면 그 자리에서 중단.
4. **자기 도메인 쪽으로 우회할 생각은 접어라.** `www.hi.co.kr` 은 회사소개·공시실 전체가 `/bin/…` 이고 robots 가 `/bin` 을 막는다. `/serviceAction.do?view=bin%2F…` 래퍼는 경로 매칭상 허용으로 계산되지만 **금지 의도를 쿼리로 우회하는 형태**라 쓰지 말 것. 게다가 검색 색인에도 hi.co.kr 쪽 복리후생 페이지는 잡히지 않는다.
5. **`direct.hi.co.kr` 를 임직원 복지 출처로 쓰지 말 것.** 다이렉트(CM/TM) 채널 사이트이고 `service.do?m=<해시>` 가 GET 에 0바이트를 준다. 한화생명 FP 선례처럼 **채널 상담직 처우와 임직원 복지를 섞는 오염 위험**이 여기다.
6. **재수집 배선 메모**(판정이 열릴 경우): 시작 URL 은 `hi.recruiter.co.kr/career/welfare` 고정, 렌더 필수(원본 HTML 14자), 갱신 감지는 `sitemap.xml` 의 `lastmod` 로 하면 안 된다 — 11개 URL 전부 **조회 시각이 그대로 찍혀 나온다**. 본문 JSON 바이트 해시로 비교할 것. 그리고 법인 지표는 **금융 세트**(`FINANCIAL_COMPANIES` 편입)로 돌려야 한다.
