## 수집 설계 시 유의 (수집·SQL은 이번 범위 밖)

1. **정본을 「최신 공고 이미지」로 고정하고 버전을 박아라.** 항목 11행은 `RecruitDetail?No=25`(2026-08-06, Last-Modified 로 확인)가 최신이다. 2025년 안내(No=13)에는 없어진 「복지포인트/카드 지원」·「도서문화생활비」가 남아 있어 섞어 읽으면 허위 항목이 생긴다. 근거표에는 공고 번호 + 이미지 파일명 + Last-Modified 를 함께 적고, 이미지 사본을 스크래치에 남겨 검증이 같은 장을 볼 수 있게 한다.
2. **출처가 사라진다.** 공고는 「채용시까지」로 걸려 있고 마감되면 `RecruitDetail` 행과 이미지 URL(UUID 파일명)이 통째로 없어질 수 있다. 반면 `/kr/About/Welfare` 는 안정적이지만 3항목뿐이다. 카드 출처 URL 은 **복지 페이지(안정)** 로 두고 항목별 근거에 공고 이미지 URL 을 병기하는 이중 표기를 권한다. 갱신 감지는 URL 이 아니라 이미지 바이트 해시로.
3. **법정 3종과 혼재 1행을 먼저 걷어내라.** HTML 의 4대 보험·주 5일제·연차휴가는 미수록. 이미지 8행 「육아 지원」은 출산 축하금·보육 수당(수록)과 출산휴가·육아휴직(법정)이 한 줄에 묶여 있어 분할이 필요하고, 7행은 법정 검진이 아니라 「종합검진비용 지원」이라는 점을 원문 그대로 남겨야 한다. 「직무발명규정 인센티브」(HTML)도 발명진흥법상 보상과 겹치는지 어휘표로 판단할 것.
4. **금액 5건은 형태가 제각각이다.** 연액(130~220만원, 직급별 구간) · 명절 1회성(각 250만원) · 물품 상당액(10만원) · 월액×기간 한정(월 50만원, 2년, 「대상자에 한하여」) · 월액(2만원). 웨이브 4 수집 계약의 1회성·일액 AMT NULL 규칙과 구간 금액 처리에 그대로 걸리니 행을 만들기 전에 규칙 대조부터 한다. 「대상자에 한하여」 같은 조건절을 떨구면 전원 지급으로 읽힌다.
5. **평문 HTTP·회사명 없는 페이지 두 가지를 수집기 쪽에서 방어하라.** ① https 로 요청하면 20초 타임아웃만 먹으므로 이 회사만 http 스킴 허용 예외가 필요하고, 출처 표기에 「HTTPS 미제공」을 남겨 둔다(링크를 https 로 자동 승격하는 렌더러가 있으면 죽는다). ② `/kr/About/Welfare` 원본에는 「제주반도체」 문자열이 0회라 회사명 가드가 오탐한다 — 도메인·푸터 주소로 귀속을 확인할 것. 또 이미지 판독 결과는 텍스트 근거가 없으므로 근거표에 「이미지 판독(파일명·좌표 구획)」임을 명시해 검증이 재판독하게 한다.
