## 4. 코드 매핑 판단 · 어휘 함정 회피

### 4-1. 분할한 3건 — 사유

- **`식사 및 간식 지원` → `meal` + `snack_bar`**: 한 라벨에 끼니와 간식이 병기돼 있다. 코퍼스 실측상 간식은 `snack_bar` 로 코딩돼 있다(`간식코너`·`간식/음료`·`간식/커피 지원`·`사내 카페/간식` 등 12행). 합쳐 `meal` 한 행으로 둔 선례(`사내 식사·간식 제공`)도 1건 있어 **양쪽 선례가 다 있는 자리**다. 비교 축에서 간식 제공 여부가 사라지지 않도록 분할을 택했다.
  ⚠ **판단이 갈릴 수 있는 지점.** 합치기로 결정되면 `snack_bar` 행을 지우고 `meal` 서술에 흡수하면 되고 다른 행은 영향이 없다.
- **`본인/가족경조사 및 자녀학자금 지원` → `event` + `child_edu`**: 경조사와 학자금은 코퍼스에서 완전히 다른 두 코드(`event` 124사 · `child_edu` 98사)다. 한 코드에 담으면 둘 중 하나가 비교에서 사라진다.
- **`종합 건강검진 및 의료비 지원` → `health_check` + `medical`**: 같은 이유(`health_check` 122사 · `medical` 72사).

### 4-2. 병합한 1건 — `본사 예식장 운영` → `event`

- 계약 8-2 가 「예식장·웨딩홀 대관 = `event` 서술(`wedding` 은 현금 축하금+휴가)」로 못박는다. 농심 원문에 축하금·휴가 서술이 없어 `wedding` 은 성립하지 않는다.
- **직접 선례**: 삼성ENA 가 「사옥 결혼식장 대관(wedding)을 경조 지원(event)에 병합 — 코퍼스 wedding 은 현금 축하금 1행 축이다」로 같은 처리를 했다(2026-09-05 검증·감사 판정).
- `event` 는 회사당 UNIQUE 라 경조사 행과 같은 행에 합쳐 `BENEFIT_NM` 을 「경조사 지원·본사 예식장」으로, `QUAL_DESC` 에 두 원문을 모두 넣었다.
- ⚠ 예식장은 원문 「행복한 가정」 섹션(항목 7), 경조사는 「안정적인 삶」 섹션(항목 11)이라 **서로 다른 섹션의 항목이 한 행으로 합쳐졌다.** SORT 는 `family` 섹션(40대)에 놓았다.

### 4-3. 분할하지 않은 1건 — `대출지원(의료비,학자금,주택)`

의료비·학자금·주택 세 용도의 대출이 한 라벨에 묶여 있다. **`housing_loan` 1행으로 두고 원문 라벨을 그대로 인용**했다. 사유:

- 코퍼스 실측상 `housing_loan` 이 사실상 **사내 대출 일반 코드**로 쓰인다 — `임직원 대출`·`사내대출`·`사내 대출`·`주택/생계 대출`·`주택 구입자금·생활 안정자금 대출`·`주거안정 대출지원`·`주택/전세/긴급 대출` 같은 명칭이 이미 이 코드에 들어 있다.
- 의료비 대출·학자금 대출에 대응하는 코드가 어휘표 87종에 **없다**(`welfare_fund_loan` 은 사내근로복지기금 명시가 있을 때만인데 원문에 그 문구가 없다). 괄호 안 열거만 보고 신규 코드를 2개 만드는 것은 과하다.
- `medical`(의료비 **지원**)·`child_edu`(자녀 학자금 **지원**)와 대출은 다른 제도라 그쪽에 섞지 않았다. 농심은 두 행이 따로 있어 섞으면 중복이 된다.

### 4-5. 제외 1건 — `자율복장 출퇴근` (신규 코드를 만들지 않았다)

원문 「즐거운 일터」 첫 항목이지만 **행으로 만들지 않았다.** 처음에는 `casual_dress` 신규 코드를 세웠다가, 코퍼스 실측으로 **기존 선례가 정반대**임을 확인하고 철회했다.

- 어휘표 87종에 복장 관련 코드는 `uniform`(근무복) 하나뿐이고, 함정 절이 「`uniform` = 근무복(**자율복장 아님**)」으로 배제한다.
- 코퍼스 138사 전 파일 grep: `복장` 을 담은 **행**은 엔켐의 `uniform`/`유니폼·복장` 1건뿐이고, 그것도 서술이 `유니폼/사원증 지급, 캐쥬얼 복장 허용` 이라 **유니폼 지급이 주(主)**인 행이다. `dress`·`casual`·`attire`·`cloth` 로 시작하는 코드는 **0건**.
- **결정적 선례 2건**
  - 원익IPS(2026-09-01 검증 판정): 「**자율복장(uniform 반증)**·사내 교육과정 체계·크로스 소통 3행 삭제」 — 자율복장 행이 검증에서 반증돼 **삭제**됐다. 신규 코드로 살리지 않았다.
  - 삼성ENA(2026-09-05): 제외 목록에 「**자율 복장(원익IPS 선례에서 uniform 반증으로 삭제된 유형)**」을 명시해 같은 처리를 반복했다.
- → 여기서 `casual_dress` 를 신설하면 **이미 두 번 확정된 코퍼스 판정을 뒤집는 것**이 된다. 계약 §5 의 신규 코드 조건(「대응 어휘가 정말 없을 때만」)은 만족하지만, 대응 어휘가 없는 이유가 「코퍼스가 이 유형을 복지 행으로 보지 않기로 했기 때문」이라 신설 사유가 성립하지 않는다.
- ⚠ **리드·감사가 방침을 바꿔 자율복장을 수록하기로 한다면**, 농심은 원문 라벨이 `자율복장 출퇴근` 으로 명확해 즉시 1행(`work_env`)을 추가할 수 있다. 그때는 원익IPS·삼성ENA 도 함께 되살려야 코퍼스 일관성이 유지된다.

## 5. 법정 제도 미수록 확인

정본 문서 전체 문자열 검사(grep) 결과:

| 법정 키워드 | 출현 |
|---|---:|

| `퇴직연금` | 0 |
| `연차` | 0 |
| `육아휴직` | 0 |
| `출산휴가` | 0 |
| `난임` | 0 |

→ 애초에 원문에 법정 제도 문구가 없어 **제거할 행이 없었고, 어떤 행의 `QUAL_DESC` 에도 법정 문구를 넣지 않았다.**

경계 항목 판단:

1. **`종합 건강검진 및 의료비 지원` → 수록.** 산안법상 의무는 「일반건강검진」이고 원문은 **「종합 건강검진」**이다. 종합검진은 회사 부담 상회분이며 코퍼스 122사가 `health_check` 를 쓴다. 다만 원문이 법정 검진 대비 무엇을 더 주는지 밝히지 않으므로 `QUAL_DESC` 에 「검진 주기·대상 가족 범위·비용 부담 미기재」로 한계를 적었다.
2. **`노동절, 창립기념일 기념품 지급` → 수록(기념품만).** 근로자의 날은 법정 휴일이라 계약 §3 대상이지만, **이 행이 담는 혜택은 휴일이 아니라 기념품 지급**이다. 원문 라벨을 그대로 인용하면 「노동절」이라는 날짜 수식어가 `QUAL_DESC` 에 남는다.
   ⚠ **판단이 갈릴 수 있는 지점.** 계약 §3 을 글자 그대로 읽으면 「근로자의 날」은 `QUAL_DESC` 에 쓰지 말라고 돼 있다. 「날짜 수식어로서의 인용은 법정 휴일 자체를 복지로 주장하는 것이 아니다」로 읽어 남겼다. 감사가 반대하면 `QUAL_DESC` 를 「창립기념일 기념품 지급 …」으로 줄이면 된다(코드·행 수 불변).
3. **`본사 어린이집 운영` → 수록.** 영유아보육법상 직장어린이집 설치의무 대상이라도 **운영 자체를 복지로 본 선례**(포스코인터내셔널 `직장어린이집`)가 있고 코퍼스 57사가 `childcare` 를 쓴다.
4. **`시차출퇴근제도` → 수록.** 법정 제도가 아니라 회사 재량 유연근무제다. 정부 유연근무 지원금과 혼동되지 않도록 `QUAL_DESC` 에 지원금 언급을 넣지 않았다.

## 6. 금액

## 9. 배포 시 주의

1. **UA 고정.** 재수집·검증 때도 `recruit.nongshim.com` 에는 **`ClaudeBot` UA + 요청 간 10초 이상**. 일반 브라우저 UA 는 `*` 그룹 `Disallow: /` 위반이다. `anthropic-ai`·`Google-Extended` 는 이 호스트 robots 명단에 없으니 쓰면 안 된다.
2. **URL 고정.** 두 호스트 `sitemap.xml` 404, `www` 메뉴의 `personnel/guide/index`·`introduce/company/index` 404. 링크 크롤로 경로를 찾게 두면 404 를 먹고, `www.nongshimtk.com`(robots 전면 차단)으로 샐 수 있다.
3. **갱신 감지**는 `<title>`·canonical 이 아니라 `div.benefits-container` 해시(`8f4c5258…`)로. TLS 인증서가 **2027-01-22 만료**라 그 전후 재수집 때 검증 실패 여부를 확인할 것.
4. **회사 추가 = 정적 재생성 필수**(기존 운영 규칙). `INDUSTRY_NM='식품'` 은 CJ제일제당·삼양식품과 **같은 값**을 그대로 썼다 — trending 폴백 쌍이 이 값으로 묶이므로 「식품/음료」 같은 변형을 만들지 않았다.
