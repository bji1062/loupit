## 할 일 (권장 순서)

### ① 모바일에서 카드의 복지 행 목록 접기 — **S · JS 0**

폰(1열)에서 카드가 27줄을 늘어놓고, 바로 아래 원장이 같은 27개를 전문과 함께 다시 보여 준다.
카드 쪽은 **카테고리 헤더 9줄만** 남기고 행 목록을 접는다.

- **본문 손실 0** — 카드 행은 이름·금액 토큰뿐이고 전문은 원장에 있다(SEO 안전).
- 미디어쿼리 한 줄이면 된다: `@media (max-width:767px) { .sc-cat ul { display:none } }` 수준.
  ⚠ 단, 이 디자인 시스템의 분기는 **`min-width:768px` 하나뿐**이고 `web/test/tokens.test.js`
  (UT-BP)가 그것을 강제한다 → `max-width` 를 새로 쓰지 말고 **기본(모바일)에서 접고 768 분기에서
  펴는** 방향으로 작성할 것.
- 접었을 때 카테고리 헤더가 원장의 그 카테고리(`#cat-{ctgr}`)로 가는 링크가 되면 자연스럽다
  (앵커·`scroll-margin-top` 은 이미 있다).

### ② 출처 렌즈(강조 스위치) — **S · JS 인핸스먼트로 결정됨**

카드 머리에 칩 한 줄: `전체 27 / 회사 공식 수치 3 / 추정치 8 / 정성 16 / 금액 미기재 0 /
재직자 등록·수정 0 / 만료 0`. 고르면 해당 행에 띠가 깔리고 나머지는 흐려진다(`opacity:.45`).
**행을 숨기지 않는다** — 숨기면 본문이 DOM 에서 사라져 SEO 가 깎이고, "복지가 8개뿐"으로 읽히는
거짓이 생긴다.

**CSS 전용이 아니라 JS 로 가기로 한 이유(2026-09-04 결정):**

- CSS 전용은 `input:checked ~ …` 형제 사슬이라 라디오가 카드·원장보다 **앞의 형제**여야 한다.
  지금 카드(`.stat-card`)와 원장(`.benefits`)은 별개 섹션이라 **회사 페이지 DOM 을 재배치**해야
  하고, 그건 선택자 제약에 맞추려고 마크업을 비트는 것이다. 다음 사람이 한 겹 감싸는 순간
  조용히 죽는다(`styles.css` 의 mshape 경고와 같은 함정).
- 렌즈는 **본문이 아니라 강조**다. NFR24 는 "본문 표시·색인이 JS 없이 완성"이지 "JS 금지"가 아니다.
  JS 가 죽으면 **지금 배포된 화면 그대로**다(기본 상태 = 전체). 실패 모드가 무해하다.
  ↔ 비교: 「연도별 추이」의 막대/꺾은선을 CSS 로 만든 이유는 JS 가 죽으면 **두 그래프가 다 보이는
  망가진 화면**이 되기 때문이다. 성격이 다르다.

**역할 분리(이걸 어기면 판정이 또 흩어진다):**

| 층 | 하는 일 |
|---|---|
| 파이썬(빌드) | 행에 `data-amt="stated\|estimated\|none"` 을 이미 박는다. **판정 끝** |
| JS (~25줄) | 칩 클릭 → 최상위에 `data-lens="est"` 하나 세팅. **그게 전부** |
| CSS | `[data-lens="est"] [data-amt="estimated"]{배경}` / `:not(...)`{opacity:.45} |

- JS 가 "이 행이 추정인가"를 **다시 판단하면 안 된다.** 그 판정은 `generator/format.py::amount_kind`
  하나가 소유한다(1차 리뷰에서 세 곳으로 갈려 있던 것을 모았다).
- **칩은 `hidden` 으로 내보내고 JS 가 벗긴다** — JS 없으면 눌러도 아무 일 없는 죽은 컨트롤이 남는다
  (편집 링크 `data-authnav-edit` 와 같은 패턴).
- **선택을 기억시키지 않는다.** 이 저장소에는 "상태 복원 장치에 화면 결정권을 주지 마라"는 비싼
  교훈이 있다(대문이 대문이 아니게 된 사고, 2026-07-31). 기본은 항상 '전체'.
- 사이드 「항목 구성」의 숫자들이 같은 스위치를 겸하면 자연스럽다(`<button>` 으로).

### ③ 항목 수 순위 재고 — **결정: 기존 순위 유지**(2026-09-04 사용자)

카드의 "113개사 중 공동 N번째"가 **107/113 페이지에서 '공동'** 이다(14항목에 12개사가 몰림).
선택지는 셋이었다(빼기 / 상위 % / 유지). **유지로 닫는다.**

- **이유**: '공동' 이 많은 것은 문구의 결함이 아니라 **데이터의 현재 상태**다. 이용자가 늘어
  재직자 등록·수정이 쌓이면 항목 수가 흩어져 동률이 저절로 풀린다 — 그때 '상위 %' 는 오히려
  덜 구체적인 표현이 된다. 지금 문구를 갈아엎으면 데이터가 좋아졌을 때 되돌려야 한다.
- **모집단은 뗄 수 없다**: 순위든 몫이든 `N개사 중` 을 달고 나간다(이 저장소 규약). 그래서
  '개사 중' 은 순위 표현의 필수 토큰이고, D-6 가드가 금액 행에서 그것을 찾는다.
- **가드**: `test_item_count_row_keeps_its_population_rank` 가 이 결정을 못박는다. 문구를
  바꾸려면 그 테스트를 함께 고쳐야 하고, 그 순간 결정이 뒤집힌다는 사실이 드러난다.

**함께 한 정리(2026-09-05)**: `corpus.rank_of()` 가 내던 `amount`·`amount_rank`·`amount_tied` 는
읽는 곳이 0곳인 **죽은 키**였다(D-6 로 렌더만 빠지고 계산이 남았다). 지웠다 — `render.py` 가
`StrictUndefined` 라 **키가 없으면 템플릿이 쓰는 순간 빌드가 죽는 것**이 낱말 가드보다 강하다.

## 시작 전에 알아야 할 함정 (1차에서 실제로 밟은 것들)

1. **판정은 한 곳** — `format.amount_kind`(금액 신뢰도) · `format.badge_state`(출처 계보) ·
   `company.benefit_anchor`(앵커). 화면이 셋인데 판정을 복사하면 같은 복지가 화면마다 다르게 나온다.
2. **금액 합계에 순위를 붙이지 마라** — 등록 금액에 대출 한도(1억)·일회성 포상이 섞여 있어
   "연 합계 1번째"가 거짓이 된다(D-6). 1차에서 화면에서 뺐고, **2026-09-05 에 계산까지 지웠다**
   (`corpus.rank_of()` 키 = `total`·`item_count`·`items_rank`·`items_tied` 넷).
3. **정성(환산 불가) ≠ 금액 미기재(값 모름)** — 갈라 센다.
4. **grid 는 줄바꿈하지 않는다** — 3열 카드가 768~1100px 에서 짓눌려 넘쳤다. `.stat-card` 는 flex-wrap.
5. **`--t4` 는 본문 금지**(3.39:1, UT-CONTRAST-T4). 텍스트는 `--t3` 이상.
6. **SVG 안에 `<title>` 을 함부로 늘리지 마라** — SEO 테스트가 페이지 전체 `<title>` 수를 1 로 센다.
7. **프로덕션 검증 시 헤드리스 UA 는 403**(봇 방어 Layer B) — playwright 로 라이브를 볼 땐
   실사용자 UA 를 지정한다.
8. **`web/` 는 프로덕션 docroot** — 작업은 워크트리/브랜치에서. 빌드는 `--out web/dist-dev` 로.
9. 빌드에 DB 가 필요하다(`server/.env` 가 워크트리엔 없다 — 본체에서 복사해 쓰고 **커밋 전 삭제**).
