## 0. 금지 · 예절

0-1. **SendFeedback 도구(피드백 · 버그 리포트 초안)는 절대 쓰지 않는다. 하위 에이전트를 띄우지 않는다**(꼭 띄워야 하면 그 지시문에도 「SendFeedback 금지」). DB 접속 · 리포 `/home/ubuntu/loupit` 쓰기 · git 금지 — 리포는 읽기 · import 만. 다른 회사 에이전트가 동시에 돈다.
0-2. **요청은 GET 만.** HEAD 는 믿지 않는다(HEAD 400 · 405 · 404 인데 GET 200 인 사이트가 많다 — 생존 판정도 GET). POST 로만 나오는 목록 · 검색은 받지 않고 「확인하지 못한 것」에. `--max-time 20` · 요청 간 ≥1초(헤드리스 렌더 포함) · robots 의 `Crawl-delay` · `Visit-time` 이 있으면 지킨다(시간 밖이면 받아 둔 사본으로).
0-3. **요청 상한:** 진입 판정까지 회사당 **40회**, 판정 뒤 수집 단계 새 요청 **60회**(판정 때 받은 사본 재사용은 0회). 렌더 하위 리소스 · robots · OpenDART · 점검기 실측 포함. 닿으면 멈추고 그때까지의 원문으로 판단하거나 「출처 없음 — 상한 도달」. 두 수를 근거표 머리에.
0-4. **개인 정보를 적지 않는다** — 근거표 · 사본 메모 · SQL 주석에 담당자 · 임원 실명 · 직통 번호 · 개인 메일함 금지. 메일은 도메인만(`@example.co.kr`). 원문 사본 안의 것은 그대로 두되 옮기지 않는다.
0-5. **경로:** 받은 파일 · 임시 스크립트 · 로그는 `W/<eng>/`(와 그 아래 `_work/`)에만 — 공용 스크래치 · 다른 회사 폴더 금지. `W/<eng>/req.log` = 줄마다 시각(UTC) · URL · 상태 · 바이트 · UA. 받은 파일마다 sha256. 산출은 `W/collect/<파일명>.sql` · `W/collect/<파일명>.evidence.md` 둘뿐.
0-6. **robots:** 호스트마다 robots.txt 를 **단독으로 먼저** 받고, 판정이 끝난 뒤에만 본문을 요청한다. 판정은 RFC 9309(가장 긴 일치 우선 — `urllib.robotparser` 는 첫 일치라 `Disallow: /` + `Allow: /appsite/` 를 금지로 오판한다, 쓰지 않는다). UA 줄 여러 개가 묶인 레코드는 레코드 단위로 읽는다(줄마다 끊으면 판정이 뒤집힌다). `*` 와 AI 봇(ClaudeBot · anthropic-ai · GPTBot · CCBot · Google-Extended) 각각 판정 · BOM 유무 기록.
- 404 · 4xx(403 포함) = 규칙 없음 = 허용(S3 `AccessDenied` 403 도 「파일 없음」). 단 robots 도 본문도 403 · 접속 거부(사이트 전체 차단)면 그 호스트는 요청하지 않는다. `User-agent` 줄 없이 `Disallow: /` 만 있으면 금지.
- `*` 가 경로를 막으면 본문을 받지 않는다. AI 봇만 이름으로 막으면 그 사실을 판정 줄에 적는다.
- **벤더 호스트 robots 도 구속한다** — 페이지 경로가 허용이어도 본문이 `Disallow: /` 인 다른 호스트(ATS 의 API · 빌더 · 정적 호스트 — `api-recruiter.recruiter.co.kr` · `api-builder…`)에만 있으면 읽지 않는다. 헤드리스 렌더로 우회하는 것도 같다(렌더가 그 호스트를 부른다). 같은 벤더라도 호스트마다 부호가 반대일 수 있다.
0-7. **UA 는 그 회사 robots 가 정한다.** 기본은 일반 브라우저 `Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/128.0 Safari/537.36`. `*` 는 막고 AI 봇만 이름으로 허용하면 ClaudeBot UA. 엣지가 AI 봇 UA 를 403 하고 robots 는 허용하면 기본 UA. 우리가 누구인지 숨기지 않는 쪽을 먼저 고른다. UA 에 curl · GPTBot · CCBot 이 들어가면 막거나 디코이로 보내는 사이트가 있다. 막혀도 UA 를 바꿔 다시 두드리지 않는다.
0-8. **렌더 · 키:** 헤드리스 렌더는 원본 HTML · `__NEXT_DATA__` · 데이터 JSON 에 항목이 없을 때만 — 먼저 페이지가 부르는 데이터 API(키 없이 열리는 JSON)를 찾는다. 렌더할 때는 끌어올 호스트의 robots 를 먼저 받고, 문서 밖 하위 요청(prefetch · other 포함)은 전부 끊고, UA 는 0-7 에서 고른 것 그대로. **사이트 JS 에 박힌 키 · 토큰으로 API 를 부르지 않는다**(공용 키라도 자격 증명 사용). 권한 시스템이 요청을 거부하면 우회하지 않고 「확인하지 못한 것」에.
0-9. **원문 보존:** 이미지 안 항목은 내려받아 판독하고 URL · 크기 · sha256 · 판독 사본(`image_transcript.txt`)을 남긴다(판독 가능한 해상도인지 적는다). SPA 면 번들 · API 를 추적해 경로를 기록(청크 해시는 index → 청크 순). 캐시버스터(`?v=<ts>`) · CSRF 토큰이 박힌 페이지는 정규화한 **항목 텍스트의 해시**를 남긴다. CSS 로 숨긴 탭은 원본 HTML 로 보고, 숨김 검사는 외부 CSS 에서 한다. 공고 원본(HTML · 이미지)도 사본 + sha256.
0-10. **OpenDART** 는 loupit 운영 키(`/home/ubuntu/loupit/server/.env` 의 `DART_API_KEY`) — 키 문자열을 사본 · 로그 · 근거표에 남기지 않는다(로그는 `<키 생략>`). 접수번호 · 보고서 이름 · 항목명을 출처 표에.

## 2. 시드 SQL 형식

2-1. **머리말** — 둘째 · 셋째 줄 모양을 바꾸지 않는다(적재 백필이 `^-- 출처: AI 파싱 \((\d{4}-\d{2}-\d{2})\)` · `^-- URL: (http\S+)` 로 읽는다 — URL 줄이 http 로 시작하지 않으면 전 행이 「근거 URL 없음」, 날짜 줄이 없으면 확인일이 2026-07-10 으로 적재된다). 날짜 = **원문을 받은 날(UTC)**:
```
-- ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
-- <표시명> 복리후생 데이터 (신규 회사 — 웨이브 <N>)
-- 출처: AI 파싱 (<YYYY-MM-DD>)
-- URL: <정본 URL>
-- badge: est
--
-- 참고:
--   정본 · 보조 출처(보고서 쪽 · 발행 연월) · 렌더 방식 · 귀속 판단(각주 여부와 이유) · 금액 요약(stated / 추정 행과 산식) ·
--   제외 요약(법정 · 업무 교육 · 다른 법인) · 공고 근거 N행 / 전체 M행 · SORT 섹션 순서
-- ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

2-2. **다섯 문장**(분할기 기준 정확히 5). 정본 URL 은 머리말 · INSERT · UPDATE 세 곳이 글자까지 같다:
```
-- 1) 회사 등록 (신규 — 이 INSERT 가 실제 등록을 수행한다)
INSERT IGNORE INTO TCOMPANY (COMP_ENG_NM, COMP_NM, COMP_TP_ID, INDUSTRY_NM, LOGO_NM, CAREERS_BENEFIT_URL)
VALUES ('<slug>', '<표시명>',
        (SELECT COMP_TP_ID FROM TCOMPANY_TYPE WHERE COMP_TP_CD = '<large|mid>'),
        '<INDUSTRY_NM>', '<로고 1자>', '<정본 URL>');

-- 2) COMP_ID 조회
SET @comp_id = (SELECT COMP_ID FROM TCOMPANY WHERE COMP_ENG_NM = '<slug>');

-- 3) CAREERS_BENEFIT_URL 갱신 (이미 행이 있으면 INSERT IGNORE 로는 안 바뀐다)
UPDATE TCOMPANY SET CAREERS_BENEFIT_URL = '<정본 URL>'
 WHERE COMP_ID = @comp_id;

-- 4) 기존 추정 데이터 삭제 (official 보존)
DELETE FROM TCOMPANY_BENEFIT WHERE COMP_ID = @comp_id AND BADGE_CD = 'est';

-- 5) 복리후생 INSERT
INSERT INTO TCOMPANY_BENEFIT
  (COMP_ID, BENEFIT_CD, BENEFIT_NM, BENEFIT_AMT, BENEFIT_CTGR_CD,
   BADGE_CD, NOTE_CTNT, QUAL_YN, QUAL_DESC_CTNT, SORT_ORDER_NO)
VALUES
  -- ── <카테고리 한글> (<category>) — <출처> ──
  (@comp_id, '<code>', '<이름>', NULL, '<category>',
   'est', NULL, TRUE, '<서술>', 10),
  (@comp_id, '<code>', '<이름>', <금액>, '<category>',
   'est', '<서술>', FALSE, NULL, 11)
ON DUPLICATE KEY UPDATE
  BENEFIT_NM=VALUES(BENEFIT_NM), BENEFIT_AMT=VALUES(BENEFIT_AMT),
  BENEFIT_CTGR_CD=VALUES(BENEFIT_CTGR_CD), BADGE_CD=VALUES(BADGE_CD),
  NOTE_CTNT=VALUES(NOTE_CTNT), QUAL_YN=VALUES(QUAL_YN),
  QUAL_DESC_CTNT=VALUES(QUAL_DESC_CTNT), SORT_ORDER_NO=VALUES(SORT_ORDER_NO);
```
2-3. **행:**
- 정성 행 = `NULL, '<category>', 'est', NULL, TRUE, '<서술>'`. 금액 행 = `<금액>, '<category>', 'est', '<서술>', FALSE, NULL` — 서술은 `NOTE_CTNT` 하나. 금액을 넣는 순간 조건 칸이 사라지므로 **조건이 붙은 급부는 금액 행으로 만들지 않는다.**
- **카테고리는 고르지 않고 어휘표 카테고리 열을 베낀다**(더 어울려 보여도 바꾸지 않는다 — 다르게 넣을 이유가 있으면 행을 만들지 말고 판단 요청). 9칸 고정.
- `BENEFIT_CD` 는 회사당 한 행(UNIQUE). 같은 코드로 귀결되는 제도는 한 행에 합치고, 다른 제도를 억지로 합치지 않는다.
- SORT = 카테고리별 10단위 섹션(첫 섹션 10, 다음 20 …, 섹션 안 +1). 섹션 순서 = 정본 페이지에 그 카테고리가 처음 나온 순서, 보조 출처에만 있는 카테고리는 끝. 섹션 머리 주석 `-- ── … ──`.
- **홑 · 겹따옴표 금지** — 문자열은 물론 **주석에도**(분할기는 주석을 모르고 따옴표 하나로 파일 전체를 한 문장으로 읽는다). 「」를 쓰고, 아포스트로피가 꼭 필요하면 U+2019 ’.
- 길이: `BENEFIT_NM` ≤100자 · `NOTE_CTNT` ≤200자 · `QUAL_DESC_CTNT` ≤500자(넘으면 적재 실패). 줄일 때는 출처 괄호를 줄인다 — 사실 · 「(추정)」 · 「환산」 표지는 지우지 않는다.
2-4. **등록 값:**
- `COMP_ENG_NM` = 리드가 준 snake_case slug — 코퍼스 · 대기 폴더와 충돌 금지(`generator/slug.py` `slug_of` 정규화 뒤 비교 — `_row_check.py` 가 본다). `COMP_NM` = 리드가 준 표시명(DART 정식명 기준 통용 표기). 기존 회사 대조는 파일명이 아니라 각 파일 `COMP_NM` 으로.
- `COMP_TP_CD` = large(대기업집단 · 대형 상장사 · 금융사 · KOSPI 대형) / mid(중견 · KOSDAQ 중소형) / public(공기업) — 잡초위키 분류이지 법정 기업 규모가 아니다.
- `INDUSTRY_NM` = **기존 값에 합류한다**(trending 폴백 쌍이 이 값으로 묶인다 — 새 변형을 만들면 쌍이 안 생긴다). 지금 값은 아래로 센다. 정말 맞는 값이 없을 때만 짧은 새 값 + 근거표에 사유(같은 웨이브 다른 회사의 새 값과 바이트까지 같은지는 감사가 본다).

3-3. **금액** — `BENEFIT_AMT` 는 **만원 · 연 단위**. 적재 때 `derive_amt_source` 가 금액 행 NOTE 에 「추정」 · 「환산」이 있거나 NOTE 가 비면 **estimated(추정치)**, 아니면 **stated(회사 공식 수치 = 회사가 밝힌 숫자로 연 금액을 적은 것)** 로 다시 판정한다 — **표지를 빠뜨리면 추정이 공식 수치로 나간다.** 같은 금액이 다른 회사와 겹치는 것은 아무 판단의 근거도 아니다.
- **stated(표지 없음):** 「연 N만원」 · 「연간 · 매년 N만원」(NOTE 에 원문 그대로) · **합산** — 원문에 나뉘어 적힌 고정 금액(「설 80만원 · 추석 80만원」 · 「50 + 35 + 35만원」 · 「각 N만원 × 횟수」)은 더한 값을 stated, NOTE 에 구성 원문 그대로 · 그 축 기존 최댓값의 2배를 넘으면(명절 상여 · 귀성여비 축 최댓값 160) 금액은 넣되 판단 요청 「급여성 혼입 의심」 · 연초에 전액을 배정하는 복지포인트 · 복지카드(원문에 「지급」 · 「배정」 · 「부여」) · 건강검진 금액은 원문에 **주기(매년 · 연 1회)** 가 있을 때만(없으면 NULL). stated 서술에는 원 · 만원 숫자가 보여야 한다.
- **estimated(표지 필수) — 넷뿐:** ① **월액 × 12** — NOTE 「월 N만원을 연 M만원으로 환산」. 대상 집단이 정해진 상시 월 지원(보육지원금 · 장애 자녀 치료비)도 같다 — 질병 · 부상 같은 **사건이 있어야** 받는 월 지급(재활수당)은 조건부라 NULL. 월액을 그대로 금액 칸에 넣지 않는다. ② **포인트 → 원**: 「연간 100만 포인트」 → 100, NOTE 끝 「1포인트 1원 기준 환산」. ③ **분포형 구간 중간값**: 직급 · 호봉별로 각자 한 값을 받는 정액(「직급별 130~220만원」) → 175, NOTE 「직급별 구간 130~220만원의 중간값 (추정)」 — 하한 · 상한을 쓰지 않는다. ④ **식대**(아래).
- **NULL(정성 — 금액 · 조건은 서술에):** 원문에 숫자가 없는 제도(**타사 금액 · 기준 금액(틀 값)을 신규 회사에 쓰지 않는다** — 예외는 식대 단가 하나) · 한도 · 상한(「연 N만원 한도」 · 「최대 N만원」 · 「N만원까지 실비」 — 배정인지 한도인지 원문에 안 드러나면 NULL + 판단 요청) · **1회성**(입학 · 출산 · 결혼 축하금 · 경조금 · 근속 포상금 · 인재추천 포상금) · 비율 · 배수(「본인 100%」 · 「상여 800%」 — 100 이 100만원이 된다) · 대출 원금 한도 · 이율 · 담보 · 질권 · 자기주식 처분 총액 · 통계 총액 · 여러 법인 합산 숫자 · 임원 보수 칸 금액 · **조건부 급부**(대상 한정 · 직군 한정 · 기간 상한 「2년간」 · 선발 조건이 하나라도) · 단가 없는 비율 · 횟수 · 주기 없는 1회 값(「100만원 상당 VIP 검진」).
- **식대:** `meal` 행은 원문에 끼니가 적혀 있으면 금액 = **1끼 단가 × 하루 끼니 × 연 240일**. 단가 = 회사가 밝힌 1끼 · 1일 단가, 없으면 **12,000원** → 한 끼 **288** · 두 끼 **576** · 세 끼 **864**. 끼니 = 회사가 제공 · 지원 · 무료 · 무상 · 지급으로 적은 조식(아침) · 중식(점심) · 석식(저녁) 각 1, 「삼시세끼 · 세 끼 · 3끼 · 3식」 3, 「1일 2식」 2, 최대 3, 「사업장별 상이」는 적힌 끼니로. **세지 않는 것:** 야식 · 간식 · 편의식 · 음료 / 야근 · 초과 근무 · 연장근로 조건부 끼니 / 회사 부담이 일부(「보조」 · 「일부 지원」 · 「저렴한 · 합리적인 가격」) / 끼니가 안 적힌 「사내 식당 운영 · 식사 제공 · 식대 지원」(금액 NULL) / 「조식부터 야식까지 … 식사 또는 편의식」처럼 끼니가 불분명한 것. NOTE 맨 끝 꼬리 식 그대로: `(하루 N끼 × 1끼 12,000원 × 연 240일 추정)` · 회사 단가면 `(점심 1끼 15,000원 × 연 240일 추정, 야근 시 저녁 제외)` · `(하루 18,000원 × 연 240일 추정, 연장근로 추가분 제외)`. 「×」는 U+00D7, 뺀 끼니는 꼬리 안 「, ○○ 제외」, 꼬리의 N 은 이름 · 본문에서 센 끼니보다 클 수 없다. 회사가 식대를 **월액 · 포인트로** 밝히면 그 조건이 먼저 — 월액 × 12 환산 · 꼬리 식 없음 · 근거표 「배포 시 주의」에 「SI-9 허용 목록(`_MEAL_NO_TAIL_OK`)에 추가 필요」.
- 금액 행 NOTE = 원문 구절 + 출처 괄호 + 꼬리 「 — ○○ 미기재」 + 맨 끝 표지(「(추정)」 · 환산 문장 · 식대 꼬리).
3-4. **어휘 · 신규 코드** — 새 코드 전에 어휘표에서 같은 뜻을 찾는다(경계 절 끝까지). 신규 코드는 대응 어휘가 정말 없고 원문이 혜택 내용을 밝힐 때만 — 근거표 「신규 코드」 절에 ① 사유 ② **그 제도어로 코퍼스 전문을 grep 한 결과 전부**(1건 찾고 멈추지 않는다 — 같은 뜻 두 코드가 그렇게 생겼다) ③ 제안 카테고리(가장 가까운 기존 코드의 카테고리). 코드 이름은 **지급 형태 · 속성이 아니라 제도 영역**(`smoking_cessation` ○ / `nonsmoking_bonus` ✗ · `grocery_support` ○ / `organic_food` ✗) — 원문에 없는 낱말을 코드에 넣지 않는다(새 코드에 `_loan` 은 원문이 대출 · 융자를 밝힐 때만 · 기존 `housing_loan` 의 범위는 어휘표 정의). 코퍼스에 대응 어휘가 있으면 신규가 아니다.
3-5. **귀속 — 그 법인 원문에 있는 문장만**
- 그룹 공통 복지를 갖다 붙이지 않는다 — 그룹 정본 문장과 글자까지 같아도 이 법인 원문에 없으면 싣지 않는다. 반대로 **법인 자기 도메인에 실린 문장은 형제 · 지주와 글자까지 같아도 그 법인 원문**이다(각주 없음). 형제 법인 이름이 주어인 페이지는 자기 도메인에 있어도 근거가 아니고, 같은 글이 여러 도메인에 있으면 이 법인 이름 · 도메인으로 실린 쪽만.
- **각주 세 꼴**(귀속의 전제라 절대 떨구지 않는다 · 서술 맨 끝 = 「 — 」 꼬리 뒤):
  ① 그룹 통합 채용 페이지 · 그룹 템플릿(법인 구분 없음) 근거 행 → 「(그룹 통합 채용 기준)」(컴퍼니 공통이면 「(○○컴퍼니 공통 채용 기준)」) · 귀속 경로를 머리말에.
  ② 자기 도메인 그룹 주어 페이지(단서 없음) 근거 행 → 출처 괄호 안 「, ○○그룹 공통 문구」.
  ③ 보고서 표가 여러 법인을 묶은 보고 범위이고 법인 구분이 없는데 그 표가 근거인 행 → 「(A · B · C 통합 보고 기준)」. 보고 범위가 여러 법인이어도 **이 법인이 주어인 문장**(「○○는」)이 근거면 각주 없음 — 합산 숫자는 쓰지 않는다. 같은 보고서로 형제를 등록하지 않는다. 자회사 시설 이름이 붙은 할인은 「계열 시설 할인」 · 시설 이름은 서술에.
  자기 발행 법인 단독 보고서 · 법인 전용 페이지 근거 행 = 각주 없음.
- **한정의 종류:** 자회사 · 관계사(다른 법인) · 임원 · 연구위원 · 사내이사 전용은 **제외**(한정을 지우면 허위). 같은 법인의 **부문** 한정은 싣고 이름 끝 「(○○부문)」 + 서술에 적용 부문. **직군** 한정(생산직 · 교대근무 · 공장 근무 · 해상직 · 여성직원 · 사업장 한정)은 싣고 이름 · 서술에 대상. 단체협약이 강제하는 직군 수당은 회사가 복지로 공시한 문장일 때만.
- 공시 **임원 · 대표이사 개인 보수 산정 칸**(기타 근로소득 항목 이름 포함)은 낱말이 「임직원」이어도 직원 복지 근거가 아니고 그 금액도 쓰지 않는다. 예외: 그 칸 문장이 직원 적용을 스스로 밝힐 때(「직원과 함께 개인성과급 산정」 · 「직원과 동일한 기준」) 그 부분만 — 임원 산정 기준(업적 · 조직평가)은 옮기지 않는다. 그런 구절이 있는지 보수지급기준 칸도 grep 한다.
- 그룹 · 형제 점검 결과(형제 정본 문장과 겹친 행 · 처리)를 근거표 머리에.
3-6. **휴가** — 코드 가르기는 어휘표 「휴가」 경계. 싣는 기준:
- **리프레시 · 연차 외 휴가는 이름만 있어도 싣는다** — 꼬리 「휴가 일수·부여 조건 미기재」.
- **이름 있는 집중 · 단체 휴무**(하계 · 연말 · 월말 · 집중휴가제)는 일수 · 대상 · 유급 여부가 없어도 싣는다 — 꼬리 「연차 사용일인지·일수·유급 여부 미기재」. 원문이 그날을 본인 법정 휴가로 쓰는 것이라고 밝히면 싣지 않는다. **의무 · 필수 집중휴가는 싣고, 권장 · 장려 휴가(「연속 휴가 사용 장려」 · 「권장휴가」 — 회사가 더 주는 날 없음)는 싣지 않는다.**
- 보상휴가제(57조)는 행도 서술도 아니다. 출장 · 심야근무 뒤 **임금과 별도로** 더 주는 휴가는 `leave_general` 사건 보상. 법정 휴가와 겹치는 휴가는 상회분만(§3-2).
3-7. **보상 · 포상 · 주식** — 코드 가르기는 어휘표 「보상 · 금전」 경계. 싣는 기준:
- 원문이 「임직원」 · 「전 직원」에게 성과금 · 인센티브가 있다고 밝히면 성과급 행(꼬리 「지급 기준·지급률 미기재」). 임원 · 사내이사 전용 보수 문장은 아니다. 지표 정의(「연봉(기본급+성과급)」)로 세운 성과급 행은 지표 문장이 아니라 **제도로 읽히는 말**로 쓰고, 연봉 인상률 반영(급여 조정)을 성과급으로 옮기지 않는다.
- 정기 상여율은 회사가 **복리후생 블록 안에** 적었을 때만 `bonus`(금액 NULL) — 임금 구성 문장은 행이 아니다.
- 포상 제도는 라벨만 있어도 선다. 싣지 않는 것: 인재추천 포상금 · 안전 · EHS 포상 · 「직무발명 보상(제도)」.
- 스톡옵션 · RSU 재량 부여는 복지가 아니다. 우리사주조합은 싣는다(제도 문장이 있을 때 — 주주 표 한 칸만으로는 아니다). 자사주 지급 = 공시 문장 그대로.
- 재무제표 주석 「장기 근속 임직원에게 기타장기종업원급여를 제공」은 직원 대상 근속 급부를 밝힌 공시 원문 → `long_service_bonus` · 꼬리 「근속 기준·급부 형태·금액 미기재」(일부러 찾지는 않는다 — 읽은 공시에 있으면).
- 퇴직금 누진제 등 법정 퇴직급여를 넘는 상회분 = `severance_plus`(금액 NULL). 급여성 수당(학위 · 자격 · 직무 · 초임 · 무사고 운전)은 복지가 아니다.
3-8. **대출 · 기금 · 주거 · 할인** — 코드 가르기는 어휘표 「생활 · 금융 · 주거」 경계.
- **사내 대출 · 대출이자 지원은 용도 · 이율이 없어도 싣는다** — 원문에 없는 용도를 서술에 덧붙이지 않는다 · 꼬리 「대출 용도·한도·이율 미기재」. 원금 한도 · 이율은 금액이 아니다.
- 혜택이 적히지 않은 그룹 제휴카드 · 제휴 할인 **이름만**은 싣지 않는다(결제 수단). 회사가 **복리후생 목록에 적은** 「제휴 할인 혜택」 · 「제휴업체 할인」 라벨은 `discount` 로 싣는다(같은 라벨이 코퍼스에 있는지 `grep "'discount'"` 부터).
3-9. **교육** — 판정 기준: 「회사가 지원하지 않으면 직원이 제 돈으로 들어야 하는 교육인가」.
- **싣는다:** 회사가 비용을 대는 것(학자금 · 자격증 취득비 · 어학비 · 사외 교육비) · 회사가 여는 어학 강좌 · 과정 · 전화외국어 · 랭귀지 세션 · 직무 필수가 아닌 자기계발 · 교양 · 문화 강좌 · 특강 · 자율 수강 온라인 과정 · **학습 플랫폼**(직무 · 리더십 콘텐츠가 많아도 전 임직원 자율 수강이면 — 통째로 빼지 말고 어학 · 교양 몫을 살린다) · 학습모임 · 일반 사무 기술 과정(OA).
- **싣지 않는다(업무 교육):** 신입 · 입문 교육 · 온보딩 · OJT · 멘토링 · 직무 필수 · 리더십 · 직급별 · 승진자 · 법정 의무 · 선발형 핵심인재 과정. 업무 교육만 적힌 원문은 행이 아니다.
- **섞이면 복지 쪽만** 서술에 남긴다 — 칸 이름이 아니라 **과정 단위**로 가른다(교육 표의 한 칸 · 원본 HTML `div` 를 끝까지 읽는다 · 「직무 역량 개발」 문단 안의 자격증 취득 지원은 복지).
- **파견형 육성**(MBA · EMBA · 석사 · 학술연수 · 지역전문가 · 주재원): 학위 = `mba`, 파견 · 경력 = `career`. 독립 항목이고 그 회사에 `career` 행이 있으면 `career`, 없으면 `mba` 서술에 흡수(행 신설 금지), MBA 와 한 복합 라벨이면 `mba`. 정본 페이지 안이면 복리후생 블록 밖이어도 싣는다. 사내 아카데미 · 직무 커리큘럼은 제외.
3-10. **근무형태 칩 이름** — `remote_work` · `telecommute` · `wfh` · `flex_work` · `refresh_leave` · `long_service_leave` 행은 회사 페이지 · 비교 · 이직 계산기의 칩이 **이름만** 읽는다(`db/seed/company_meta.py` `ws_conditions`). 전 직원 제도가 아니면 한정을 이름에 **정해진 꼴**로:
- 대상 한정 = 이름 **앞** 「육아기 」 · 「자녀돌봄 」 · 「부서별 」(뒤 띄어쓰기 — 붙이면 맨 칩으로 샌다), 자녀 연령으로 대상을 정하면 이름 끝 「(자녀를 둔 …)」.
- 사유 한정 = 이름 끝 「(필요 시)」(누구나 신청하는 「필요시 신청」 일반 제도엔 달지 않는다) · 끝 「(조건부)」(공시 표 주석 「특별 사유로 활용」 같은 사유 한정). 부문 한정 = 끝 「(○○부문)」(한 행 일부만이면 「(휴가는 건설부문)」).
- 이 꼴 밖의 괄호(「(주 1회)」 · 「(WFA)」 · 「(재택근무 포함)」)와 이름 중간 괄호는 한정으로 안 읽힌다. 이름에 육아 · 자녀 · 부문 · 필요시가 보이는데 조건으로 안 읽히면 게이트(SI-13d)가 깬다. 근거표 행마다 「칩: 맨 칩 / 조건 ○○」. 근속 조건은 제도 본성이라 `long_service_leave` 는 맨 칩.
3-11. **사용자 노출 문안**(`BENEFIT_NM` · `NOTE_CTNT` · `QUAL_DESC_CTNT` — API · 회사 페이지 · 비교 · 항목 페이지 · `/find` 로 그대로 나간다):
- **모양:** `원문 구절 (출처 표기) — ○○ 미기재`. 출처 표기 = 「공식 채용 페이지 복리후생 ○○ 항목」 · 「2026 지속가능경영보고서 47쪽 ○○ 항목」 · 「2026 반기보고서 직원 등 현황 항목」. 출처가 둘 이상이면 「원문 구절 (출처1), 원문 구절 (출처2) — ○○ 미기재」. **출처 괄호에는 「항목」 · 「공식」 · 「페이지」 같은 메모 낱말을 넣는다** — 없으면 항목 페이지가 괄호를 원문으로 읽는다(「(… 가족친화인증 보도자료)」의 「가족」이 다른 면을 켰다).
- **「 — 」 꼬리는 서술 맨 끝 하나뿐.** 항목 페이지가 첫 「 — 」부터 끝을 메모로 걷으므로 원문 사이에 「 — 」를 쓰면 뒤 원문이 사라진다. 원문 사이 구분은 「, 」 · 「 · 」.
- **허용** = 원문 라벨 + 출처 페이지명 + 조건 · 대상 + 미기재 사항. **금지** = 판단 근거 · 법조문 · 행 구조 · 수집 방법 · 페이지 품질 낱말: 「코퍼스」 「선례」 「어휘」 「규칙 N」 「수집」 「검증」 「감사」 「병합」 「판독」 「정본」 「시드」 「미수록」 「흡수」 「회피」 「항목명 그대로」 「카드에는 별도 항목 없음」 「○○로 표기」 「○○로 기재」 「하나로 기재」 「영문 표기로 기재」 「⚠」 「구본」 「승계」 「앵커」 「틀 값」. 레인 메모 낱말 금지: 「전문:」 · 「을/를 합친」 · 「덧붙인 · 덧붙일」 · 「을/를 빼면」 · 「#숫자」.
- **「연차」 · 「반차」 · 「반반차」 낱말 금지** — 원문 항목명을 인용할 때도(「생일 반차」 → 「생일 반일 휴가」). 예외는 원문이 법정분과 회사분을 스스로 가른 「연차 외 추가 N일」 · 「연차와 별도」 꼴뿐.
- **서술은 명사로 끝낸다**(화면 문장 생성기가 조사 · 부사형 어미 뒤에 「…를 지원합니다」를 붙인다).
- 복합 라벨을 코드별로 쪼갰으면 **각 행은 자기 몫만** 말한다(원문 라벨 전체를 모든 행에 복사하면 「미기재」 목록이 없는 제도를 전제하고, 항목 페이지가 다른 행 몫의 칸을 켠다). 한 방이 두 시설이면 두 행 + 「겸용」.
- 공시 문장은 공시가 말한 것만 · 연도 · 대상은 공시 그대로. 원문 밖 단언(「전 직원」)과 원문에 없는 낱말(「명절」 · 「자녀」)을 더하지 않는다.
3-12. **행 수 · 이름만 · 공고 · 공시**
- 목표 12~25행. 원문 항목이 적으면 억지로 늘리지 않고(라벨만 있는 회사는 라벨 수 그대로), 많고 코드가 다 다르면 넘어도 된다 — 억지 분리 · 억지 확장만 결함. 병합은 같은 코드로 귀결되는 항목만.
- **이름만 있는 항목:** 회사가 **복리후생 목록 · 제도 표의 항목**으로 적은 이름은 설명이 없어도 싣는다(꼬리에 미기재 사항). 같은 표의 항목은 같은 기준으로 — 하나는 이름만으로 세우고 다른 하나는 빼지 않는다. 표가 이 법인 제도 항목으로 따로 적었으면 본문이 한 번의 실시 사례(공동 개최 행사)를 들어도 제도로 싣는다. 회사가 자기 제도로 적은 이름(「유연근무제 운영」)도 이름만으로 선다. **싣지 않는 것:** 사옥 시설 나열 · 사진 캡션의 시설 이름(샤워실 · 회의실 · 탈의실) · 보고서 지표 표의 이름 칸(같은 기간 대상이 있었는데 지급 0).
- **공고 근거:** 회사가 운영하는 채용 공고를 근거로 쓴 행이 있으면 근거표 머리에 **「공고 근거 N행 / 전체 M행」**(공고가 닫히면 근거가 사라지고 점검기는 못 잡는다). 상시 페이지 · 공시 · 자기 보고서로 받칠 수 있으면 그쪽을 정본으로. 같은 복리후생 블록이 **지금 게시 중인 공고 여럿에** 있으면 현행 원문으로 인정. 회사 자기 공고 급여 칸 「성과급 내부 규정에 따라 지급」 = 성과급 행(대상 직무를 서술에).
- **공시:** 사업 · 반기보고서의 「임직원 복지」 문장(사내 카페 · 시차출퇴근 · 우리사주 · 유연근무제도 사용 현황 표의 제도 이름)은 이 법인 공시 원문이다 — 「임직원 복지」 · 「복지」 grep 은 직원 현황 절 밖(신규사업 · 주석 절)까지 돌린다. 공시 표의 제도 이름(재택근무 · 원격근무제)은 이름 · 서술을 표 낱말 그대로 · 꼬리 「대상 직무·사용 조건 미기재」로 행을 세운다(다른 행 서술에 묻지 않는다). 재무제표 주석 「종업원에게 지급할 성과급」 · 기관 경영공시 평균보수 표 성과상여금 = 직원 성과급 원문. 임원 · 사내이사 전용 칸은 아니다(§3-5).
3-13. **이메일 도메인 관측** — 채용 페이지 · 보고서 문의처 · 개인정보처리방침에서 관측한 회사 공식 메일 도메인(재직인증용)을 근거표에 — 없으면 「미관측」. 웹 도메인과 메일 도메인이 다를 수 있다 — MX 를 확인했으면 적는다. 그룹 · 지주 공용 도메인으로 보이면 그렇게 적는다(등록은 리드 · 감사).
3-14. **출처가 없을 때 · 벽 · 공시만**
- **출처 없음:** 공식 출처를 끝내 못 찾으면 SQL 을 쓰지 않는다(0행 파일 금지). 근거표에 판정 · 「출처 탐색」(찾아본 URL · robots · 제외 사유)만, 보고 첫 줄 **「출처 없음」**. 3자 사이트 · 스니펫 · 다른 법인 페이지로 채우지 않는다.
- **벽(robots · 렌더):** 우회하지 않는다. **사람이 브라우저로 열면 그 본문이 보이는 공식 페이지의 정확한 URL** 을 근거표 첫 줄 아래와 보고 첫 줄에 `붙여넣기 필요: <URL>`(공고 근거 페이지면 그렇게 적는다). 다른 공개 원문(보고서 · 자기 도메인)으로 행을 세울 수 있으면 세워 두고 붙여넣기 뒤 보강한다(그때 판정은 「가능」 + 「붙여넣기 필요(보강)」). 붙여넣기를 부탁할지는 리드가 정한다.
- **붙여넣기로 다시 투입되면:** 그 페이지는 다시 받지 않는다 — 사본 sha256 을 `.sha256` 과 대조하고, 행마다 사본 줄을 인용한다. 보조 출처 · 정본 셸의 robots · 점검기 조건만 실측. 붙여넣기에 그룹 · 형제 문장이 섞였는지부터 본다.
- **공시만:** 공시 문장으로만 행을 세울 수 있으면 「출처 없음」으로 보고하고, 서는 행만 `W/<eng>/<파일명>.candidate-<N>row.sql` 에 둔다(collect/ 에 쓰지 않는다 — 등록 여부는 리드).

## 4. 근거표 (`W/collect/<파일명>.evidence.md`)

**머리**(맨 위): `**판정: …**` + 3줄(정본 URL · 행 수 · 렌더) · 점검 ①~⑥ 결과 줄 · 요청 수(판정 n / 수집 n) · UA · 사이트 키 사용 없음 · 그룹 · 형제 점검 결과 · 공고 근거 N행 / 전체 M행 · (벽이면) `붙여넣기 필요: <URL>` · (캠페인 도메인이면) 만료일 · (DART 이력 짧음) · 그리고 **위험 표시**:

| 위험 표시 | 해당이면 행(SORT) |
|---|---|
| 그룹 공통(그룹 주어 페이지 · 「계열사별 상이」 단서) | |
| 그룹 통합 채용 페이지 · 템플릿 근거 | |
| 보고 범위가 여러 법인(통합 보고 각주 · 「○○는」 문장만 골라 씀) | |
| PDF 표 짝 맞추기(이름 · 설명이 다른 줄 · 순서로 흩어진 표를 짝지어 읽음) | |
| 이미지 판독 | |
| 사용자 붙여넣기 사본 | |
| 기등록 형제(코퍼스 · 대기 폴더에 같은 그룹 법인) | |

해당 없으면 「위험 표시 없음」 한 줄. 검증은 이 표로 전체 재수집 여부를 정한다 — **빠뜨리면 검증이 사본 대조로 끝난다.**

**절**(짧게 — 판단이 없는 절은 「없음」 한 줄):
1. **출처 표** — 채택 · 제외 URL · 호스트별 robots 판정 · UA · 렌더 · 받은 날(UTC) · sha256 · **사본 경로** · 보고서 발행 연월 · 보고 기간 · 보고 범위 · 공시 접수번호. 정본을 고른 이유 · 점검기 결과(⑥).
2. **행별 인용표** — SORT · 코드 · 이름 · **원문 문장 그대로 · 사본 경로:줄**(PDF 는 텍스트 사본 경로:줄 + 쪽) · 출처 표기 · 칩. 검증이 이 열로 재다운로드 없이 대조한다.
3. **코드 판단** — 경계 절과 부딪힌 행만 한 줄씩 + 「신규 코드」 절(없으면 「없음」). 근거표에 적는 코퍼스 선례 · 수치(「○○사도 이 코드」 · 「n 곳」)는 **이번 세션 grep 결과로만** — 행 이름만이 아니라 그 행 서술까지 확인한다.
4. **법정 제도** — 걷은 문구 · 상회분 판정 · 직원 수와 재취업지원 판정 · 🚨 11-27 재계산 대상.
5. **금액** — 금액 행마다 원문 숫자 인용 · 산식 · 예측 금액 출처(④ 출력) · §3-3 어느 갈래인지. 숫자가 있지만 비운 것(한도 · 1회성 · 비율 · 조건부 · 합산 숫자)도 표로.
6. **제외 목록** — 원문에 있었지만 싣지 않은 항목 · 이유(법정 · 업무 교육 · 다른 법인 · 임원 전용 · 급여성 · 이름뿐인 시설 · 권장 휴가 · 옛 출처).
7. **낱말 스윕 · 항목 페이지** — ③ 검출 줄마다 허용 / 교체 / 삭제 · ⑤ 에서 문안으로 고친 것과 예외 후보.
8. **판단 요청** — 규칙으로 결론이 안 나는 것만, **기본안을 붙여서**(검증이 받아 권고로 확정하고 그 권고가 기본 채택된다 — 리드는 사용자 규칙과 부딪힐 때만 본다). 추측으로 메우지 않는다.
9. **이메일 도메인 관측**(§3-13).
10. **배포 시 주의** — 정본 점검기 조건(`robots` · PDF keyword None · 연도 파일명 · Crawl-delay 가 점검기 같은 호스트 간격 10초보다 긴 것 · Visit-time) · 한시적 출처(공고) · SI-9 허용 목록 등 리드가 처리할 것.
11. **확인하지 못한 것**.

## 5. 보고 (최종 응답 · 짧게)
