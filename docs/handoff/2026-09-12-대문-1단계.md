- **번들에 회사 등록일 필드가 없다.** 회사 dict 키는 10종(`aliases`·`benefits`·
  `careers_benefit_url`·`comp_eng_nm`·`comp_id`·`comp_nm`·`comp_tp_cd`·`industry_nm`·
  `logo_nm`·`work_style_val`)뿐이다. 그래서 「새로 등록된 회사」 24곳의 **출처는 웨이브

  날짜는 문서 작성일이 아니라 **서빙 반영일**(2026-09-06 · 2026-09-01)을 적었다.
  2단계에서 자동 갱신하려면 등록일을 어디서 얻을지 먼저 정해야 한다.
- **링크 드리프트 게이트는 `web/dist` 를 볼 수 없다.** `.gitignore` 에 `/web/dist` 가 있어
  커밋되지 않고 CI 러너에는 아예 없다. 회사 경로의 정본을 **커밋된 시드 SQL**
  (`db/seed/benefit/sql/*.sql` 126개)에서 뽑아 `slug_of(COMP_ENG_NM)` 로 만든다 —
  126/126 파싱되고 대문이 쓰는 82 slug 가 전부 그 집합 안에 있다. 시드에서 이름이 바뀌면
  즉시 붉어진다. 게이트가 실제로 붉어지는지 확인했다(`/company/kai` → `kai-renamed` → 실패).
- **`/compare` 와 `/compare/` 는 같은 곳인데 표기가 둘이다.** nginx 가
  `location = /compare { return 301 /compare/$is_args$args; }` 로 넘기지만,
  `web/compare/index.html` 의 `canonical`·`og:url` 은 슬래시 **없는** 쪽이고
  `_ALLOWED_STATIC_ROUTES` 도 `/compare` 다. 대문·`find.js` 는 리다이렉트 한 홉을 아끼려고
  슬래시 붙은 쪽을 쓰므로, 게이트가 끝 슬래시 한 겹을 같은 것으로 본다(`_variants`).
  ⓘ **표기를 하나로 정하는 일은 열린 채 남겨 뒀다**(아래 미결).
- **`app.js` 를 뺀 자리에 주석이 남는다.** 「왜 싣지 않는가」를 적어 두면 `"app.js" in html`
  같은 순진한 검사는 그 주석에 걸린다. 그래서 게이트는 **script 태그의 `src`** 를 본다 —
  설명을 지우게 만드는 테스트는 계약이 아니라 함정이다.
- **새 절의 크기 리터럴은 토큰으로 덮이지 않는 값들이다.** `.home { max-width:1040px }` ·
  `.home-chips a { min-height:32px }` · `.home-trust { border-left:3px }` ·
  `.home-row/.home-rank { line-height:1.9 }` · `.home-four { minmax(max(40%,220px)) }` ·
  `.home-rank { max-width:36ch }` 등. 색·간격 토큰만 강제되고(`UT-NO-LITERAL` 은 색만 본다)
  치수 리터럴은 `.sc-left { max-width:520px }`·`.find-search { flex:0 1 360px }` 처럼 **기존
  관행**이다. 토큰 체계에 폭·행간 축이 없어서 생긴 자리이고, 새로 만들지 않았다.
- **`og:site_name` 은 바꾸지 않았다.** `CFG.site_name` 이 `'jobcho.wiki'` 이고
  `test_header_markup.py::test_brand_text_matches_site_name` 이 브랜드 텍스트를 그 값과

## 남긴 것 (리드가 정할 것)

1. **PR·머지·배포·nginx** — 전부 미실행. 대문은 `location = /`(수기 `web/index.html`)를
   그대로 쓰므로 **이번 단계에는 nginx 변경이 필요 없다**. 배포 전 스냅샷 권장:
   `curl -s https://jobcho.wiki/ > ~/index-before-$(date +%F).html`.
2. **`/compare` vs `/compare/` 표기 통일** — 생성 페이지(`/vs/` CTA)는 슬래시 없는 쪽,
   대문·`find.js` 는 있는 쪽. 어느 한쪽으로 모으면 리다이렉트가 사라지고
   `_ALLOWED_STATIC_ROUTES`·`canonical` 도 한 값이 된다. 이번 범위 밖이라 손대지 않았다.
3. **숫자가 썩는 시점** — 126·2,032·76·558·신규 24사는 **웨이브 3(09-13 이후) 첫 배포부터
   거짓**이 된다. 「2026-09-12 기준」이 방어선이고, 해법은 2단계
   `generator/pages/home.py`·`templates/home.html` 이관이다. ⚠ 2단계에서 `base.html` 을
   상속하면 폰트 preload 2,057,688 B 가 붙는다 — block 으로 제외해야 한다. ⚠ nginx
   `location = /` 를 `web/dist` 로 돌리는 순서를 틀리면 `/` 가 404 가 된다.
4. **「실제 구성원들의 경험을 더해」는 아직 기여 0건**이다(재직자 복지편집 0 · 커뮤니티 글 1 ·
   댓글 0 · 회원 3). 운영자 판단으로 문안을 유지했고, 완화 장치는 「재직자가 직접 고칩니다」
   블록이 참여 방법을 그대로 설명한다는 점이다. `/edits` 가 공개 0행이라는 사실은 인지해 둘 것.
5. **인지도 높은 회사가 업종 목록에서 빠진다** — 선택 규칙이 「복지 항목 수 상위」라
   삼성전자(13항목)·LG전자·카카오·KT 가 묶음 목록에 없다(삼성전자·기아·카카오는
   「숫자로 보는 회사」·「비교 예시」로 도달). 규칙을 바꿀지는 2단계 생성 규칙과 함께 정할 일이다.
6. **순위 표기 규칙 — 「공동」은 정수 항목에만 붙인다(2단계 생성 규칙으로 넘긴다).**
   복지 항목 수는 정수라 27 = 27 이 참이고 `corpus.py` 가 동률을 사실로 낸다(LG CNS·SK텔레콤
   공동 27항목). 반면 평균 근속은 소수다 — 화면의 「S-Oil 17.4년 · 삼성생명 17.4년」은 raw
   **17.42 / 17.35** 로 동률이 아니고, 표시 반올림이 만든 착시일 뿐이다. 그래서 지금 코드는
   **순서는 raw 로 정하고 표시만 반올림**하며 소수 지표에는 「공동」을 붙이지 않는다. 이번
   판단은 옳지만 규칙이 어디에도 적혀 있지 않아 2단계에서 되풀이 판단이 필요하다 —
   생성 규칙에 「공동 표기는 정수 항목 수 전용 · 소수 지표는 raw 순서 + 표시 반올림」으로
   명시할 것.
7. **회사 직링크 규모** — 지금 75(업종) + 24(신규) = 고유 82사. `<details>` 접힘으로 126 전량을
   넣을지는 아티팩트 권고대로 **4주 뒤 Search Console 결과를 보고** 정하는 것이 좋다.
