# 복지 수집 가능성 프로브 — HD현대 (지주회사, KOSPI 267250)

프로브 일자: 2026-09-01 · **판정만. 수집·SQL 없음.**

## 판정: 수집 가능 (조건부) — 「그룹 공통」으로만 인정

HD현대 **그룹 통합 채용사이트**에 복지 전용 페이지가 있고, 항목이 제목+설명 형태로
18개 명시되어 있다. 다만 페이지 자체가 **"계열사간 일부 상이할 수 있습니다"** 를
각주로 달고 있으므로, 지주회사 단독 복지가 아니라 **그룹 공통 복지**로 라벨링해야 한다.

## ① 공식 채용/복지 페이지 URL (공식 도메인)

| 용도 | URL |
|---|---|
| 복지 전용 페이지 (정본) | `https://recruit.hd.com/kr/mainLayout/benefit` |
| 채용 메인 | `https://recruit.hd.com/kr` |
| 제도소개(참고, 미검증) | `https://recruit.hd.com/kr/mainLayout/initiatives` |
| 사이트맵 | `https://recruit.hd.com/sitemap.xml` (benefit 포함 확인) |

- `hd.com` 은 HD현대의 **공식 도메인**. `recruit.hd.com` = 공식 그룹 통합 채용사이트.
- ⚠ **혼동 함정**: `careers.hyundaigroup.com` 은 **현대그룹(현정은)** 이며 HD현대와 **무관**.
  검색 상위에 섞여 나온다. 절대 채택 금지.
- ⚠ 코퍼레이트 사이트 `www.hd.com` 은 **CloudFront WAF 403** (UA 위장해도 차단).
  복지 수집은 `recruit.hd.com` 만 사용.
- 계열사 전용 사이트(`recruit.hhi.co.kr`, `www.hd-ce.com`, `recruit-hhi-ce.com`,
  `www.hd-hyundaies.co.kr`)는 **각 계열사 것** — 지주 것으로 오인 금지.

## ② 복지 항목 명시 여부 — **명시됨 · 18개 / 3개 카테고리**

각 항목이 `benefitTitle` + `text`(설명문) 구조라 문장까지 확보 가능.

- **Work / 업무 몰입 (8)**: 선택근로제, 유연근로, 자율좌석제, 워케이션, 아침/점심/저녁 제공,
  칸틴 운영, 편안한 근무 환경, 통근버스 운영
- **Life / 생활 지원 (7)**: 생활안정, 기숙사, 우리 아이 지원, 자유로운 휴가 문화,
  그룹사 패밀리 카드 운영, 유류비 지원 혜택, 범현대 계열사 할인
- **Health / 건강 지원 (3)**: 종합검진, 직원 휴식 지원, 건강 케어 (GRC)

예시 2건(원문 그대로):
1. **선택근로제** — "근무시간을 자유롭게 설계할 수 있는 선택 근로제를 운영하고 있습니다.
   코어타임인 10시에서 15시를 제외한 시간은 자유롭게 근무시간을 선택할 수 있습니다."
2. **우리 아이 지원** — "0세부터 5세까지 구성된 학급으로 최고 시설의 교육환경을 갖춘
   어린이집을 운영하고 있습니다. … 만 4세부터 6세의 자녀가 있는 직원에게는 매월 50만원의
   교육비가 지원됩니다."

## ④ 접근성 — **JS(Vue SPA) / 단, JS 렌더링 불필요**

- `/kr/mainLayout/benefit` 을 curl 하면 **1,781 byte 셸**만 온다(메인과 바이트 동일).
  본문 0. → 순수 클라이언트 라우팅 SPA.
- **그러나 복지 데이터는 API 가 아니라 JS 번들에 하드코딩되어 있다.**
  `benefitList` 상수가 정적 청크 안에 그대로 있어 헤드리스 브라우저 없이 텍스트 추출 가능.
  - 오늘 기준 위치: `https://recruit.hd.com/js/5869.08a09a96.js` (52KB)
  - 진입점: `https://recruit.hd.com/js/app.deed2f3e.js` → 라우트 `benefit-kr` → 청크 목록
- 인증/쿠키/차단 없음. 일반 UA 로 200. 429·봇 방어 징후 없음.

### 접근 경로 2안
- **A(권장·저비용)**: `app.<hash>.js` → 청크 해시 맵 파싱 → `5869` 청크 → `benefitList` 파싱.
  브라우저 불필요.
  ⚠ **파일명 해시가 재배포마다 바뀐다** — 해시를 하드코딩하면 조용히 404. 반드시 `app.js`
  에서 동적으로 풀어야 하고, `app.js` 해시 자체는 `/kr` HTML 에서 읽어야 한다(3단 추적).
- **B(안정)**: 헤드리스 렌더링 후 `.benefit__container` 텍스트 수확.
  ⚠ 메모리 2코어 서버 부담 + 우리 쪽 헤드리스 UA 이슈는 무관(외부 사이트).

## 지주 / 그룹공통 / 계열사전용 구분 — **그룹 공통**

- 페이지 각주 원문: **"*복리후생은 계열사간 일부 상이할 수 있습니다."**
  → 사이트 스스로 그룹 공통 서술임을 선언. 계열사 편차 인정.
- 항목 다수가 **GRC(분당 글로벌R&D센터, "HD현대 그룹을 대표하는 사옥") 사무직 기준**
  (자율좌석제, 칸틴, 허먼밀러 의자, 건강 케어(GRC)). 지주 본사가 GRC 소재라 지주 직원에게
  실제로 적용되는 항목군이나, **지주 전용이라는 근거는 없다.**
- ⚠ 사이트의 회사 필터 목록(`allCompanyList`, 19개)에 **HD현대(지주) 자체는 없다.**
  즉 이 사이트는 "HD현대 브랜드의 그룹 통합 채용" 이지 "지주회사 HD현대 채용" 이 아니다.
  → **지주 단독 복지 출처는 확인되지 않음.**

### 적재 시 지켜야 할 정직성
- 출처 표기는 `HD현대 그룹 통합 채용사이트(recruit.hd.com) — 그룹 공통 복리후생`.
- 화면 문구에 **"계열사 간 일부 상이할 수 있음"** 을 반드시 동반. 각주를 떼면 우리가
  원문에 없는 확정을 만들어내는 것이 된다.
- 계열사(중공업·오일뱅크·일렉트릭 등) 상세 페이지에 이 데이터를 **복제 전개하지 마라.**
  같은 문단이 N개 회사에 붙으면 애드센스 관점의 중복 콘텐츠이자, 각주와도 모순된다.
