## ③ robots

- `https://www.hdec.kr/robots.txt` → HTTP 200, **19바이트**, 내용은 `User-agent: *` 한 줄뿐. **Disallow 없음 = 전면 허용.**
- `/kr/career/benefit.aspx` 를 막는 규칙 없음. Crawl-delay·Sitemap 지시자도 없음.

## ④ 접근성

- **정적 SSR**: `benefit.aspx` 응답 80,170바이트 HTML 안에 복지 항목 텍스트가 **전부 들어 있음**. JS 렌더링 불필요, 헤드리스 브라우저 불필요. 단순 GET + 파싱으로 끝.
- 본문 추출 텍스트 약 4.7KB(태그 제거 후) — 우리 상세 페이지 본문 보강에 충분한 분량.
- 인코딩 UTF-8, 로그인·쿠키·세션 불필요.

### ⚠ 함정 1건 — UA 필터(WAF)

`hdec.kr` 앞단에 UA 기반 차단이 있다. 실측:

| User-Agent | 결과 |
|---|---|
| 기본 `curl/x.y` | HTTP **200** 인데 본문 939바이트 `<title>deny</title>` 차단 페이지 |
| `Mozilla/5.0 (compatible; loupitbot/1.0; +https://jobcho.wiki)` | HTTP 200, 정상 80,170바이트 |
| `Mozilla/5.0 (Windows NT 10.0 ...) Chrome/126.0` | HTTP 200, 정상 80,170바이트 |

- 차단이 **HTTP 200 으로 내려온다** → 상태코드만 보는 수집기는 차단 페이지를 정상 수집으로 오인한다. 길이/본문 키워드 검증 필수.
- 브라우저 위장까지는 불필요. `Mozilla/5.0 (compatible; ...)` 형태의 **정직한 봇 UA** 로 통과한다. 위장 대신 이 형태를 쓸 것.

## 종합

robots 전면 허용 + 정적 SSR + 항목 12개가 제목·설명 쌍으로 정돈 → **난이도 최하, 즉시 수집 대상**.
유일한 대비책은 UA 헤더 설정과 "차단 페이지 200" 방어 검증.
