### robots.txt

- **careers.kbfg.com/robots.txt** — 실질 **부재**. HTTP 200 이지만 본문은 `text/html` SPA 셸
  (`<title>KB Careers</title>` … `<div id="app">`)이다. SPA 의 catch-all 라우팅이 200 을 돌려준 것이고
  robots 지시자는 한 줄도 없다 → 매칭 규칙 없음 = **전면 허용**.
- 페이지 자신의 메타는 `<meta name="robots" content="index, follow">` — 색인·수집 허용 명시.
- 수집 UA: 일반 Chrome UA(`Mozilla/5.0 … Chrome/126.0 Safari/537.36`). 차단·레이트리밋 없이 200.
- **JS 렌더 필요**: 본문이 SSR 되지 않는다. 두 경로로 같은 결과를 얻어 교차검증했다.

  2. Playwright(chromium, networkidle) 렌더 — 섹션 5개가 화면에 보이고, 상세 21개 항목은

## 3. 코드 매핑 판단 근거

### 신규 코드 1개 → **0개** (검증 판정 반영, §6)

- ~~**`vacation_program`**~~ → **`travel_support`** (SORT 61, leisure) — 「휴양프로그램」.
  아래는 초안의 신규 코드 판단이며, 웨이브 여행·휴양 코드 통합 판정으로 **철회**되었다.
  정식 어휘의 `resort` 는 같은 페이지의 「임직원 전용 콘도」가 이미 가져갔고(코드 UNIQUE),
  `leisure_ticket`(이용권)·`company_event`(사내 행사)·`summer_leave`(휴가) 중 어느 것도
  "시즌별로 운영되는 휴양 프로그램"을 뜻하지 않는다. 두 항목은 페이지에서 **별개 항목**으로
  나열되므로 합치면 정보가 사라진다 → 새 snake_case 를 만들었다.
  (`server/models/benefit_edit.py` 의 `_BENEFIT_CD_RE = ^[a-z][a-z0-9_]{1,29}$` 통과.
  `generator/pages/heatmap.py` 의 `ITEM_LABEL` 은 화이트리스트가 아니라 라벨 폴백 맵이라
  — 주석: "없는 코드는 그 코드의 가장 흔한 benefit_nm 으로" — 새 코드가 조용히 떨어지지 않는다.)

### 어휘 함정 회피

- **`family_day` 안 씀** — 「KB 패밀리데이」는 이름만 보면 `family_day` 지만, 코퍼스의 `family_day` 는
  **조기퇴근** 의미(계약 규칙 5 명시)다. KB 것은 사옥 초청 **가족 행사**라 `company_event` 로 갔다.
  선례 있음(다른 회사 `company_event` = "가족친화 프로그램", 같은 사유의 주석 포함).
- **`flex_work` 1행으로 병합** — 「선택적 근로시간제」와 「시차출퇴근제」는 원문상 2항목이지만
  둘 다 `flex_work` 이고 코드는 회사당 UNIQUE 다. DB손해보험 선례(`flex_work` / NM
  "시차출퇴근제/선택근무제")를 그대로 따라 한 행에 두 제도를 담고 `QUAL_DESC` 에 양쪽을 적었다.
  → 원문 21항목 대비 여기서 1행이 줄고, `health_check`/`medical` 분리에서 1행이 늘어 총계 21행 유지.
- **`health_check` + `medical` 분리** — 원문이 한 항목이지만 문장 자체가 "**건강검진 및 의료비 지원**
  제도(복수)를 운영"이라 두 제도를 명시한다. 코퍼스에서도 둘은 각각 89회·48회 쓰이는 별개 축이고,
  회사 간 비교가 목적이라 분리가 정확하다. 삼성카드 선례도 같은 문장을 두 행으로 나눴다.
- **`meal` 1행 유지** — 「사내식당 및 카페」는 `meal` + `snack_bar` 로 쪼갤 수도 있으나,
  원문이 한 항목이고 사내카페는 간식바가 아니라 식음 시설이라 과잉 해석을 피해 한 행으로 뒀다.
- **`team_dinner`** (SORT 83) — 「부서 내 문화행사 지원」. 코퍼스의 `team_dinner` 는 "팀 회식비 지원"
  = **부서 단위 활동비 지원** 버킷이다. `company_event` 는 패밀리데이가 점유했고 `culture_day` 는
  전사 문화의 날(연 1회 행사일)이라 뜻이 다르다 → 부서 단위 지원이라는 실질이 같은 `team_dinner` 채택.
  BENEFIT_NM 은 원문 그대로 "부서 문화행사 지원"으로 두어 표기상 오해가 없게 했다.
- **`lounge`(work_env) vs `leisure_room`** — 원문이 "사옥 내" 시설이라 근무환경 축의 `lounge`.
  코퍼스 `lounge` 14회 전부 work_env 로 일관.
- **`housing_support`(≠`housing_loan`)** — 원문이 "임차보증금 일부를 **지원**"이라 대출이 아니다.

### 법정 제도 미수록 (계약 규칙 3)

- 「휴가제도」 행은 **법정 연차 자체가 아니라** 원문의 "기본적인 연차부여 **외에**" 부분,
  즉 건강검진·본인 생일 등 회사 재량 휴가만 담았다. NM 도 "휴가제도(연차 외)".
- 「경조사 지원」의 경조휴가는 회사 재량분이라 그대로 `event` 행 서술에 포함.
- 4대보험·퇴직연금·주5일에 해당하는 서술은 페이지에 아예 없다 → 해당 없음.
- **`birthday_leave` 를 따로 만들지 않았다** — 원문이 "건강검진, 본인 생일 **등** … 니즈를 반영한
  휴가제도"라고 예시를 나열할 뿐 별도 제도명을 주지 않는다. 별도 행으로 세우는 것은 과잉 해석이라
  `leave_general` 한 행의 서술에 흡수했다.
