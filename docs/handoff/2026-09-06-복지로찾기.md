## 알게 된 것

1. **코드 사전은 DB 에 없다 — 집계다.** 번들(`reference/all`)은 회사별 복지 행만 싣는다. 「고를 수 있는 항목 86종」의 대표 이름·별칭·카테고리·보유 회사 수는 전부 세어서 만든다. 그래서 같은 계산이 **파이썬(정적 표)과 JS(칩) 두 곳**에 있다.
2. **그 둘의 동률 규칙이 원래 달랐다.** JS 는 `localeCompare('ko')`, 파이썬은 코드포인트. 최빈 `benefit_nm` 이 동점일 때 같은 코드가 표와 칩에서 **다른 이름**을 갖는다 — 화면에서만 보이고 테스트로는 안 잡히는 종류다. 양쪽 다 로케일 없는 비교로 못 박고 같은 픽스처로 확인한다.
3. **표시명이 겹치는 코드가 실제로 두 뭉치 있다.** 「통근버스」 = `transport`(24곳)·`commute_subsidy`(44곳), 「장기근속 포상」 = `long_service_leave`(54)·`long_service_bonus`(21)·`long_service`(1, 구 코드). 다섯을 손으로 못 박고 나머지 중복만 별칭을 병기한다. 실데이터 126사에서 중복 표시명 0.
4. **`URLSearchParams` 가 쉼표를 `%2C` 로 굽는다.** `/find?b=meal%2Cwelfare_point` 는 공유 링크로 읽히지 않는다. 쉼표는 쿼리 값에서 합법(RFC 3986 sub-delims)이라 되돌려도 왕복은 그대로다.
5. **접힘의 진동은 문턱 여유가 막는다.** 접힘 문턱을 「덱 위 + 펼친 높이 + 8px」에 두면 보정으로 되돌아간 위치가 펼침 문턱보다 항상 아래다. 이 여유가 없으면 접자마자 다시 펼쳐진다. 테스트는 스크롤을 **상대 이동**으로 흉내낸다 — 절대 좌표로 밀면 우리 보정이 없던 일이 돼 진동 버그가 테스트를 통과한다.
6. **`globalThis` 는 window 가 아니다(node 에서).** 기본값을 `globalThis` 로 두니 스크롤 배선이 부팅 자체를 깨뜨렸다. `globalThis.window || globalThis` 로 고쳤다.
7. **비-JS 본문이 이 페이지의 전부다.** 도구는 JS 라 색인되지 않는다. 카테고리 9 × 코드 86 표를 항상 보이게 두니 태그 제외 본문 약 **5,190자**(현재 회사 페이지 중앙값 1,974 의 두 배 반) — 콘텐츠 두께에 그대로 보탬이 된다.

## 프로토타입과 달리 한 결정 셋

1. **접힘 경계 900 → 768.** `styles.css` 는 분기가 `min-width:768px` 하나이고 `max-width` 분기를 테스트가 금지한다(UT-BP). 900 을 유지하면 768~900 에서 덱이 고정된 채 접히지 않아 화면 절반을 먹는다. JS 상수와 CSS 분기를 같은 값으로 묶었다.
2. **`overflow-anchor:none` 을 CSS 전역이 아니라 `find.js` 가 붙인다.** 필요한 것은 이 페이지에서 JS 가 켜졌을 때뿐이고, `html` 전역 규칙으로 두면 다른 페이지의 스크롤 동작까지 바뀐다.
3. **정적 본문을 도구 아래에 항상 둔다.** 프로토타입에는 없던 층이다(그쪽은 데모라 도구가 전부였다). 크롤러·비-JS·색인 세 이유가 겹친다.

부수로 **GNB 순서가 바뀌었다**: 홈 · 복지로 찾기 · 회사정보 · 히트맵 · 커뮤니티(브리프 지정). 커뮤니티가 끝으로 갔다.

## 남긴 것 (미결)

- **배치·배포는 하지 않았다.** nginx 두 파일에 줄만 넣었고 `nginx -t`(worktree 경로 사본)까지만 했다. 리드가 배치 → reload → `release.sh` 순으로 낸다. **회사 추가와 달리 새 라우트라 nginx 배치가 빠지면 `/find` 는 404 다.**
- **v2 후보 넷**(SPEC 18 SP-FIND-9): 코드별 정적 페이지 86개(`/benefit/<code>`, G1 관찰 뒤) · 회사 페이지 복지 카드 역링크 · GNB 검색창 복지 키워드 폴백 · 「금액 적힌 항목만」의 뜻(지금은 「고른 항목 전부에 금액」).
- **「재직자 확인만」 필터**는 비활성 체크박스 + 툴팁으로 남겼다. 지금은 전 항목이 `official` 이라 켜면 아무 일도 하지 않는다 — 재직자 편집이 쌓이면 `badge.js` 계보 판정을 그대로 재사용해 켠다(새 판정을 만들지 말 것).
- **브라우저 실물 확인 없음.** 접힘은 좌표 산수까지만 검증했다(가짜 window 13개). 실제 스크롤 느낌·sticky 겹침·모바일 폭 전환은 배포 뒤 눈으로 봐야 한다.

## 검증자가 볼 지점

1. **파이썬↔JS 코드 사전이 정말 같은가** — `generator/pages/find.py::derive_codes` 와 `web/assets/js/find.js::deriveCodes`. override 다섯과 동률 규칙은 테스트가 강제하지만, 카테고리 최빈값·별칭 순서까지 같은지는 실데이터로 한 번 더 대조할 값어치가 있다(`ref.json` 126사).
2. **접힘 알고리즘의 문턱 산수** — `initDeckCollapse` 의 `anchorTop + expandedH + 8` 과 `anchorTop + 8`. 덱이 뷰포트보다 높거나(아주 좁은 창) 페이지 하단에서 스크롤 여유가 모자랄 때의 거동은 테스트에 없다.
3. **렌더 이스케이프** — 결과 행·제안·칩 전부 `dom.js::el` 만 쓰는지. 회사명에 `&`(삼성E&A)가 실재한다. `innerHTML` 로 문자열을 넣는 경로가 하나라도 생기면 그 순간 규약이 깨진다.
