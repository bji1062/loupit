## 알게 된 것 (실측)

- **nginx 는 Basic 인증 헤더(`Authorization`)를 업스트림에 그대로 넘긴다** — 격리 nginx 1.18 + 에코 업스트림으로
  확인. 앱은 쓰지 않으므로 관리 vhost 블록마다 `proxy_set_header Authorization "";` 로 끊었다(AH-9).
- `proxy_set_header X "";` 는 클라이언트가 보낸 같은 이름 헤더를 **업스트림에 보내지 않는다**(본·베타에서 위조
  헤더 소멸 확인). 관리 vhost 의 `proxy_set_header X-Loupit-Admin-Gate "<비밀>"` 은 클라이언트 위조값을 **덮는다**.
- `return`·`if … return` 은 rewrite 단계라 **auth_basic 보다 먼저** 나간다 → 비밀번호 없는 스캐너가 경로마다 다른
  답을 받았다. `try_files`(access 뒤)로 미루니 비밀번호 없는 8경로 전부 401(격리 실측).
- 라우터 의존성은 라우트 매칭 **뒤**에 돈다 — 틀린 메서드 405(`Allow`)·깨진 JSON 422·끝 슬래시 307 이 관문 전에
  나가 존재를 알렸다. 매칭 단계(`APIRoute.matches`)에서 거부하면 셋 다 404 가 된다(AH-15).
- nginx `$host` 는 소문자·포트 없음 — 클라이언트가 `ADMIN.JOBCHO.WIKI:443` 을 보내도 앱엔 `admin.jobcho.wiki`.
  SNI=`jobcho.wiki` + Host=`admin.jobcho.wiki` 는 관리 vhost 로 간다(401) — 우회로 아님.
- 이 서버에는 `htpasswd`(apache2-utils)가 없다. bcrypt(`$2y$`, `htpasswd -B` 형식)는 nginx 1.18 에서 인증 통과
  확인. 설치 없이 하려면 `openssl passwd -6 -stdin`($6$)도 통과 확인.
- sites-enabled 는 `loupit-beta.conf`·`loupit.conf` 둘뿐이고 `default_server` 가 없다 → 이름순 첫 파일(베타)이
  미매치 Host 폴백. 관리 vhost 를 `loupit-admin.conf` 로 걸면 폴백이 바뀐다 → **`zz-loupit-admin.conf`** 로 건다.
- 배포 대상 라이브 파일(`loupit.conf`·`loupit-beta.conf`·`conf.d/loupit-limits.conf`·보안 스니펫)은 2026-09-18 기준
  리포 `main` 과 **바이트 동일**(드리프트 0). 배포 직전 다시 diff 한다(§2).
- `server/` 디렉터리는 root 소유 · `server/.env` 는 ubuntu 600 — `sudo -u ubuntu sed -i` 는 임시 파일을 못 만들어
  실패하고, root `sed -i` 는 파일을 root 소유로 **새로 만든다**. 기존 파일에 `>>`·`cat >` 로 쓰면 소유권이 유지된다.

## 배포 절차 (리드가 한다 — 순서대로)

> ⚠ **§4·§5 는 Claude 세션의 `!` 로 돌리지 말고 SSH 터미널에서 직접** — `!` 출력은 대화 기록에 남는다.
> 아래 명령은 비밀번호·비밀이 **화면에도, 명령 인자(`ps`)에도** 나오지 않게 짰다: 비밀번호는 `read -s` → 파이프

> 항상 `sudo nginx -t &&` 를 앞에 붙이고, 적용 여부는 확인 명령으로 본다.

### §3 인증서 — 80 블록만 먼저 걸고 webroot 발급

전체 conf 는 인증서 파일이 없으면 `nginx -t` 에서 실패한다. 80 블록만 뽑아 임시로 건다(추출 결과는 격리 nginx 로 검증함):

```bash
cd /home/ubuntu/loupit
sed -n '/^# ── HTTP :80/,/^}/p' infra/nginx/loupit-admin.conf | sudo tee /etc/nginx/sites-available/zz-loupit-admin-bootstrap.conf >/dev/null
sudo ln -s /etc/nginx/sites-available/zz-loupit-admin-bootstrap.conf /etc/nginx/sites-enabled/zz-loupit-admin-bootstrap.conf
sudo nginx -t && sudo systemctl reload nginx
sudo certbot certonly --webroot -w /home/ubuntu/loupit/web -d admin.jobcho.wiki
sudo ls /etc/letsencrypt/live/admin.jobcho.wiki/                                    # fullchain.pem privkey.pem
sudo rm /etc/nginx/sites-enabled/zz-loupit-admin-bootstrap.conf /etc/nginx/sites-available/zz-loupit-admin-bootstrap.conf
```

webroot 는 jobcho.wiki·beta 와 **공유**하는 `/home/ubuntu/loupit/web` 이다(자동갱신이 여기에 쓴다 — 관리 conf 의 80
블록 ACME root 와 같아야 한다). ⚠ 발급하는 순간 호스트명이 인증서 투명성 로그에 공개된다 — 정상이다(방어는 이름이
아니라 두 잠금이다).

### §4 비밀번호(첫째 잠금) — SSH 터미널에서, stdin 으로만

```bash
sudo apt-get install -y apache2-utils                    # htpasswd 가 없다(2026-09-18 확인). 설치가 싫으면 아래 대안
read -rsp '관리 화면 비밀번호(20자 이상, 비밀번호 관리자에 저장): ' PW; echo
printf '%s\n' "$PW" | sudo sh -c 'umask 027; htpasswd -c -i -B /etc/nginx/loupit-admin.htpasswd ops' >/dev/null
unset PW
sudo chgrp www-data /etc/nginx/loupit-admin.htpasswd && sudo chmod 640 /etc/nginx/loupit-admin.htpasswd
sudo ls -l /etc/nginx/loupit-admin.htpasswd              # -rw-r----- root www-data
```

- `-i` = 비밀번호를 **stdin** 으로 받는다(`ps`·화면에 안 나온다), `-B` = bcrypt(격리 nginx 1.18 에서 `$2y$` 인증 통과 확인).
  `umask 027` 이라 파일이 만들어지는 순간부터 남이 못 읽는다(nginx 워커 = www-data 가 그룹으로만 읽는다).
- 설치 없는 대안(같은 성질 — stdin, $6$ SHA-512 crypt, 역시 실측 통과):
  `printf 'ops:%s\n' "$(printf '%s' "$PW" | openssl passwd -6 -stdin)" | sudo sh -c 'umask 027; cat > /etc/nginx/loupit-admin.htpasswd'`
  (`read` 뒤, `unset PW` 앞에서. 그다음 같은 chgrp·chmod.)
- 사용자명 `ops` 는 예시다.

### §5 게이트 비밀 — root 셸 안에서 생성해 곧바로 두 파일에

```bash
grep -c '^ADMIN_' /home/ubuntu/loupit/server/.env        # 0 이어야 한다(있으면 §되돌리기 「앱 쪽 입구 닫기」로 먼저 정리)
sudo sh -c '
  umask 077
  s=$(openssl rand -hex 32)
  printf "proxy_set_header X-Loupit-Admin-Gate \"%s\";\n" "$s" > /etc/nginx/snippets/loupit-admin-gate.conf
  printf "ADMIN_HOST=admin.jobcho.wiki\nADMIN_GATE_SECRET=%s\n" "$s" >> /home/ubuntu/loupit/server/.env
'
sudo ls -l /etc/nginx/snippets/loupit-admin-gate.conf    # -rw------- root root (600)
ls -l /home/ubuntu/loupit/server/.env                     # -rw------- ubuntu ubuntu (600) — `>>` 는 소유권을 안 바꾼다
```

비밀은 `sh` 안의 변수로만 존재하고 셸이 끝나면 사라진다 — 화면·명령 인자·대화 기록·호출한 셸의 변수 어디에도
남지 않는다(`openssl rand` 의 출력은 파이프로 받고, `printf` 는 dash 내장). 사람은 이 값을 볼 일이 없다 — 두 파일이
서로 같기만 하면 된다.

🚨 **`.env` 소유권 함정**: root 로 편집기(`vim`·`sed -i`)를 쓰면 파일이 새로 만들어져 root:root 가 되고 `loupit-api`·
`loupit-beta-api` 가 **둘 다 죽는다**(User=ubuntu 가 못 읽는다 — 2026-07-17 실사고). 위처럼 기존 파일에 `>>` 로
덧붙이면 소유권이 유지된다. 혹시 바뀌었으면 `sudo chown ubuntu:ubuntu /home/ubuntu/loupit/server/.env && sudo chmod 600 /home/ubuntu/loupit/server/.env`.
(`OPERATOR_EMAILS` 는 이미 들어 있다 — 건드리지 않는다.)

- 세 번째가 `{"detail":"Not Found"}` 이면 게이트가 닫힌 것이다: `journalctl -u loupit-api --since '5 min ago' | grep 게이트`
  → "게이트 헤더가 설정과 다르다(헤더 없음|값 불일치)" 가 보이면 스니펫과 `.env` 값이 다르거나 §7 재시작을 빠뜨렸다.
- 폰: `https://admin.jobcho.wiki` → 비밀번호 → 콘솔 로그인(운영자 이메일 코드) → 탭 다섯. 비운영자 계정으로
  로그인하면 「운영자 계정이 아니다」 + 「지금 세션 로그아웃」 버튼이 나오는 것이 정상이다.
- 게시판에서 글 하나를 숨겼다 복구하면 「최근 조치」에 「복구 · MBR 1 · …(총 2회)」가 보여야 한다(이력 표 동작).
- 터널도 그대로 열리는지 한 번 본다.

## 되돌리기

| 무엇을 | 명령 | 효과 |
|---|---|---|
| 관리 호스트를 즉시 닫기 | `sudo rm /etc/nginx/sites-enabled/zz-loupit-admin.conf && sudo nginx -t && sudo systemctl reload nginx` | 관리 vhost 소멸(요청은 폴백 베타로 → 앱이 Host 로 404) |
| 앱 쪽 입구 닫기 | 아래 「`.env` 에서 줄 빼기」로 `^ADMIN_` 두 줄 제거 → `sudo systemctl restart loupit-api` | 통과 B 닫힘(터널만) |
| 비밀 교체(유출 의심) | 아래 「게이트 비밀 교체」 → `sudo nginx -t && sudo systemctl reload nginx` → `sudo systemctl restart loupit-api` | 옛 비밀 무효 |
| 비밀번호 교체·폰 분실 | §4 재실행 + 비밀 교체 + 세션 폐기: `mysql -h 127.0.0.1 --protocol=TCP -u APP_LOUPIT -p LOUPIT -e "UPDATE TSESSION SET REVOKED_DTM=UTC_TIMESTAMP() WHERE MBR_ID=1 AND REVOKED_DTM IS NULL"` | Basic 자격증명·30일 세션 무효(본 사이트 세션도 함께 끊긴다) |
| nginx 파일 원복 | `bash infra/deploy/rollback-nginx.sh <§2 의 TS>` | 존·본·베타 conf 를 백업으로(헤더 제거 줄은 남겨도 무해하다) |
| 코드 원복 | 머지 revert → pull → API 재시작 | 새 탭·관문 교체 되돌림(`.env` 의 `ADMIN_*` 는 옛 코드가 무시한다). `TPOST_ACTION_LOG` 는 남겨도 무해(옛 코드는 안 쓴다) — 지우려면 `DROP TABLE TPOST_ACTION_LOG` |

**`.env` 에서 줄 빼기**(소유권 유지 — 새 파일을 만들지 않고 기존 파일에 다시 쓴다):

```bash
sudo sh -c 'umask 077; f=/home/ubuntu/loupit/server/.env; grep -v "^ADMIN_" "$f" > "$f.tmp" && cat "$f.tmp" > "$f" && rm -f "$f.tmp"'
ls -l /home/ubuntu/loupit/server/.env                     # ubuntu ubuntu 600 그대로
```

**게이트 비밀 교체**(§5 와 같은 성질 — 값이 화면·인자에 안 나온다):

```bash
sudo sh -c '
  umask 077
  s=$(openssl rand -hex 32); f=/home/ubuntu/loupit/server/.env
  printf "proxy_set_header X-Loupit-Admin-Gate \"%s\";\n" "$s" > /etc/nginx/snippets/loupit-admin-gate.conf
  grep -v "^ADMIN_GATE_SECRET=" "$f" > "$f.tmp" && printf "ADMIN_GATE_SECRET=%s\n" "$s" >> "$f.tmp" && cat "$f.tmp" > "$f" && rm -f "$f.tmp"
'
```

## 남긴 것 (미결·위험)

- **폰 분실**: Basic 자격증명(브라우저 저장)과 30일 세션이 폰에 남는다 → 「비밀번호 교체·폰 분실」 행.
- **호스트명 공개**: 인증서 투명성 로그 — 방어는 두 잠금이지 이름이 아니다.
- **복지 이력 되돌리기**는 이번 범위 밖(읽기 전용). 넣는다면 그것도 새 편집 이력 행으로 남겨야 한다(편집 경로 재사용).
- **조치 이력 조회 화면**은 게시판 행의 「최근 조치」(마지막 1건 + 건수)까지만이다. 대상별 전체 이력 목록이 필요하면
  `idx_action_target` 을 타는 조회 하나를 더한다.
- 콘솔 페이지 JS 는 파이썬 문자열이라 노드 단위 테스트가 없다 — 화면 동작은 헤드리스 점검(Playwright 라우트
  가로채기, 서버·DB 무접촉)으로만 확인했다. 페이지를 크게 고칠 때는 같은 점검을 다시 돌려라.
