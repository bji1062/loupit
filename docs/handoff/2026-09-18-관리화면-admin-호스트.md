## 알게 된 것 (실측)

- **nginx 는 Basic 인증 헤더(`Authorization`)를 업스트림에 그대로 넘긴다** — 격리 nginx 1.18 + 에코 업스트림으로
  확인. 앱은 쓰지 않으므로 관리 vhost 블록마다 `proxy_set_header Authorization "";` 로 끊었다(AH-9 가 지킨다).
- `proxy_set_header X "";` 는 클라이언트가 보낸 같은 이름 헤더를 **업스트림에 보내지 않는다**(본·베타에서 위조
  헤더 소멸 확인). 관리 vhost 의 `proxy_set_header X-Loupit-Admin-Gate "<비밀>"` 은 클라이언트 위조값을 **덮는다**.
- nginx `$host` 는 소문자·포트 없음 — 클라이언트가 `ADMIN.JOBCHO.WIKI:443` 을 보내도 앱엔 `admin.jobcho.wiki`.
  그래서 앱은 포트가 붙은 Host 를 불일치로 본다(그 요청은 관리 vhost 를 안 거쳤다).
- SNI=`jobcho.wiki` 인데 Host=`admin.jobcho.wiki` 면 nginx 는 **관리 vhost** 를 고른다 → 401. 우회로 아님.
- 이 호스트에는 `htpasswd`(apache2-utils)가 없다 → `openssl passwd -6`($6$ SHA-512 crypt)로 만든다. nginx 1.18 에서
  인증 통과 확인.
- sites-enabled 는 `loupit-beta.conf`·`loupit.conf` 둘뿐이고 `default_server` 가 없다 → 이름순 첫 파일(베타)이 미매치
  Host 폴백. 관리 vhost 를 `loupit-admin.conf` 로 걸면 폴백이 관리 vhost 로 바뀐다 → **`zz-loupit-admin.conf`** 로 건다.
- 배포 대상 라이브 파일(`loupit.conf`·`loupit-beta.conf`·`conf.d/loupit-limits.conf`·보안 스니펫)은 2026-09-18 기준
  리포 `main` 과 **바이트 동일**(드리프트 0) — 리포 파일을 덮어써도 되는 상태였다. 배포 직전 다시 `diff` 하라(§2).

### §2 nginx — 존 추가 + 본·베타 게이트 헤더 제거

```bash
cd /home/ubuntu/loupit
# 드리프트 점검 — 라이브와 새 리포 파일의 차이가 **게이트 헤더 줄과 주석 추가뿐**이어야 한다(아무것도 안 나와야 정상)
for f in loupit.conf loupit-beta.conf; do echo "== $f"; diff /etc/nginx/sites-available/$f infra/nginx/$f | grep '^[<>]' | grep -v -e 'X-Loupit-Admin-Gate' -e '^> *#'; done
diff /etc/nginx/conf.d/loupit-limits.conf infra/nginx/loupit-limits.conf | grep '^<'   # 지워지는 줄 없음 = 정상
TS=$(date +%Y%m%d-%H%M%S)
sudo cp /etc/nginx/conf.d/loupit-limits.conf /etc/nginx/conf.d/loupit-limits.conf.bak-$TS
sudo cp /etc/nginx/sites-available/loupit.conf /etc/nginx/sites-available/loupit.conf.bak-$TS
sudo cp /etc/nginx/sites-available/loupit-beta.conf /etc/nginx/sites-available/loupit-beta.conf.bak-$TS
sudo cp infra/nginx/loupit-limits.conf /etc/nginx/conf.d/loupit-limits.conf
sudo cp infra/nginx/loupit.conf /etc/nginx/sites-available/loupit.conf
sudo nginx -t && sudo systemctl reload nginx
sudo bash infra/deploy/deploy-beta.sh          # 베타 conf 는 이 스크립트로만(직접 cp 금지 — ACME root 가드). limits 도 다시 놓는다
echo "백업 접미사: $TS"                         # 되돌리기: bash infra/deploy/rollback-nginx.sh $TS
```

> 드리프트 점검에서 무언가 나오면 **멈춰라** — 라이브에만 있는 수기 수정이 덮여 사라진다(2026-09-18 기준 드리프트 0 확인).

확인 — 본 사이트는 그대로, 위조 헤더는 무력:


### §3 인증서 — 80 블록만 먼저 걸고 webroot 발급

전체 conf 는 인증서 파일이 없으면 `nginx -t` 에서 실패한다. 80 블록만 뽑아 임시로 건다:

```bash
cd /home/ubuntu/loupit
sed -n '/^# ── HTTP :80/,/^}/p' infra/nginx/loupit-admin.conf | sudo tee /etc/nginx/sites-available/zz-loupit-admin-bootstrap.conf >/dev/null
sudo ln -s /etc/nginx/sites-available/zz-loupit-admin-bootstrap.conf /etc/nginx/sites-enabled/zz-loupit-admin-bootstrap.conf
sudo nginx -t && sudo systemctl reload nginx
sudo certbot certonly --webroot -w /home/ubuntu/loupit/web -d admin.jobcho.wiki
sudo ls /etc/letsencrypt/live/admin.jobcho.wiki/                                    # fullchain.pem privkey.pem
sudo rm /etc/nginx/sites-enabled/zz-loupit-admin-bootstrap.conf /etc/nginx/sites-available/zz-loupit-admin-bootstrap.conf
```

webroot 는 jobcho.wiki·beta 와 **공유**하는 `/home/ubuntu/loupit/web` 이다(자동갱신이 여기에 쓴다 — 관리 conf 의 80
블록 ACME root 와 같아야 한다). ⚠ 발급하는 순간 호스트명이 인증서 투명성 로그에 공개된다 — 정상이다(방어는 이름이
아니라 두 잠금이다).

### §4 비밀번호(첫째 잠금) — SSH 터미널에서

```bash
read -rsp '관리 화면 비밀번호(20자 이상 권장, 비밀번호 관리자에 저장): ' PW; echo
printf 'ops:%s\n' "$(openssl passwd -6 -stdin <<<"$PW")" | sudo tee /etc/nginx/loupit-admin.htpasswd >/dev/null
unset PW
sudo chown root:www-data /etc/nginx/loupit-admin.htpasswd && sudo chmod 640 /etc/nginx/loupit-admin.htpasswd
```

사용자명 `ops` 는 예시다. 무작위 비밀번호가 필요하면 비밀번호 관리자에서 만들어 붙여 넣어라.
비밀번호를 `openssl passwd -6 "$PW"` 처럼 **인자로** 넘기지 않는다 — 실행 중 `ps` 로 다른 사용자에게 보인다
(`-stdin` + here-string 은 인자에 안 실린다. `printf`·`read` 는 셸 내장이라 프로세스가 생기지 않는다).

### §5 게이트 비밀 — 스니펫과 `.env` 에 **같은 값**, SSH 터미널에서

```bash
grep -c '^ADMIN_' /home/ubuntu/loupit/server/.env      # 0 이어야 한다(이미 있으면 그 줄을 먼저 정리)
SECRET=$(openssl rand -hex 32)
printf 'proxy_set_header X-Loupit-Admin-Gate "%s";\n' "$SECRET" | sudo tee /etc/nginx/snippets/loupit-admin-gate.conf >/dev/null
sudo chown root:root /etc/nginx/snippets/loupit-admin-gate.conf && sudo chmod 600 /etc/nginx/snippets/loupit-admin-gate.conf
printf 'ADMIN_HOST=admin.jobcho.wiki\nADMIN_GATE_SECRET=%s\n' "$SECRET" | sudo -u ubuntu tee -a /home/ubuntu/loupit/server/.env >/dev/null
unset SECRET
ls -l /home/ubuntu/loupit/server/.env                   # 반드시 ubuntu ubuntu -rw------- 그대로
```

🚨 **`.env` 소유권 함정**: root 로 편집기(`vim`·`sed -i`)를 쓰면 파일이 새로 만들어져 root:root 가 되고 `loupit-api`·
`loupit-beta-api` 가 **둘 다 죽는다**(User=ubuntu 가 못 읽는다 — 2026-07-17 실사고). 위처럼 `sudo -u ubuntu tee -a`
로 덧붙이면 소유권이 안 바뀐다. 혹시 바뀌었으면 `sudo chown ubuntu:ubuntu /home/ubuntu/loupit/server/.env && sudo chmod 600 /home/ubuntu/loupit/server/.env`.
(`OPERATOR_EMAILS` 는 이미 들어 있다 — 건드리지 않는다.)


- 세 번째가 `{"detail":"Not Found"}` 이면 게이트가 닫힌 것이다: `journalctl -u loupit-api --since '5 min ago' | grep 게이트`
  → "게이트 헤더가 설정과 다르다(헤더 없음|값 불일치)" 가 보이면 스니펫과 `.env` 값이 다르거나 §7 재시작을 빠뜨렸다.
- 폰: `https://admin.jobcho.wiki` → 비밀번호 → 콘솔 로그인(운영자 이메일 코드) → 탭 다섯. 비운영자 계정으로
  로그인하면 「운영자 계정이 아니다」 + 「지금 세션 로그아웃」 버튼이 나오는 것이 정상이다.
- 비밀번호 없이는 **어느 경로든 401** 이어야 한다: `for p in / /x /api/v1/console/overview /api/v1/members/login-code; do curl -s -o /dev/null -w "$p %{http_code}\n" https://admin.jobcho.wiki$p; done`
- 터널도 그대로 열리는지 한 번 본다.

- **감사 한계**: 게시판 숨김/복구의 DB 흔적은 대상 행 `MOD_ID`(마지막 조작자)뿐 — 전체 이력은 journald 한 줄씩.
  필요해지면 이력 테이블(스키마 단독 작업).
- **폰 분실**: Basic 자격증명(브라우저 저장)과 30일 세션이 폰에 남는다 → 위 「비밀번호 교체·폰 분실」 행.
- **복지 이력 되돌리기**는 이번 범위 밖(읽기 전용). 되돌리기를 넣는다면 그것도 새 이력 행으로 남겨야 한다(편집 경로 재사용).
- 콘솔 페이지 JS 는 파이썬 문자열이라 노드 단위 테스트가 없다 — 화면 동작은 헤드리스 점검(Playwright 라우트
  가로채기)으로만 확인했다. 페이지를 크게 고칠 때는 같은 점검을 다시 돌려라.
