## 2. 이 작업의 두 함정과 그 처리

### ① 렌더러가 Python·JS 둘이 됐다

`radar.py` 머리 주석의 계약은 「JS 로 한 벌 더 그리지 않는다」였는데 모드 A 는 브라우저 도구라
피할 길이 없었다. 갈라짐을 막는 장치는 골든 픽스처 하나다 —
`generator/tests/data/radar_pair_cases.json` 이 같은 입력에서 **SVG 문자열 전체의 바이트 일치**를
고정한다(`points` 조각만 걸면 순서·공백·속성 표기가 샌다).

**두 언어가 실제로 갈리던 지점이 둘 있었고, 둘 다 손으로 맞췄다.**

- **`.1f` 반올림** — 파이썬은 짝수 쪽, JS `toFixed` 는 위. 값이 **정확히 x.25** 일 때만 다르다
  (`151.25` → 파이썬 `151.2` / toFixed `151.3`). 그리고 그 값은 실제로 나온다: 축 값 3·눈금 8 이면
  `200 − 130×3/8 = 151.25` 다. `radar.js::f1()` 이 그 한 경우만 되돌리고, 픽스처의
  `quarter_rounding` 케이스가 고정한다.
- **이스케이프** — 파이썬 `html.escape` 는 `'` 를 `&#x27;` 로, `dom.js::escapeHtml` 은 `&#39;` 로
  쓴다. `radar.js::esc()` 는 **파이썬 쪽**을 따른다(이 파일의 계약이 바이트 일치라서).

같은 함정이 **평균값에도** 있고, 여기서 한 번 틀렸다가 1차 검증에서 잡혔다. `round(x, 2)` 는
정확한 동점에서 `Math.round` 와 갈리는데 — 그 동점은 **`x = 홀수/8` 일 때만** 생긴다((2n+1)/200 이
이진수로 떨어지려면 분자가 25 의 배수여야 한다) — 처음 구현은 판정에 `x * 200` 을 썼다. ×8 은
무손실이지만 ×200 은 ×25 를 포함해 무손실이 아니라서, **비이진 값이 동점으로 오판**됐다:

| 값 | 옛 구현 | 파이썬 `round(x,2)` |
| --- | --- | --- |
| 3/120 = 0.025 | 0.02 | **0.03** |
| 7/40 = 0.175 | 0.18 | **0.17** |
| 2.675 | 2.68 | **2.67** |

전수 대조(회사 수 100~260 × 카테고리 합 0~9n = **260,981**건)에서 옛 구현은 **560건**을 틀렸고
전부 회사 수 **120·160·200·240** 이었다 — 그 규모가 됐을 때 정적 페이지와 도구의 9각형 좌표가
말없이 갈렸을 자리다. 지금 구현(×8 판정 + `toFixed(2)`)은 같은 전수에서 **불일치 0**이다.
픽스처에는 8곳(정확한 동점)과 120곳(가짜 동점) 두 케이스를 함께 뒀다 — 하나만 두면 오답의 다른
방향이 조용히 통과한다.

**날짜에도 같은 성격의 함정이 있었다.** `verified_dtm` 은 오프셋 없는 문자열이라 `Date.parse` 가
로컬 시각으로 읽는데 출력이 `getUTC*` 여서, KST 브라우저에서 확인일이 **하루 앞으로** 밀렸다
(4월 15일 → 4월 14일). 확인일은 「그날 확인했다」는 사실이지 시각이 아니다 — 시간대 개념이 없다.
그래서 `Date` 를 아예 거치지 않고 ISO 앞 10자만 쓰고, 최신값 비교도 그 10자의 사전순이다.

> 픽스처를 다시 뽑을 때: `RADAR_GOLDEN_WRITE=1` / `CATEGORY_STATS_WRITE=1` 로 pytest 를 돌린 뒤
> **반드시 JS 테스트도 함께** 돌려라. 픽스처만 갱신하면 「두 렌더러가 다르다」가 「픽스처가 JS 를
> 따라갔다」로 조용히 바뀐다.

### ② 덱 분리

`initDeckCollapse` 를 `deck.js` 로 옮기고 `find.js` 가 **같은 함수를 재수출**한다(사본이 아니라는
것을 `deck.test.js` 가 동일성으로 검사한다). find 의 접힘 13건·CSS 계약 5건은 **한 글자도 안
고쳤고** 그대로 초록이다.

- `headerEl` — sticky top 을 **런타임 실측**해 `wrap.style.top` 에 적는다. `--header-h:57px` 는 한 줄
  헤더의 값이고, 360px 에서 GNB 가 두 줄(97px)이 되면 미니바 위 40px 이 헤더 밑에 묻혀 버튼이
  안 눌린다(`styles.css:1145-1148` 이 「되돌릴 길 없는 상태」로 기록해 둔 형태). find 쪽 호출부도
  같은 함정을 안고 있어 **함께** 배선했다.
- `minWidth` — 접힘 경계를 옵션으로(기본 768 = CSS 의 유일한 분기).
- `expandBtn`·`collapseBtn` 을 **선택**으로 바꿨다. 모드 A 의 덱은 접힌 한 줄이 펼친 덱과 같은
  것을 말해서 「임시로 펼침」이 뜻이 없고, 쓰이지 않는 버튼을 마크업에 심는 편이 더 나쁘다.
- CSS 는 find 절에서 **복제**했다(`.cmp-*`). 합치면 find 의 CSS 계약 테스트 5개가 깨진다 — 그
  테스트가 보는 것이 셀렉터 문자열 자체다. `benefits.test.js` 에 같은 모양의 계약 7건을 새로 걸었다.

## 3. 정직성 규칙이 코드에 어떻게 박혔나

- **0 은 어디서나 「등록 없음」**. 말로 바꾸는 함수는 `fmt` **하나**(파이썬·JS 각 한 벌, 골든으로
  묶임)이고 판독문·aria-label·막대 라벨·목록 머리·표 셀이 전부 거기서 나온다. 회사 상세 레이더의
  「0항목」 표기도 같이 바꿨다(상세와 비교가 결측을 다르게 부르면 같은 회사가 두 화면에서 다른
  말을 한다).
- **금액 합계·순위·「더 낫다/우세」 없음**. `benTotal`·`renderBenefitHeadline`·`badgeKind` 를 부르지
  않는 것을 테스트가 **코드에서** 검사한다(주석은 제거하고 본다 — 설명 문장이 금지어로 오탐되면
  주석을 못 쓴다). 화면 텍스트에 「총액」이 나오는 곳은 딱 하나, **만들지 않는다는 선언**이다.
- **배지 계보 섹션 없음**(2,032행 전부 official 이라 모든 쌍이 같은 결과). 금액 옆 칩은
  `amt_source`(공식 수치/추정치)이지 출처 계보가 아니다 — 두 축을 한 낱말로 섞지 않는다.
- **근무형태는 `true` 만 사실**, 나머지는 「표기 없음」(overtime 은 126사 전부 null).
- **광고 0** — `mountAds` 호출이 `benefits.js` 코드에 없다(셸의 `data-page-type="input"` 도 그대로).

## 4. 라우팅 — 의도된 계약 변경

**두 슬롯이 찼을 때의 목적지가 입력 뷰 → 복지 비교로 바뀌었다.** 판정의 집은
`benefits.js::pairTarget()` **하나**다(부팅 폴백과 `ui.js::maybeAdvance` 가 따로 적으면 「주소로
들어오면 비교, 검색으로 고르면 입력」처럼 경로마다 다른 화면이 뜬다 — 버그가 아니라 설계가 둘인
상태라 고치기 어렵다). `ui.js` 가 `app.js` 를 import 하면 순환이라 집을 `benefits.js` 에 뒀다.

`#input` 은 **사용자가 명시한 모드 B** 라 쌍이 차 있으면 그대로 입력 뷰다(폴백을 태우면 새로고침할
때마다 계산기가 비교 화면으로 되돌아간다).

히스토리: `go()` 에 `replace` 옵션을 더했다. 「회사 바꾸기」는 항목을 쌓지 않고(뒤로가기를 다섯 번
눌러야 나가는 상태를 만들지 않는다), 모드 전환(`#input`)은 항목을 남긴다(뒤로가기로 비교 화면에
돌아올 수 있어야 한다). `syncPairUrl()` 이 `?a=&b=` 를 **화면과 같게** 맞춘다(언제나 replaceState).

기대값을 갱신한 테스트는 전부 사유 주석을 달았다: `app.test.js` resolveBootScreen·프리필·부팅 8건,
`ui.test.js` maybeAdvance 2건 + UI-10b·UI-10f. **UI-10f 는 요지를 그대로 뒀다** — 「고른 적 없는
회사를 바꿀 길이 그 화면 안에 있어야 한다」이고, 그 길만 입력 슬롯 버튼 → 덱 「회사 바꾸기」로
옮겼다.

## 6. 남은 것 (다음 세션)

1. **PR·머지·배포** — 미실행. 새 라우트가 없어 **nginx 변경은 불필요**하다(모드 A 는 기존
   `/compare/` 셸 안에 산다). 대문 CTA 가 `/compare/#input` 을 가리키는데 이것도 기존 라우트다.
2. **`/vs` 3쪽 산문** — 템플릿에 `{# 산문 #}` 슬롯만 비워 뒀다. 🚨 이 3쪽의 색인 가치를 가르는
   것은 손으로 쓴 산문뿐이고, 방금 얹은 그림을 포함해 **자동 생성물은 「비슷한 페이지」 판정을
   바꾸지 못한다**. 지금 형태(고유 완결문장 0 + 광고 3자리)가 심사에 가장 불리하므로, 못 쓸 것
   같으면 **폐기 + 301 이 방치보다 낫다**. 테스트가 슬롯을 지우지 못하게 지키고 있다.
3. **회사가 늘면 정적 재생성 필수** — 쌍 레이더의 눈금·평균이 전 회사 corpus 에서 나온다. 회사가
   하나 늘면 `/vs`·회사 상세가 전부 움직이고, 도구(런타임 집계)는 즉시 바뀌므로 재생성을 미루면
   **정적과 도구가 다른 눈금을 말한다**.
4. **모드 A 본문 광고** — 승인 시점 결정으로 남아 있다(설계는 「완결 문장 3개 이상 렌더된 뒤에만
   마운트」라는 조건까지만 정했다).
5. **360px 헤더 97px 은 재현됐다**(한국어 로캘 컨텍스트). 지금은 768 미만에서 덱이 sticky 가
   아니라 그 높이가 화면을 가리지는 않지만, 경계를 낮추는 날 곧바로 걸리는 값이다 — 실측 배선이
   이미 그 값을 따라가는 것을 확인했다.

## 6-1. 알게 된 것 (다음 사람이 밟지 않도록)

- **`x * 200` 같은 비-2거듭제곱 곱으로 부동소수 동점을 판정하지 마라.** ×8·×4 는 무손실이지만
  ×25 가 섞이는 순간 비이진 값이 정수로 반올림돼 **동점으로 오판**된다. 전수 대조 전까지 이 오답은
  회사 수가 120·160·200·240 이 되는 날까지 숨어 있었을 것이다.
- **오프셋 없는 날짜 문자열에 `Date` 를 대지 마라.** 「그날 확인했다」는 시각이 아니다 — 파싱하는
  순간 시간대가 붙고, 보는 사람에 따라 사실이 달라진다.
- **고정 2열은 `.main-cols` 레일과 곱해진다.** 본문이 전체 폭이 아니라 「전체 − 레일 300px」이라,
  768 에서 고정 320px 칸을 두면 남는 것이 68px 이다. 분기를 더 만들지 말고 `flex-wrap` 으로
  스스로 쌓이게 두는 편이 분기 하나를 아끼면서 모든 폭에서 맞는다.
- **해시 없는 주소는 히스토리 항목에 아무 말도 남기지 않는다.** SPA 에서 「정본 주소에 해시를 두지
  않는다」를 택했다면, 부팅 항목에 `replaceState` 로 표식을 남겨야 뒤로가기가 제자리를 찾는다.
- **이 화면에서 초록은 낱말이 아니라 「회사 A」다.** 계열 색이 정체성을 지닌 화면에서는 버튼·라벨
  같은 중립 요소가 그 색을 입는 순간 소속을 주장하게 된다.
- ⚠ **문서 불일치 하나**: `docs/SPEC/10-디자인-토큰.md` R2 가 「다크 기본」이라고 적고 있는데 실제
  구현·테스트(`UT-LIGHT-DEFAULT`)는 **라이트 단일**이다. 이번 범위 밖이라 손대지 않았다 — 리드 판단.

## 7. 열린 결정을 이렇게 닫았다

- **모드 A 의 h2** = 「복지 비교」(회사명 아님). `go()` 가 뷰 전환 때 첫 헤딩에 포커스를 옮기는데,
  회사명을 넣으면 바로 위 덱·미니바와 같은 말을 두 번 하게 된다. **회사명은 덱이 말한다.**
- **덱에 검색 입력을 넣지 않는다**(v1). 모드 A 의 덱 = 이름 + 「A·B 바꾸기」·「회사 바꾸기」·「이직
  계산기 →」. 검색은 기존 `#view-search` 가 맡는다 → SPEC 의 `.cand-list` 오버레이 항목은 v1 범위
  밖이다(SPEC 19 에 한 줄로 적어 뒀다).
- **집계 문장의 마지막 절**은 아티팩트의 산문형(「그중 2개는 같고 나머지 3개는 NAVER 가 큽니다」)
  대신 **절 단위**로 냈다(「금액이 같은 항목은 2개, NAVER 쪽이 큰 항목은 3개입니다」). 나머지가
  한쪽으로 몰리지 않는 일반 쌍에서도 참이어야 하기 때문이다. 「우세」 어휘는 쓰지 않는다.
- **축별 문장에 한 줄 추가** — 0 대 0 을 「같은 곳」으로만 세면 「둘 다 갖췄다」로 읽힌다. 목업의
  두 번째 문장(「근무환경은 두 회사 모두 등록 없음입니다」)을 문형에 넣었다.
- **`swapSlots` 가 바꾸는 것**은 회사에 딸린 상태(matched·benS·wsState·chosenType·inputMode·cmtS)
  뿐이다. 연봉·인상률은 **내 숫자**라 슬롯이 아니라 사람을 따라간다.
