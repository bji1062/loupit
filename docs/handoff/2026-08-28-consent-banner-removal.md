# 세션 기록 — 2026-08-28 · 관제 · 광고 동의 배너 제거

발단: 히트맵 스크린샷 하단의 검은 띠(동의 배너)를 짚었더니 사용자가 "애드센스는 자동으로 광고를
붙이는데 동의 배너가 필요하냐"고 물었다. 코드를 확인하니 배너는 게재 여부가 아니라 **개인화 여부**를
정하는 장치였고, 지금은 그 개인화가 일어나지 않는다(AdSense 거절 상태).

## 판단
1. 광고가 안 나가는데 "맞춤형 광고에 동의하겠느냐"를 묻고 있었다 — 일어나지 않는 처리에 대한 동의.
2. 광고를 안 붙이는 페이지(히트맵·회사목록)에도 떴다 — `base.html` 공통이라.
3. 자체 UI 는 구글 인증 CMP(TCF)가 아니라 EEA/영국 요건을 애초에 못 채운다.
→ 배너를 걷고 **개인화를 아예 요청하지 않는** 쪽으로. 사용자 확정(선택지 A).

## 알게 된 것
- **저장 계층은 남겼다**(`getConsent`/`setConsent`/`parseConsent`/`isPersonalized`) — `DENY_FALLBACK`
  폴백이 읽고, 승인 후 구글 CMP 신호를 이 자리에 꽂으면 된다. 다만 **개인화 신호를 좌우하지 않는다**.
- 문서 체인이 깊어(117곳) 전면 재작성 대신 **정본 1개 + 개정 배너**로 처리했다 — 성장성 폐기(2026-07-20)와
  같은 방식. 계약을 실제로 쥔 절(SP-ADS-7.2·CS-2·A-5·FR-78)만 본문을 고쳤다.

## 남긴 것
- **AdSense 승인 시 체크리스트**가 DECISION 문서 §"언제 되돌리나" 에 있다 — 순서를 지키지 않으면
  (문안보다 코드가 먼저 가면) 처리방침이 즉시 허위가 된다.
- 히트맵의 "광고 없는데 배너만 뜬다" 문제도 이걸로 함께 사라졌다.
