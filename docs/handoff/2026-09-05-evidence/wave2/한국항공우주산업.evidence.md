## 2. ⚠ 이 회사의 결정적 함정 — 정본 29항목이 전부 PNG 1장 안에 있다

A 페이지의 `<div class="cont">` 에서 HTML 텍스트로 나오는 것은 리드 4줄뿐이다:

> 구성원에 대한 경제적 지원, 가정의 안정, 자기계발, 삶의 여유를 위해 5대 영역의 다양한 복리후생제도를 운영 중에 있습니다.
> 이러한 다양한 복리후생은 입사에서 정년까지 생애별 개인의 라이프 사이클(Life Cycle) 및 수혜의 형평성을 고려하여 설계하고 있습니다.
> 또한 매년 구성원들의 복리후생에 대한 만족도를 높이기 위해 운영 중인 제도를 개선하고 기준을 보완하는 등 노사협의를 통해 다양한 제도를 도입 및 개선하고 있습니다.

항목 29개와 카테고리 5개는 **전부 이미지 내부 텍스트**이고, 이미지 태그는 딱 하나다:

```html
<img src="../images/sustainability/WelfareSystem_cont01_v260723.png" alt="복리후생제도" />
```

`alt` 가 「복리후생제도」 한 개뿐이라 **alt 로는 항목도 카테고리도 못 얻는다** → **HTML 스크래핑만 돌리면 0건**이 나와 「복지 미기재 회사」로 오판한다. B 페이지는 더 심해서 `<img style="margin-left: 45px" src="../images/ex/rc/5.png">` 한 줄이고 **`alt` 속성 자체가 없다.**

## 3. ⚠ C 는 SPA — 확보 경로 (KB금융 선례와 같은 유형)

C 는 Next.js App Router CSR 이다. `curl` 원본 23.8 KB 중 가시 텍스트는 `<title>` 23자뿐이고, `__NEXT_DATA__` 가 없으며 `self.__next_f` 플라이트 청크 14개(13 KB)를 디코드해도 **메타데이터만** 나오고 본문은 0자다.

본문은 **두 경로로 독립 확보**했고 문자열이 일치함을 확인했다:

1. **Playwright 렌더 DOM** → `C_benefits_rendered.html` (93 KB) / 가시 텍스트 `C_benefits_text.txt` (678자).
2. **ATS 빌더 JSON** → `C_builder2.json` (65 KB). 항목명·설명이 `{"type":"paragraph", ... "text":"출퇴근 통근버스 지원"}` 형태로 들어 있다.

⚠ **빌더 JSON URL 을 하드코딩하면 안 된다.** 실제 주소는 `https://infra1-static.recruiter.co.kr/builder/recruiter/<YYYY/MM/DD>/<uuid>.json` 형태로 **날짜와 UUID** 가 들어가고, 그 URL 을 알아내는 발견 API(`api-recruiter.recruiter.co.kr/design/v2`)는 브라우저 밖에서 Referer 를 맞춰도 **500(NullPointerException)** 을 낸다. 즉 JSON URL 은 런타임에만 발견되며 개정 즉시 깨진다. **재수집은 Playwright 렌더 후 DOM 텍스트를 뽑는 쪽이 안정적이다.**

### 개별 판단이 필요했던 매핑

- **`commute_subsidy` vs `transport`** — 「통근버스」는 버스 운행 자체를 가리키고 금액이 없다 → 심텍·셀트리온 선례대로 `commute_subsidy`.
- **「설/추석 귀성여비」 → `holiday_gift` (transport 아님)** — 현대건설이 「단신부임 직원의 귀향 교통비 지원」 을 `transport` 로 넣은 선례가 있어 후보였으나, 코퍼스에 **「명절 귀성여비」 라벨 그대로의 `holiday_gift` 행이 존재**한다(라벨 완전 일치). 완전 일치 선례를 택했다.
- **`holiday_gift` 카테고리 = compensation** — 코퍼스 36행이 compensation 23 / perks 12 / family 1 로 갈린다. 「명절/창립기념일 선물」 은 perks 선례이고 「명절 귀성여비」 는 compensation 선례다. KAI 는 **여비(현금성)** 가 앞이라 다수파이자 라벨 일치인 **compensation** 을 택했다. ⚠ 검증자가 perks 로 뒤집어도 근거는 있다.
- **「창립기념일 상품권」 → `holiday_gift` 병합 (`foundation_day_leave` 아님)** — `foundation_day_leave` 는 **휴가** 코드다. KAI 원문은 상품권이라 휴가 근거가 없다. 코퍼스에 「명절/창립기념일 선물」 = `holiday_gift` 병합 선례가 있어 그대로 따랐다. 창립기념일 **휴가** 는 원문에 없으므로 행을 만들지 않았다(창작 금지).
- **「수유실/휴게실」 → `lounge`** — 코퍼스에 `lounge` 서술로 「수유실, 휴게실, 수면실, 사내 정원」 선례가 있다. 수유실 전용 신규 코드를 만들지 않은 이유는 계약 규칙 5(대응 어휘가 있으면 신설 금지). ⚠ 다만 KAI 는 가족친화 인증 기업이라 수유실을 family 축으로 보고 싶은 검증자가 있을 수 있다 — §10 의심 지점 참조.
- **「사내 편의시설 - 은행/매점/카페테리아 등」 → `snack_bar`** — 코퍼스 `snack_bar` 47행의 대표 명칭에 「카페테리아」 가 있고, **정본 이미지에 카페테리아 사진이 캡션과 함께 실려 있어** 실재가 확인된다. `lounge` 는 「수유실/휴게실」 이 이미 점유해 같은 코드 2행이 불가하다(`uq_comp_benefit`).
- **「물리치료실/체력단련실」·「의무실/심리상담실」 → clinic + mental + fitness (2불릿 → 3행)** — 의무실·물리치료실은 사내 의료시설이라 `clinic`(사내 부속의원·건강관리실 선례), 심리상담실은 `mental`, 체력단련실은 `fitness`(C 의 헬스장/풋살장/농구장/테니스장이 보강). 두 불릿이 각각 의료·비의료를 섞어 놓아 코드 기준으로 재편했다.
- **「학위취득 지원제도」 → `mba`** — 코퍼스 `mba` 대표 명칭이 「MBA/학위파견」·「MBA/석사과정」 이다. 「국내 협약대학 석·박사학위 취득 지원」 은 학위 취득 지원이라 정확히 이 코드다. `edu_support`(직무교육) 나 `self_development`(자기계발비) 보다 정밀하다.
- **「정년퇴직자 지원」+「퇴직예정자 지원 제도」 → `retirement_support`** — 코퍼스에 「퇴직자 지원 제도」(growth) 선례가 1건 있다. 라벨·내용 모두 일치.
- **「모범 및 근무유공자 포상, 해외연수」 → `excellence_award` 병합** — 해외연수는 포상의 **부상**이라 별도 `career` 행으로 떼지 않고 같은 행 서술에 넣었다. 떼면 회사가 상시 운영하는 해외연수 제도가 있는 것처럼 읽힌다(과잉 해석).
- **「제휴 리조트 지원」 + 「협약 항공기 할인」 → `resort` 1행** — 항공기 할인만 떼면 `discount` 후보이나 원문이 **한 카드 안의 한 문장**이라 쪼개지 않고 서술에 병기했다. ⚠ 검증자가 `discount` 로 분리하면 35행이 된다.
- **「하기휴가(5일)」 + 「하기휴가비」 → `summer_leave` 1행** — 한미반도체 선례(`refresh_leave` = 특별 휴가 1주일 + 휴가비)가 휴가와 휴가비를 한 행에 병기한다. 심텍은 **휴가 없이 휴가비만** 있어 `summer_vacation_subsidy` 를 신설했지만, KAI 는 휴가 일수가 명시돼 있으므로 신규 코드 없이 `summer_leave` 로 흡수하는 쪽이 맞다.

### 병합/분리 내역

- **분리 3건** (복합 라벨 → 2행씩): 「근속기념품/휴가/축하금 지원」 → `long_service_bonus`+`long_service_leave` · 「물리치료실/체력단련실」+「의무실/심리상담실」 → `clinic`+`mental`+`fitness` · 「사내 편의시설」/「수유실/휴게실」 → `snack_bar`+`lounge`.
- **병합 5건** (같은 코드로 귀결): 귀성여비+창립기념일 상품권 → `holiday_gift` · 자랑스러운 KAI인 상+모범/유공자 포상 → `excellence_award` · 정년퇴직자 지원+퇴직예정자 지원 제도 → `retirement_support` · Culture Event+신입사원 부모님 초청행사+가족 초청 행사+사내 음악회 → `company_event` · 하기휴가+하기휴가비 → `summer_leave`.
- 병합은 전부 **같은 코드로 귀결되는 항목만**이다(계약 규칙 9). `uq_comp_benefit` 때문에 회사당 같은 코드 2행이 불가하므로 병합이 강제되는 경우이기도 하다.
- **금액 중복 계상 위험 없음**: 분리·병합한 행 중 금액을 가진 행이 하나도 없다.

## 9. 금액

| 코드 | BENEFIT_AMT | 근거 (원문 그대로) | 처리 |
|---|---:|---|---|
| `parenting` | **1000** | 「출산장려금 1,000만원 지급」(C) — D 가 「종전 100만 원에서 1, 2자녀 각 1,000만 원, 3자녀 3,000만 원으로 상향」 으로 **교차 확인** | `QUAL_YN FALSE`, `NOTE_CTNT` 에 명시값 근거 + **자녀 1인당 1회성 지급이며 연 환산액이 아니라는 단서** |
| 나머지 33행 | **NULL** | 원문에 금액 표기 없음 | `QUAL_YN TRUE` + `QUAL_DESC` 에 원문 인용 + 무엇이 미기재인지 |

**금액 stated 1건 / estimated 0건.** 신규 회사라 승계할 구본 앵커가 없고, 타사 앵커(`health_check`·`meal`·`resort`·`welfare_point` 등 코퍼스 금액)를 **끌어오지 않았다**.

| 원문 수치 | 왜 AMT 가 아닌가 |
|---|---|
| 「매월 개인연금 **100%** 회사지원」 | **비율**이다. 월 납입액이 없어 연 환산이 불가능하다(SI-B2 는 월액×12) |
| 「본인(**전액**)/배우자/부양가족 의료비 실비지원」 | 보전 **비율**이고 한도 금액이 없다 |
| 「최초 연차 **22일**」 · 「하기휴가(**5일**)」 | **일수**이지 금액이 아니다 |
| 「**50개 이상** 동호회」 | 동호회 **개수**다 |
| 「주거안정자금 **대출**이자 지원」 | 계약 규칙 4 — **대출 원금 한도는 금액이 아니다.** 이자 지원율·한도 모두 미기재라 정성으로 뒀다 |

⚠ **출산장려금 1,000만원은 이 시드에서 가장 논쟁적인 값이다.** §10 참조.

## 10. 검증자가 봐야 할 의심 지점

1. **`parenting` = 1000 (출산장려금)** — 코퍼스 `parenting` 금액 선례는 「출산축하금 50」·「출산축하 용품 10」 뿐이라 **1000 은 20배 규모의 이상치**다. 근거는 확실하다(C 명시 + D 교차 확인, 공식 도메인 2곳). 채택 근거는 코퍼스 규약이 **1회성 출산축하금도 명시액 그대로 AMT 에 넣어 왔다**는 점이다. 다만 이 값은 **연 환산액이 아니라 자녀 1인당 1회성**이라, 금액 순위·연간 합계 화면에서 KAI 를 실제보다 후하게 보이게 만들 수 있다. 최근 CJ 주택자금 대출 한도 사건(연간 환산 칸에 비연간 값이 들어간 사례)과 같은 계열의 위험이다. **대안은 `AMT NULL` + `QUAL_DESC` 에 1,000만원 기재**이고, 그렇게 뒤집으면 KAI 는 금액 stated 0건이 된다. 판단을 검증 레인에 넘긴다.
2. **34행이 계약 목표 12~25를 넘는다** — 세 공식 출처의 합집합이라 억지로 늘린 행은 없지만(행마다 원문 불릿이 1:1), 형제 회사 최대치가 29행(삼성ENA)이라 상단 이상치다. 줄여야 한다면 근거가 가장 얇은 순서는 ① `lounge`(수유실·휴게실) ② `snack_bar`(사내 편의시설) ③ `clinic`(의무실·물리치료실) ④ `pc_off`(D 한 문장 안의 한 단어) 다. 넷 다 원문 근거는 있으나 라벨뿐이고 설명이 없다.
3. **`holiday_gift` 카테고리** — compensation 으로 넣었으나 코퍼스가 compensation 23 / perks 12 로 갈린다(§6). 「명절/창립기념일 선물」 선례만 보면 perks 가 맞다.
4. **「양성평등상담」 제외** — A 29항목 중 **유일하게 행이 되지 않은 항목**이다(§8). 법정 의무 이행 창구라는 판단인데, 회사가 복리후생 카드에 넣어 게시한 항목을 우리가 뺀 것이라 이견이 있을 수 있다.
5. **`lounge` 에 들어간 수유실** — 가족친화 인증 기업의 수유실을 work_env 로 분류했다. family 축으로 옮기거나 별도 코드를 신설할지는 코퍼스 일관성(선례는 `lounge`·`nap_room` 서술에 수유실 병기) 대 제품 가치의 문제다. 신규 코드 신설은 계약 규칙 5 에 걸려 하지 않았다.
