## 5. 코드 매핑 판단 · 어휘 함정 회피

어휘표(85종)를 전수 대조한 뒤 매핑했다. 판단이 갈릴 수 있는 것만 적는다.

### 분리 (2건) — 어휘에 둘 다 있고 실체가 다를 때만

- **`commute_subsidy`(셔틀버스) ↔ `transport`(유류비·통행료)**: 심텍 evidence 가 세운 house rule 그대로 — **운행 자체 = `commute_subsidy`, 금전 지급 = `transport`**. 원문이 두 급부를 한 카드 안에서 **별개 문장**으로 쓰고, 셔틀버스는 화성 한정인데 유류비는 한정 표기가 없어 적용 범위도 다르다. 코퍼스에 두 코드를 함께 쓰는 회사가 **4곳**(HD현대·SK이노베이션·아이센스·원익IPS) 있다. 둘 다 금액 NULL 이라 중복 계상 위험 없음.
- **`long_service_bonus`(장기근속) ↔ `excellence_award`(성과·공로)**: 근속 기반 자동 지급과 심사 기반 포상은 성격이 다르고 어휘·코퍼스에 둘 다 있다. 심텍 선례와 동일한 분리다.

### 병합 (1건, 4항목 → 1행)

- **`excellence_award`** 에 신제품 개발 포상 · 직무발명포상 · 원가혁신과제 포상 · 모범·우수사원 포상 **4종을 묶었다.**
  - `uq_comp_benefit`(COMP_ID, BENEFIT_CD) 때문에 같은 코드 2행이 불가하고, 4종이 전부 이 코드로 귀결된다.
  - **직무발명을 신규 코드로 만들지 않은 이유**: 코퍼스에 이미 `excellence_award` = 「직무발명 보상제도」(`우수사원·직무발명자·우수제안자 포상제도 운영`) 선례가 있고, 「우수사원/연구/특허 포상」·「연구개발상」도 전부 `excellence_award` 다. 계약 규칙 5(대응 어휘가 정말 없을 때만 신규)에 걸린다.
  - 4종 이름을 `BENEFIT_NM` 에 다 넣어 비교 화면에서 내용이 사라지지 않게 했다.

### 신규 코드 (1건) — `degree_allowance`

- 근거 원문: 「**박사 학위자 별도 수당 지급**」 (S1 카드2 「추가 보상」).
- **어휘 85종 전수 대조 결과 대응 없음.** `mba`·`edu_support` 는 코퍼스 실사용이 전부 **학위 파견/학비 지원**(회사가 공부를 시켜주는 것)이고, 이 항목은 **이미 학위를 가진 사람에게 주는 수당**이라 방향이 반대다. `incentive`(연 2회 인센티브)는 같은 카드의 **다른 행**이 이미 점유했고, `bonus`·`profit_sharing` 은 성과 연동이라 뜻이 다르다.
- 카테고리 `compensation`, 길이 16자(`VARCHAR(30)` 여유), `server/models/benefit_edit.py` 의 `^[a-z][a-z0-9_]{1,29}$` 통과(실측 확인). 히트맵 `ITEM_LABEL` 은 화이트리스트가 아니라 미등록 코드를 최빈 `benefit_nm` 으로 폴백하므로 렌더가 깨지지 않는다.
- ⚠ **이 행은 판정이 갈릴 수 있다 — §9 의심 지점 ① 참조.**

## 6. 법정 제도 미수록 확인 (계약 규칙 3)

- 4대보험 · 퇴직연금(DC/DB) · 주5일 · 법정 육아휴직/육아기 단축 · 법정 출산휴가 → **두 출처 모두 언급 자체가 없다.** 행 0건.
- **연차 관련 행(`leave_general`)의 근거는 법정 연차가 아니다.** 원문은 「연차, **반차, 반반차** 제도 운영」이고, 근로기준법은 연차를 **일 단위**로 부여할 뿐 반차·반반차 분할 사용 제도를 요구하지 않는다. 회사 재량 부분(분할 사용 단위)이 원문에 명시돼 있어 그 부분만 근거로 삼았고, `QUAL_DESC` 에 「법정 연차 자체가 아니라 반차·반반차 분할 사용 단위가 회사 재량 부분이다」라고 못박았다.
- **`summer_leave`** 는 원문이 「하계휴가 **별도** 운영」이라 법정 연차와 별개임을 원문이 스스로 밝힌다 → 계약 규칙 3 의 「회사 재량 상회분」에 해당.
- **`event`** 의 경조휴가는 법정 휴가가 아니다(근로기준법에 경조휴가 규정 없음) → 수록 가능. 단 별도 행이 아니라 `event` 안에 서술로 넣었다.
- **`childcare`**(직장 어린이집)는 영유아보육법상 일정 규모 사업장에 설치 의무가 있으나, 코퍼스가 42개사에서 `childcare` 를 복지 행으로 다루고 있어 선례를 따랐다. 계약 규칙 3 의 열거 목록에도 없다.

## 9. 검증자가 봐야 할 의심 지점

① **`degree_allowance`(SORT 11) 를 복지로 볼 것인가.** 「박사 학위자 별도 수당」은 회사 자신이 복지 페이지의 「추가 보상」 카드에 올린 항목이지만, 실체는 **학위 보유자에게만 붙는 급여 항목**이다. 같은 카드의 초임(5,040만원)을 급여라고 제외했으면서 이 수당은 남긴 것이 일관적인지 판정이 필요하다. 남긴 근거는 (a) 회사가 복리후생 페이지에 게시했고, (b) 초임은 **기본급 수준**이지만 이건 기본급에 **추가**되는 급부라는 점이다. 제외 판정이면 행 1개와 신규 코드 1개가 동시에 사라져 정리 비용이 낮다. **어느 쪽이든 신규 코드가 1개사만 쓰는 축이 되는 점은 감수해야 한다.**

② **`leave_general`(SORT 21) 이 법정 연차 수록에 해당하는가.** 원문이 「연차, 반차, 반반차」로 **법정 연차를 먼저** 쓴다. 나는 반차·반반차 분할 운영만을 재량 근거로 삼아 수록했고 `QUAL_DESC` 에 그렇게 못박았지만, 계약 규칙 3 을 엄격히 읽으면 「원문이 상회 조건을 밝힐 때」의 상회 조건이 **일수 증가**가 아니라 **분할 단위**인 것이 약하다고 볼 여지가 있다. 코퍼스에는 `leave_general` = 「연차/반차/반반차」 선례가 25행 있다.

③ (참고) **2019 보조 출처를 살린 2행**(`club`·`fitness`)은 정본에 없다. 7년 된 서술이라 현재도 운영 중인지 회사 확인이 필요하고, `QUAL_DESC` 에 출처와 연도를 남겼다. 폐지 판명 시 이 2행만 지우면 된다.

## 11. 배포 시 주의

- ⚠ **회사 추가 시 정적 재생성 필수**(프로젝트 상시 함정). 적재하면 회사 상세·디렉터리·히트맵 정적 페이지를 다시 구워야 한다.
