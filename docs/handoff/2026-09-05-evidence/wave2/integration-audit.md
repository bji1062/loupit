|---|---|---|---|---|

세 코드 모두 `benefit_edit` 코드 정규식 `^[a-z][a-z0-9_]{1,29}$` 를 통과한다. 웨이브 1 은 신규 17종이었는데 이번이 3종뿐인 이유는 코퍼스가 74 → 85종으로 커져 흡수처가 늘었기 때문이고, 어휘 압력이 낮아졌다는 뜻이지 수집이 얕다는 뜻은 아니다.

### 1-2. `smart_office` — `lounge` 유지는 불가, `free_seating` 흡수는 왜곡

원문(LG이노텍 Work 섹션 #6): 「업무 상황에 따라 최적의 공간을 선택할 수 있도록 포커스 존, 스탠딩 회의실 등의 공간이 마련」 — **업무 공간**이다.

세 선택지를 코퍼스에 대고 봤다.

- **`lounge` 유지 불가.** 코퍼스 `lounge` 실측 18행의 BENEFIT_NM 은 전부 휴게실·라운지·사내카페·영화관·안마의자·복지동 등 **휴게·문화 공간**이다. 이 행이 들어가면 「LG이노텍에 휴게 공간이 있다」는, 원문에 없는 주장이 비교표에 선다. 같은 웨이브에서 넷마블 SORT 90(옥외 조경)·삼성E&A SORT 21(명상실)도 같은 `lounge` 오염이라 세 건을 한 기준으로 처리해야 한다(§2 I-2).
- **`free_seating` 흡수 부적합.** 코퍼스 유일 행은 HD현대 「자율좌석제」이고 근거 문장이 「개인별 좌석을 지정하지 않고」다. LG이노텍 원문은 **좌석 미지정을 말하지 않는다** — 공간 유형 선택이지 좌석 정책이 아니다.
- **`work_tools`·`office_furniture` 부적합.** 둘 다 장비·가구 축이고 원문은 공간이다(수집기 기각 사유 타당).
- **삭제(19행) 차선.** 비교축 손실은 없다. 다만 원문에 있는 실제 제도를 잃는다.

**판정: `smart_office`(work_env) 신설.** 비용을 직접 확인했다 — 코퍼스 코드는 SQL 밖 어디에도 등록되지 않는다(`free_seating`·`workation`·`blood_bank`·`car_wash`·`nap_room` 전부 `db/seed/benefit/sql/` 밖 참조 **0건**, `lounge` 만 테스트 픽스처·디자인 목업에 등장). 웨이브 1 이 `free_seating`·`workation` 을 1개사 코드로 신설한 것과 같은 논리이고, 스마트오피스는 후속 대기업에서 재현될 제도다.

```
SORT 30: 'lounge' → 'smart_office'   (카테고리 work_env·BENEFIT_NM·QUAL_DESC 그대로)
```

### 1-3. 기각한 두 코드의 정보 보존

- 동진쎄미켐: SORT 11 행 삭제 후 SORT 10 `incentive` 서술을 그대로 둔다. 「박사 학위자 수당」을 QUAL_DESC 에 남기면 **급여를 복지로 옮긴 것과 같아지므로 넣지 않는다**(`_ACTIONS.md` 초안의 「미수록」 한 구절 추가안은 §9 편집 주석 금지에도 걸린다 — **채택하지 않음**).
- 이수페타시스: SORT 51 행 삭제. 회사 확인으로 「재직 장애인·보훈대상자 대상 수당/휴가」임이 밝혀지면 그때 코드를 연다.

### 3-1. 앵커 반복은 백필 M-4 강등 대상이 아니다

넷마블 두 값이 코퍼스 앵커와 겹치지만 **복사가 아니다**. 250 은 원문이 연액으로 못 박았고(웰니스 페이지 명시값), 240 은 원문 월 20만원의 산술 환산이다. 겹치는 이유는 업계 표준값이기 때문이다 — 코퍼스 `welfare_point` 는 200 이 33행, `meal` 은 432(월 36만원)가 43행으로 이미 값이 뭉쳐 있다. 근거가 원문에 있으므로 M-4 강등 사유 없음.

### 3-2. KAI 1000 — 1회성 지급액을 AMT 에 넣는 것은 코퍼스 규약과 같다

코퍼스 AMT 631행에는 연 환산이 아닌 1회성 지급이 이미 섞여 있고, `generator/corpus.py:16` 이 그 사실을 명시적으로 인정한다. 같은 `parenting` 코드 안의 선례가 결정적이다.

전부 1회성이고 전부 AMT 에 들어가 있다. **KAI 1000 은 같은 축 안의 동종 비교다.**

CJ 5개사 사건(`b181314`)과는 성격이 다르다. 그쪽은 **대출 원금 한도**가 금액 칸에 들어간 것이고(규칙 4 가 명시적으로 금지하는 유형), 이쪽은 회사가 두 공식 페이지에 못 박은 실지급액이다. 이번 웨이브의 `housing_loan` 8행이 전부 AMT NULL 인 것도 그 함정을 제대로 피했다는 증거다.
