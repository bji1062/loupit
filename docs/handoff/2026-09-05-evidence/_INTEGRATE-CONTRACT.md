# 웨이브 2 통합 계약 (W-3/W-4 — SQL 수정자, Opus ×1) — 2026-09-05

목적: 검증(verify 13건)·감사(integration-audit.md §5·§9) 판정을 시드 SQL 13개에 **행 단위로 반영**해 리포 `db/seed/benefit/sql/` 에 최종본을 쓴다. 판단은 이미 끝났다 — 수정자는 **조치 목록을 그대로 집행**하고, 목록끼리 충돌하거나 원문이 애매한 곳만 「보류」로 보고한다.

## 입력
- 스크래치 원본(수정 금지 — 보관용): `…/scratchpad/wave2/<파일>.sql` 13개(LOGO_NM·INDUSTRY_NM 은 이미 교정됨)
- 조치 정본: `…/scratchpad/wave2/integration-audit.md` §5(회사별 행 조치)·§9(편집 주석 대체 문안) → 이것이 1순위. 감사가 다루지 않은 세부는 `…/scratchpad/wave2/verify/<회사>.verify.md` 의 「조치 권고」 열과 `…/scratchpad/wave2/_ACTIONS.md` 로 보완.
- 형식 정본: `docs/handoff/2026-09-05-evidence/_COLLECT-CONTRACT.md` 산출물 절(행 형식·카테고리 9종·SORT 10단위·따옴표 금지·코드 UNIQUE).

## 출력
- `db/seed/benefit/sql/<파일>.sql` 13개(파일명은 스크래치와 동일: LG이노텍·넷마블·대덕전자·동진쎄미켐·삼성ENA·삼성SDS·삼성중공업·삼성화재·삼양식품·셀트리온제약·이수페타시스·한국항공우주산업·한화생명)
- 각 파일 헤더 `-- 참고:` 끝에 「⚠ 검증·감사 판정 반영(2026-09-05): …」 한두 줄(무엇을 삭제·병합·재코딩했는지 — 심텍.sql 선례)
- 보고: 회사별 최종 행 수 표 + 합계 + 보류 목록

## 집행 규칙
1. **삭제**는 행 튜플 전체 제거 후 SORT 를 다시 매기지 않는다(구멍 허용 — 선례). 마지막 행의 `,`/`)` 처리로 문법을 깨지 말 것.
2. **병합**은 남는 행의 QUAL_DESC 에 흡수되는 제도의 원문 문구를 덧붙이고(「/」 구분 금지 — 「·」 또는 문장), BENEFIT_NM 은 필요하면 병기.
3. **재코딩**은 코드·카테고리·SORT 섹션을 함께 옮긴다(카테고리별 10단위 섹션 규칙).
4. **편집 주석 일소**: QUAL_DESC_CTNT·NOTE_CTNT·BENEFIT_NM 에서 「코퍼스」「선례」「어휘표」「규칙」「수집기」「검증」「병합」「미수록」「회피」「흡수」「정본」「판독」「시드」「SI-B2」「별도 행」「합쳤다」「수록」「정성 항목」「부연」「우리 판단」「⚠」 등 내부·공정 용어를 없앤다. 허용 문안은 **원문 라벨 + 출처 페이지명(「공식 채용 페이지 … 항목」 등) + 조건 + 미기재 사항**뿐. 감사·verify 가 준 대체 문안이 있으면 그대로, 없으면 같은 정책으로 최소 수정.
5. **금지**: 새 행 추가(MISSED 반영도 감사가 「흡수」로 지시한 경우 기존 행 서술에만), 금액 변경(감사 §3 지시 외), 홑·겹따옴표(아포스트로피는 U+2019 ’), 코드 중복.
6. 13파일 다 쓴 뒤 `python3 …/scratchpad/wave2/_precheck.py` 를 **리포 경로로 바꿔** 실행(글롭을 `db/seed/benefit/sql/` 의 13파일로) — 분할기 5문장·중복 0·카테고리·따옴표 통과 확인 후, 편집 주석 키워드 재스캔 0 확인.
7. 리포의 다른 파일은 건드리지 않는다(핀·등록 접점은 리드가 처리). 구본(삼성카드·유진테크 편집 주석 2행)도 이번엔 건드리지 않는다.
