## ③ robots 허용 — **전면 허용, AI 봇 차단 없음**

`https://www.lginnotek.com/robots.txt` (HTTP 200, **21 bytes**, `text/plain; charset=UTF-8`):

```
User-agent: *
Allow:/
```

- 그룹은 `*` **하나뿐**이다. Disallow·Crawl-delay·Sitemap 지시 전부 없음.
- ClaudeBot / anthropic-ai / GPTBot / CCBot / Google-Extended 를 **명시적으로 차단하는 줄이 없다** → 전부 `*` 그룹 적용 = `/recruit/worklife.lgit` 허용. (네패스 선례 같은 AI 봇 표적 차단 없음)
- **BOM 없음** (첫 바이트 `U`). `Allow:/` 는 콜론 뒤 공백이 없는 표기 — 공백을 요구하는 엄격한 파서를 쓰면 이 줄을 놓칠 수 있다.
- `sitemap.xml` 은 **404**(196B, iso-8859-1 오류문서). 사이트맵 경유 발견 경로는 없다.

**실측 UA 테스트** — 7종 전부 HTTP 200, 응답 바이트 **85,100 으로 완전 동일**(UA별 콘텐츠 차등 없음):

## 수집 설계 시 유의 (수집·SQL은 이번 범위 밖)

1. ⚠ **HTML 주석 유령 4건.** `worklife.lgit` 안에 예전 버전 Life 블록이 `<!-- ... -->` 로 남아 있다(2,056 bytes). 주석 안 항목은 `<h3>` 가 아니라 `<h2>` 를 쓰고 **설명문이 현행과 다르다** — 종합건강검진에 "**연 1회**", 본인/가족 의료비에 "**단체보험 및** … **실손** 의료비". 주석을 안 걷고 태그만 제거하면 **20개가 24개가 되고 4건은 옛 문구와 충돌**한다. 파싱 첫 단계에서 반드시 주석 제거.
2. **셀렉터는 `<h3>` 로 고정.** 주석 제거 후 페이지 전체 `<h3>` 20개 = 복지 항목 20개로 정확히 일치한다. 카테고리는 직전 `<h2>`(`Work` / `Life`)로 잡으면 된다. 클래스명(`articleLifeWrap art1/art2`, `textForm`)에 의존하면 리뉴얼에 약하다.
3. **`www.` 필수.** apex `lginnotek.com` 은 NXDOMAIN 이고, DART `hm_url` 의 `.co.kr` 은 HTTPS 핸드셰이크 실패 + HTTP 403 으로 완전히 죽었다. 수집기 기본 도메인을 `.co.kr` 로 두면 조용히 0건이 된다.
4. **금액 데이터 0건.** 정성 항목으로만 적재하고 연간 환산 칸은 비운다. 대신 설명문이 항목마다 있어 본문 분량 기여는 좋은 편(항목당 1~2문장).
5. **설명문 안 `<br class="mobNone">` 을 공백으로 치환**해야 문장이 붙지 않는다. 그대로 태그 제거하면 "…범위에서근무시간을" 처럼 단어가 엉킨다.
6. TLS 만료 **2027-01-08** — 그 이후 재수집 시 인증서 갱신 여부 확인.
