- `https://shinhan.recruiter.co.kr/robots.txt` → 200, BOM 없음. `Allow: /` · Disallow `/*/attachFile`, `/attachFile*`, `/bbs*`, `/resources*`, **`/app*`**. → `/career/*` 는 허용이지만 **채용공고 목록 `/app/jobnotice/list` 는 robots 금지**(가져오지 않았다).

## 결론

지주 법인에 대해 **공식 출처 기반 복지 수집 불가**. 하나금융지주·우리금융지주와 같은 구조이고, KB금융처럼 지주 법인을 채용 주체로 노출하는 그룹 채용사이트가 신한에는 **존재하지 않는다**. 신한은행 복지 페이지를 지주 카드에 붙이면 법인 불일치(배지 계보 오염)다. 재시도 조건은 둘 중 하나:

1. shinhangroup.com 에 채용/복리후생 메뉴가 신설될 때(현재는 채용 대분류 자체가 없음), 또는
2. 지주 카드가 아니라 **신한은행 법인**을 별도 등록하고 헤드리스 렌더로 `shinhan.recruiter.co.kr/career/welfare_` 본문을 확보할 때(그때도 출처 도메인이 `recruiter.co.kr` 서드파티 ATS 라는 점을 표기해야 하고, `/app*` 은 robots 금지라 공고 목록은 건드리지 말 것).

## 수집 설계 시 유의

1. **robots 그룹 파싱 함정**: shinhangroup.com 은 AI 봇 UA 9종을 나열한 뒤 `*` 까지 같은 레코드에 묶고 `Allow: /` 를 준다. UA 줄 단위로 그룹을 끊는 파서는 「AI 봇 명시 차단」으로 정반대 판정을 낸다.
2. **404 가 43KB 로 온다**: 이 사이트는 경로 탐색 시 본문 크기가 커도 404 다. HTTP 코드로만 판정하고 크기 휴리스틱(<2KB=차단)을 쓰지 말 것.
3. **법인 경계**: `shinhan.recruiter.co.kr`(은행) / `shinhands.recruiter.co.kr`(DS) / `recruit.shinhansec.com`(투자증권) / `shinhancard.com`(카드)은 각각 다른 상장·비상장 법인이다. 「신한」 접두사만 보고 지주로 귀속시키면 안 된다.
4. `group.shinhan.com` 처럼 **DNS 는 살아 있는데 443 이 refused 인 유령 호스트**가 있다. DNS 생존만으로 후보를 채택하지 말 것.
5. 재시도 시 확인 지점은 딱 하나 — **shinhangroup.com 전체 메뉴에 채용 대분류가 생겼는지**. 그전까지는 어떤 렌더러를 붙여도 항목 0이다.
