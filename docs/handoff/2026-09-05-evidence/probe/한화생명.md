## ③ robots 허용 — **전면 허용, AI 봇 별도 차단 없음**

`https://company.hanwhalife.com/robots.txt` (HTTP 200, 81 bytes):

```
User-agent : *
Allow : /

Sitemap : https://company.hanwhalife.com/sitemap.xml
```

- **BOM 없음.** 대신 파일 **첫 바이트가 개행(`\n`)** 이고 `User-agent`/`Allow` 뒤에 공백을 낀 콜론(`User-agent : *`)이라는 비표준 표기다. Python `urllib.robotparser` 로 실측한 결과 `*`·ClaudeBot·anthropic-ai·GPTBot·CCBot·Google-Extended 전부 `can_fetch=True` — 파싱은 무사하다.
- Disallow 0건, Crawl-delay 없음. AI 봇 UA 를 겨냥한 별도 그룹이 없다.
- 참고: `www.hanwhalife.com/robots.txt` 도 `User-agent: *` / `Allow:/` 전면 허용(BOM 없음, Sitemap `sitemap_index.jsp`). 다만 그쪽엔 복지 페이지가 없다.

## 수집 설계 시 유의 (수집·SQL은 이번 범위 밖)

1. **도메인을 틀리면 0건이 나온다.** DART `hm_url` 계열로 잡히는 `www.hanwhalife.com` 에는 채용·복지 메뉴가 없고, 그 도메인은 OpenSSL 3 기본 설정에서 TLS 실패(exit 35)까지 난다. 정본은 `company.hanwhalife.com` 이며 이쪽은 TLS 정상이다. 수집기가 www 만 보고 "복지 미기재"로 오판하지 않게 시작 URL 을 고정할 것.
2. **`benefit` 이라는 단어에 속지 마라.** `www.hanwhalife.com/main/benefit/...`, `/static/main/benefit/...` 는 전부 **보험 고객 대상 혜택**(건강·할인·웰니스) 페이지다. 임직원 복지와 이름만 같다. 경로 키워드로 긁으면 고객 혜택이 복지 카드로 들어간다.
3. **쉼표 분할은 5블록 중 3블록에서만 맞다.** 02·03·04 는 쉼표 나열이라 분할이 통하지만, 01 「카페테리아 플랜」은 설명 문장 안의 쉼표 때문에 4조각으로 찢어지고 05 도 깨진다. 01·05 는 카테고리 자체를 1~3개 항목으로 수동 매핑해야 한다. 셀렉터 `p.welfare-num + strong + span` 은 안정적이니 분할만 조심하면 된다.
4. **법정 제도 2건을 걷어내라.** `4대보험`(생활안정지원)과 `출산 & 육아휴가 제도`(모성보호지원)는 법정이라 프로젝트 규칙상 미수록이다. 18개 중 16개가 실제 등록 대상이다. 금액은 전 항목 0건이므로 전부 정성 항목으로 넣는다.
5. **`복지제도 더보기` 버튼을 따라가면 안 된다.** `<a href>` 가 아니라 JS `<button>` 이고, 클릭하면 `https://www.hanwhain.com/` **루트**가 새 창으로 뜬다. 그룹 통합 채용 플랫폼이며 Vue SPA 라 원본 HTML 이 비어 있고, 한화생명 계열사 상세 페이지에도 복지 항목이 0개다. 그쪽에서 얻을 것이 없다.
6. **갱신 감지는 `lastmod` 로 하면 안 된다.** `sitemap-ko.xml` 의 37개 URL 이 전부 조회 당일 날짜(2026-09-05)를 달고 나온다 — 동적 생성값이지 실제 수정일이 아니다. 본문 바이트 해시로 비교할 것.
7. **FP 위촉직 처우와 절대 섞지 말 것.** 한화생명금융서비스(주)는 별개 법인이고 자기 도메인(`hanwhalifefs.com`)에 「Financial Planner / FP 지원·등록」 페이지를 따로 갖고 있다. 배지 계보 오염 위험이 여기다.
