## 수집 설계 시 유의 (수집·SQL은 이번 범위 밖)

1. **⚠ 최대 함정 — `koreaaero.recruiter.co.kr/career/welfare` 는 마켓컬리 템플릿 오염이다.** sitemap.xml 에 등재돼 있고 HTTP 200 에 KAI 도메인·KAI GNB 를 달고 있지만, 본문은 ATS 빌더의 **컬리 샘플 데이터 그대로**다("마켓컬리 임직원 적립금 지급", "컬리만의 아이덴티티가 담긴 웰컴키트", "브랜드디자인 그룹 김성진", "팀 또는 기업에 대한 소개를 입력합니다"). **정본은 `/career/benefits` 하나뿐이다.** sitemap 을 크롤 시드로 쓰면 남의 회사 복지 10건이 KAI 카드에 그대로 박힌다. 같은 사이트맵의 `home(1)`·`home2`·`ideal(1)`·`process(1)`·`faq78` 등 중복 슬러그도 전부 미완성 사본 의심 대상이니 화이트리스트로만 접근할 것.
2. **HTML 스크래핑만으로는 A·B 에서 0건**이 나온다. 29개는 PNG 안이고 `alt` 는 카테고리 하나짜리("복리후생제도")라 **이미지 판독이 유일한 경로**다. 텍스트 파싱만 돌리고 "복지 미기재 회사"로 오판하지 말 것 — 심텍과 같은 유형이되 이미지가 1258×2510 한 장이라 **분할 판독**이 필요하다(가로 폭 전체, 세로 4등분 정도가 읽기 좋다).
3. **소스 3개의 항목 집합이 서로 다르다.** A(29) ⊃ B(10) 이 아니고, C(12)에만 있는 항목(유연근무제·학위취득 지원·연차 22일·피트니스)이 있으며 B 에만 있는 항목(퇴직예정자 지원 제도의 창업·재취업·여행·귀농·재무, 해외연수)도 있다. **A 를 기준 골격(5카테고리)으로 삼고 C·D 의 텍스트로 설명·금액을 덧붙이는 병합**이 항목 수와 본문 분량 모두에서 최선이다. 병합하면 중복 제거 후 대략 35개 안팎이 된다.
4. **C 는 렌더 없이는 못 얻는다.** 페이지 콘텐츠는 `https://infra1-static.recruiter.co.kr/builder/recruiter/<YYYY/MM/DD>/<uuid>.json` (65KB) 에 항목명·설명이 전부 들어 있어 curl 로 바로 받을 수 있지만, **그 URL 을 알아내는 경로가 `api-recruiter.recruiter.co.kr/design/v2` 인데 브라우저 밖에서는 Referer 를 맞춰도 500(NullPointerException)** 이다. 즉 JSON URL 은 런타임에만 발견되고 날짜·UUID 라 하드코딩하면 개정 즉시 깨진다. **Playwright 렌더 후 DOM 텍스트를 뽑는 쪽이 안정적이다.**
5. **URL·robots 함정 넷을 배선에 반영할 것**: ① apex 는 타임아웃이니 항상 `www.`, ② 생존 확인을 `HEAD` 로 하면 302 가 온다(GET 로 판정), ③ `robots.txt` 가 200 짜리 **에러 페이지 HTML** 로 돌아오므로 robots 파서가 그걸 규칙으로 읽으면 안 된다(302 + `Content-Type: text/html` 이면 robots 없음으로 취급), ④ 페이지 HTML 에 주석 처리된 GNB 잔해가 29덩이·5KB 있으니 **주석 제거 후 파싱**.
6. **갱신 감지**: A 의 이미지 파일명에 개정일이 박혀 있다(`WelfareSystem_cont01_v260723.png`) — 개정되면 **URL 자체가 바뀐다.** 반대로 B 는 `5.png` 고정에 `?ver=` 조차 없어 내용이 바뀌어도 URL 이 그대로다. **A 는 페이지 HTML 에서 img src 를 매번 다시 읽고, B 는 바이트 해시로 비교**해야 한다.
7. TLS 인증서가 **2026-10-20 만료**다. 그 이후 재수집 때 검증 실패가 나면 우리 쪽 문제가 아닐 수 있으니 먼저 인증서를 확인할 것.
