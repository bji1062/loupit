### 자기 도메인(samsungsds.com)에는 채용·복지 페이지가 없다 — 확인 근거 4가지

1. `recruit.samsungsds.com` · `careers.samsungsds.com` **둘 다 NXDOMAIN**(DNS 미등록). 채용 전용 서브도메인 없음.
2. `https://www.samsungsds.com/kr/sitemap.xml` 의 **loc 3,181개 전수 스캔** — `career|recruit|welfare|benefit|talent|job` 매칭은 전부 insights/techreport 마케팅 글이고 채용 섹션 자체가 없다. 최상위 디렉터리 분포는 news 1,230 · insights 1,041 · event 165 순이고 `company` 는 **6개뿐**(overview·vision·ceo·history·award·global_offices).
3. 홈(`/kr/index.html`, 91.8KB)과 회사소개 페이지의 링크·GNB 스크립트(`/resource/kr/js/header_ko_26.js`)를 전부 grep 해도 `채용|career|recruit` 링크가 **0건**.
4. 역으로 그룹 사이트의 삼성SDS 페이지가 자기 도메인을 **가리킨다** — 「홈페이지 `https://www.samsungsds.com`」, 직무 더보기 버튼 `onclick="location.href=https://www.samsungsds.com"`.

## ③ robots — **차단 없음. 단 두 도메인의 상황이 다르다**

**samsungcareers.com (정본 도메인): robots.txt 부재**
- `https://www.samsungcareers.com/robots.txt` → **302 → `/sub/etc/error.html`**, 본문은 `{"code":500,"status":999,"message":"Internal server error"}` 59바이트. apex 도 301→www 후 동일.
- 즉 **soft-404**. robots.txt 가 없는 것과 같으므로 기본 허용. `sitemap.xml` 도 302(오류 페이지). BOM 판정 대상 없음.

**samsungsds.com (자기 도메인): 11,276바이트 robots.txt, AI 봇을 이름으로 허용**
- `User-agent: *` → `Allow: /`. Disallow 는 `/*/search/`, `/*/gartner/`, `/cn/*`, `/module_src/*`, `/*.txt`, 테스트 페이지 다수. **BOM 없음**(첫 바이트 `User-agent`), 줄바꿈 CRLF.
- 「AI CRAWLERS — AEO / GEO」 블록에서 **ClaudeBot·Claude-SearchBot·GPTBot·OAI-SearchBot·Google-Extended·CCBot·PerplexityBot·Applebot·FacebookBot·cohere-ai·YouBot 을 전부 명시적으로 Allow** 한다(공통 예외는 `/*/search/`, `/module_src/*` 정도). AI 인용을 **환영하는** 방침이 robots 에 문서화돼 있다.
- 정본이 이 도메인에 없어서 실익은 없지만, 회사정보 탭용 보조 수집을 할 때는 걸림돌이 전혀 없다.

## 수집 설계 시 유의 (수집·SQL은 이번 범위 밖)

1. **출처 표기에 도메인 불일치를 반드시 반영한다.** 정본이 `samsungcareers.com`(그룹 공통 채용사이트)이지 `samsungsds.com` 이 아니다. 배지 계보상 「공식」으로 잡되, 출처 URL 은 법인 전용 경로 `/subsid/detail/C60` 을 쓰고 그룹 공통 `/insight/welfare` 는 **절대 섞지 않는다** — 그쪽은 26개 관계사 공통이라 붙이는 순간 법인 오염이다(문구 자체가 "회사별", "사별로 대출상품 연계"라고 갈라 말한다).
2. **`C60` 코드가 갱신 감지의 급소다.** URL 에 회사명이 없어 코드가 바뀌면 조용히 다른 법인 페이지를 긁게 된다. 재수집 시 본문에 `삼성SDS` 와 `sdsjobs@samsung.com` 이 있는지 **먼저 검증**한 뒤 파싱할 것.
3. 파서는 `#a6` 섹션 안에서 `h3` = 카테고리, `button.tag.tip` = 항목으로 잡고 항목명은 **버튼의 첫 텍스트 노드**만 취한다. `textContent` 를 통째로 쓰면 뒤에 붙은 `<span>` 설명이 항목명에 딸려 들어와 "의료비 지원임직원 본인, 배우자…" 같은 합성 라벨이 생긴다. 설명은 `data-tip` 에서 따로 뽑는 게 안전하다.
4. **금액이 하나도 없다** → 전 항목 정성 처리. CJ 5개사 주택자금 사례처럼 "일부 지원"을 금액 칸에 끌어들이지 말 것.
5. 사업장 한정 문구("대규모 사업장(잠실, 상암 등)", "(잠실/판교)")는 원문 그대로 보존한다. 잘라내면 전 사업장 공통 제도인 것처럼 과장된다.
6. TLS 인증서가 **2026-11-09 만료** → 그 이후 재수집 시 검증 실패 가능성 점검. CDN(CDNetworks) 뒤라 인증서 CN 은 `support100.cdnetworks.net` 이고 SAN 으로 도메인이 잡힌다.
