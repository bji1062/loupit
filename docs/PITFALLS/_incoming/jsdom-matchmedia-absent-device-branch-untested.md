# 🚨 jsdom 에는 `matchMedia` 가 없다 — 기기 분기는 "테스트가 있어도 없는 것"이 된다

`trending.js` 의 `prefersReducedMotion()` 은 2026-07 부터 있었고 테스트도 697개가
초록불이었지만, **그 분기의 참(true) 쪽은 한 번도 실행된 적이 없다.**

`trending.test.js` 는 `globalThis.window = dom.window` 만 세팅한다. 모듈은 베어 전역
`matchMedia` 를 보는데 그건 세팅되지 않았고, jsdom 은 `window.matchMedia` 를 주더라도
**항상 `matches: false`** 를 답한다(레이아웃이 없으니 미디어 조건을 평가할 수단이 없다).
그래서 `typeof matchMedia === 'function'` 이 거짓 → 함수는 언제나 `false` 반환 →
스위트 전체가 **데스크톱·모션 허용 분기 하나만** 검증한다.

터치 오조준 결함(§3-7)이 2026-07-31 부터 2026-08-27 까지 살아남은 이유가 이것이다:
"호버가 없다"가 결함의 성립 조건인데, 테스트 환경은 언제나 호버가 있는 척했다.

- **탐지**: 미디어 쿼리·기기 능력(`matchMedia`·`navigator.maxTouchPoints`·
  `PointerEvent.pointerType`)을 읽는 코드에서 **분기의 양쪽이 각각 실행되는 테스트가
  있는지** 세라. 한쪽만 있으면 그 기능은 미검증이다. 커버리지 숫자는 이걸 못 잡는다 —
  줄은 밟히지만 조건은 늘 같은 값이다.
- **수정**: 전역을 명시적으로 스텁하고, 스텁이 다음 describe 로 새지 않게 DOM 부트스트랩
  헬퍼에서 지운다(`delete globalThis.matchMedia`). 2026-08-27 `trending.test.js`
  `setPrimaryInput('touch'|'mouse')` 참고.
- **부류**: 함정 ㉙("0건은 부재의 증거가 아니라 무증거")의 테스트 판.
  **초록불은 "그 코드가 옳다"가 아니라 "우리가 시킨 조건에서 옳다"만 말한다.**
  기본값이 한쪽으로 고정된 환경(jsdom·헤드리스·CI)에서는 반대쪽이 조용히 사라진다.
- **관련**: HANDOFF-2026-07-31 §2 부수교훈("우리 방어가 우리 진단을 막았다")과 같은
  모양 — 검증 도구의 성질이 검증 대상을 가린다. 이번 결함도 Playwright 클릭 타임아웃
  이라는 **도구의 고장**으로 먼저 드러났지 테스트로 드러나지 않았다.

## 곁가지: 모바일 전용 결함은 "숨은 것"이 아니라 "볼 수 없던 것"이었다

터치에서 이 위젯은 10개 중 **1개만** 도달 가능했다(펼칠 호버가 없다). 오조준보다 이쪽이
더 큰 기능 손실인데도 아무 기록이 없었다 — 접힘/펼침을 호버로만 설계하면 모바일에서
무엇이 사라지는지 데스크톱에서는 보이지 않는다. 모바일 우선 사이트에서 호버를 **유일한**
상태 전환 수단으로 쓰지 마라.
