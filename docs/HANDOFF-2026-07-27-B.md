## 1. 이 세션에서 한 일

### 1-1. §3-A 메일 레이트리밋 배선 (라이브 적용 완료)

`SPEC/11` 이 `loupit_mail` 존을 13회 명세했으나 `/etc/nginx` 전체에 **0건**이었다. Resend 실전환
직전이라 이대로 켜면 단일 IP 로 분당 300통 — 무료 티어 20초 소진 + 도메인 평판 손상.

공격 경로(실측): `POST /members/login-code` 는 세션 불필요, `require_csrf` 는 공개 상수 헤더의
**존재만** 검사, 앱 쿨다운은 이메일 해시 스코프라 **주소를 바꾸면 안 걸린다** → IP 상한이 유일한 방어.

배선한 것:
- `conf.d/loupit-limits.conf` — `loupit_mail` 존 `3r/m`
- `loupit.conf`·`loupit-beta.conf` — 메일 2종에 `=` 전용 블록(`loupit_api` 이중 + `X-Loupit-Client` 재선언)
- `loupit-beta.conf` — `limit_req_status 429` + `^~ /api/v1/` 에 `loupit_api`
  ↳ **beta 에는 `limit_req` 가 하나도 없었다.** M9 가 켜져 실메일이 나가는 유일한 호스트가
    프로덕션보다 방어가 약했다.

**실측 검증**: 무헤더 `403` / prod 헤더포함 6연속 `404·404·404·429·429·429` / 21초 후 토큰 회복
`204` / 베타 페이지·자산 무회귀 / `SMOKE PASS`

> 🚨 **사고를 하나 막았다**: 라이브 `loupit-beta.conf` 에는 리포에 없는 M9 클린 URL 블록 5개
> (`/login`·`/mypage`·`/verify`·`/edit`·`/edits`)가 있었다. 통째 복사했으면 e2e 대상 로그인
> 페이지가 전부 404 였다. → 리포로 역이식 + 파일 상단에 "통째 복사 금지" 경고 추가.

### 1-2. §3-B Resend 실메일 전환 (완료)

**핸드오프 A 의 §3-B 2번이 부정확했다.** `loupit-beta-api` 는 `server/.env` 가 아니라
**`server/.env.beta`** 를 `EnvironmentFile` 로 읽는다. 다만 pydantic `env_file` 이 항상
`server/.env` 를 보고 `.env.beta` 에 `MAILER_MODE`·`SMTP_*` 가 없어 **결과적으로는 `server/.env`
값이 적용**된다(우선순위 실측: 프로세스 env > `.env` 파일).

`server/.env` 쪽을 바꾼 이유 — `.env.beta` 에만 넣으면 나중에 prod M9 를 켤 때 `MAILER_MODE` 가
`console` 로 남아 **인증코드가 평문으로 journald 에 쌓인다**(코드가 명시적으로 경계하는 실패 모드).
prod 는 `validate_mail_config` 가 `m9_enabled` 부재 시 즉시 반환하므로(`main.py:97-98`) 무영향.

절차: `.env` 수정 **전에** 발송 선검증(`MAILER_MODE=smtp python3 infra/deploy/verify_mail.py <주소>`,
6단계 전부 통과) → `.env` 전환 → bash `source`·python-dotenv **양쪽 파싱 검증**(§2-4 ① 함정,
`SMTP_PASS` 36자 유실 없음) → `loupit-beta-api` 재시작 → e2e.

**e2e 결과**: `204` / `ConsoleMailer` 누적 로그 **15건 → 15건(증가 0)** / `"인증 코드 메일 발송 실패"`
로그 **0건** / `TAUTH_CODE` 행 생성(해시 64자만, 평문 없음, 5분 TTL) = SMTP 경로 확정.

## 3. 남은 작업 (우선순위 순)

### P1 — 메일 경로 마무리

1. **기업 게이트웨이 수신 확인** (미완). 개인 메일(gmail)은 도달 확인했으나 `@samsung.com` 같은
   **기업 게이트웨이가 실제 위험**이다. 사용자에게 회사 주소를 받아 `verify_mail.py <주소>` 로 확인.
   실패하면 DMARC 레코드 추가·전용 서브도메인 검토가 다음 수순.
2. **DMARC 레코드 부재**. 현재 SPF·DKIM 만 있다. `_dmarc.jobcho.wiki` TXT 미설정 — 기업
   게이트웨이 통과율에 직결된다. 가비아에서 `v=DMARC1; p=none; rua=...` 부터 시작 권장.
3. **배달주소 기준 일일 상한 미구현**(§1-3 의 정직한 상한). 쿨다운은 창당 1통을 허용하므로
   한 수신함 기준 `86400/60` = **1,440통/일**은 여전히 가능하다. 낮추려면 `mail_resend_cooldown_sec`
   상향 또는 별도 카운터가 필요(리텐션 퍼지가 `TAUTH_CODE` 행을 지워 행 카운트로는 못 셈).

### P2 — M9 공개 경로

4. **`m9-frontend` → `main` 병합 시점**(이전 세션부터 미결). 병합하면 beta docroot 드리프트가
   해소되고 `loupit-beta.conf` 의 "통째 복사 금지" 경고를 지울 수 있다.
   정정: "병합 = M9 공개"는 과대평가 — prod nginx 에 `location = /login` 류가 **없어** 클린 URL 은 404.
5. **prod M9 활성화**. `server/.env` 에 `M9_ENABLED=1` **한 줄**이면 즉시 실메일 경로가 열린다
   (nginx 리밋은 이미 선배포됨 — 그게 선배포한 이유). 단 그 전에 **정책 문안**(약관 T5·개인정보 P7,
   SP-POL)과 **pepper 3종 주입**(NFR30, `session_hash_pepper`·`comp_email_hmac_pepper`·
   `login_code_hmac_pepper` — 현재 전부 빈 문자열)이 선행돼야 한다. 체크리스트는
   `docs/HANDOFF-로그인기능-ML-A.md` §H-5.
   ⚠ pepper 를 `.env` 에 넣으면 `test_config.py::test_AU5_...` 가 또 터질 뻔했으나 `f48e19b` 에서
   구조적으로 격리했다 — 이제 안 터진다.

발송기가 된다.** `smoke.sh:7` 의 `BASE=https://jobcho.wiki` 라 지금은 prod M9 OFF(404) 덕에
우연히 안전할 뿐, prod M9 를 켜는 순간 매 릴리스마다 실제 메일이 나간다.

> 🚨 **"잘못된 이메일을 쓰면 된다"는 기준은 위험하다.** `_EMAIL_RE`
> (`server/models/member.py:14` = `^[^@\s]+@[^@\s]+\.[^@\s]+$`)는 느슨하다. 실측:
> ```
> x@example.invalid → PASS  ⚠ 발송 경로 진입(존재하지 않는 TLD 로 하드 바운스)
> a@b.c             → PASS  ⚠ 발송 경로 진입
> not-a-valid-email → REJECT 422 ✓ 안전
> smoke-no-mail     → REJECT 422 ✓ 안전
> no-mail@          → REJECT 422 ✓ 안전
> ```
> **안전한 규칙 = `@` 가 아예 없는 문자열**(예: `"smoke-no-mail"`). `@` 만 있으면 통과할 수 있다.

구현 형태: ① `X-Loupit-Client: web` 로 4연타 → 마지막 `429` ② 무헤더 1회 → `403`, 두 줄이면 충분.
`limit_req` 는 PREACCESS 라 앱이 422 를 내도 429 관측에는 영향이 없다.
⚠ 이 체크는 **러너 IP 의 prod·beta 공유 `loupit_mail` 버킷을 약 80초 비운다** — 주석에 남길 것.
이번 세션에 넣지 않은 이유: **릴리스 게이트 변경**을 사용자 검토 없이 세션 말미에 넣을 일이 아니다.

**② `.env.beta` 가 자기 메일 모드를 소유하지 않는다**
베타 프로세스의 `/proc/<pid>/environ` 키는 `M9_ENABLED` 뿐 — `MAILER_MODE`·`SMTP_*` 가 없어
**prod 소유의 `server/.env` 를 폴백으로 읽는다**. 그래서 prod 쪽 한 줄 수정이 베타를 조용히 뒤집는다
(오늘 `13:08:33` `.env` 수정 → `13:09:58` 베타 재시작이 정확히 그 사례다).
남는 실결함: **베타 테스트가 prod 발신 도메인·무료 티어 쿼터를 공유**한다 — 이번 리밋이 막으려던
"도메인 평판 손상"이 다른 문으로 열려 있다.
→ 수정안: `.env.beta` 에 `MAILER_MODE=` 를 **명시**(상속 금지). 베타 실발송 e2e 가 계속 필요하면
베타 전용 키 + 서브도메인(`no-reply@beta.…`)으로 분리. `verify_mail.py:46` 은 `mailer_mode != 'smtp'`
만 실패로 보므로 "베타는 X 여야 한다"를 표현할 수 없다 → 대상 호스트 인자 + 역방향 어서션.
（심각도 정정: 원 지적은 blocker 였으나 `server/.env` 주석과 SPEC §3.4.5 합성표가 이미 명문화하고
있어 "몰랐던 사고"는 아니다 → **minor**.）

**③ nginx `429` 에 `Retry-After` 없음** — 실측(격리 하네스, 라이브와 동일 지시자):
`HTTP/1.1 429` + `Content-Length: 178`, `Retry-After` 헤더 **부재**(178B 는 라이브 `access.log` 의
`429 178` 과 일치). `rate=3r/m` 이라 실제 대기는 **20초**인데 아무도 그 값을 모른다.
→ 메일 `=` 블록 4곳에 `add_header Retry-After 20 always;`(429 는 에러 응답이라 `always` 필수)
+ `api.js` 의 `ApiError` 에 값을 실어 "20초 뒤에 다시 시도해주세요"로 숫자 노출.

**④ logrotate `size` 상한 없음** — `daily`+`rotate 14`+`compress` 뿐. `limit_req_log_level` 기본이
`error` 라 **429 마다 `error.log` 약 231B + `access.log` 약 116B**(실측)가 쌓인다.
⚠ **이 변경 탓이 아니다** — `4fd61a2^` 에 이미 `limit_req` 4개가 있어 429→error.log 경로는 **선재**했고,
고정 공격률에서 diff 전후 로그량은 사실상 같다. 현재 총 2.5M·루트 14G 여유라 급하지 않다.
→ 운영 위생 차원에서 `/etc/logrotate.d/nginx` 에 `maxsize 200M`(라이브 파일이라 별도 승인 필요).

**⑤ 프론트 abort(8s)와 SMTP 소켓 타임아웃(8s)이 동일** — `mailer.py:30` `_SMTP_TIMEOUT_SEC=8` vs
`api.js:6` `DEFAULT_TIMEOUT=8000`. `mailer.py:26-27` 주석이 스스로 밝히듯 smtplib timeout 은 **대화
전체가 아니라 개별 소켓 연산** 상한이라 총 소요가 8s 를 넘을 수 있고, 그 순간 브라우저가 먼저 끊어
`login.js:28` 의 "네트워크 오류예요"로 떨어진다. 다만 재클릭해도 60초 쿨다운이 **실발송을 억제**하므로
추가 메일은 안 나간다 — 소모되는 건 nginx 토큰과 사용자 신뢰뿐.
→ 메일 발송 호출만 `{ timeout: 20000 }`(nginx `proxy_read_timeout 15s` 보다 길게) 또는
`_SMTP_TIMEOUT_SEC` 를 4~5 로.

#### ✅ 반증됨 — 조치 불필요 (전부 실측)

- **경로 정규화·인코딩으로 `=` 블록 우회 — 없음.** 22개 변형 실측. `//`·`/./`·`/../`·`%6C`·`%61`·
  `%2e`·`?query` 는 nginx 가 정규화해 `=` 에 그대로 매칭. `=` 를 벗어나는 7개(`…login-code/`·`%2f`·
  `LOGIN-CODE`·`;foo`·`%20`·`.`·`%09`)는 `^~` 로 가지만 앱이 **404 5건 / 307 2건**이고, 307 의
  `Location` 은 리밋되는 `=` 경로 자신이며 Starlette `redirect_slashes` 라 **엔드포인트 실행 전**이라
  메일이 안 나간다. **리밋 없이 발송에 닿는 경로 0건.**
- **`X-Forwarded-For` 로 키 흐리기 — 불가.** `/etc/nginx` 전체에 `set_real_ip_from`·`real_ip_header`
  **0건**(실측) → XFF 는 애초에 키에 반영되지 않는다. XFF·X-Real-IP·CF-Connecting-IP·True-Client-IP
  를 매 요청 바꿔 6연타 → `204 204 204 429 429 429`. 키는 TCP 피어 고정.
- **nginx 를 건너뛰고 앱 직접 타격 — 불가.** uvicorn 이 `127.0.0.1:8000`/`127.0.0.1:8001` 바인드
  (`ss -lntp` 실측), iptables 는 80/443/22 외 전부 REJECT.
- **IPv6 로 키 분산 — 불가.** 호스트에 global scope IPv6 없음, 양 도메인 `dig AAAA` 없음.
- **프론트 안내가 리밋된 엔드포인트를 다시 누르게 한다 — 오인.** `verify.js:68` 의 429 는 nginx 가
  아니라 **앱**이 낸다(`routers/employment.py:49` 코드 대조 시도 상한). 그 엔드포인트
  `POST /employment/verify` 는 `=` 블록이 아니라 `loupit_mail` 을 타지도 않는다. nginx 429 를 받는
  발송 경로는 `verify.js:44` 로 "요청이 너무 잦아요…" — 재클릭 유도 문구가 없다. **서로 다른 두 429 를
  합친 지적.**
- **`conf.d/*.bak-*` 가 include 된다 — 아니다.** 글롭이 `conf.d/*.conf` 라 `.bak-<날짜>` 는 미매칭.
  개명 시 중복 존은 `nginx -t` 가 fail-closed 로 즉시 잡는다(배포 스크립트도 `nginx -t` 게이트).

## 5. 이 세션에서 배운 함정 (반드시 읽어라)

**① `limit_req` 는 PREACCESS 페이즈다 — `return 204` 로 끝내는 location 에서는 평가되지 않는다.**
레이트리밋 테스트 하네스를 짤 때 반드시 더미 업스트림 + `proxy_pass` 를 써야 한다.
1차 측정에서 이걸로 **위양성**을 냈다("리밋이 안 걸린다" → 실제로는 하네스 결함).

**② nginx 롤백은 `reload` 의 exit 0 을 믿으면 안 된다.**
존 정의만 되돌리고 참조가 남으면 `[emerg] zero size shared memory zone` 인데, `systemctl reload`
는 **성공을 보고**하고 마스터는 **구설정으로 계속 서빙**한다. 운영자는 "롤백 완료"를 보지만 아무것도
안 바뀌었다. → `infra/deploy/rollback-nginx.sh` 를 써라(존 정합성 검사 + 워커 pid 교체 확인).

**③ `nginx -t` 는 `root` 디렉터리·파일의 존재를 검사하지 않는다.**
docroot 가 틀려도 문법은 완벽히 유효하다 → 배포 스크립트의 `nginx -t` 롤백 가드가 **못 잡는다**.
`deploy-beta.sh` 는 이제 배치 **전에** docroot 안에 실제 페이지가 있는지 직접 확인한다.

**④ 라이브 `loupit-beta.conf` 를 리포에서 통째 복사하지 마라.**
docroot 가 `/home/ubuntu/loupit-fe/web`(별도 체크아웃)이다. 반영 후 반드시
`diff <라이브> <변환본> | grep -c '^<'` = **0** 을 확인하라.

**⑤ `Settings(_env_file=None)` 은 `.env` 파일만 끊고 `os.environ` 은 못 끊는다.**
`conftest.py:36` 의 `load_dotenv` 가 배포 설정을 `os.environ` 에 붓기 때문에, "선언된 기본값"을
보려는 테스트가 **배포 상태에 따라 RED** 가 된다. 격리하려면 `monkeypatch.delenv` 로 필드명을
대문자로 뒤집어 지워라(`f48e19b` 참조).

**⑥ 이메일 정규화는 두 종류다 — 섞지 마라.**
계정 식별키(`_normalize_email`, `+태그` 보존)와 폭탄방지 배달주소키(`_delivery_address`, `+태그` 제거)는
목적이 다르다. 도트 제거는 **구글 계열 한정**이어야 한다 — 전역 적용하면 제3자가
`v.ictim@naver.com` 을 요청해 `victim@naver.com` 의 로그인을 막는 **반대 방향 사고**가 된다.

**⑦ `server/.env` 는 bash `source` 로도 읽힌다**(`release.sh:39`).
`SMTP_FROM` 은 반드시 따옴표로 감싸라 — 따옴표 없는 `<` 는 리다이렉션으로 파싱돼 그 뒤
`SMTP_PASS` 까지 통째로 유실된다. 주석(`#`)은 안전하다. `.env` 를 고쳤으면
`bash -c 'set -a; source server/.env; echo ${#SMTP_PASS}'` 로 **양쪽 파서를 다 확인**하라.

**⑧ 이 머신은 코어가 2개다.** Workflow 툴의 동시 상한이 `min(16, 코어수-2)` 라 **사실상 직렬**로
돈다(29건 반증이 기어갔다). 병렬이 필요하면 **Agent 툴로 팬아웃**하라 — 그 상한과 무관하고,
이 작업들은 CPU 가 아니라 API 대기라 2코어가 병목이 아니다(로드 0.17 관측).

---

**⑨ 메일 엔드포인트를 안전하게 시험하는 법 — `@` 가 없는 문자열을 보내라.**
beta 는 이제 실발송이라 `login-code` 에 유효한 body 를 POST 하면 **진짜 메일이 나간다**. 그런데
리밋·라우팅을 확인하려면 그 엔드포인트를 쳐야 한다. 해법: 이메일 필드에 **`@` 가 없는 문자열**
(`"smoke-no-mail"` 등)을 주면 pydantic 이 **발송 전에** 422 로 끊는다. 응답만으로 전부 판별된다 —
`429`=리밋 적용됨 / `422`=앱 도달(리밋 우회) / `404`=라우트 불일치 / `307`=슬래시 리다이렉트.
경로 정규화 우회·XFF 위조 검증을 이 방법으로 **메일 0통**에 끝냈다.

> 🚨 **"잘못된 이메일"이라는 기준은 안 된다.** `_EMAIL_RE`(`models/member.py:14`)가 느슨해
> `x@example.invalid`·`a@b.c` 는 **통과해서 실제로 발송된다**(실측). `@` 유무가 유일하게 안전한 기준이다.
> 이 문서 초판이 "잘못된 이메일 body" 라고 썼다가 검증 에이전트가 잡아 교정했다.

⚠ 또 `loupit_mail` 은 prod·beta 공유 버킷이라 **앞선 요청이 뒤 결과를 오염**시킨다. 변형을 나열해
한 번에 돌리면 첫 요청이 버킷을 먹어 나머지가 전부 429 로 보인다(1차 시도에서 실제로 오독했다) —
판정 전에 버킷 상태를 의식하고, 애매하면 20초 간격을 두거나 순서를 바꿔 재현하라.
