## 2. 🚨 이번 세션의 가장 큰 교훈 — **사양대로 동작한 소멸**은 오류를 남기지 않는다

사용자가 "TOP 10 이 사라졌다"고 했다. 회귀를 찾을 뻔했지만 코드는 멀쩡했다:

> 위젯은 집계 0건이면 **스스로 숨도록 설계돼 있었다**(`if (!items.length) return null`).
> `TCOMPARE_LOG` 마지막 행이 2026-07-20, 7일 윈도우가 **07-27에 비면서** 조용히 사라졌다.

무엇도 실패하지 않았다. 500 도, 콘솔 에러도, 알림도 없다. **정상 동작과 기능 소멸이 구분되지
않는다** — 함정 ㉙("0건은 부재의 증거가 아니라 무증거")의 UI 판이다. 그리고 이건 콜드스타트
기능의 **일반 속성**이다: 집계로 채우는 자리는 초기에 반드시 비고, 비면 사라지고, 사라지면
아무도 모른다.

### 부수 교훈 — 우리 방어가 우리 진단을 막았다

라이브를 헤드리스로 열었더니 **403** 이 났다. 하마터면 "사이트가 403 을 뱉는다"로 오진할
뻔했는데, 원인은 우리가 2026-07-21 에 넣은 봇 방어 Layer B(`headlesschrome|playwright` 차단)
였다. **자동 검증 도구는 우리가 막기로 한 바로 그 특징을 갖고 있다.**

### 부수 교훈 2 — 문턱을 낮추는 변경은 혼자 오지 않는다

"기록 시점을 앞당기자"는 한 줄짜리 요구였지만, 그대로 넣으면 B-7(집계 부풀림)이 즉시
재현되고(슬롯 왕복·재비교가 그대로 순위가 된다), 위젯 클릭이 자기 자신을 밀어올리며,
크롤러가 밟는 딥링크가 집계에 섞이고, **개인정보 처리방침이 허위 기재가 된다.**
문턱을 낮출 땐 "무엇이 더 들어오나"를 네 방향으로 세라.

  집계형 기능을 만들 땐 **콜드스타트 대체 경로를 같은 커밋에서** 설계하라. 그리고 그 대체
  콘텐츠는 **집계인 척하면 안 된다**: 제목만 바꾸고 순위 번호(1·2·3)를 남기면 문구로 부인하면서
  숫자로 주장하는 꼴이다.
- (58) 🚨 **`GET /` 로 트래픽을 세면 10~100배 과대평가한다.** nginx 는 하루 300~800건을
  보여주지만 실브라우저 세션은 **2~10개**다. 차이는 전부 JS 미실행 클라이언트다.
  정직한 계수기는 **JS 부팅 시에만 나가는 요청**(`GET /api/v1/reference/all`)의 고유 IP 뿐이다.
  "기능이 고장났다"의 상당수는 실제로는 **"아무도 안 쓴다"**이므로, 진단 순서에서 이걸 먼저 배제하라.
- (59) 🚨 **기록 문턱을 낮추면 중복 제거가 같은 커밋에 와야 한다.** 시점을 앞당기면 같은 쌍이
  한 세션에서 여러 번 발사된다(슬롯 왕복·재비교·리포트 왕복). 실제 증거가 DB 에 있었다 —
  최다 조합 `CJ올리브네트웍스 vs DB손해보험 22회` 는 인기가 아니라 **한 사람의 반복 클릭**이다.
  그리고 **집계를 소비하는 UI 가 그 집계에 다시 기여하면 자기강화 루프**가 된다(위젯이 보여준
  조합을 클릭 → 그 조합이 또 오름 → 1위가 자기를 밀어올린다). 소비 경로는 기여에서 끊어라.
- (60) **봇이 밟는 URL 경로에 집계 로그를 걸지 마라.** `/compare/?a=<slug>` 는 GoogleOther 가
  계속 긁는 경로다(실측). URL 프리필에 로그를 걸면 집계가 **봇의 크롤 빈도**를 재게 된다.
  기록은 사람이 조작한 지점(슬롯 선택)에서만 하라.
- (61) 🚨 **수집 시점을 바꾸면 개인정보 처리방침이 그 순간 허위가 된다.** `P2` 가 "비교 실행 시"
  라고 명시하고 있었다 — 코드만 고치면 문안이 사실과 어긋난다. 처리방침은 **정적 생성물**이라
  `policy.py` 수정 + `generator.build` 재생성까지 해야 라이브에 반영된다(코드만 고치고 끝내면
  조용히 어긋난 채로 남는다). 수집 시점·범위·주체를 건드리는 커밋은 문안을 **같은 커밋**에서 옮겨라.
- (62) **우리 봇 방어가 우리 자동 검증을 막는다.** 라이브를 헤드리스로 열면 403 이다 —
  Layer B 가 `headlesschrome|playwright|puppeteer|selenium` 을 차단하기 때문이다.
  이걸 모르면 **"사이트가 403 을 뱉는다"로 오진**한다. 자체 사이트를 브라우저로 검증할 땐
  실사용자 UA 를 쓰고, 403 을 만나면 제품 결함으로 결론짓기 전에 `loupit-botdefense.conf` 를 먼저 보라.

- (63) 🚨 **"렌더러가 셋"이라고 센 순간 넷째가 생긴다 — 판정을 복사하면 반드시 갈라진다.**
  배지를 출처 계보로 바꾸며 정적 페이지·비교 리포트·디렉터리 셋을 고쳤는데, **GNB 검색 →
  회사 복지 페이지(`company.js`)** 가 빠져 '공식/추정' 2종에 남아 있었다. 편집 이력이 0행이라
  **아직 아무도 못 봤을 뿐**, 재직자가 편집을 시작하는 순간 같은 복지가 화면마다 다른 출처를
  달게 돼 있었다. → 판정을 `web/assets/js/badge.js` 한 곳으로 모으고 네 렌더러가 import 한다.
  같은 것을 그리는 화면이 몇 개인지 **세지 말고 grep 하라**(`grep -rn edit_origin`).
- (64) 🚨 **화이트리스트 정규화는 서버의 Pydantic 과 똑같이 필드를 조용히 떨군다**(함정 (55)의

  필드만 통과시켜 `edit_origin` 이 `REF → matched → benS` 경로에서 사라졌고, **비교 리포트의
  계보 판정이 통째로 죽어 있었다**(report.js 는 제대로 읽는데 값이 도달을 못 함).
  더 나쁜 건 테스트가 전부 초록이었다는 것이다 — `renderBands` 에 항목을 **직접 주입**해
  정규화 구간을 건너뛰었다(함정 (54)의 재현). → ①특정 필드가 아니라 **"모델이 선언한 필드는
  전부 살아남는다"**를 계약으로 걸고(`inputs.test.js` 가 `server/models/reference.py` 를 직접
