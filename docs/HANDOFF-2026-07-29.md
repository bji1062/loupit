## 2. 🚨 이번 세션의 가장 큰 교훈 — 활성화는 테스트의 숨은 전제를 먼저 깨뜨린다

M9 활성화 릴리스가 **4번 만에** 성공했다. 실패 3번의 뿌리가 하나다:

> **테스트가 "이 키는 환경에 없다"를 전제하면, 그 키를 쓰는 날 반드시 깨진다.**

| # | 증상 | 원인 |
|---|---|---|
| ① | 표면 계약 3건(TS-1·M9G2·MW-1) | conftest 가 `.env` 를 로드 → 운영 서버에서만 웹훅 라우터가 켜짐 |
| ② | M9G2·MW-1b | `.env` 에 `M9_ENABLED=1` 이 생기자 **`delenv` 로 OFF 를 표현 못 함**(pydantic 이 dotenv 재독) |
| ③ | PM-10 | `GenConfig` 기본값이 **모듈 임포트 시점** 바인딩이라 `delenv` 자체가 무효 |

→ 대응: 픽스처가 값을 **명시 고정**한다(빈 값/`"0"` 으로 덮기, dotenv 보다 프로세스 env 가 우선).

⚠ `M9_ENABLED=0` 을 **전역으로 주는 것은 금지**다(conftest `setdefault` 무력화 → 베이스 61건 RED).

**네 번째는 진짜 인프라 결함이었고 데이터를 실제로 잃었다**(`bd97adf`):
`TCOMPANY_EMAIL_DOMAIN` 은 FK 위상상 참여 테이블이라 백업 목록에 있었지만 **내용은 시드**다.

## 4. 함정 — 이번 세션에 추가된 것 (⑳~)

**①~⑬ 은 `-27-B` §5, ⑭~⑲ 는 `-28` §4 가 정본이다.** 아래는 그 뒤.

- ⑳ **정적 문안만 바꿀 때 `release.sh` 를 쓰지 마라.** 테스트 게이트가 서빙 스키마를
  DROP/CREATE 하는데 이제 실회원 데이터가 생길 수 있다. `generator.build --out web/dist`
  (원자적 스왑 + `dist.prev`)를 쓰고, **스크래치로 먼저 빌드해 대조**하라.
  대조 요령: 바뀐 값만 치환해 diff 하면 "다른 변경이 섞였는가"를 **0줄**로 판정할 수 있다.
- ㉑ **`.gz` 는 gzip mtime 때문에 항상 다르게 보인다.** 압축 해제해서 비교해야 실차이를 안다
  (실측 40개 중 39개가 허위 차이).
- ㉒ **monkeypatch 스텁은 실제 드라이버 동작을 검증하지 않는다.** `ops list-suppressed` 가
  라이브에서 즉사했다(`TypeError: tuple indices must be integers`) — ops.py 의 SELECT 는
  `pymysql.cursors.DictCursor` 필수인데 기본 커서를 썼고, 스텁이 항상 dict 를 돌려줘 **거짓
  초록**이었다. **DB 를 건드리는 기능은 실 SQL 실행 확인을 따로 하라.**
- ㉓ **서명 검증을 시험할 땐 "서명 대상"과 "전송 대상"이 갈라져 있는지부터 확인하라.**
  변조 테스트가 보낼 본문으로 서명을 다시 계산해서, 실제로는 정상 요청을 보내고 200 을 받아
  놓고 "기대 401"이라 적고 있었다. **A 를 서명하고 B 를 전송**해야 성립한다.
- ㉔ **`pytest.raises(같은 예외)` 로는 두 실패 원인을 구분할 수 없다.** 잘못된 시크릿도 결국
  서명 불일치를 내므로, "시크릿을 거부했다"를 검증하려면 **강도를 소유한 단위를 직접** 불러야
  한다(뮤테이션 2회 생존으로 배움).
- ㉕ **메일 테스트 전에는 수신 도메인의 MX 를 먼저 확인하라.** `bji1062@gamil.com` 은 **실재하는
  타이포스쿼팅 도메인**이었다(MX `mail.gamil.com`) — 그대로 보냈으면 로그인 코드가 제3자
  수신함으로 갔다.
- ㉖ **`Resend` 는 평판을 해치지 않는 시뮬레이터 주소를 제공한다**: `bounced@resend.dev` ·
  `delivered@` · `complained@` · `suppressed@`. 바운스 경로 검증에 실주소를 쓰지 마라.
- ㉗ **DB 테이블을 추가하면 세 곳을 같이 봐라**: `db/schema.sql` · `conftest.TABLE_CREATE_ORDER` ·
  `run_tests.sh PART_TABLES`. 셋이 어긋나면 릴리스마다 데이터가 사라진다(가드가 잡지만,
  **가드 자체가 하드코딩 사본이면 못 잡는다** — 파생형으로 유지하라).

```bash
# 테스트
DB_NAME=loupit_test python3 -m pytest server/tests -q -m "not sc14"   # 451
DB_NAME=loupit_test python3 -m pytest server/tests -q -m sc14         # 3
python3 -m pytest generator/tests -q                                   # 225
node --test 'web/**/*.test.js'                                         # 617

# 라이브 스모크(릴리스 게이트) — ⚠ 러너 IP 메일 버킷을 약 2분 비운다. 메일 0통.
bash infra/deploy/smoke.sh

# 정적물만 재생성(문안 변경 등) — ⚠ web/dist 는 라이브. 먼저 스크래치로 대조하라
set -a; . server/.env; set +a
python3 -m generator.build --out /tmp/<scratch>/dist-new    # 확인용
python3 -m generator.build --out web/dist                   # 실반영(원자적 스왑, dist.prev 백업)

# 전체 릴리스 — ⚠ 테스트 게이트가 서빙 스키마를 DROP/CREATE 한다(실데이터 위험)
RELEASE_CONFIRM=1 bash infra/deploy/release.sh

# 운영 CLI
python3 -m server.ops list-pending                    # 재직 수동 승인 큐
python3 -m server.ops list-company-requests           # 회사 등록 요청 큐
python3 -m server.ops decide-company-request <id> --approve|--reject [--by N] [--note S]
python3 -m server.ops list-suppressed                 # 메일 발송 억제 목록
python3 -m server.ops release-suppression <이메일>    # 억제 해제(오탐 복구)

# nginx — ⚠ release.sh 는 conf 를 배포하지 않는다(함정 ⑭). 항상 손으로 배치
sudo cp -a /etc/nginx/sites-available/loupit.conf{,.bak-$(date +%Y%m%d-%H%M%S)}
sudo install -m644 infra/nginx/loupit.conf /etc/nginx/sites-available/
sudo nginx -t && sudo systemctl reload nginx
DRY_RUN=1 bash infra/deploy/rollback-nginx.sh 20260729-023244   # 롤백(드라이런 먼저)
```
