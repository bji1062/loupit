## SP-MET-2. 🚨 금융업 대안 (OI-D 확정)

금융업은 **매출이 없다.** `ifrs-full_Revenue` 는 7곳 중 **2곳(카카오뱅크·카카오페이)** 뿐이고,
은행·보험·증권은 단일 "영업수익" 계정을 아예 내지 않는다(이자수익·수수료수익·투자영업수익 등
구성요소로만 낸다).

**⛔ 하지 않는 것**: 이자수익 + 수수료수익 + 투자영업수익을 더해 "매출"이라 부르는 것.
그건 **우리가 만든 지표**이고, 회사마다 구성이 달라 나란히 놓으면 비교 불가능한 숫자를
비교 가능한 것처럼 보이게 한다. **DEC-B 위반이다.**

**✅ 확정 — 금융 세트의 세 번째 지표는 `자산총계`다.** 7/7 이고, 은행·보험의 표준 규모
지표이며, 공시 원문 그대로다.

| 금융 세트 카드 | 계정 | 커버리지 |
|---|---|---|
| 영업이익 | `dart_OperatingIncomeLoss` → 없으면 `ifrs-full_ProfitLossFromOperatingActivities` | **7/7** |
| 당기순이익 | `ifrs-full_ProfitLoss` | **7/7** |
| **자산총계**(매출 자리) | `ifrs-full_Assets` | **7/7** |

실측(2025, 억원): 기업은행 자산 5,006,926 · 영업이익 36,555 / 삼성생명 3,506,857 · 25,804 /
카카오뱅크 764,097 · 6,493 / 카카오페이 53,395 · 503.

> ⓘ **영업이익이 지금까지 빈 것은 계정 ID 를 안 넣어서였다.** SPEC 15 는 "금융은 순이익만"으로
> 적었지만 그건 사실이 아니라 매핑 누락이었다. SP-MET-3 과 같은 종류의 함정이다.

🚨 **이 판정을 쓰는 곳은 세 곳이고 전부 `finance.metric_columns` 하나를 부른다**(2026-08-28 확정).
회사 상세의 **표**(`_finance_table.html`)·**카드**(`_metrics.html`)·**회사 인덱스**(`companies.html`)다.
표와 인덱스는 구 판본에서 `financial` 이면 순이익 열만 그리고 "금융업은 계정 체계가 달라 순이익만
표시합니다"라고 적었다 — **그 문장은 거짓으로 판명됐다.** 지금 문안은 세 곳 모두
「금융업은 단일 매출 계정을 공시하지 않아 그 자리에 자산총계를 싣습니다」이며, 열 구성을 템플릿이
스스로 판정하지 않는다. 가드: `test_FN5_column_set_is_decided_by_one_function_not_by_the_template`.

⚠ **두 영업이익 계정이 한 회사에 모두 있고 값이 다르면** 회사·연도를 실패 목록에 찍고 종료 코드 1.

## SP-MET-5. 🚨 합계행 — 인원이 정확히 두 배가 된다

7사가 부문행과 합계행을 **함께** 낸다. 전부 더하면 삼성전자가 128,881 → 257,762 명이 된다.

- 판정: `fo_bbm` 이 `합계`·`총계` 를 포함하면 합계행(`성별합계`·`성별 총계` 실측).
- **합계행이 하나라도 있으면 합계행만** 집계한다. 없으면 부문행 전부.
- **검사(필수)**: 어떤 부문의 인원 합 == 나머지 전체 인원 합인데 합계행으로 판정되지 **않았으면**
  회사·연도를 실패 목록에 찍고 종료 코드 1.
  ⚠ 이 검사는 **셀트리온을 오탐**한다(생산직 1,565 vs 나머지 1,588 — 우연의 일치).
  자동 제외 금지 — **사람이 확인한 예외 목록**(`KNOWN_NOT_TOTAL`)으로만 통과시킨다.
- 🚨 **이름 붙은 합계행이 이미 있으면 이 검사는 돌지 않는다**(2026-08-28 실수집 검수로 추가).
  검사의 목적은 '이름이 합계가 아닌 합계행'을 찾는 것이고, 라벨이 붙은 합계행이 있으면 집계가
  그 행만 세므로 두 배 사고 자체가 성립하지 않는다. 이 규칙이 없으면 삼성전자 DS·삼성바이오
  공정직처럼 **가장 큰 부문**이 매 실행 실패 목록에 오르고(실측 9건), 게이트가 영영 빨간불이면
  아무도 안 보게 된다 — 그때부터 진짜 합계행도 같이 묻힌다.
- 🚨 **반대 방향 예외 `KNOWN_TOTAL` 도 있다** — 이름이 합계가 아닌데 사람이 합계행이라고 확인한 것.
  실측 1건: **NC 2018 `전사`**(남 2,367 + 여 1,091 = 3,458 == 관리사무직 1,090 + 연구개발 2,368).
  다 더하면 6,916명, 정확히 두 배였고 급여도 `전사` 행에만 있었다. 이 손잡이가 없으면 검사는 매번
  빨간불인데 고칠 방법이 없다.
  ⚠ `전사` 를 **이름 규칙에 넣지 않는다**: 실측 3,840행에서 `전사` 는 226번 쓰이고 127 회사·연도는
  그 행 하나뿐이며, 삼성전기 2015 의 `전사지원`(2,491명)은 나머지 9,283명과 다른 **진짜 부문**이다.
  예외는 이름이 아니라 **회사** 단위여야 한다.
- 🚨 **재수집은 그 회사·연도를 통째로 갈아 끼운다**(`DELETE` 후 `INSERT`, 2026-08-28 검토 확정).
  upsert 만으로는 부족하다: UNIQUE 키에 든 `SEGMENT_NM`·`SEX_CD` 가 DART **자유 텍스트**라
  `"커머스부문"` → `"커머스 부문"` 한 글자만 바뀌어도 키가 달라져 새 행이 들어오고 옛 행이 남는다.
  그러면 집계가 두 벌을 다 세어 인원이 늘고 — 수집기 종료 0, 빌드 무예외, 화면에 표시 없음.
  ⚠ 지우는 시점은 **쓸 행을 손에 쥔 뒤**다. 013(데이터 없음) 응답에 지우면 재수집이 멀쩡한 과거를
  날리는 도구가 된다.

## SP-MET-6. 🚨 급여 단위가 연도마다 바뀐다

같은 회사가 해마다 단위를 바꾼다. CJ ENM: `96,000,000`(2018, 원) · `83`(2019, 백만원) ·
`84,283,000`(2020, 원). 그대로 쓰면 **2019년 평균연봉이 0원**이 된다.

```python
SALARY_MIN, SALARY_MAX = 20_000_000, 500_000_000   # 상장사 1인평균 타당 범위
def salary_won(v):
    if not v: return None
    if v < 1_000:       v *= 1_000_000    # 백만원 단위
    elif v < 1_000_000: v *= 1_000        # 천원 단위
    return v if SALARY_MIN <= v <= SALARY_MAX else None   # 범위 밖은 지어내지 않고 결측
```
범위 밖으로 떨어진 행은 **개수를 세어 보고**한다(조용한 결측 금지).

## SP-MET-8. 집계 (`generator/employ.py`)

회사 단위 값은 **인원 가중평균**이다. 단순평균은 남녀·부문 규모를 무시해 58개사가 5% 이상 틀어진다.

```
평균연봉 = Σ(AVG_SALARY_AMT × HEADCNT) / Σ(HEADCNT)      ← 값이 있는 행만
평균근속 = Σ(TENURE_YEAR   × HEADCNT) / Σ(HEADCNT)
직원수   = Σ(HEADCNT)
```
⛔ **`fyer_salary_totamt`(연간급여총액)를 쓰지 않는다.** CJ CGV 는 `총액/인원` 이 공시 1인평균과
**4.8배** 어긋난다. 저장도 하지 않는다.

⚠ **성별은 표시하지 않는다**(사용자 결정 2026-08-28). 집계에만 쓰고 화면·표·툴팁 어디에도
남녀 구분을 내지 않는다.

## SP-MET-9. 차트 (`generator/charts.py`) — 순수 함수, 정적 SVG

`generator/treemap.py` 와 같은 계약: **빌드 시점에 좌표를 계산해 HTML 에 박는다. JS 없이

JS 로 차트를 그리지 않는다(단위·결측·부호 규칙이 두 언어로 갈라지면 반드시 어긋난다 — 배지 함정).

  음수는 기준선 아래로. 첫 유효값에 직접 라벨.
- **호버 툴팁(2026-09-01 추가)** — 두 그래프 모두 연도 칸마다 투명 히트 렉트(`fill="transparent"`,
  유일 허용 fill 속성 — 색이 아니라 포인터 수신 장치)를 맨 위에 얹고 SVG 네이티브 `<title>` 로
  `{연도}년 {fmt(값)}` 을 말한다(JS 0 유지). 값이 아니라 **칸**에 다는 이유: 2px 스텁·결측 해도
  호버가 잡혀야 하며, 결측은 "값 없음"이라고 말한다. 칸은 이어 붙어 사각지대가 없다.
  · **즉시 라벨(2026-09-04)** — 네이티브 `<title>` 은 1초 지연·터치 불가·브라우저 기본 모양이라
  실사용에서 "안 된다"로 보고됐다. 같은 문구를 칸(`g.hc`) 호버에 **CSS 로 즉시** 그린다
  (`text.hv`, `paint-order:stroke` 흰 테두리, 여전히 JS 0). 문구는 `_hover_col` 한 곳에서 만들어
  title 과 라벨이 갈라질 수 없다. 스탯 카드 9각형(SP-GEN-5.6)도 같은 장치(`rd-hit`·`rd-hv`).
  · **막대 폭 상한 `MAX_BAR=56`**(2026-08-28 화면 검수 추가). 연도가 2~4개뿐인 회사는 칸이 넓어
    막대가 카드 절반을 덮는 **덩어리**가 되고 두 해의 차이가 눈에서 사라진다(2개년이면 한 개가
    132px). 좁힌 막대는 칸 **중앙**에 둔다 — 왼쪽에 붙이면 칸 중앙에 찍히는 연도 라벨과 어긋난다.
    5개년부터는 자연 폭이 48.8px 라 상한에 닿지 않으므로 **긴 계열의 그림은 바뀌지 않는다**.
- `line_svg(values, years, fmt) -> str` — **데이터 범위에 맞춘 축**. 위치가 값을 뜻하므로 허용되지만
  **실제 최댓값·최솟값을 눈금으로 반드시 적는다**(안 적으면 속임수다). 음수가 있으면 0 을 범위에 포함하고
  0 선을 긋는다. 면적은 부호로 갈라 12% 워시.
- **결측(None)은 잇지 않는다.** 선은 구간을 끊고, 막대는 자리를 비운다. 0 으로 그리지 않는다.
- 눈금 라벨은 전부 같은 x·같은 앵커에 찍히므로 **세로로 가까우면 겹쳐 둘 다 못 읽는다**(`LABEL_GAP`).
  최댓값·최솟값이 먼저 자리를 잡고 0 라벨은 겹치면 생략한다 — **0 선은 그대로 긋는다**(기준을
  말하는 것은 선이다). 소폭 적자 한 해가 섞이면 실제로 일어난다: [43.6, 35.9, −0.5, 26.9, 51.6]
  에서 −0.5 와 0 이 0.2px 차이였다(2026-08-28).
- 색: 양수 `--pos`, 음수 `--neg`. `validate_palette` 통과값 — `#2f7d43`/`#e11d48`.
  부호는 색 말고 **기준선 위아래와 − 부호**로도 말한다.
  ⚠ **다크 값(`#158d4e`/`#e2617d`)은 넣지 않았다**(2026-08-28 확정). 이 사이트에는 다크 테마가
  없다 — `styles.css` 에 `prefers-color-scheme` 분기는 reduced-motion 하나뿐이다. 그래프에만
  다크 토큰을 달면 다크를 선호하는 사람에게 **밝은 페이지 위의 어두운 그래프**가 나간다.
  다크 테마를 도입하는 날 사이트 전체 팔레트와 함께 넣는다.
- 꺾은선의 **선 자체는 중립색**(`--t2`)이다. 경로가 한 벌이라 0 선을 넘나드는 구간에서 부호로 색을
  가를 수 없기 때문이다 — 부호는 면적 색·0 선·값의 − 기호가 말한다.

## SP-MET-10. 화면

- 위치: 회사 상세의 복지표 → 기존 실적 표 → **본 섹션**. 기준 배지 유지.
- 제목은 **「연도별 추이」**(사용자 결정 2026-08-28, 초안의 「실적 · 직원」 을 대체). 바로 위 표가
  이미 「실적」 이라 둘 다 '실적'으로 시작하면 같은 것의 반복으로 읽힌다. 표는 값을 정확히 읽는
  자리, 이 섹션은 11개년 흐름을 보는 자리 — 그 역할 차이를 제목이 말한다.
- **기본 모양은 막대**(사용자 결정 2026-08-28). 0 기준선이 고정이라 축이 거짓말을 못 한다.
  처음 온 사람이 보는 화면이라 사실상의 결정이고, 꺾은선은 라디오로 언제든 고를 수 있다.
- **형제 페이지(CJ ENM 두 부문)는 법인 1벌 수치를 그대로 공유한다**(사용자 결정 2026-08-28).
  `fo_bbm` 부문명과 우리 페이지 구분이 1:1 이라는 보장이 없어, 나누는 순간 근거 없는 매핑을
  우리가 만들게 된다.
- 카드 6장(3열 → 2열 → 1열). 각 카드 = 지표명 · 단위 · 최신값(큰 숫자) · 전년 대비 · 그래프.
- 전년 대비: 부호가 뒤집히면 `흑자 전환`/`적자 전환`, 둘 다 음수면 `적자 확대/축소 N%`.
- 금액 단위는 **회사마다 하나**로 통일한다(유효값 최솟값이 1조 미만이면 억원, 아니면 조원).
  한 회사 안에서 조/억을 섞으면 세 그래프를 나란히 읽을 수 없다.
- 🚨 **소수 자릿수도 회사마다 하나**이고 카드가 들고 다닌다(2026-08-28 실데이터 검토). 조원은 1자리,
  억원은 0자리 — **단, 최솟값이 1억 미만이면 억원도 1자리다.** 정수로 자르면 그 값이 `0` 이 되는데
  0 에는 부호가 없어 **적자가 흑자로 보인다**: 리메드 2025 순이익 −35,468,721원이 `0억원` 이 되고
  막대가 기준선 **위에 초록으로** 그려졌다. 숫자를 잃는 것보다 나쁜 것은 부호를 잃는 것이다.
- 전년 대비는 **표에서도** 직전 '행'이 아니라 직전 '연도'와 비교한다. 연도가 통째로 빠진 회사가
  있다(LIG디펜스앤에어로스페이스 연결 2018, 실측) — 행 기준이면 2017→2019 를 "전년 대비"라 적고,
  같은 페이지의 카드는 그 자리를 비워 **한 페이지가 두 말을 한다**.
- **막대/꺾은선 토글**: 두 벌을 다 HTML 에 넣고 라디오 + `:checked` 로 CSS 가 전환한다. **JS 0**.
  실측 전송량 gzip 막대 3.5KB + 선 2.2KB = **5.1KB**(현재 회사 페이지 전체가 3.2KB).
- JS 는 `web/assets/js/metricshape.js` 하나뿐이며 **선택 기억만** 한다(`localStorage`,
  try/catch, 값은 `bar|line` 만 허용). ⚠ **이 저장값은 그래프 모양만 정한다.** 어떤 화면을
  보여줄지는 절대 정하지 못한다(대문 사고 재발 방지).
- 없는 값은 비우고 그렇게 말한다. 금융업 매출 자리는 자산총계로 대체되므로 빈칸이 아니다.
- 표현은 사실만 — 등급·전망·평가 어휘 금지. `test_finance_guard` 의 금칙어 검사를 본 섹션까지 넓힌다.
