# SPEC 21 — 가이드 (SP-GUIDE)

**상위 추적**: 애드센스 2차 거절(2026-09-24, 스팸 정책 3유형(빈약한 제휴 · 스크랩 · 도어웨이) — 도어웨이 유력 — `docs/ADSENSE-거절사유-원문.md`, 미추적 파일) · 가이드 글 시안 v2(`loupit-evidence/2026-09-24-guide-drafts/`, D 패널) · 리드 판정 (77)(2026-10-06 — D편 게시 범위) · SP-GEN(07, 정적 생성·sitemap·게이트) · SP-MARK(범위·계보 표시) · SP-AUTH 배지 계보(`format.badge_state` · `badge.js`).

**목적**: 사이트가 복지 데이터를 **어디서 가져오고 · 어떻게 나누고 · 금액을 어떻게 표시하고 · 언제 다시 확인하는지**를 그때그때의 실제 숫자로 밝히는 고유 글을 싣는다. 회사 페이지 템플릿 150쪽이 대부분인 사이트에 「이 사이트는 무엇을 근거로 무엇을 하는가」를 말하는 글이 없다는 것이 거절 사유 후보였다.

**범위 경계**: 글 둘(D편 `/about/data` · A편 `/guide/report-<판>`)과 목록 `/guide`, 상단 탭 「가이드」. 새 API · DB 컬럼 · JS 0. C편(법정 제도)은 이 SPEC 의 후속이고, 푸터 링크 · 회사 페이지의 출처 링크는 범위 밖이다. 「AI 사용 표기」는 넣지 않는다(사용자 결정 2026-09-28) — 단 「검색 요약」 출처 설명은 사실 기술이라 넣는다.

## SP-GUIDE-2 — 숫자 정의

숫자는 전부 빌드 데이터(`ctx.companies[*].benefits` · `ctx.finance` · `ctx.employ`)에서 센다 — **사람 문장에 숫자를 박지 않는다**(테스트가 content 모듈의 숫자 리터럴을 막는다). 0 이면 그 문장을 통째로 뺀다.

| 자리 | 정의 |
|---|---|
| asof | 복지 `verified_dtm` 전 행 최댓값(`YYYY년 M월 D일`). **빌드 날짜가 아니다** |
| N | 회사 수 |
| url_comp | `careers_benefit_url` 이 있는 회사 수 |
| summary_comp / summary_rows | `badge_src_cd == marks.SUMMARY_SRC_CD` 행이 있는 회사 수 / 행 수. 행이 전부 금액 없음일 때만 「금액을 넣지 않습니다」 문장을 싣고, 아니면 `BuildError` |
| fin / emp | 재무 · 직원 카드를 그리는 회사 수 — 회사 페이지와 같은 `employ.company_metrics` 를 한쪽씩만 먹여 센다 |
| fy_min ~ fy_max | 재무 수치가 있는 사업연도 범위 |
| names | 서로 다른 `benefit_nm` 수(대소문자 무시 — DB DISTINCT 와 같은 판정) |
| codes | 서로 다른 `benefit_cd` 수 |
| resort_* | `resort` 코드 회사 수 · 서로 다른 이름 수 · 빈도순(같으면 이름순) 상위 10개 이름 칩 |
| cats | `company.CATEGORY_ORDER` 길이(고유어 수사 「아홉」) · 칩 라벨은 `CATEGORY_LABEL` |
| rows / st / es / no | `trust.welfare_totals` — 전체 / `stated` / `estimated` / 정성 + 금액 빈 행. **대문 `home._trust` 가 같은 함수를 쓴다** |
| legal / work_edu | `marks` 범위 표시 행 수(라벨 · 구절은 `marks.KINDS`) |
| vmin ~ vmax | 확인일 범위(검색 요약 행의 요약 기준일은 뺀다 — 대문과 같다) |

**상수**(코드 정본과 테스트로 묶는다): ±5% · ±20% · 15%p = `web/assets/js/calc.js` `BAND_BASE.stated` · `BAND_BASE.estimated` · `BAND_EXPIRE` · 만료 18개월 = `server/services/benefit_edit.py` 의 `INTERVAL 18 MONTH`. 라벨은 정본에서 읽는다 — 검색 요약 = `marks.SUMMARY` · 회사 공식 수치 · 추정치 = `company.LENS_BUCKETS` · 공식 · 공식·재직자 수정 · 재직자 등록 · 만료·재확인 필요 = `format.badge_state`(`badge.js` 와 같은 글자 — 테스트가 대조).

## SP-GUIDE-3 — 기준일 규칙

기준일은 **복지 확인일의 최댓값**이다. 빌드 날짜를 찍으면 릴리스마다 본문이 바뀌어 sitemap `lastmod` · IndexNow 가 거짓으로 갱신된다(`release.lastmod_index` 는 내용 지문으로 정한다). 같은 데이터면 빌드 시각이 달라도 HTML 이 바이트 동일해야 한다.

## SP-GUIDE-4 — 탭 규칙

글이 하나뿐인 동안 탭 「가이드」 = `/about/data` 였고, **2026-10-08 A편이 나와 글이 둘이 되면서 탭을 `/guide` 목록으로 옮겼다**(`GNB_TABS` · 수기 셸 7개 · nginx 두 줄 · 이 SPEC 을 함께 — `test_gnb_tabs` 가 어긋남을 잡는다). `/guide` · `/guide/*` · `/about/data` 모두 가이드 탭이 현재 탭이다. D편 빵부스러기 「가이드」는 `/guide` 링크(`partials/_guide_crumb.html` 공용). 탭 폭: 「커뮤니티」(4자)가 빠진 자리에 「가이드」(3자)라 헤더는 57px 상태보다 좁다.

## SP-GUIDE-6 — 운영 메모

- **검색 요약 행에 금액이 생기면 `BuildError` 로 릴리스가 멈춘다** — 「이 항목들에는 금액을 넣지 않습니다」가 거짓이 되기 때문이다. 데이터 오류가 아니라 **문안 판정 필요**(리드에게 올린다).
- 근거 주소가 있는 회사가 0곳인데 회사가 있으면 `BuildError`(「번들 필드 누락 의심」) — 번들에서 `careers_benefit_url` 이 조용히 떨어진 것이다.
- **헤더 등 공통 셸을 바꾸면 한 번 전 URL 의 lastmod 가 갱신된다**(내용 지문이 바뀌므로 정상). 탭 「가이드」 추가가 그런 변경이다.
- **배포 순서**: ① nginx `loupit.conf` 의 `location = /about/data` 를 서버에 수동 배치 · `nginx -t` · reload ② 머지 뒤 pull ③ 곧바로 `release.sh`(생성물이 바뀌므로). ①을 빼먹으면 새 탭이 전 페이지에서 404 로 간다. pull 하는 순간 수기 셸 7개(web/ = 라이브 docroot)에 「가이드」 탭이 먼저 보이고, release 스왑이 끝날 때까지 그 탭은 404 다 — pull 과 release 를 곧바로 잇는다.

- URL `{origin}/guide/report-2026-10` · 파일 `guide/report-2026-10.html` · `<title>` = `회사 {N}곳의 복지 공개 현황 — {판} 판 | jobcho.wiki` · description = 리드 첫 문장 + 「2026년 10월 판.」 · sitemap · canonical · OG(website) · 무광고 · 탭 활성 `/guide`.
- **고정판 원칙**: 숫자는 스냅숏 JSON 에서만 읽는다(빌드 ctx 숫자 금지 — 테스트: ctx 를 바꿔도 HTML 이 같다). 파일 sha256 을 테스트가 고정한다 = 「이 판의 숫자는 바꾸지 않는다」를 코드로. 판을 바꾸려면 **새 파일 = 새 판 = 새 주소**.
- **스냅숏 정의**(사이트 정본 함수 재사용, 하드코딩 없음): 셈 대상 = `marks.countable`(법정 · 업무 교육 표시 행을 뺀 행; 검색 요약 행은 셈에 든다) · 금액 갈래 = `format.amount_kind`(stated · estimated · none) · 회사 유형 = `comp_tp_cd`(`large` · `mid`) · 라벨 = 항목 페이지 제목 → 없으면 `find.derive_codes` 표시명 · 이름 수 = D편 `about_data._fold`(casefold).
  - `top`: 코드별 공개 회사 수 · 비율(÷N, 소수 1자리) · 라벨 · slug · 대/중견 비율 · 정렬(회사 수 desc, 라벨) · `half` = 회사 수×2 > N 인 항목 전부(「절반 넘는」 — 정확히 절반은 넘지 않는다).
  - `amount`: stated · estimated · none 건수와 비율(셈 대상 기준) · 금액 0곳(stated·estimated 행이 하나도 없는 회사) · stated 있는 회사 수 · stated 최다 항목.
  - `gap`: **선정 규칙 = 공개 회사 15곳 이상(`GAP_MIN_COMPANIES`) 항목 중 (대기업 비율 − 중견 비율) 큰 쪽 5 · 작은 쪽 5**(`GAP_SIDE`) · 공개 항목 수(회사별 서로 다른 코드 수) 중앙값(대 · 중견).
  - `marks`: 법정 · 업무 교육 행 · 회사 수(전체 행 기준) · 검색 요약 행 · 회사 수(셈 대상 안) · 확인일 범위(검색 요약 행 제외) · 이름 수 · 표준 항목 수 · 근거 주소 회사 수 · `meal_large_pct`(해설 상자 예시) · `child_edu_slug`.
  - 검색 요약 행에 금액이 있으면 스냅숏 생성이 멈춘다(「이 항목들에는 금액이 없습니다」가 거짓이 된다 — 리드 판정 필요).
- **링크는 실제 생성된 항목 페이지에만**(`benefit.links`) — 스냅숏의 slug 는 기록일 뿐. 금액 갈래 라벨 = `company.LENS_BUCKETS` · `about_data.KIND_NONE_LABEL`(D편과 같은 정본). 추정치 정의 = D편 · 대문과 같은 뜻(셀 수 있으면 그 조건으로 · 셀 수 없으면 같은 종류 제도의 기준 금액).
- **금액 정의 문장(2026-10-08 검증 반영)**: 「회사 공식 수치」(= `stated`)는 「회사가 밝힌 숫자로 **연 금액을** 적은 것」이다 — 「회사가 금액을 밝힌 것」 전체가 아니다(월액 × 12 는 추정치, 1회성 금액은 금액 미등록). 추정치에는 재직자가 넣은 금액도 든다. 「금액 미등록」은 「연 금액이 등록돼 있지 않다」이고 「제도만 알려져 있다」가 아니다. 대문 home-trust · D편 `KIND_STATED` · `KIND_NONE` 이 같은 말을 한다.
- **게시 전 데이터 정정 반영(2026-10-08)**: 2026-10 판은 아직 게시 전이라, 데이터 정정 #111(금액 표시 8행)이 들어간 운영 DB 로 **같은 판 키로 스냅숏을 다시 떴다**(stated 64 → 56 · estimated 389 → 392 · none 2,720 → 2,725 · 금액 0곳 38 → 39 · stated 회사 39 → 37 · 최다 복지포인트 28 → 27, 나머지 그대로) — 새 sha256 을 테스트가 고정한다. **게시 뒤에는 같은 판을 다시 뜨지 않는다**(바뀌면 새 판). 대문 · D편 · 회사 페이지 LENS `stated` 설명 · 이직 계산기 리포트(`report-calc.js`)가 같은 정의 문장(「회사가 밝힌 숫자로 연 금액을 적은 값」)을 쓴다.
- **판별 문안(M-4)**: 판마다 다른 사실에 기대는 문장은 `content/guide_report_editions.py` 의 판 키 아래에 둔다. 공통 모듈에는 두지 않는다. 판 문안의 `gap_codes` 가 스냅숏의 gap 항목과 다르면 `build_view` 가 `BuildError` 로 멈춘다(조용히 틀린 묘사를 싣지 않는다).
- **다음 판 내는 법**: ① 운영 번들로 새 스냅숏 `python3 -m generator.guide_report --edition 2026-11 --asof <날짜> --out generator/data/guide/report-2026-11.json`(DB 는 SELECT 만) ② 새 판의 gap 항목 · 카드 · 상자를 보고 `guide_report_editions.EDITIONS` 에 **새 판 키**를 더한다(옛 판 항목은 건드리지 않는다) ③ `content/guides.py::REPORT_EDITIONS` 맨 앞에 한 줄 ④ `test_guide_report.py::SNAPSHOT_SHA256` 에 새 판 한 줄(테스트는 판 목록을 돌며 해시 · 문안 · 숫자를 대조하므로 다른 테스트를 고치지 않는다) ⑤ 옛 판 파일 · 주소는 그대로 둔다.
- 그림 ③ 라벨 이음은 「, 」(쉼표) — 항목 이름 안에 「·」가 있어서다.
