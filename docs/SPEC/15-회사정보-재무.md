# SPEC 15 — 회사정보 탭·DART 재무 (SP-FIN)

**상위 추적**: `docs/PLAN-회사정보-확장-2026-08-21.md`(DEC-A~D · §3 설계 요구 4 · §5-1 매칭 · §5-2 함정) · `docs/PLAN-커뮤니티-회사정보탭-2026-08-27.md` §3-3 · SPEC 02(TCORP·TCOMPANY_CORP·TCORP_FINANCE DDL, 2026-08-21 적용 완료) · SPEC 07(SP-GEN 회사 페이지·인덱스) · 함정 (55)(68)(69).

**범위 경계**: 재무 **적재·수집·렌더**를 소유한다. DDL 은 SP-DB. 런타임 API(`reference/all`)는 **건드리지 않는다** — 소비처가 정적 페이지뿐이라 생성기 전용 로더로 싣는다(INV-2 3키·600KB·`models/reference.py` 무영향, 함정 (55) 회피). 뉴스(계획 5단계)는 범위 밖.

**표현 규약(DEC-B, 코드로 강제)**: 수치·전년 대비 증감률·추이만. **등급·전망·평가 어휘 금지**("우수"·"양호"·"A등급"·"전망"·"성장성"). 기준(연결 CFS/별도 OFS)과 출처(접수번호)를 화면에 명시. 없는 데이터는 비워 두고 "공시 데이터 없음"이라고 말한다.

## SP-FIN-2 — 적재 (`load_corp.py`)

- 입력 `db/seed/corp_code_map.csv`(comp_id, comp_nm, status, corp_code, stock_code, note). `status=UNMAPPED` 는 **건너뛰고 표준출력에 남긴다**(CJ올리브영).
- `INSERT … ON DUPLICATE KEY UPDATE` 로 멱등. `TCORP.CORP_NM` 은 DART 개황명(없으면 CSV comp_nm), `ACCT_SET_CD` 는 금융 7사(DB손해보험·NH투자증권·기업은행·삼성생명·삼성카드·카카오뱅크·카카오페이) `financial`, 나머지 `general`; `FS_DIV_CD` 기본 `CFS`.
- `load.py --fresh` 이후 **재실행 필요**(참조 5테이블 재생성으로 COMP_ID 가 재배정될 수 있다) — `load.py` 마지막 단계에서 호출해 잊지 않게 한다. 대상 스키마 가드(`LOUPIT_ALLOW_FRESH`·schema_guard)는 그대로 상속.

## SP-FIN-3 — 수집 (`dart_finance.py`)

- 엔드포인트 `fnlttSinglAcntAll.json` · `reprt_code=11011`(사업보고서) · `bsns_year` 최근 5개년 · `fs_div ∈ {CFS, OFS}`.
- **지표는 `account_id` 로만**: `ifrs-full_Revenue`(매출) · `dart_OperatingIncomeLoss`(영업이익) · `ifrs-full_ProfitLoss`(당기순이익). `sj_div`·`account_nm` 으로 거르지 않는다(함정 (68), SK하이닉스 CIS).
- 금융 세트(`ACCT_SET_CD=financial`): 순이익 + **영업수익 계정은 첫 실행에서 실측해 확정**(OI-D). 확정 전까지 순이익만 저장하고 나머지는 NULL(=없음, 0 아님).
- **결측 검사(필수)**: 일반 세트인데 3지표 중 하나라도 최신연도에 없으면 회사명·연도·지표를 실패 목록으로 출력하고 종료 코드 1. 금융 세트는 순이익 부재만 실패.
- 레이트: 102×5×2 ≈ 1,020 호출(일 20,000 안). 재실행은 `(CORP_CODE, BSNS_YEAR, FS_DIV_CD, ACCT_ID)` UNIQUE 로 멱등. `RCEPT_NO` 저장.
- 키 없으면 **즉시 실패**(조용한 0건 금지). 키는 `server/.env` `DART_API_KEY`(pydantic `dart_api_key`), 로그 출력 금지.
- 픽스처: `db/seed/tests/fixtures/dart_*.json`(삼성전자·SK하이닉스(CIS)·삼성생명(금융)·LG(연결≠별도)) 로 HTTP 무접촉 테스트.

## SP-FIN-4 — 생성기 로더 (`generator/finance.py`)

- `load_finance(conn)` : `TCOMPANY_CORP ⋈ TCORP ⋈ TCORP_FINANCE` 를 회사별로 묶어 `{comp_id: {corp_nm, stock_cd, acct_set, fs_div, years:[{year, revenue, op_income, net_income, rcept_no}], siblings:[comp_id…]}}`. `fs_div` 는 `TCORP.FS_DIV_CD` 기본값 1벌만 화면에(둘 다 있을 때 표기 "연결 기준").
- `bundle.py`: `load_bundle()` 이 같은 커넥션으로 `finance` 를 **번들 옆에**(`bundle["_finance"]` 아님 — `build_context(bundle, finance=…)` 인자) 전달. `--bundle-json` 경로는 `--finance-json` 으로 대응. `build_reference_bundle` 무변경(test_arch T3 단일 소스 그대로).
- `siblings`(같은 corp_code 의 다른 페이지) 는 "법인 기준 공시 — CJ ENM 커머스부문과 같은 법인" 문장에 쓴다.

## SP-FIN-5 — 렌더

- **회사 상세 '실적' 섹션**(`_finance_table.html`): `<h2>실적</h2>` · 기준 배지("연결 기준"/"별도 기준") · 연도별 표(연도 · 매출 · 영업이익 · 순이익, 억원, 전년 대비 %) · 출처 줄("출처: 금융감독원 전자공시(DART) 사업보고서 · 접수번호 …" — `https://dart.fss.or.kr/dsaf001/main.do?rcpNo=` 아웃링크, `rel="noopener"`) · 고지 한 줄("공시 수치이며 평가나 전망이 아닙니다"). 금융 세트는 열이 다르다(영업수익·순이익). 데이터 없음 → `<p>공시 데이터 없음(비상장 또는 미제출)</p>`.
- 위치: 복지표 **뒤**, CTA 앞. 복지가 이 사이트의 본체다.
- **`/companies` 인덱스**: `<h1>회사정보 — 등록 회사 N곳</h1>` 유지 + 섹션 2개("일반"·"금융") + 행에 최신연도 매출·영업이익·순이익(억원)·기준. 정렬 가나다 유지(GC-27). 재무 없는 회사는 "—".
- JSON-LD 확장 없음(1차).
- 콘텐츠 두께 목표: 회사 페이지 +400~600자(중앙값 1,402 → ~1,900).
