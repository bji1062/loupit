## SP-BEN-2 — 페이지 구성 (순서 고정 — 승인 시안)

1. 빵부스러기 `복지검색 › {카테고리} › {title}` — 카테고리 = `find.derive_codes` 의 최빈 `benefit_ctgr_cd`(/find 표와 **같은 집계**라 두 화면이 다른 칸을 가리키지 않는다), 링크 `/find#cat-{key}`.
2. h1 = 설정의 `title`. `derive_codes` 라벨을 쓰지 않는다(「CJ 계열사 할인」류 한 회사의 표기가 이름이 되는 오류가 있다).
3. 「회사들이 부르는 이름 N가지」 칩 — `benefit_nm` 빈도순(동률 = 짧은 것 → 코드포인트, `find._prefer_name`) 8개 + 「외 N가지」.
4. 요약 수치 — 보유 회사 N곳 / 등록 M곳 중 % · 금액 출처(회사 공식 수치 · 추정치 · 정성 · 금액 미기재(>0 일 때)) = `company.lens_keys` 의 금액 축(회사 카드 「항목 구성」과 같은 통).
5. 한눈에 보기 = `intro` 문단.
6. 회사마다 뭐가 다른가 — `modes` 가 있으면 누적 막대 + 범례(개수는 **글로**), 이어서 `facets` 막대 「회사가 공개한 원문에 적힌 것 — N곳 중」(0 = 「없음」).
7. `money_facet` 이 있고 해당 행 ≥ 3 이면 「금액이 적힌 원문 n곳」 표(회사 · 방식 칩 · 원문) + `notes.money`.
8. 입사 전에 물어볼 것 — 질문마다 「원문에 밝힌 회사 n곳 / N곳」 미니 막대(`benefit_rules.answered`). 0 이면 강조 + 「원문에 밝힌 회사 없음」.
9. 법으로 정해진 것 — SP-BEN-6.
10. 이 복지가 있는 회사 N곳 — 회사명(`/company/{slug}#{benefit_anchor(code)}` — 회사 원장 행 id 와 같은 함수) · 방식 칩 · 원문(`format.benefit_desc`, 회사 원장과 같은 표시) · 금액 칸(`company.amount_view`). 첫 12행은 **방식마다 번갈아** 뽑고 나머지는 `<details>`.

- 방식 색은 **표시 순서**로 붙는다: 첫째 `--brand` · 둘째 `--slot-b` · 셋째 `--purple` · 넷째 `--amber` · `extra` = 첫째·둘째 사선 줄무늬 · fallback = `--bg-4`. 규칙 순서(매칭 우선순위)로 붙이면 화면 맨 앞 칸이 둘째 색이 된다. 규칙은 4개까지(`MAX_MODE_RULES`).
- 9카테고리 밖 행은 회사 원장에 그려지지 않으므로 앵커 없이 회사 페이지로만 링크한다(맨 위로 떨어지는 링크 금지).
- 메타: `<title>` = `{title} — 회사 N곳의 복지 원문 비교 | jobcho.wiki` · description = `{title} — 등록 회사 M곳 중 N곳 · {intro 첫 문장}`(155자) · canonical·OG 는 기존 관례. GNB 활성 = 복지검색.

## SP-BEN-3 — 데이터 규칙

- 행 = 번들 회사들의 복지 중 `benefit_cd == code`(회사당 1행 — 2행이면 `BuildError`). 매칭·해시 원문 = `qual_desc_ctnt`(`desc`) + `note_ctnt`(`note`).
- **법정 행(SP-LEGAL-5, `legal.is_legal_row`)**: 표 맨 끝에 회사 원장과 같은 「법정」 배지로 남기고, **모든 집계**(N·방식·원문 항목·질문·금액 출처·부르는 이름)에서 뺀다. 머리에 「+ 법정 제도만 적은 회사 n곳」.
- **`exclude` 예외**(`overrides[] = {comp, h, exclude: true, why}`): 이 코드로 **잘못 분류된** 행(예: 어린이집 코드인데 어린이집 없이 수당만 주는 회사)을 법정 행과 같은 길로 모든 집계에서 빼고, 법정 행과 달리 **표에서도** 뺀다. 데이터 재코딩은 별도 작업이고 그 전까지 항목 페이지만 정확하게 한다 — 빌드 로그에 `예외로 뺀 행 n곳(회사…)` 한 줄(재코딩 목록). 해시가 다르면 다른 예외처럼 꺼지고(`stale`) 행이 다시 나타난다.
- **문턱 `MIN_COMPANIES = 20`**(법정 행·`exclude` 를 **뺀 뒤** 개수): 미만이면 페이지를 만들지 않고 빌드 로그에 `건너뜀` 한 줄. 얇은 페이지가 곧 거절 사유다. 회사가 늘면 저절로 생긴다(실측 2026-09-18: 87종 중 36종 · 2026-09-21 회사 150곳: 90종 중 38종이 법정 행을 뺀 행 수로 넘는다 — `exclude` 를 빼면 더 줄어든다, SP-BEN-13).
- `classify()` 의 `stale` 경고는 빌드 로그(`예외 경고`)로 — 실패 아님.
- 원문 매칭은 `core_text`(수집자 메모 괄호·꼬리를 걷은 **사본**)로 한다. 화면의 원문은 회사 페이지와 같은 `benefit_desc` 다. 메모 판별 낱말 = 공식·페이지·미기재·미표기·미공개·채용·항목·추정·사이트·출처(꼬리는 미기재·미표기·미공개·다름·정본·공식·페이지·항목). 괄호는 **안쪽부터** 바뀌지 않을 때까지 걷는다 — 남길 회사 괄호는 표식으로 가려 두므로 「(공식 페이지 (유·무이자) 항목 미기재)」 같은 겹괄호 메모도 통째로 걷히고, 메모 낱말이 없는 겹괄호는 그대로 남는다.

## SP-BEN-4 — 설정 JSON · 구조 검사

필수 키 `code·slug·title·intro·facets·questions`, 선택 `modes·money_facet·notes·overrides`. 본보기 = `housing_loan.json`.

`benefit_rules.validate`(빌드가 **실패**로 막는다 — 전부 「틀려도 화면이 조용히 나오는」 종류다):
- slug 형식(`[a-z0-9]+(-[a-z0-9]+)*`)·설정 간 slug 중복·**설정 간 같은 사람 글 문장**(`validate_all`, SP-BEN-7) · 파일 이름 = `code`(`load_pages`).
- `answered_by` 는 존재하는 `facet:키` 또는 `mode:known`(방식이 있을 때만) — 틀리면 질문 칸이 거짓 「없음」을 찍는다.
- `modes.display` ⊆ 정의된 키(중복 없음; 빠진 키는 끝에 붙여 막대에서 사라지지 않게) · 규칙 ≤ 4 · 정규식 컴파일.
- `overrides` 의 `mode`·`facets_add/remove` 키 존재, `comp·h·why` 필수(`exclude` 도) · `exclude` 는 `true` 만, `mode`·facets 와 함께 쓰지 않는다 · `money_facet` ∈ facet · `notes` 키 ∈ `modes·facets·money·questions·companies`(템플릿이 아는 자리 — 모르는 키는 에러 없이 사라진다).

## SP-BEN-5 — 사람 글 규칙 · 예외 해시

- **숫자 금지**(`check_no_digits`, 빌드 게이트 GC-29) · **수량어 금지**(`check_quantifiers` — 대부분·대다수·많은·적은·보통·일반적으로·흔히·절반·일부 회사, 테스트). 개수는 빌드가 원문에서 센다 — 사람 글에 숫자·수량이 있으면 데이터가 바뀌는 날 그 문장만 **에러 없이** 거짓이 된다. ⚠ 「적은」은 「원문에 적은」(적다=쓰다)에도 걸린다 — 「원문에 쓴」으로.
- **예외는 원문 해시에 묶는다**(`overrides[].h = text_hash(desc, note)`). 원문이 바뀌면 예외가 저절로 꺼지고 `stale` 경고가 난다 — 옛 원문을 보고 내린 판정이 새 원문에 조용히 붙지 않는다. 행이 사라져도 `stale`.

## SP-BEN-6 — 법으로 정해진 것

`legal_baseline.json` 의 items 중 `benefit_cds` 에 이 코드가 든 것을 **옮기기만** 한다: 제도 이름 · 법령 + 조문 · 법정 기준(`baseline` 값·단위, 다태아·근속별 범위) · 급여(`paid_note`, 없으면 `paid` 라벨) · 시행일 + `확인필요` 표식 · 표 검토일. **새 법 문장을 만들지 않는다**(법이 바뀌면 표 하나만 고친다). 표의 `note` 는 싣지 않는다 — 수집 메모(「우리 데이터의 …은 재수집 대상」)가 섞인 내부 칸이다. 해당 항목이 없으면 문장이 아닌 라벨 「법정 기준선 표에 없는 항목」.

## SP-BEN-7 — 🚨 필러 규칙

애드센스 거절 사유 = 「가치가 별로 없는 콘텐츠」, 공식 정의 = **필러**. 여러 페이지에 똑같이 반복되는 완결문장이 곧 필러다(A안 2026-09-16 에 회사 페이지에서 걷어 냈다).
- 템플릿이 고정으로 내보내는 글은 **제목·라벨·수치 표기만**. 완결문장은 설정의 사람 글과 회사 원문(그리고 기준선 표의 칸)에서만 나온다. 면책 partial 도 싣지 않는다(푸터가 면책 페이지로 잇는다).
- 테스트로 고정: 렌더 결과(`<main>`)에서 사람 글·원문·기준선 칸을 걷어 낸 나머지에 `다.`/`요.` 종결 0(`test_template_emits_no_fixed_sentences`).
- **설정 사이의 같은 문장도 필러다** — `validate_all`(`repeated_sentences`)이 서로 다른 설정의 사람 글을 문장 단위(종결 「다.」「요.」「?」 뒤 공백으로 쪼갬 — 「등.」「무급.」 같은 마침표에서는 안 자른다, 공백 정규화)로 맞대어 하나라도 같으면 **빌드를 멈춘다**. 한 설정 안의 반복은 한 페이지 안의 일이라 보지 않는다. 계기: 2026-09-18 첫 배치에서 `medical`·`long_service_leave` 의 `notes.money` 가 한 문장 겹쳤다.
- **정형 맺음도 필러다(2026-09-21)** — 첫 배치 10쪽의 `intro` 가 전부 「…있으니, 입사 전에 아래 질문을 직접 확인해 보세요.」로 끝났다. 앞 절이 달라 문장 검사(`repeated_sentences`)는 통과했지만 같은 꼬리가 모든 페이지에 붙은 틀이다. 걷어 내고 사실 절만 남겼다. 질문 칸은 페이지에 이미 있다 — 사람 글이 그 칸을 안내하지 않는다. `notes.money` 의 훈계 꼬리(「…같은 줄에 놓고 크기를 비교하면 안 됩니다」「…로 읽으면 안 됩니다」「…원문을 함께 보세요」, 일곱 쪽)도 같은 이유로 걷고 금액의 성격을 밝힌 사실 문장만 남겼다. 새 설정도 페이지마다 되풀이되는 맺음 틀을 만들지 않는다(검증 레인이 본다).

## SP-BEN-9 — nginx

`/company/` 와 같은 모양(`$uri.html` 만 — `/benefit/<slug>.html` 직접 접근은 404):

```nginx
location ^~ /benefit/ { root /home/ubuntu/loupit/web/dist; include /etc/nginx/snippets/loupit-security.conf;
```
