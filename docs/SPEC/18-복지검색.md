# SPEC 18 — 복지검색 (SP-FIND)

**상위 추적**: 프로토타입 변형 B(2026-09-06 사용자 결정 — 스크롤하면 덱이 한 줄로 접히는 검색 탭) · SP-FE(06, 무빌드 ES 모듈·부팅 번들 1회·렌더 안전) · SP-GEN(07, 정적 생성·sitemap·GC-10 비-JS 본문) · SP-DS(10, 토큰·단일 분기) · SP-HEAT(16, 정적 셸 + JS 모듈의 가장 가까운 선례) · 벤치마크 복지리 `bokziri.com/search`(회사 5,772 · 키워드 칩 · AND 조합 없음 — 2026-09-06 데스크톱 1회 열람, 구조만 기록하고 데이터는 쓰지 않았다).

**이름**: 페이지 제목·h1·`<title>`·이 문서의 이름은 「복지검색」다. **GNB 탭 라벨만 「복지검색」(4자)** 인데, 5자 라벨은 익명·M9 ON 의 360·390px 에서 헤더를 두 줄 97px 로 만들었기 때문이다(2026-09-06 헤드리스 실측 — 탭 폭 +71px 로 「로그인」이 둘째 줄로 밀린다). 라벨을 다시 늘리려면 그 폭에서 헤더 높이를 먼저 재라.

**범위 경계**: 생성 페이지 1개(`/find`)와 그 클라이언트 도구(`web/assets/js/find.js`)·CSS 절·GNB 한 자리를 소유한다. **새 API·새 DB 컬럼·새 엔드포인트는 만들지 않는다** — 데이터는 부팅 번들 `reference/all` 하나다. 회사 페이지·비교 툴·히트맵은 건드리지 않고, 결과에서 그쪽으로 **나가기만** 한다.

**v1 범위 밖(하지 않은 것)**: 회사 페이지 복지 카드의 역링크 · GNB 검색창의 복지 키워드 폴백 · 코드별 정적 페이지 86개(`/benefit/<code>`) · 광고 슬롯 · 「재직자 확인만」 필터의 활성화(체크박스는 비활성 + 툴팁으로 남겨 둔다).

## SP-FIND-2 — 데이터 계약: 코드 사전은 **집계**다

번들은 회사마다 복지 행을 들고 있을 뿐 **코드 사전을 싣지 않는다**. 고를 수 있는 항목 목록은 행 전부를 세어서 만든다(`deriveCodes` / `derive_codes`).

| 필드 | 뜻 | 규칙 |
| --- | --- | --- |
| `label` | 화면에 내는 이름 | 최빈 `benefit_nm` → 중복이면 아래 SP-FIND-3 |
| `aliases` | 그 코드로 등장한 모든 이름(빈도순) | 검색 색인이자 표의 「다른 이름」 칸 |
| `ctgr` | 최빈 `benefit_ctgr_cd` | 같은 코드를 회사마다 다른 카테고리에 넣은 것이 실제로 있다(`holiday_gift`·`work_tools` 등 6종) |
| `count` | 그 코드를 가진 **회사 수** | 행 수가 아니다(회사 안에서 코드는 UNIQUE 라 값은 같지만 뜻이 다르다) |
| `amtCount` | 그중 금액이 있는 회사 수 | 표의 「금액 있음」 |

- **동률은 「이름 길이 오름차순 → 코드포인트」** 로 가른다. 길이가 먼저인 이유: 86종 중 **26종은 이름이 전부 1회씩**이라 라벨이 tie-break 로만 정해지는데, 코드포인트 순은 라틴·숫자·괄호를 한글 앞에 세워 「KB 패밀리데이」가 야유회 코드의, 「Global MBA/유학」이 대학원비 코드의 이름이 됐다 — 한 회사의 표기가 86종 전체의 이름이 된 것이다(2026-09-06 실데이터 검증). 짧은 쪽은 대개 수식어 없는 일반명이다. 마지막 키가 로케일이 아닌 이유: 파이썬(표)과 JS(칩)가 사전을 각자 만드는데 `localeCompare('ko')` 는 파이썬의 코드포인트 비교와 달라 같은 코드가 **두 이름**을 갖게 된다.
- 카테고리 안 표시 순서(보유 회사 수 내림차순 → 라벨)도 **양쪽이 같아야 한다** — 칩 줄과 정적 표가 같은 순서라는 약속이다. JS 가 로케일 정렬을 쓰는 동안 네 카테고리에서 갈려 있었다.
- 두 구현이 같은 것을 고르는지는 **저장소 안 픽스처**가 잰다: `generator/tests/data/find_label_cases.json`(실 번들의 코드→이름 빈도표 86종 + 카테고리 순서). 파이썬·JS 테스트가 같은 파일을 읽어 같은 기대값을 검사하므로 CI 에서도 돈다. 번들이 크게 바뀌면 다시 뽑는다(생성 절차는 handoff).
- `benefit_cd` 가 없는 행은 건너뛴다 — 코드가 이 화면의 축이고, 이름으로 대신 묶으면 다른 항목이 한 칸에 뭉친다.
- 금액은 `qual_yn` 이 참이면 0이다. 실데이터에서 정성과 금액은 배타(1,398 / 634)지만, 재직자가 금액을 비운 채 저장하면 깨지므로 둘 다 본다.

## SP-FIND-3 — 표시명 중복 해소

실데이터에 대표 이름이 겹치는 코드가 두 뭉치 있다: 「통근버스」(`transport` 24곳 · `commute_subsidy` 44곳)와 「장기근속 포상」(`long_service_leave` 54 · `long_service_bonus` 21 · `long_service` 1, 구 코드).

- 이 다섯은 **손으로 못 박는다**(`LABEL_OVERRIDE`). 자동 별칭 병기만 쓰면 「통근버스 · 교통비」/「통근버스 · 야간 교통비」처럼 둘 다 헷갈리는 이름이 나온다.
- 그 밖의 중복은 `대표 이름 · 첫 별칭`(별칭이 없으면 `대표 이름 · 코드 id`).
- override 표는 `generator/pages/find.py` 와 `web/assets/js/find.js` 양쪽에 있고 **문자열로 같음을 강제**한다(`test_find_page.py::test_label_override_matches_the_js_module`).
- 실데이터 126사에서 중복 표시명 0을 확인했다(2026-09-06).

## SP-FIND-4 — URL·매칭·정렬

```
/find?b=코드,코드&m=and|or&tp=large&ind=반도체&amt=1&sort=match|amt|total|name
```

- **기본값은 URL 에 싣지 않는다** → 왕복(parse→build→parse)이 항등이고 공유 링크가 짧다. 쉼표는 `%2C` 로 굽지 않는다(RFC 3986 sub-delims, 사람이 읽는 링크).
- 검색 제안 순위는 **일치 정도(정확 → 접두 → 포함) → 보유 회사 수 → 이름**이다. 보유 수만 보면 「사택」이 별칭에 「주택자금/사택」을 가진 `housing_loan`(68곳)을 먼저 내놓고 이름이 정확히 「사택」인 `dormitory`(32곳)는 둘째가 된다. Enter 는 목록의 **첫 항목**을 고르고, 그것이 회사면 그 회사 페이지로 간다.
- **알 수 없는 값은 조용히 기본값**으로 떨어진다. 코드·유형·업종은 번들에 있는 값만 살린다 — 없는 값을 링크로 받으면 결과 0건이 되는데 사용자에게는 "조건을 잘못 골랐다"로 보인다.
- 매칭: `and`(기본) = 고른 코드를 전부 가진 회사, `or` = 하나라도. 유형·업종은 조건이 없어도 걸린다.
- **「금액 적힌 항목만」** = 고른 항목 중 금액이 있는 것만 hit 로 센다 → AND 에서는 「고른 항목 **전부**에 금액이 있는 회사」가 남는다. 조건이 없으면 hit 자체가 없어 아무 일도 하지 않는다.
- 정렬: `match` 맞는 수 → 금액 합 → 전체 항목 수 → 이름 / `amt` 금액 합 → 맞는 수 → 이름 / `total` 항목 수 → 이름 / `name`. **동률은 언제나 회사명**으로 끝나 순서가 흔들리지 않는다.
- 결과는 30개씩(「더 보기」). 조건이 없으면 전체 회사 + 행마다 금액 큰 항목 3개.

## SP-FIND-5 — 화면·렌더 안전

- 결과 행: 로고 이니셜 · 회사명(→ `/company/<slug>`) · 유형 · 업종 · 복지 N개 · **고른 항목별로** 실제 명칭 / 연 환산 금액(명시=`--blue` · 추정=`--amber`, 없으면 「금액 미기재 · 조건형」) / 조건 문장 1줄 · 비교 A·B(`--purple`) · 회사 페이지 →.
- 해시태그를 쓰지 않는다. 「#휴양시설」 세 글자보다 「휴양시설 — 연 120만원(명시), 콘도 제휴」가 근거다.
- 비교 담기: 같은 회사를 A·B 로 둘 다 고를 수 없고, **둘 다 찼을 때만** `/?a=<eng>&b=<eng>` 링크를 연다(한 곳만 고른 링크는 입력 뷰로 떨어진다 — 비교 툴의 「입력 뷰 자격 = 두 슬롯」 규약).
- **렌더는 전부 `dom.js::el`**(textContent·setAttribute). 회사명에 `&` 가 들어가고(삼성E&A) 복지 설명은 회사가 쓴 자유 문장이라, 데이터 문자열이 `innerHTML` 에 닿는 경로를 만들지 않는다(NFR21).
- slug 를 만들 수 없는 회사는 **링크를 만들지 않는다**(404 로 가는 링크는 링크 없는 것보다 나쁘다).

## SP-FIND-6 — 접힘 알고리즘(변형 B)

스크롤을 내리면 덱이 한 줄(minibar)로 접히고 맨 위로 돌아오면 펼쳐진다. 네 가지가 **함께** 있어야 조용하다:

1. **스크롤 앵커링을 끈다**(`overflow-anchor:none`). 브라우저도 우리도 같은 스크롤을 보정하면 화면이 두 번 움직인다. CSS 전역이 아니라 `find.js` 가 이 페이지에서만, JS 가 켜졌을 때만 붙인다.
2. **높이 차이만큼 스크롤을 직접 보정**한다(`scrollBy`) — 보던 내용이 제자리에 남는다.
3. **그 보정이 만든 scroll 이벤트는 1회 무시**한다(`suppress`). 없으면 보정이 판정을 부르고 판정이 또 보정한다.
4. **접힘 문턱 = 덱 위쪽 + 펼친 높이 + 8px.** 보정으로 되돌아간 위치가 펼침 문턱(덱 위쪽 + 8px)보다 항상 아래여야 한다. 이 여유가 없으면 접자마자 펼침 문턱 안으로 들어가 진동한다.

**🚨 접힘의 실체는 CSS 다.** `find.js` 는 class 를 토글할 뿐이고 높이는 스타일이 만든다. 768 블록에 이 세 줄이 없으면 한 줄이 덱 **위에 추가**돼 고정 블록이 385→447px 로 **오히려 커진다**(2026-09-06 검증에서 실제로 그 상태가 잡혔다):

```css
.find-deckwrap.collapsed:not(.open) .find-deck,
.find-deckwrap.collapsed:not(.open) .find-summary { display:none; }
.find-deckwrap.collapsed:not(.open) .find-minibar { display:flex; }
.find-deckwrap.collapsed.open      .find-minibar { display:none; }
```

**덱은 사이트 헤더 아래에 붙는다.** 이 사이트 헤더는 `position:sticky; top:0; z-index:40`(57px)이라 `top:0` 인 다른 sticky 는 전부 그 밑으로 들어간다 — 접힌 한 줄과 「검색·조건 바꾸기」가 **클릭조차 안 되는**(되돌릴 길이 없는) 상태가 됐다. `top:var(--header-h)` 이고 그 토큰은 헤더 규칙 옆 `:root` 에 한 번만 적는다.

- 판정은 rAF 로 스로틀하고, 조건이 바뀌어 덱 높이가 달라질 때마다(= 매 렌더) 문턱을 다시 잰다.
- **무시 예약은 쓰이지 않고 남을 수 있다** — 문서 끝이거나 보정값이 반올림돼 0px 이면 브라우저가 scroll 이벤트를 내지 않는다. 스크롤이 실제로 안 움직였으면 즉시 되돌리고, 그래도 남으면 300ms 뒤 0 으로 턴다(안 그러면 사용자의 다음 스크롤 판정 한 번이 사라진다).
- **폭 768px 미만에서는 고정도 접힘도 없다.** 이 값은 `styles.css` 의 유일한 분기(`min-width:768px`)와 **같아야 한다** — 이 디자인 시스템은 분기가 하나이고 `max-width` 분기를 금지한다(UT-BP). 프로토타입은 900 이었지만 그러면 768~900 에서 덱이 고정된 채 접히지 않아 화면 절반을 먹는다.
- 요소가 하나라도 없으면 아무것도 하지 않는 컨트롤러를 돌려준다(마크업이 바뀌어도 페이지는 산다).

## SP-FIND-7 — 비-JS 본문(정적 셸)

- 도구(`[data-find-tool]`)는 `hidden` 으로 나가고 번들을 받은 뒤에 열린다. 번들 로드가 실패하면 도구는 닫힌 채 안내 한 줄만 뜬다.
- 정적 본문 = **카테고리 9개 × 코드 86종의 보유 회사 수 표**. 도구가 켜져도 **숨기지 않는다** — 크롤러가 보는 것은 이쪽이 전부이고(도구는 JS 라 색인되지 않는다), 표의 각 줄이 `/find?b=<code>` 로 도구에 들어가는 입구가 된다. 실데이터에서 태그 제외 본문 약 5,190자.
- 표는 `.table-scroll` 안에서만 가로 스크롤한다(SP-GEN-5.8 / SPEC 10 MD-4).
- `page_type` 미선언 = 광고 0(검색 화면 무광고 규약).
- 템플릿의 `data-*` 훅은 마크업과 `find.js` 사이의 **계약**이다. 하나가 빠지면 화면이 에러 없이 절반만 그려지므로 양쪽 테스트가 훅 집합의 포함을 강제한다.
