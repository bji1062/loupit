## SP-CMP-3 — 정직성: 빈칸은 언제나 「등록 없음」

스키마에는 「이 회사에 이 제도가 없다」를 적는 곳이 없다(긍정 행만). 따라서 A 에 있고 B 에 없는 코드는 **「B 등록 없음」**이지 「B 제도 없음」이 아니다. 임의 쌍에서 한쪽만 있는 행이 합집합의 중앙 71.4%라 이 표기를 틀리면 화면 대부분이 거짓이 된다.

- 셀·판독문·막대 라벨·목록 머리·aria-label 전부 **「등록 없음」**. 「없음」·「미제공」·「—」·숫자 0 금지. 숫자 0 을 「등록 없음」으로 바꾸는 함수는 **하나**(`fmt`)이고 모든 렌더가 그것을 쓴다.
- 범례 고정: 「'등록 없음'은 이 사이트에 등록되지 않았다는 뜻이며, 제도가 없다는 확인이 아닙니다.」
- 근무형태는 `true` 만 사실로 쓰고 `false/null` 은 「표기 없음」(overtime 은 126사 전부 null).
- **금액 합계·순위·「더 낫다/우세」 어휘 금지**(항목 수는 질이 아니다 — D-6, 대출 한도·일회성 포상 혼입). `benTotal`·`renderBenefitHeadline` 을 모드 A 에서 부르지 않는다. 도형 넓이·막대 길이를 점수로 바꾸는 문장을 두지 않는다.
- 금액 옆 칩은 **금액 출처**(`amt_source`: 「공식 수치」/「추정치」)다. 출처 계보 배지(`badge_cd`)는 2,032행 전부 official 이라 모드 A 화면에서 **섹션째 뺀다**(모든 쌍이 같은 결과). 두 축을 한 낱말 「공식」으로 섞어 쓰지 않는다.

## SP-CMP-5 — 카테고리별: 나비차트 + 카테고리 클릭 펼침 (2026-09-12 확정)

덤벨(점 두 개 + 선)은 첫눈에 읽기 어렵다는 사용자 피드백으로 **나비차트**를 채택했다(덤벨 병기안은 폐기, 아티팩트에 기록만 남긴다).

- 한 줄 = 카테고리. 가운데 **카테고리 버튼**, 왼쪽으로 A 막대, 오른쪽으로 B 막대(인구 피라미드 문법). 막대 길이 = 등록 항목 수, 눈금은 양쪽 0~8 로 같고(9각형과 같은 자), **세로 눈금 = 126개사 평균**을 양쪽에 찍는다.
- 막대 끝에 숫자(굵게). **「등록 없음」은 길이 0 막대라 글자로 찍고, 평균 눈금 바깥에 둔다**(겹침 실측).
- 막대 색 = 슬롯 색(A `#2F7D43` · B `#2A78D6`). 막대는 사각(둥근 끝 없음 — 프로덕션 표 스타일과 같이), 높이 14px, 행 32px.
- **카테고리 버튼을 누르면** 그 카테고리에 **각 회사가 등록한 복지 목록**이 아래로 펼쳐진다 — 왼쪽 A 목록, 오른쪽 B 목록. 줄 = 항목명 + 연 환산 금액(만원) + 「공식 수치/추정치」 칩, 금액이 없으면 「정성」 표식. 목록 머리 = 「{회사} · {카테고리} N항목」, 0 이면 「등록 없음」. **코드로 짝짓지 않고 설명 원문도 싣지 않는다** — 짝짓기·설명·밴드 판정은 항목 대조표·금액 맞대결의 몫(사용자 결정: 펼침은 목록만). 다시 누르면 접힌다. 「모두 펼치기/접기」 하나.
- 마크업 계약: 버튼 `aria-expanded`·`aria-controls`, 패널 `hidden`. 항목 목록은 `dom.js::el` 로만(항목명은 회사가 쓴 자유 문장, NFR21). **JS 가 없으면** 막대·숫자·「등록 없음」 글자는 그대로 보이고 항목은 아래 항목 대조표가 대신한다(패널은 닫힌 채).
- 얻는 것: 좌우 대칭이라 「어느 쪽이 더 많은가」가 즉시 읽히고, 카테고리 → 항목 동선이 화면 하나에 든다. 비용: 막대가 반대 방향이라 두 길이를 직접 겹쳐 비교하지 못한다(차이 크기는 숫자가 말한다) · 펼침 상태가 URL 에 남지 않는다(v2).
- 표시 순서·라벨은 `CATEGORY_ORDER`·`CATEGORY_LABEL` 그대로(보상·유연성·근무환경·휴가·건강·가족·성장·여가·복리후생).

## SP-CMP-6 — 항목 대조표 · 금액 맞대결 (유지)

- **항목 대조표는 그대로 둔다**(2026-09-12 결정). 합집합 행(중앙 25, p90 32)이 스크롤 본체이고 `benefit_cd` 로 짝짓는다(`report.js` 와 같은 키). 한쪽 셀은 「등록 없음」, 숨기지 않는다(한쪽만 있는 행이 곧 차별점이고 숨기면 거짓 동률).
- 정성 행은 값(설명 원문)만, 칩 없음. 금액 행은 금액 + 금액 출처 칩.
- **금액 맞대결** = 양쪽 모두 금액이 적힌 공통 코드만(임의 쌍의 41.8%는 0개 → 0건이면 표 대신 문장 하나). **항목 판정** = 두 구간 `[amt×(1−c), amt×(1+c)]` 의 겹침. `c` 는 `calc.js bandCoeff(항목)` 과 같은 값(공식 ±5% · 추정 ±20% · 만료 +15%p) — 계수를 문서·JS 두 곳에 적지 않고 `bandCoeff` 를 import 하는 `pairVerdict(a, b, now)` 한 함수를 `calc.js` 에 두고 골든 테스트로 고정한다. 겹치면 「말할 수 없음」(값이 같으면 「같음」), 겹치지 않으면 큰 쪽. **총액 판정은 만들지 않는다.**
- 실측(NAVER vs 카카오, 2026-09-12): 공통 11 · 한쪽에만 17 · 합집합 28 · 양쪽 금액 5(종합건강검진·휴양시설 같음, 복지포인트·식대·명절 선물 NAVER 큼) · NAVER 금액 12(공식 7·추정 5) · 카카오 8(공식 2·추정 6).
