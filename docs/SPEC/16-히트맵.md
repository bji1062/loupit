# SPEC 16 — 복지·실적 히트맵 (SP-HEAT)

**상위 추적**: PRD SC16(2026-08-27) · SC12(랭킹/리스트 2차 검토 — 이 페이지가 그 시각화 실현) · SP-FIN(재무 로더·표현 규약 DEC-B) · SP-GEN(정적 생성·GC-20·sitemap) · 벤치마크 prober.kr `/product/heatmap/stockKor`(KRX 업종 29종 그룹·시가총액 크기·등락률 7단계 — 번들·API 실측).

**범위 경계**: 생성 페이지 1개(`/heatmap`)와 그 배치·색·업종 시드·탭 JS 를 소유한다. 재무 수치는 SP-FIN 로더를 그대로 소비하고, 스키마·API 는 건드리지 않는다.

## SP-HEAT-2 — 그룹 = KRX 업종 분류
- 종목코드(`TCORP.STOCK_CD`)로 CSV 매칭. 102곳 중 100곳(코드 99개 — CJ ENM 2페이지 1코드). 비상장·미매칭은 `비상장` 그룹, 추측으로 채우지 않는다.
- 왜: 우리 `INDUSTRY_NM` 67종은 1곳짜리 업종이 51개(비교판 실측) · 임의 대분류는 검수가 따라붙는다 · KRX 분류는 공식·자동. 원 업종은 툴팁(`title`)에 남긴다.
- DB 컬럼을 두지 않는다 — 소비처가 이 페이지뿐(`combinations.json` 관례).

## SP-HEAT-3 — 배치
- `nested_layout`: 그룹 squarify → 그룹 안 회사 squarify. 그룹 면적 = 가중치 합(그룹 순서 = 큰 순). 작은 그룹은 여백·머리줄을 줄여 **타일이 사라지지 않게**(첫 목업에서 15곳 소실 → 테스트 `test_nested_layout_keeps_every_member_even_in_tiny_groups`).
- 가로(100×62.5)·세로(100×133.3) 두 배치를 모두 렌더, 640px 미만에서 세로만 표시(CSS).
- 불변식(테스트): 면적 합 = 캔버스 · 경계 안 · 겹침 0 · 회사 누락 0.

## SP-HEAT-4 — 모드·색
| 모드 | 크기 | 색 | 대상 |
|---|---|---|---|
| 복지 `w` | 복지 항목 수 | 금액 합계(정량 항목만) **7분위** `c0~c6` 연두→진녹 | 전 회사 |
| 실적 `f` | 최신연도 매출(억) | 영업이익 전년 대비 `d0~d6` — 경계 −30/−10/−3/+3/+10/+30% | 일반 세트 + 2개년 있는 회사(금융업 제외) |
| 카테고리 `c` | 복지 금액(정성은 카테고리 최소 금액의 60% 최소 칸) | **출처** `s-stated`(회사 공식) / `s-est`(추정, 빗금) / `s-qual`(정성, 회색) | 9 카테고리 패널 × 안의 **항목 묶음**(`ITEM_LABEL`, 없으면 최빈 benefit_nm) × 복지 행 전부 |
- 카테고리 모드의 그룹은 업종이 아니라 항목이다 — "같은 식대인데 더 주는 곳"은 식대 묶음 안에서 본다. 색을 출처로 두는 이유: 정량 645건 중 공식 73건(11%)이라 금액 색은 추정 상수 줄 세우기가 된다. 추정·정성 칸 툴팁에 재직자 편집 안내(SC14 유입구).
- 재무 미적재 빌드는 실적 모드를 **내지 않는다**(SP-FIN-5 규칙 동일).
- 표현: 범례는 수치 구간, "읽는 법" 절이 추정치·평가 아님을 고지. 금지 어휘(성장성·등급·전망·우수·양호·추천) 가드 테스트 + FN-6 전역 가드에 편입.

## SP-HEAT-5 — 페이지·배선
- `Page(path="heatmap.html", url=/heatmap, in_sitemap=True)` · `nav_active="/heatmap"` · `page_type` 미선언(광고 0) · `base.html` `css_extra` 블록으로 전용 CSS.
- 상단 탭 `히트맵`(GNB_TABS 홈·커뮤니티·회사정보·히트맵) — 수기 셸 8개 동기화(test_gnb_tabs).
- nginx `location = /heatmap`(dist, max-age=300) prod·beta — 수동 배치(함정 ⑭).
- JS 없이: 모드 3개(카테고리 9패널 포함)가 세로로 나란히. JS: 탭·칩 전환 + `?mode=f`·`?mode=c&cat=perks` 복원(`activate`·`activatePanel` 순수 함수).

## SP-HEAT-7 — 강조(2026-08-27 후반, prober 동작 + 확장)
- prober 히트맵은 칸에 마우스를 올리면 그 칸과 **소속 그룹 사각형**을 함께 칠한다(파란 stroke 2px/1.5px). 같은 동작을 class 토글로 구현하고 **같은 회사의 다른 칸**(카테고리 모드에서 한 회사가 여러 항목 묶음에 흩어진다)을 점선으로 더한다.
- 연결 정보는 **정적 HTML** 에: 칸 `data-g`(그룹 키)·`data-c`(회사 slug), 그룹 `data-g`·`data-nm`. 그룹 키는 패널마다 이름 정렬 순 `g0…` 이고 **가로·세로 배치가 공유**한다(배치별로 번호를 매기면 어긋난다 — `_group_keys`).
- 묶음 이름은 그룹 요소에만 둔다 — 칸 2,930개에 중복 출력하면 정적 HTML 이 약 90KB 커진다(실측).
- `heatmap.js`: `highlight(map, tile)` → `{group, peers, groupEl}` · `clearHighlight` · `readoutText(tile, group)` · `bindMap`(mouseover·focusin / mouseleave·focusout). 관련 요소 몇 개만 건드린다(1,400칸 일괄 dim 금지).
- **판독줄**(`[data-readout]`, `aria-live=polite`): 작은 칸(xs·sm)은 글자가 들어가지 않으므로 닿은 칸의 묶음·회사·수치를 문장으로 띄운다. 키보드 포커스도 같은 강조·판독을 받는다.
- JS 가 없으면 강조가 없을 뿐 문서는 그대로 완결이다(`title` 툴팁은 브라우저가 그린다).
