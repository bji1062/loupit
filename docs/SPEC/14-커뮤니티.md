## SP-COMM-3 — 4테이블 컬럼 계약 (DDL 은 SP-DB-18)

공통: T-접두 · `_CD/_NM/_CTNT/_CNT/_DTM` 접미 · 감사 4종 · ENUM 금지(값집합은 앱 강제) · utf8mb4.

| 테이블 | 핵심 컬럼 | 제약·의도 |
|---|---|---|
| `TPOST` | `POST_ID` PK · `MBR_ID` FK→TMEMBER **ON DELETE SET NULL** · `CATEGORY_CD` VARCHAR(12) ∈ {notice,free,career,suggestion} · `TITLE_NM` VARCHAR(100) · `BODY_CTNT` TEXT · `COMP_ID` FK→TCOMPANY NULL **ON DELETE SET NULL** · `LIKE_CNT` INT 0 · `COMMENT_CNT` INT 0 · `STATUS_CD` VARCHAR(12) ∈ {active,deleted,hidden} · `EDITED_YN` BOOL 0 | `INDEX (STATUS_CD, CATEGORY_CD, POST_ID)` · `INDEX (STATUS_CD, LIKE_CNT, POST_ID)` · `INDEX (STATUS_CD, COMMENT_CNT, POST_ID)` · `INDEX (COMP_ID, POST_ID)`. **VIEW_CNT 없음.** 회원 삭제(TMEMBER 행 삭제는 없지만) 시 SET NULL 존치 = 편집 이력 규약 |
| `TPOST_COMMENT` | `COMMENT_ID` PK · `POST_ID` FK **CASCADE** · `MBR_ID` SET NULL · `BODY_CTNT` VARCHAR(1000) · `STATUS_CD` ∈ {active,deleted,hidden} | `INDEX (POST_ID, COMMENT_ID)` |
| `TPOST_REACTION` | `POST_ID` FK CASCADE · `MBR_ID` FK CASCADE · `REACTION_CD` VARCHAR(8) ∈ {like} | `UNIQUE (POST_ID, MBR_ID)` — 회원당 1회. PK 는 `REACTION_ID` |
| `TPOST_REPORT` | `REPORT_ID` PK · `TARGET_TYPE_CD` ∈ {post,comment} · `TARGET_ID` INT · `MBR_ID` SET NULL · `REASON_CD` ∈ {spam,abuse,privacy,other} · `DETAIL_CTNT` VARCHAR(300) · `STATUS_CD` ∈ {pending,actioned,dismissed} · `DECIDED_BY_ID` · `DECIDED_DTM` · `DECIDE_NOTE_CTNT` VARCHAR(500) | `UNIQUE (TARGET_TYPE_CD, TARGET_ID, MBR_ID)` 중복 신고 차단 · `INDEX (STATUS_CD, REPORT_ID)`. TARGET_ID 는 FK 가 아니다(두 테이블을 가리킨다) |

- 격리: `conftest.PARTICIPATION_CREATE_ORDER` 끝에 `TPOST → TPOST_COMMENT → TPOST_REACTION → TPOST_REPORT`(부모→자식). `run_tests.sh` 는 격리 전환(2026-08-26) 후 백업 목록이 없다 — 동반 수정 불요(test_runner_backup 이 그 부재를 지킨다).
- 닉네임은 **조인**으로 읽는다(`LEFT JOIN TMEMBER`). NULL 이면 "탈퇴한 회원".

## SP-COMM-4 — 읽기 (FR-121~123)

- 목록 SQL: `WHERE STATUS_CD='active' [AND CATEGORY_CD=%s] [AND POST_ID < %s] ORDER BY <sort> LIMIT %s+1` — 1건 더 읽어 `next_before` 판단. `sort=likes` → `ORDER BY LIKE_CNT DESC, POST_ID DESC`(커서는 POST_ID 만, 동률 경계 중복 수용 — FR-121).
- 재직자 배지: `TEMPLOY_VERIFICATION`(활성·미만료) 을 작성자 기준 LEFT JOIN 해 `verified_comp_nm`(회사명) 을 준다. 회사 태그와 같은 회사면 UI 가 "재직자" 로 표기.
- `optional_member`: `loupit_sid` 쿠키가 있으면 `resolve_session`, 실패해도 None(401 금지). `is_mine`·`liked` 계산 전용. **익명 GET 의 dependant 트리에 `require_member` 가 없다는 AU-2 계약은 유지된다**(optional 은 다른 심볼).

## SP-COMM-5 — 쓰기 (FR-124~129)

- 의존성 순서: `require_csrf` → `require_member` (→ 소유자 검사는 서비스에서 403).
- 공지: `category=='notice' and not is_operator(email)` → 403. 이메일은 `require_operator` 처럼 TMEMBER 재조회(세션은 MBR_ID 만 준다).
- 카운터(`LIKE_CNT`·`COMMENT_CNT`)는 **같은 트랜잭션**에서 `UPDATE … SET x = x ± 1`. 좋아요 토글은 `INSERT … ; UPDATE +1` 또는 `DELETE … ; UPDATE -1` 을 `database.transaction` 으로 묶는다(UNIQUE 충돌 = 이미 있음 → 삭제 경로).
- 소프트 삭제 마스킹: 글 `TITLE_NM='(삭제됨)', BODY_CTNT=''`, 댓글 `BODY_CTNT=''`. 원문 보존 없음.
- 일일 카운트: `SELECT COUNT(*) FROM TPOST WHERE MBR_ID=%s AND INS_DTM >= UTC_DATE()`(복지 편집 관례).

## SP-COMM-6 — 신고·콘솔 (FR-130·131)

- 접수 시 대상 존재·`active` 확인(404). UNIQUE 충돌 → 409.
- 콘솔 `queues` 에 `reports` 키 추가. `decide(hide)` 는 대상 테이블을 `STATUS_CD='hidden'` 으로 바꾸고, 같은 대상의 pending 신고를 전부 `actioned` 로. 글을 숨기면 `COMMENT_CNT` 등은 손대지 않는다(상세가 404 라 보이지 않음).
- 되돌릴 수 있는 것만(SP-AUTH-19.4): 하드 삭제 라우트 없음. `ops digest` 에 pending 건수.

## SP-COMM-7 — 입력 신뢰 경계 (FR-132)

Pydantic `model_validator(after)`: strip → 빈 문자열 422 · 제어문자(`\x00-\x08\x0b\x0c\x0e-\x1f`) 제거 · URL 3개 초과 422 · `category` 값집합 · `comp_id ≥ 1`. 저장은 바인딩, 응답은 원문(이스케이프는 표시 계층 `textContent`). 서버는 HTML 을 만들지 않는다.

## SP-COMM-8 — 프론트

- 셸 `web/community/index.html`: gnb(탭 + 검색 + authnav) · `<main id="community">` · noscript 안내 · 푸터. `data-page-type` **미선언** = 광고 0.
- `community.js` 라우터: `pathname` 을 `/community/` → list · `/community/write` → write · `/community/{id}/edit` → edit · `/community/{id}` → detail 로 매칭. History API 로 목록↔상세 전환(뒤로가기 보존). 전부 `textContent`/`createElement` 렌더(innerHTML 금지, `dom.js` 헬퍼 재사용).
- 로그인 상태: `getMe()` 프로브(authnav 와 동일 3분기). 401 이면 쓰기 버튼은 `/login?next=<path>` 링크. **`login.js` 에 `next` 지원 추가**(same-origin 경로만, `//`·`http` 거부).
- `api.js` 헬퍼: `listPosts`·`getPost`·`getComments`(apiFetch) · `createPost`·`updatePost`·`deletePost`·`createComment`·`deleteComment`·`toggleLike`·`submitReport`(apiSend).
- 초안: `loupit.community.draft`(localStorage, 24h, 화면별 키). 제출 성공 시 삭제.
- 테스트: `community.test.js`(라우터 순수 함수·렌더 XSS·초안 만료), `api.test.js` 확장, `login.test.js` next 검증.
