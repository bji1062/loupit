# 커뮤니티 (USECASE)

**목적**: 익명 열람·비교(A1·A2)와 인증 기여자(A6)의 복지 편집 위에, **회원 A6 가 글·댓글·좋아요·신고로
참여하는 카테고리 게시판**(SC15, 2026-08-27 증분)의 상호작용을 표준 유즈케이스로 정의한다. 벤치마크는
prober.kr 커뮤니티(카테고리·정렬·글쓰기 로그인 필수·댓글·좋아요)이며, 우리 결정은
`docs/PLAN-커뮤니티-회사정보탭-2026-08-27.md` §1·§3-2 가 정본이다.

**상위 추적**: PRD 범위 SC15(In-scope 증분)·SC10(소셜피드 = 팔로우·타임라인·개인화 피드, 영구 제외)·
NFR16·NFR20·NFR21·NFR31. 기능 계약은 FRD 14(커뮤니티 API), 구현 계약은 SPEC 14(SP-COMM). 로그인·세션은
SC14(USECASE 09 UC-70·71)를 **그대로 재사용**한다 — 커뮤니티가 새 인증 방식을 만들지 않는다.

**범위 경계**: 열람(UC-80·81)은 로그인 없이 그대로다. 쓰기(UC-82~86)는 **로그인 세션 필수**, 재직 인증은
요구하지 않는다(재직 인증자의 글에는 '재직자' 배지만). 조회수·대댓글·싫어요·인기 TOP·알림은 1차 범위 밖이다.
소셜피드(팔로우·타임라인)는 어떤 UC 에도 등장하지 않는다(SC10).

**공통 사전조건(쓰기 UC: UC-82~86)**

1. 세션 쿠키(`loupit_sid`)가 유효하다(UC-71). 없으면 401 → 화면은 `/login?next=<현재 경로>` 로 보낸다.
2. 쓰기 요청은 `X-Loupit-Client` 헤더를 동반한다(CSRF, FR-113 규약 그대로).
3. 계정·일 단위 상한이 있다: 글 10건/일 · 댓글 50건/일 · 신고 20건/일(NFR31 계열, FR-132).
4. 표시는 `textContent` 로만 한다(마크다운 없음, 줄바꿈만). 본문에 URL 은 3개까지(스팸 경계).

## UC-80 게시글 목록 열람

- **사전조건**: 없음(익명).
- **기본 흐름**: ① `/community/` 진입 → ② 기본 필터 `전체`·정렬 `최신` 으로 20건 → ③ 카테고리 탭(공지·자유·이직 고민·건의사항) 또는 정렬(최신·댓글·좋아요) 변경 → ④ "더 보기" 는 마지막 `post_id` 를 커서로 다음 20건.
- **표시 항목**: 카테고리 · 제목 · 작성자 닉네임(+재직자 배지) · 작성일 · 댓글 수 · 좋아요 수 · 회사 태그. **조회수 없음.**
- **대안 흐름**: 목록이 비면 "아직 글이 없어요 — 첫 글을 남겨 보세요"(로그인 상태면 글쓰기 버튼).
- **예외**: API 실패 시 재시도 버튼(비교 도구 FR-E1 패턴). 본문 표시는 JS 필요(noscript 안내).

## UC-81 게시글 상세 + 댓글 열람

- **기본 흐름**: ① `/community/{post_id}` → ② 글 본문(줄바꿈 보존·이스케이프) + 좋아요 수 + 댓글 목록(오래된 순, 커서 페이징) → ③ 로그인 상태면 댓글 입력창·좋아요 버튼·(본인 글이면) 수정/삭제·신고 버튼 노출.
- **대안**: `deleted`/`hidden` 글은 404("삭제되었거나 숨겨진 글입니다"). 삭제된 댓글은 자리만 "삭제된 댓글입니다".
- **회사 태그**: 있으면 회사 페이지(`/company/{slug}`) 로 링크.

## UC-82 게시글 작성

- **사전조건**: 로그인 세션.
- **기본 흐름**: ① `/community/write` → ② 카테고리(자유·이직 고민·건의사항. **공지는 운영자 계정에만 노출**) · 제목(≤100) · 본문(≤5,000) · 회사 태그(선택, 등록 회사 검색) → ③ 제출 → 201 → 상세로 이동.
- **초안**: 입력 중 localStorage 에 24h 보존(비교 입력 초안 관례) — 로그인 만료로 401 을 받아도 글이 날아가지 않는다.
- **예외**: 422(길이·공백-only·URL 초과·카테고리 오류) · 403(일반 회원이 공지) · 429(일일 상한 — "내일 다시").

## UC-83 게시글 수정·삭제

- **사전조건**: 로그인 + **본인 글**.
- **수정**: `/community/{post_id}/edit` → 제목·본문·회사 태그 → PUT → 상세로. 카테고리는 바꿀 수 없다(공지↔일반 우회 차단).
- **삭제**: 확인 후 DELETE → **소프트 삭제**(`STATUS_CD=deleted`, 본문 마스킹, 댓글은 존치하되 상세가 404 라 보이지 않음) → 목록으로.
- **예외**: 남의 글 403 · 삭제된 글 404.

## UC-84 댓글 작성·삭제

- **작성**: 상세 화면 입력창(≤1,000) → POST → 목록 갱신, `COMMENT_CNT` +1.
- **삭제**: 본인 댓글만, 소프트 삭제("삭제된 댓글입니다"), `COMMENT_CNT` −1.

## UC-85 좋아요 토글

- 회원당 글 1회. PUT 은 **토글**이며 멱등 — 응답 `{liked, like_cnt}` 로 버튼 상태를 맞춘다. 본인 글에도 가능(제한 없음, 단순화).

## UC-86 신고

- **대상**: 글 또는 댓글. 사유(스팸·욕설/비방·개인정보·기타 + 300자 이내 설명) → POST → 202 "접수됐습니다".
- 같은 회원이 같은 대상을 두 번 신고하면 409(중복). 신고는 즉시 숨기지 않는다 — 운영자가 본다(UC-87).

## UC-87 신고 처리(운영 콘솔)

- **사전조건**: SSH 터널 + 운영자 세션(SP-AUTH-19).
- **흐름**: 콘솔 큐에 신고 대기 목록(대상 발췌·사유·건수) → `hide`(대상 `STATUS_CD=hidden`) 또는 `dismiss` → `DECIDED_BY_ID` 자동 주입.
- **되돌릴 수 있는 것만**: 하드 삭제 없음. 숨김 해제는 같은 콘솔에서(2차, 1차는 DB 직접).
- **일일 요약**: `ops digest` 에 "신고 대기 N건" 한 줄.
