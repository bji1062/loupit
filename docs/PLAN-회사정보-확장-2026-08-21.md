# 회사 정보 확장 계획 — 재무·뉴스 (2026-08-21)

> **목적**: 회사 페이지에 복지 외 정보(실적 추이·기사)를 얹어 ①페이지 얄팍함을 해소하고
> ②체류시간을 늘린다. 사용자 요구에서 출발했다 — *"복지만 비교하고 가기에는 머무는 시간이
> 적다. 지금 이 회사는 어떤가 궁금해서 기사도 보고, 영업이익은 어떤지 확인 가능하게."*

---

## 0. 왜 지금인가 — 세 증상이 한 뿌리였다

2026-08-21 실측으로 확인된 것:

| 증상 | 실측 |
|---|---|
| 애드센스 **거절** | 배선은 정상(`static-ads.js` 로드·슬롯 예약). 코드 문제가 아니다 |
| 구글 크롤 거의 없음 | 진짜 Googlebot 200 응답이 3주간 손에 꼽음. 네이버는 색인 114건 정상 |
| 유입 없음 | 실세션 하루 **1~4**, `TCOMPARE_LOG` 3주간 **2행** |

원인은 하나다 — **회사 페이지 102개 본문 중앙값 1,402자, 1,000자 미만 20개**(최소 520자
알테오젠). 전수 측정(`web/dist/company/*.html`, 태그·스크립트 제거 후 `wc -m`).

그리고 **가용 복지 데이터는 이미 100% 렌더된다**(`qual_desc_ctnt`·`note_ctnt` 전부 출력 중,
2026-07-20 실측). 회사당 복지 평균 14.4행이 페이지 두께의 상한을 만든다 —
**회사를 더 추가해도 페이지는 두꺼워지지 않는다.** 새 축의 데이터가 필요하다.

## 1. 확정 결정 (2026-08-21)

- **DEC-A: 소스는 OpenDART(공식 오픈 API).** `docs/RESEARCH/benefit-scraping.md` §2 가 이미
  **1군(보강)** 으로 티어링해 둔 소스다 — *"공식 API 직접 호출(크롤링 불필요). 정식 API,
  출처표시 조건 재배포 허용."* 크롤링이 아니므로 잡플래닛·블라인드류의 봇차단·DB권 리스크와
  성격이 근본적으로 다르다.
- **DEC-B: 표현은 "사실만".** 수치·증감률·추이만 제시하고 **해석은 사용자에게 맡긴다.**
  - ✅ `2025년 영업이익 1조 2,340억 (전년 대비 +18.2%)` — 공시 사실
  - ❌ `성장성 A등급` · `성장 전망 양호` — 우리의 평가 = **투자자문 오인 위험**
- **DEC-C: 기사는 제목 + 날짜 + 출처 + 아웃링크만.** 본문 복제 금지(기존 원칙
  "원문 미복제·사실만 재서술·출처 아웃링크" 그대로).
- **DEC-D: 재무 먼저, 뉴스 나중.** 재무는 공시라 안정적이고 **영구 콘텐츠**가 되지만,
  뉴스는 계속 바뀌어 **정적 생성 구조와 충돌**한다(회사 페이지가 정적 → 재생성 주기 설계 선행).

## 2. ⚠ "성장성"은 한 달 전에 폐기됐다 — 부활이 아니다

2026-07-20 에 브랜드 축(성장성·안정성)을 엔진·UI·서버·테스트에서 **통째로 제거**했다
(`docs/ANALYSIS-성장성-용어-2026-07-20.md` §6-1 (c)). **폐기 이유가 지금 하려는 것과 정반대다:**

```
당시 성장성 = 회사 유형별 상수     large 4.0% · mid 2.7% · startup 10%
            ↑ 텔레칩스의 성장률이 아니라 "중견기업이면 2.7%"
```

**회사별 실측이 아니라 유형 상수를 회사 지표인 양 보여줬기 때문에** 걷어냈다. 지금 얹으려는
것은 회사별 실제 공시 수치다 — **폐기는 이 방향의 반증이 아니라 근거다.**

- ⚠ **같은 이름(`성장성`)을 재사용하지 마라.** 폐기 이력과 뒤섞이고, 무엇보다 DEC-B(사실만)를
  어기는 이름이다. 실적/실적 추이 같은 중립어를 쓴다.
- ⓘ 실측 결과 `TCOMPANY_TYPE` 에 `GROWTH_RATE_VAL` 컬럼은 **이미 없다**. 분석 문서 §6-1 은
  "DB 컬럼·시드는 의도적으로 남겼다"고 적혀 있으나 그 뒤 마이그레이션으로 제거된 것으로
  보인다 — **죽은 컬럼을 잘못 재사용할 위험은 없다.**

## 3. 🚨 매칭 목록에서 드러난 설계 이슈 — "영업이익 한 줄"이 성립하지 않는다

102개 회사명을 실제로 뽑아보니, **회사마다 "영업이익"의 의미가 다르다.** 이걸 무시하고
한 줄로 나열하면 틀린 정보가 되고, 배지 계보로 쌓아온 신뢰를 깎는다.

| 군 | 회사 | 문제 |
|---|---|---|
| **금융업** | DB손해보험 · NH투자증권 · 기업은행 · 삼성생명 · 삼성카드 · 카카오뱅크 · 카카오페이 | **재무제표 양식 자체가 다르다.** 매출액 대신 **영업수익**을 쓰고 제조업 영업이익과 의미가 다르다. 같은 표에 나열하면 잘못된 비교 |
| **지주회사** | LG · LS · 두산 · 한화 · 삼성물산 | **연결 vs 별도**의 차이가 극단적이다. 순수지주는 별도 기준 매출이 배당·상표권 수익뿐 |
| **동일 법인 2페이지** | CJ ENM 엔터테인먼트부문 · CJ ENM 커머스부문 | DART 상 **한 법인**이다. 사업부문 분리는 우리 서비스의 구분이지 공시 단위가 아니다 → 그대로 붙이면 **두 페이지에 똑같은 숫자**가 나온다 |
| **비상장** | CJ올리브네트웍스 · CJ올리브영 | 상장사와 공시 범위·주기가 다르다(감사보고서 기준). CJ올리브영 상장 여부는 **확인 필요** |

**→ 설계 요구사항:**
1. **업종별 지표 세트를 분리**한다(제조·서비스 = 매출액/영업이익 · 금융 = 영업수익/순이익).
2. **기준(연결/별도)을 화면에 명시**한다. 숨기면 그 자체가 부정확한 주장이 된다.
3. **법인 단위와 페이지 단위를 분리**한다 — CJ ENM 2페이지가 1법인을 가리키는 구조를 스키마가
   표현할 수 있어야 한다(`corp_code` 는 회사당 1:1 이 아니다).
4. 데이터가 없는 회사는 **비워 두고 그렇게 말한다.** 없는 자리를 추정으로 채우지 않는다.

⚠ **계열사 오매핑 전력이 있다** — bokziri 집계 770개 중 **148개가 회사명 오염**이었고,
`CJ.sql` 이 실제로는 CJ올리브네트웍스였다. 위 목록에 CJ 계열이 6개, 삼성 6개, 현대 6개,
한화 4개, 카카오 4개, LG 5개다. **회사명 문자열 매칭은 반드시 사람 검수를 거친다.**

ⓘ 자산: `TCOMPANY_ALIAS` **264행**(예: `CJ CGV` → `CGV`·`CJCGV`·`씨지브이`)이 이미 있어
매칭 후보 생성에 재사용할 수 있다. 다만 별칭은 **검색용**이지 법인 식별용이 아니다.

## 5. 함정 (착수 전 필독)

- **`web/assets` 저장 = 즉시 프로덕션.** 라이브 문서루트다(2026-07-20 실사고).
- **스키마 테이블 추가 시 `conftest` + `run_tests.sh` 편입 필수.** 빠뜨리면 테스트가 그 구간에 없다.
- **번들에 필드 추가 시 `server/models/reference.py` 도 함께.** Pydantic 이 조용히 필드를 떨군다
  (함정 (55)). 클라이언트 화이트리스트 정규화도 같은 실패를 한다(함정 (64)).
- **회사/데이터를 추가하면 정적 재생성 필수.** 안 하면 라이브에 반영되지 않는다.
- **픽스처가 파이프라인을 건너뛰는 테스트는 그 구간에 없는 것과 같다**(함정 (54)·(64)).
  실제 데이터 경로 전체를 통과하는 회귀 테스트를 최소 1개 둔다.
- **개인정보 처리방침**: 재무·뉴스는 외부 공시/공표 정보라 개인정보 수집이 아니다. 다만
  **수집 시점·범위·주체를 건드리는 변경은 문안을 같은 커밋에서 옮긴다**(함정 (61)).
  처리방침은 정적 생성물이라 `policy.py` 수정 + 재생성까지 해야 라이브에 반영된다.

## 5-2. 🚨 수집 파이프라인 함정 — `sj_div` 로 거르면 회사마다 조용히 빈다

지표는 **`account_nm`(이름)이 아니라 `account_id`(표준계정 ID)로 조회**해야 한다.

| 지표 | account_id |
|---|---|
| 매출액 | `ifrs-full_Revenue` |
| 영업이익 | `dart_OperatingIncomeLoss` |
| 당기순이익 | `ifrs-full_ProfitLoss` |

**실제로 놓칠 뻔했다**: 첫 시도에서 `sj_div=='IS'` 로 걸렀더니 **SK하이닉스 영업이익이
사라졌다** — 이 회사는 손익을 `IS` 가 아니라 **`CIS`(포괄손익계산서)** 에 싣는다. 회사마다
제표 구분이 달라서, `sj_div` 로 거르면 **에러 없이 그 회사만 항목이 빈다.** 함정 (57)과 같은
계열(정상 동작과 소멸이 구분되지 않는다) → **수집기에 "회사별 필수 지표 결측" 검사를 넣는다.**

제조   SK하이닉스   매출   971,467억 / 영업이익 472,063억 / 순이익 429,479억   ✅ (CIS 경유)

넣으면 빈칸이 되거나 다른 의미의 숫자가 들어간다.

## 6. 미결
