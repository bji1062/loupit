### 1-B. P3 ③⑤ (같은 날 후반 세션)

**③ 429 에 `Retry-After`** — `conf.d/loupit-limits.conf` 에 `map $status $loupit_retry_after`
(429→20, 그 외 빈 값) + 메일 `=` 블록 **4곳**(prod·beta × login-code·verify-code)에
`add_header … always`. `api.js` 가 10진 정수로만 파싱해 `ApiError.retryAfter` 에 싣고
`login.js`·`verify.js` 가 "20초 뒤에 다시 시도해주세요"로 노출한다.

> **왜 `map` 인가 — 격리 하네스 실측(nginx 1.18.0)이 셋을 갈랐다.** 더미 업스트림 + `proxy_pass`
> 필수(함정 ①):
>
> | 형태 | 204 | 403 | 429 |
> |---|---|---|---|
> | 정적 `add_header Retry-After 20 always` | **20 오부착** | 부착 | 부착 |
> | `map` + `always` 없음 | 미부착 | 미부착 | **미부착** |
> | `map` + `always` | 미부착 | 미부착 | **20** ✅ |

**⑤ 타임아웃 순서** — `MAIL_TIMEOUT = 25000` 을 메일 발송 **2종에만**. 이제
**SMTP 8s < 엣지 18s < 프론트 25s**. 엣지 기준선은 `proxy_read_timeout`(15s) 혼자가 아니라
`proxy_connect_timeout 3s` 를 더한 **18s** 다 — 브라우저 타이머는 `fetch()` 즉시(DNS·TLS 전)
시작하므로 20s 로는 느린 회선에서 여전히 브라우저가 먼저 끊는다. `_SMTP_TIMEOUT_SEC` 는 8 유지
(핸드오프의 "4~5 로 낮추기" 대안은 채택하지 않았다 — 개별 소켓 연산 상한이라 총 소요를 못 묶는다).

**회귀 가드**: 프론트 +18개 · `MG-8`(엣지<프론트, 전역 상향 아님) · `MG-9`(4블록 전수+map 형태) ·
스모크 `SM-23`·`SM-23b`(**추가 요청 0건**) · `rollback-nginx.sh` map 고아 검사. **전부 red 확인 후 green.**

**적대검토(27 에이전트) 23건 제기 → 10건 생존 → 전건 반영.** 무거운 것 넷:

1. **`verify.js` 늦은 204 레이스**(신규 발견). '보내는 중…' 대기 중 '변경' 버튼은 안 잠긴다

   되살려 **회사 없는 코드 입력 화면**이 그려지고, '인증하기' 를 누르면 "회사를 먼저 선택해주세요."
   가 뜬다. `#code-step` 은 `#email-step` 의 **형제**라 함께 안 숨는다. 기존 결함이지만 ⑤ 가 창을

2. **`SM-23b` 동어반복 축약**. 첫 응답이 이미 429 면 대조군이 곧 429 라 SM-23 의 재확인이 되고

**⚠ 실측이 반증한 내 주장 하나**(주석·SPEC 에 정정 기록):

| ③ | **`nginx -t` 는 `root` 디렉터리·파일 존재를 검사하지 않는다** — docroot 오류를 문법검사가 못 잡는다 |
| ⑦ | **`server/.env` 는 bash `source` 로도 읽힌다** — `SMTP_FROM` 은 반드시 따옴표. 고쳤으면 **양쪽 파서로 검증** |
| ⑧ | **코어 2개** — Workflow 동시 상한이 사실상 1. 병렬은 **Agent 팬아웃**으로 |
| ⑨ | **메일 엔드포인트 시험은 `@` 가 없는 문자열로** — `x@example.invalid`·`a@b.c` 는 **통과해서 실제 발송된다** |
| ⑫ | **하네스는 대조군이 200 을 내는지 먼저 확인하고 판정하라** — 전부 404 인 걸 성공으로 읽는다(권한 문제로 실제 겪음) |
| ⑬ | **`git merge-tree --write-tree` 는 git 2.34 에 없다**(이 호스트). 충돌 검사는 구형 3인자 형태나 **임시 워크트리 리허설**로 |

**이번 세션에 추가로 확인한 것**(§4 에 정식 등재 대기):
- **beta 의 `/assets/v2/` 도 별도 경로였다** — 드리프트 해소 전, `web/*.html` 만 동기화하면
  자산이 빠져 스크립트가 404 로 미로드된다. **지금은 트리가 하나라 해당 없음**이지만, 임시
  워크트리를 다시 만들면 같은 함정이 돌아온다.
- **`header:not([data-global]) nav` 는 내용 너비** — `margin-left:auto` 가 밀 여백이 없다.
  `nav { flex:1 1 auto }` 를 함께 줘야 우측 정렬이 된다.
- **Playwright 기본 UA(`HeadlessChrome`)는 prod 봇 방어(Layer B)에 403** — 정상 Chrome UA 로
  측정하라. root 실행이라 `chromium_sandbox=False, args=["--no-sandbox"]` 필요
  (gstack `browse` 스킬은 root 샌드박스 문제로 실패한다).
- **`pgrep -f`/`pkill -f` 는 자기 명령줄을 잡는다** — 정리 검증 시 `ps -eo args | grep 'up[.]py'`
  처럼 자기참조를 피하거나 포트 확인으로 판정하라. **이번에 실제로 당했다**: `pkill -f
  'harness/upstream.py'` 가 그 문자열을 담은 자기 bash 를 죽여 셸이 exit 144 로 날아갔다.
  → **PID 로 죽이고 포트로 판정하라**(`ss -lntp` → `kill <pid>`).

**2026-07-28 후반 세션에서 추가된 함정(§4 정식 등재 대기)**:
- ⑭ **`release.sh` 는 nginx conf 를 배포하지 않는다** — `[6/7]` 은 `nginx -t && reload` 뿐이다.
  `/etc/nginx` 로 복사하는 것은 `provision.sh`(최초 프로비저닝)·`deploy-beta.sh`(베타) 뿐이고
  release 는 둘 다 부르지 않는다. **리포의 nginx 변경은 손으로 배치해야 한다**(절차는 §1-C ·
  SPEC §11.2 의 ⚠ 블록. 2026-07-28 반영으로 현재 시차는 없다 — 다음 변경 때 다시 걸린다).
- ⑮ **`add_header` 는 `always` 없이는 4xx/5xx 에 안 붙고, 값이 빈 문자열이면 헤더 자체가 생략된다.**
  후자가 `map $status … { default ""; }` 로 "429 에만 부착"을 만드는 원리다. 정적 값을 쓰면
  **성공 204 에도 붙는다**(실측표는 §1-B).
- ⑯ **`limit_req` 거부(429)는 excess 를 올리지 않는다** — nginx 는 `NGX_BUSY` 에서 커밋하지 않는다.
  "연타하면 대기가 길어진다"는 **틀린 모델**이다. 다만 연타는 **풀리는 토큰을 즉시 먹어** 공유
  버킷의 다른 경로를 굶긴다(실측 근거 §1-B).
- ⑰ **스모크 전량이 약 1.8초다.** "직전 실행이 버킷을 비웠으니 다음 실행은 다르겠지"를 기대하지 마라 —
  연속 재실행은 20초 회복 창 **한복판**에 떨어진다. 버킷 상태에 의존하는 판정은 반드시
  **대조군 부재 시 SKIP**(통과 아님)으로 설계하라.
- ⑱ **nginx `limit_req` 에 `burst=0` 은 문법 오류다** — 버스트 없음은 `burst` 를 **생략**한다.
- ⑲ **`web/assets` 는 라이브다**(기존 함정의 재확인). 이번엔 **red 검증조차** 원본을 못 건드려
  `git show HEAD:<파일>` 로 스크래치 사본을 만들어 돌렸다. 뮤테이션 테스트는 항상 사본에서.
