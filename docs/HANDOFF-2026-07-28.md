### P1 — 메일 경로

**3. 배달주소 기준 일일 상한 미구현.** 쿨다운이 창당 1통을 허용하므로 한 수신함 기준
`86400/60` = **1,440통/일**은 여전히 가능하다. 낮추려면 `mail_resend_cooldown_sec` 상향 또는
별도 카운터가 필요하다(리텐션 퍼지가 `TAUTH_CODE` 행을 지워 행 카운트로는 못 셈).

**4. 바운스 웹훅 (신규, prod 켜기 전 권장).** Resend API 키가 **발송 전용**이라
(`GET /emails` → `restricted_api_key` 401) 배달 결과를 조회할 수 없다.
→ **게이트웨이가 거부·격리해도 앱은 영영 모른다.** 화면엔 "코드를 보냈습니다"가 뜨는데 실제로는
안 간 상태가 될 수 있고, 그 사용자는 로그인을 아예 못 한다.

- 🚫 **전권(`full_access`) 키로 바꾸지 마라 — 검토 후 기각했다.** Resend 는 등급이
  `sending_access`/`full_access` **둘뿐이고 읽기 전용이 없다**. 그리고 전권 키는
  `GET /emails/{id}` 로 **본문까지 읽는다** — 우리 본문은 `인증 코드: 123456` 이다.
  그 키는 `server/.env` 에 있어 웹서버 위에 놓이므로, 서버 침해 시 **모든 로그인 코드가 읽힌다**.
  DB 에 평문을 안 남기는 설계를 정면으로 무너뜨린다. 도메인 제한(`domain_id`)도 발송 전용 키에만 걸린다.
- ✅ **웹훅이 정답** — 읽기 권한 없이 Resend 가 결과를 밀어준다. 이벤트: `email.bounced`·
  `email.delivered`·`email.complained`·`email.failed`·`email.delivery_delayed`·`email.suppressed`.
  서명은 Svix(`svix-id` 중복 제거 필요 — at-least-once 배달).
- ⚠ **구현 시 함정**: 웹훅은 **새 공개 POST 엔드포인트**라 nginx `^~ /api/v1/` 의 Layer A 게이트
  (`X-Loupit-Client` 요구)에서 **빼줘야** 한다 — `= /api/v1/health` 예외와 같은 패턴.

**DMARC 후속(선택).** Postmark 무료 등급이 **월요일 아침 주간 요약**을 `bji1062@gmail.com` 으로
보낸다(첫 요약까지 며칠). 몇 주 데이터로 정렬률·사칭 발신원을 확인한 뒤
`p=none` → `p=quarantine` → `p=reject` 로 올리면 `no-reply@jobcho.wiki` **사칭이 차단**된다.
로그인 코드를 메일로 보내는 서비스라 이게 최종 목표다.
⚠ **데이터 없이 올리면 우리 로그인 메일이 막힐 수 있다.** 반드시 보고서를 보고 판단하라.
⚠ `aspf=r`(완화) 유지 필수 / `ruf=` 절대 금지(본문 일부가 제3자에게 갈 수 있다).

### P3 — 적대검토 잔여 4건 (①은 `8a8734e` 로 해소)

**③ nginx `429` 에 `Retry-After` 가 없다.** 실측(격리 하네스): `HTTP/1.1 429` +
`Content-Length: 178`, `Retry-After` **부재**. `rate=3r/m` 이라 실제 대기는 **20초**인데 아무도 그
값을 모른다.
→ 메일 `=` 블록 **4곳**(prod·beta × login-code·verify-code)에
`add_header Retry-After 20 always;` (429 는 에러 응답이라 `always` 필수)
+ `web/assets/js/api.js` 의 `ApiError` 에 값을 실어 "20초 뒤에 다시 시도해주세요"로 숫자 노출.

**⑤ 프론트 abort(8s)와 SMTP 소켓 타임아웃(8s)이 같다.** `server/mailer.py` `_SMTP_TIMEOUT_SEC=8`
vs `web/assets/js/api.js` `DEFAULT_TIMEOUT=8000`. smtplib timeout 은 **대화 전체가 아니라 개별
소켓 연산** 상한이라 총 소요가 8s 를 넘을 수 있고, 그 순간 브라우저가 먼저 끊어
`login.js` 의 "네트워크 오류예요"로 떨어진다. 다만 재클릭해도 60초 쿨다운이 실발송을 억제한다.
→ 메일 발송 호출만 `{ timeout: 20000 }`(nginx `proxy_read_timeout 15s` 보다 길게) 또는
`_SMTP_TIMEOUT_SEC` 를 4~5 로.

> ③·⑤ 는 **함께 하는 게 좋다** — 둘 다 "메일이 느릴 때 사용자가 뭘 봐야 하는가" 문제이고
> 손대는 파일이 겹친다(`api.js`·메일 nginx 블록).

**② `.env.beta` 가 자기 메일 모드를 소유하지 않는다**(minor). 베타 프로세스의
`/proc/<pid>/environ` 키는 `M9_ENABLED` 뿐 — `MAILER_MODE`·`SMTP_*` 가 없어 **prod 소유의
`server/.env` 를 폴백으로 읽는다**. 그래서 prod 쪽 한 줄 수정이 베타를 조용히 뒤집는다.
남는 실결함: **베타 테스트가 prod 발신 도메인·무료 티어 쿼터를 공유**한다.
→ `.env.beta` 에 `MAILER_MODE=` 를 **명시**(상속 금지). 베타 실발송 e2e 가 계속 필요하면 베타 전용
키 + 서브도메인(`no-reply@beta.…`)으로 분리. `verify_mail.py` 는 `mailer_mode != 'smtp'` 만 실패로
보므로 "베타는 X 여야 한다"를 표현할 수 없다 → 대상 호스트 인자 + 역방향 어서션.

**④ logrotate `size` 상한 없음**(운영 위생). `daily`+`rotate 14`+`compress` 뿐.
`limit_req_log_level` 기본이 `error` 라 **429 마다 `error.log` 약 231B + `access.log` 약 116B**가
쌓인다. ⚠ 이 변경 탓이 아니다 — `limit_req` 는 선재했다. 현재 총 2.5M·루트 14G 여유라 급하지 않다.
→ `/etc/logrotate.d/nginx` 에 `maxsize 200M`(라이브 파일이라 별도 승인 필요).

> **✅ 반증돼 조치 불필요한 것들**(경로 정규화 우회 · XFF 로 키 흐리기 · 앱 직접 타격 · IPv6 분산 ·
> 프론트 안내 오인 · `conf.d/*.bak` include)은 `[B §3 P3]` 의 "반증됨" 절에 실측 근거와 함께 있다.
> **다시 조사하지 마라.**

| ① | **`limit_req` 는 PREACCESS** — `return` 으로 끝내는 location 에선 평가되지 않는다. 리밋 하네스는 **더미 업스트림 + `proxy_pass`** 필수 |
| ② | **nginx 롤백은 `reload` 의 exit 0 을 믿지 마라** → `infra/deploy/rollback-nginx.sh` 를 써라(`DRY_RUN=1` 먼저) |
| ③ | **`nginx -t` 는 `root` 디렉터리·파일 존재를 검사하지 않는다** — docroot 오류를 문법검사가 못 잡는다 |
| ⑦ | **`server/.env` 는 bash `source` 로도 읽힌다** — `SMTP_FROM` 은 반드시 따옴표. 고쳤으면 **양쪽 파서로 검증** |
| ⑧ | **코어 2개** — Workflow 동시 상한이 사실상 1. 병렬은 **Agent 팬아웃**으로 |
| ⑨ | **메일 엔드포인트 시험은 `@` 가 없는 문자열로** — `x@example.invalid`·`a@b.c` 는 **통과해서 실제 발송된다** |
| ⑫ | **하네스는 대조군이 200 을 내는지 먼저 확인하고 판정하라** — 전부 404 인 걸 성공으로 읽는다(권한 문제로 실제 겪음) |
| ⑬ | **`git merge-tree --write-tree` 는 git 2.34 에 없다**(이 호스트). 충돌 검사는 구형 3인자 형태나 **임시 워크트리 리허설**로 |

**이번 세션에 추가로 확인한 것**(§4 에 정식 등재 대기):
- **beta 의 `/assets/v2/` 도 별도 경로였다** — 드리프트 해소 전, `web/*.html` 만 동기화하면
  자산이 빠져 스크립트가 404 로 미로드된다. **지금은 트리가 하나라 해당 없음**이지만, 임시
  워크트리를 다시 만들면 같은 함정이 돌아온다.
- **`header:not([data-global]) nav` 는 내용 너비** — `margin-left:auto` 가 밀 여백이 없다.
  `nav { flex:1 1 auto }` 를 함께 줘야 우측 정렬이 된다.
- **Playwright 기본 UA(`HeadlessChrome`)는 prod 봇 방어(Layer B)에 403** — 정상 Chrome UA 로
  측정하라. root 실행이라 `chromium_sandbox=False, args=["--no-sandbox"]` 필요
  (gstack `browse` 스킬은 root 샌드박스 문제로 실패한다).
- **`pgrep -f`/`pkill -f` 는 자기 명령줄을 잡는다** — 정리 검증 시 `ps -eo args | grep 'up[.]py'`
  처럼 자기참조를 피하거나 포트 확인으로 판정하라.
