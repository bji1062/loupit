### D-1. 범위 개정 — "소셜피드 영구 제외"(SC10) 와의 충돌

`docs/PRD/04-범위.md` SC10 은 **"비밀번호·OAuth/소셜 로그인·소셜피드 = 영구 제외"** 다. 커뮤니티
게시판은 소셜피드와 이웃이다. 그냥 만들면 문서와 코드가 어긋난 채로 간다(함정 (61) 계열 —
문서가 허위가 된다).

→ **제안: SC15 "커뮤니티(게시판)" 를 신설**하고 SC10 의 '소셜피드' 정의를 좁힌다.
*소셜피드 = 팔로우·타임라인·개인화 피드* (계속 제외) / *커뮤니티 = 카테고리 게시판 + 댓글 +
좋아요* (SC15 In-scope). 2026-07-14(비교 로그)·07-21(SC14) 개정과 같은 절차 — PRD/04·SPEC/04
INV-1 표면 열거·TASK/14 신설.

### D-2. 쓰기 권한 — 로그인(M9) 필수, 열람은 익명

| 안 | 장점 | 단점 |
|---|---|---|
| **A. 로그인 필수(추천)** | 기존 M9(이메일 코드 로그인·세션·CSRF·닉네임) 그대로 재사용 · 스팸 1차 방어 · 신고·삭제 시 주체 특정 가능 · prober 와 동일 | 실회원 3명 — 초기 글은 운영자가 채워야 한다 |
| B. 익명 쓰기 | 진입 마찰 0 | 스팸·명예훼손 글에 대한 임시조치(정보통신망법 §44-2) 주체 특정 불가 · 봇 플러드(실측: `GET /` 하루 1,875~11,036건 vs 실세션 1~4) · 새 익명 쓰기 표면(INV-1) |

**"재직자" 배지**를 붙일 수 있다 — 배지 계보(`badge.js`)가 이미 이 개념을 갖고 있다.

### D-3. 회사정보 탭의 내용물 — DART 재무. **키가 선행 조건**

`PLAN-회사정보-확장` 의 3단계(수집)가 미완이다. `server/.env` 에 `DART_API_KEY` 가 **없다**
(키 이름 목록 확인: DB·SMTP·pepper·OPERATOR 뿐). 수집기는 키 없이 만들 수 있지만(픽스처로
테스트) **실데이터 적재·재생성은 키가 있어야** 한다.

→ 사용자가 키를 `server/.env` 에 넣거나(⚠ root 편집 후 `chown ubuntu:ubuntu` — 함정,
`loupit-deploy-host`), 이 세션에 알려주면 내가 넣는다. **데이터 없는 "준비 중" 탭은 라이브에
내지 않는다** — "화면은 뜨는데 아무것도 없는" 반배포는 이 프로젝트가 이미 한 번 겪은 사고다.

## 3. 설계

### 3-1. 내비게이션

```
gnb(수기 셸):   [로고]  홈  커뮤니티  회사정보  비교 조합 ·········· [검색] [로그인]
생성기 헤더:    [로고]  홈  커뮤니티  회사정보  비교하기 ················· [로그인]
```

- 현재 탭에 `aria-current="page"` — 활성 스타일 1규칙(`styles.css` 핫스팟, 한 레인만).
- **회사정보 → `/companies`**(기존 인덱스를 "회사정보" 로 확장). 새 URL·nginx 블록 없음.
- **커뮤니티 → `/community/`**. 탭은 **커뮤니티가 실제로 열리는 PR 에서** 넣는다(죽은 탭 금지).
- 동기화 테스트 `generator/tests/test_gnb_tabs.py`: 생성기 partial 과 수기 셸 7개의 탭 `(라벨, href)`
  목록이 상수 `GNB_TABS` 와 일치. `test_authnav.py` 와 같은 문자열 검증 방식.
- 로그인 셸(login/mypage/verify/edit/edits)은 지금 "← 비교하러 가기" 하나뿐이다 — 같은 탭 세트로 통일.

### 3-2. 커뮤니티 (SC15)

**URL** (nginx `location ^~ /community/ { try_files $uri /community/index.html; }` 1블록 +
`location = /community { return 301 /community/; }` — compare 패턴):

| URL | 화면 | 권한 |
|---|---|---|
| `/community/` | 목록(`전체`·공지·자유·이직 고민·건의사항 탭 · 정렬 · 페이징) | 익명 |
| `/community/{post_id}` | 상세 + 댓글 + 좋아요 | 익명(쓰기 버튼은 로그인 시) |
| `/community/write` | 작성 | 로그인 → 아니면 `/login?next=` (login.js 에 `next` 지원 추가 필요 — 현재 없음) |
| `/community/{post_id}/edit` | 수정 | 본인 |

셸은 `web/community/index.html` **하나**, `community.js` 가 `location.pathname` 으로 4화면을 가른다
(SPA 셸 패턴 = `web/index.html` + `app.js` 와 동일). 본문은 JS 렌더라 **1차는 색인을 기대하지 않는다**
(robots 허용은 하되 noindex 도 안 붙임). 2차에 게시글 정적 스냅샷 재생성을 검토한다.

**스키마 4테이블** (T-접두·`_CD/_NM/_CTNT/_CNT/_DTM` 접미·감사 4종·ENUM 금지 규약 그대로):

```
TPOST          POST_ID · MBR_ID(FK TMEMBER, ON DELETE SET NULL — 편집이력과 같은 존치 규약) ·
               CATEGORY_CD(notice/free/career/suggestion) · TITLE_NM(100) · BODY_CTNT(TEXT, 5,000자) ·
               COMP_ID(FK TCOMPANY, NULL 허용, ON DELETE SET NULL — 회사 태그) ·
               LIKE_CNT · COMMENT_CNT(비정규화 카운터) · STATUS_CD(active/deleted/hidden) ·
               INS/MOD 4종 · INDEX (CATEGORY_CD, POST_ID) · (COMP_ID, POST_ID) · (STATUS_CD, POST_ID)
TPOST_COMMENT  COMMENT_ID · POST_ID(FK CASCADE) · MBR_ID(SET NULL) · BODY_CTNT(1,000) · STATUS_CD
TPOST_REACTION POST_ID · MBR_ID · REACTION_CD(like) · UNIQUE(POST_ID, MBR_ID) — 회원당 1회
TPOST_REPORT   REPORT_ID · TARGET_TYPE_CD(post/comment) · TARGET_ID · MBR_ID · REASON_CD ·
               DETAIL_CTNT(500) · STATUS_CD(pending/actioned/dismissed) · DECIDED_BY_ID · DECIDED_DTM
```

- **조회수는 두지 않는다.** 봇 트래픽이 실사용의 수백 배라(`GET /` 1,875~11,036 vs 실세션 1~4)
  조회수는 곧 거짓 숫자가 된다 — 함정 (57)("대체 콘텐츠가 집계인 척") 과 같은 계열. 정렬은
  **최신·댓글·좋아요** 3종.
- 삭제는 **소프트**(STATUS_CD=deleted, 본문 마스킹). 신고 처리(hidden)는 운영 콘솔.
- M9 참여 테이블 그룹(FK 가 TMEMBER)이라 `conftest.PARTICIPATION_CREATE_ORDER` 에 편입,
  라우터 등록도 `m9_enabled` 조건 안(prod ON 이므로 즉시 활성).

**API** (`/api/v1`, 라우터 `server/routers/post.py`, 서비스 `services/post.py`, 모델 `models/post.py`):

| 메서드·경로 | 권한 | 비고 |
|---|---|---|
| `GET /posts?category=&sort=latest\|comments\|likes&limit=20&before=` | 익명 | 키셋 페이징(편집 이력 `before` 관례). `no-store` 또는 `max-age=30` |
| `GET /posts/{id}` | 익명 | `hidden/deleted` 는 404 |
| `GET /posts/{id}/comments?before=` | 익명 | |
| `POST /posts` | member+CSRF | 일일 상한(`daily_post_limit`=10) → 429. `category=notice` 는 운영자만(아니면 403) |
| `PUT /posts/{id}` · `DELETE /posts/{id}` | 본인 | 남의 글 403 |
| `POST /posts/{id}/comments` · `DELETE /posts/{id}/comments/{cid}` | member / 본인 | 일일 상한 50 |
| `PUT /posts/{id}/like` | member | 토글 → `{liked, like_cnt}` (멱등) |
| `POST /reports` | member | 대상 유형·ID·사유 → 콘솔 큐 |
| `GET /console/queues` 확장 · `POST /console/reports/{id}/decide` | 운영자(터널) | hide/dismiss. 되돌릴 수 있는 것만(하드 삭제 없음 — SP-AUTH-19.4 규약) |

- 익명 GET **+3**, 참여 쓰기 **+8**, 콘솔 **+1** → TS-1 개정. 미들웨어 0 불변(TS-2) 유지.
- 입력 신뢰 경계: 길이 제한·공백-only 금지·URL 3개 초과 시 422(스팸)·표시는 `textContent` 만
  (마크다운 없음, 줄바꿈만). 회사 태그는 `comp_id` 로만(이름 문자열 금지).
- 응답의 작성자 식별은 **닉네임만**(INV-8) + `is_mine`(세션 있을 때) + `verified_comp`(재직 배지).

**프론트** (`web/assets/js/community.js` + `community.css`, 테스트 `community.test.js`):
목록·상세·작성·댓글·좋아요·신고. 로그인 상태는 `getMe()` 프로브(authnav 와 동일 3분기).
`api.js` 에 헬퍼 +9(`listPosts`·`getPost`·`createPost`…). 초안은 localStorage 24h(입력 초안 관례).

**정책·운영**: privacy **P10**(게시물 항목·보존·탈퇴 시 처리 = 닉네임 존치·본문 존치 또는 삭제 선택),
terms **T6**(게시물 책임·금지행위·임시조치·이용허락). `ops digest` 에 신고 대기 건수 추가.

### 3-3. 회사정보 탭 — DART 재무를 화면에 (PLAN-확장 4단계 착지)

**노출 지점 2곳**:

1. **`/companies` 확장** = 회사정보 탭의 착지. 제목 "회사정보 — 등록 회사 102곳", 각 행에
   **최신 사업연도 매출·영업이익·순이익**(억원, 기준 표기) + 업종. **일반/금융 두 섹션**으로 분리
   (지표 세트가 다르다 — 같은 표에 넣으면 빈칸 또는 다른 의미의 숫자). 데이터 없는 회사는
   "공시 없음(비상장)" 로 **비워 두고 그렇게 말한다**.
2. **회사 상세 `/company/{slug}` 에 "실적" 섹션**(`partials/_finance_table.html`): 최근 5개년
   연도별 표 + 전년 대비 증감률(사실) + 기준(연결/별도) + 출처(DART 접수번호 → `dart.fss.or.kr`
   아웃링크) + 한 줄 고지("공시 수치이며 평가·전망이 아닙니다"). CJ ENM 2페이지는 같은 법인
   수치 + "법인 기준 공시" 표기.

**데이터 파이프라인** (`PLAN-확장` §4 1-a~1-d 그대로, 도구 위치만 확정):

| 단계 | 산출물 | 비고 |

| 1-a 매칭 적재 | `db/seed/load_corp.py` — `corp_code_map.csv` → `TCORP`·`TCOMPANY_CORP` 멱등 upsert | UNMAPPED(CJ올리브영) 건너뜀. `load.py --fresh` 는 참조 5테이블만 DROP 하므로 재시드 후 **재적재 필요** — load.py 단계에 편입 |
